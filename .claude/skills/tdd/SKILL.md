# 테스트 우선 개발

## 1. 준비

1. 작업의 요구사항과 완료 조건을 확인합니다. Jira 이슈, 기능 명세의 기능 ID(F-xx), `docs/A305_기획안/04_AI용_요구사항명세서.md` 8절의 테스트 ID(T-xx)를 근거로 삼습니다.
2. 영역 지침을 읽습니다. 백엔드는 `backend/AGENTS.md`, 프론트엔드는 `frontend/AGENTS.md`입니다. 테스트 방식과 실행 명령은 영역 지침을 따릅니다.
3. 요구사항이 모호하거나 문서끼리 내용이 다르면 가정하고 진행하지 않고 사용자에게 확인합니다.
4. 테스트 우선 적용 대상인지 판단합니다. 제외할 수 있는 변경은 `docs/code-conventions.md`의 "테스트 우선 개발"을 따릅니다. 제외하면 이유를 기록하고 변경에 맞는 검증으로 대신합니다.

## 2. 테스트 목록 작성

구현 전에 검증할 시나리오를 목록으로 정리합니다.

- 정상 동작
- 경계값과 빈 값
- 실패 상황: 잘못된 입력, 외부 서비스 오류·시간 초과, 사용량 소진, 중복 요청
- 상태를 바꾸는 동작이면 변경 전후의 상태

목록은 작업 계획에 적습니다. 시나리오가 많거나 요구사항 해석이 필요한 항목이 있으면 구현 전에 사용자에게 목록을 보여주고 확인을 받습니다.

## 3. Red-Green-Refactor 반복

목록의 시나리오를 하나씩 처리합니다. 테스트를 한꺼번에 작성한 뒤 구현을 몰아서 작성하지 않습니다.

### Red

1. 시나리오 하나를 검증하는 테스트를 작성합니다.
2. 테스트를 실행해 실패를 확인합니다.
3. 기대한 동작이 없어서 실패하는지 확인합니다. 컴파일 오류로 실패하면 클래스와 메서드 시그니처만 만들어 검증 단계에서 실패하게 합니다. 테스트 코드의 오타나 설정 문제로 실패하면 테스트를 고친 뒤 다시 확인합니다.

### Green

1. 실패한 테스트를 통과시키는 만큼만 구현합니다. 목록의 다음 시나리오나 가상의 요구사항을 미리 구현하지 않습니다.
2. 작성 중인 테스트와 관련 테스트를 실행해 모두 통과하는지 확인합니다.

### Refactor

1. 테스트가 통과하는 상태에서 이름, 중복, 책임 분리를 정리합니다. 새 동작은 추가하지 않습니다.
2. 정리한 뒤 테스트를 다시 실행합니다.
3. 정리할 것이 없으면 다음 시나리오로 넘어갑니다.

## 4. 버그 수정

1. 버그를 재현하는 테스트를 먼저 작성하고 현재 코드에서 실패하는지 확인합니다.
2. 재현하지 못하면 코드를 고치지 않고, 확인한 내용과 재현에 필요한 정보를 사용자에게 알립니다.
3. 테스트를 통과시키도록 수정한 뒤, 같은 원인으로 생길 수 있는 다른 경우도 테스트로 확인합니다.

## 5. 지켜야 할 기준

- 구현 코드를 먼저 작성하고 테스트를 맞춰 넣지 않습니다.
- 테스트를 통과시키려고 기존 테스트를 삭제·비활성화(`@Disabled`, `[Ignore]` 등)하거나 기대값을 바꾸지 않습니다. 요구사항이 바뀌어 테스트를 고쳐야 한다면 근거를 설명하고 사용자 확인을 받습니다.
- 반환값, 상태, 응답, 발생한 오류처럼 밖에서 관찰할 수 있는 결과를 검증합니다. private 메서드나 내부 호출 순서를 검증하지 않습니다.
- 자동 테스트에서 외부 AI 서비스(STT·LLM·TTS)와 실제 네트워크를 호출하지 않습니다.
- 실행 시점, 실행 순서, 난수에 따라 결과가 바뀌는 테스트를 만들지 않습니다.
- 실행하지 않은 테스트를 통과했다고 보고하지 않습니다. 테스트를 직접 실행할 수 없으면 실행 방법을 안내하고, 사용자의 실행 결과를 받은 뒤 다음 단계로 진행합니다.

## 6. 마무리

1. 영역 지침의 전체 테스트와 포맷·검사 명령을 실행합니다. 검사 도구가 아직 구성되지 않았다면 그렇다고 기록합니다.
2. 아래 형식으로 결과를 보고합니다. MR의 검증 항목에 그대로 옮길 수 있게 작성합니다.

```text
## 테스트 우선 진행 결과
- 요구사항: <Jira 키, 기능 ID, 테스트 ID>
- 추가·변경한 테스트: <시나리오별 테스트 이름>
- Red 확인: <실행 명령, 시나리오별 실패 이유 요약>
- Green 확인: <실행 명령, 결과>
- 전체 검사: <실행 명령, 결과>
- 테스트 우선 제외 항목: <항목과 이유, 대신 수행한 검증>
- 확인하지 못한 사항: <항목과 이유>
```
