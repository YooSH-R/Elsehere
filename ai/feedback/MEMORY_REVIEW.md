# 저장된 NPC 기억 응답 점검

S15P31A305-139의 로컬 오류 분석 도구다. 이미 저장된 사실별 기억 응답을 읽고 형식·근거 참조·변경 계획을 검사하며, 의미 검토할 항목을 표시한다. 외부 모델 호출·키 로딩·다운로드 기능은 없다.

## 입력 준비

- [회귀 데이터셋](samples/memory_regression/README.md)의 G01–G22가 의미 검토 대상이다. P 유형은 의도적으로 잘못된 고정 후보이므로 실제 모델 품질 대상에서 제외한다.
- 각 응답을 UTF-8 JSON으로 `G01.json`, `G03.json`처럼 저장한다. 응답은 해당 사례의 전체 사실별 참조 계약 `0.1.0` 출력이어야 한다.
- 응답의 요청 ID·사용자·NPC·대화·대화 리비전·분석 설정·기억 기준 버전이 입력과 맞아야 한다. 다른 요청의 응답을 평가하려고 식별자를 임의 변경하지 않는다.
- 기존 `/v1/memory` 전체 카드 응답이나 LLM 원시 본문만 있는 자료는 이 형식과 다르다. 도구는 누락된 식별자·범위·버전을 추측해서 채우지 않으며 `invalid_structure`로 표시할 수 있다.
- 응답이 없는 사례는 파일을 만들지 않는다. 고정 정답으로 채우지 않으며 `not_run`으로 집계한다. 폴더에는 알려진 G 사례 응답 JSON만 둔다. 별도 메타데이터·P 자료·이름이 다른 파일이 있으면 먼저 분리한다.

## 실행

`ai/feedback/`에서 실행한다. 응답 출처를 반드시 지정하며, 모델명은 호출자가 제공한 표시값이고 출처 인증이 아니다.

```powershell
# 이미 저장된 모델 응답 점검. 이 명령은 모델을 호출하지 않는다.
python -X utf8 review_memory_results.py --responses-dir <응답폴더> --origin saved_model_response --model <저장당시모델명> --output <새_보고서.json>

# 합성 응답으로 검사기 동작 점검. 실제 모델명은 붙이지 않는다.
python -X utf8 review_memory_results.py --responses-dir <합성응답폴더> --origin synthetic_demo

# 도구 회귀 검사. 실제 외부 연결을 금지한다.
python -m pytest tests/test_memory_review.py -q
```

`--dataset`으로 다른 개발용 합성 자료 폴더를 지정할 수 있다. 현재 입력 형식은 `memory-regression-1.0`이다. `--output`은 새 파일만 만들며 기존 결과를 덮어쓰지 않는다.

종료 코드 0은 모든 대상의 자동 검사가 통과했다는 뜻이며 의미 품질 합격이 아니다. 1은 표시할 차이·거부 응답·미실행이 있다는 뜻, 2는 입력·출처·파일 저장 오류다. 실제 호출 옵션이나 자동 재시도는 제공하지 않는다.

## 결과 해석

| 상태 | 의미 |
| --- | --- |
| `checks_passed` | 계약과 기대 변경 계획의 비교에서 표시할 차이가 없음. 의미 검토는 `pending` |
| `flagged` | 누락·추가·활성 값·처리 상태 차이가 있어 사람이 검토해야 함 |
| `rejected` | JSON·구조·참조·정책·파일 읽기 오류. 활성 기억으로 적용하지 않음 |
| `not_run` | 저장된 응답 파일 없음. 합격·오답·0토큰 결과로 대체하지 않음 |

| 오류·검토 코드 | 확인할 것 |
| --- | --- |
| `invalid_json` | 잘린 JSON 등 파싱 불가 |
| `invalid_structure` | 사실별 계약 형식 불일치. 기존 카드 응답 등 계약 종류부터 확인 |
| `invalid_reference_or_policy` | 실제 인용·발화·대상·요청 범위·버전·허용 키·상한 확인. `detail_code`는 기존 정책 오류 코드이며 개별 의미 오류를 확정하는 분류가 아님 |
| `duplicate_fact_key` | 완료 후보 안에 같은 키가 여러 번 등장 |
| `missing_expected_change` | 기준 계획에 있는 action/key가 반영 계획에 없음. 누락 의심 |
| `unexpected_change` | 기준에 없는 action/key. 정당한 추가인지 검토 |
| `missing_active_fact`, `unexpected_active_fact` | 계획 적용 후 활성 키의 누락·추가 |
| `value_diff_review` | 같은 키의 내용·종류가 다름. 의역인지 실제 오류인지 사람 판단 필요 |
| `outcome_mismatch` | 계획 상태 또는 다음 버전이 기준과 다름 |
| `missing_response`, `unreadable_response` | 미수령 또는 파일 읽기·인코딩 오류 |

`issue_counts`는 코드 발생 횟수다. 한 응답에 여러 항목이 있을 수 있어 합계를 실패 사례 수나 정확도로 계산하지 않는다. 형식이 맞고 원문 인용이 존재해도 의미가 뒷받침되지 않는 사실을 만들 수 있다. 자동 표시가 없는 응답도 의미 검토를 거쳐야 한다.

## 수동 의미 검토

1. 거부 응답은 구조·참조·정책부터 확인한다. `flagged`는 누락·불필요한 추가·모순·기억 손실 여부를 대조한다.
2. `checks_passed`도 발화 의미와 후보 내용을 대조한다. `rubric.must`와 `must_not`의 충족 여부를 기록한다. 이 문자열을 모델에 보내 정답을 노출하지 않는다.
3. 정답 문장과 표현이 달라도 같은 뜻이면 의미상 오류로 세지 않는다. 정책이나 의도가 모호하면 판단 보류한다.
4. [품질 기준](../../docs/ai-memory-quality.md)에 따라 정확성·중복·모순·누락·보존을 각각 판정한다. 이번 합성 정답도 팀 검토 전 초안이므로 기준이 잘못됐다면 기대값을 덮어쓰기 전에 근거를 남긴다.

```text
사례 ID / dataset_version:
request_sha256 / response_sha256:
검토자 / 검토일:
정확성 / 중복 / 모순 / 누락 / 보존: 합격·불합격·판단 보류·N/A
근거 설명 / 오류 분류 / 개선 대상:
```

해시는 검토한 입력·응답의 구분용이다. 호출 출처나 정답의 정확성을 인증하지 않는다. 입력이나 응답이 바뀌면 이전 의미 판정을 그대로 재사용하지 않는다. 이 도구는 사람 판정을 자동 수입하거나 의미 점수를 계산하지 않는다.

보고서는 원문 응답·대화·API 키를 복사하지 않고 사례 ID·코드·해시를 기록한다. 저장된 실제 응답과 검토 기록은 승인된 로컬 위치에서 관리한다. 결과의 `provenance_verified: false`, `model_calls_made: 0`, `semantic_quality_evaluated: false`를 유지하며 실제 모델 평가를 마친 것으로 보고하지 않는다.
