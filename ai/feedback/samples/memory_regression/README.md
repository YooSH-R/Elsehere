# NPC 기억 회귀 데이터셋

S15P31A305-130의 개발용 합성 자료다. `memory-regression-1.0`은 독립 JSON 34건으로 구성된다. 실제 플레이 데이터나 담당자가 수집한 음성을 사용하지 않았다. AI 도움으로 대화와 기대값 초안을 작성했으며, 팀의 의미 검수와 운영 정책 승인은 아직 받지 않았다.

## 자료 구분

| 유형 | 개수 | 의미 |
| --- | --- | --- |
| `semantic_reference`, G01–G22 | 22 | 대화에서 무엇을 기억·변경·유지해야 하는지 검토할 입력과 기대값 초안 |
| `policy_regression`, P01–P12 | 12 | 잘못된 근거·키·대상, 오래된 결과, 한도 오류 등에 대한 고정 후보와 기대 처리 |

각 JSON은 다른 사례나 Python 테스트 함수를 가져오지 않고 읽을 수 있다. 기준 응답은 모델 호출로 얻지 않았으며, 실제 코드 실행 결과를 복사해 정답으로 만든 것도 아니다. P 유형에는 의도적으로 잘못된 응답이 있으므로 모델의 정상 출력 예제로 사용하지 않는다.

현재 `/v1/memory`의 전체 카드 응답과는 다르다. 이 데이터는 [사실별 참조 계약 0.1.0](../../feedback/contract_v01.py)과 [기억 변경 계획](../../MEMORY_POLICY.md)의 개발용 자료다. 기존 HTTP API나 피드백 계약 0.3.0을 변경하지 않는다.

## 파일 구조

| 필드 | 설명 |
| --- | --- |
| `dataset_version`, `case_id`, `case_type` | 자료 버전·사례 식별자·유형 |
| `title_ko`, `source`, `tags` | 설명·합성 출처·점검 범주 |
| `rubric.must`, `rubric.must_not` | 사람이 의미를 검토할 때 볼 기대 판단과 금지 판단 |
| `request` | 대화·현재 요청 스냅샷을 포함한 독립 입력 |
| `fixture_response` | 고정 응답. G 유형은 기대 응답 초안, P 유형은 검사용 정상/비정상 후보 |
| `current` | 변경 계획 검사에 전달할 서버 측 현재 범위·기억·대화 리비전 |
| `policy` | 사례별 허용 키와 상한 |
| `expected` | 계획의 상태·다음 버전·활성 값·변경 대상 목록 또는 기대 오류 코드 |

`case.schema.json`은 자료 파일 자체의 형식이다. 요청·응답의 의미와 인용 참조는 실행 시 기존 계약 검사를 추가로 거친다. `expected`의 활성 값은 자유 문장 동의어를 자동 채점하는 정답 사전이 아니다.

## 포함 사례

| ID | 점검 내용 |
| --- | --- |
| G01–G05 | 명시적 선호, 단순 주문, 선호 변경, 동일 사실 반복, 특정 기억 철회 |
| G06–G09 | 친구의 선호, 가정, 인용, 현재 선호 부정 |
| G10–G13 | 수정 전사, 한국어 입력, 차단 발화 제외, final 발화 사용 |
| G14–G17 | 숙소·쇼핑·교통 선호와 게임 내 호칭 |
| G18–G22 | 결제·보상 권한, 새 대화의 기억 보존, 입력 내 지시문, 질문, 유효 전사 없음 |
| P01–P03 | 비허용 키, NPC 근거, 허구 인용 |
| P04–P07 | 철회 후 과거 결과, 다른 사용자, 잘못된 대상 ID, 같은 키의 복수 변경 |
| P08–P12 | 한도 부족, 묶음 일부 오류, 개수 상한, 수정 전사 리비전, 스냅샷 불일치 |

전체 제목·기대 판단은 [INDEX.md](INDEX.md)에서 볼 수 있다. G13은 이미 `final`로 넘어온 입력의 처리 사례이며 `abusive: null → final` 변환기를 검사하는 사례는 아니다.

숙소·쇼핑·교통 키는 확장 가능성을 검토하는 합성 사례용이다. 운영 키와 상한을 최종 확정한 것으로 취급하지 않는다. G09의 철회는 현재 사례 정책에 부정 선호를 저장할 별도 키가 없다는 전제다.

## 외부 호출 없이 검사

기존 개발 의존성이 설치된 환경에서 `ai/feedback/` 기준으로 실행한다.

```powershell
# 전체 JSON의 형식·고정 응답·기대 변경 계획 검사
python -X utf8 run_memory_regression.py

# 사례 하나 확인
python -X utf8 run_memory_regression.py --case G03

# 새 파일에 결과 저장. 이미 있는 파일은 덮어쓰지 않음
python -X utf8 run_memory_regression.py --output <새_결과파일.json>

# 검사기와 기본 포함 자료의 회귀 테스트
python -m pytest tests/test_memory_dataset.py -q
```

종료 코드는 0=모든 고정 사례 일치, 1=기대 처리 불일치, 2=자료·옵션·저장 오류다. 빈 자료, 중복 사례 ID, 다른 버전, 자료 형식 오류는 검사를 중단한다. 결과 파일은 사례 ID·유형·불일치 항목을 담고 원문 대화는 복사하지 않는다.

이 도구에는 `.env` 로딩, 외부 모델, 다운로드, 자동 재시도·실호출 옵션이 없다. `actual_model_evaluated: false`, `external_calls: 0`을 명시한다. 통과율은 고정 응답의 코드 회귀 결과이며 모델 정확도·WER·F1·실제 DB 유지 성능이 아니다.

## 이후 의미 평가에 쓰는 방법

1. 팀원이 G 유형의 확정 발화, `rubric`, 기대 응답을 검토한다. 애매한 사례는 보류하고 정책을 확정한다.
2. 실제 모델 호출을 별도로 승인받았을 때만 평가를 준비한다. 모델에 보낼 입력은 `request`이며, `fixture_response`·`expected`·`rubric`을 함께 보내 정답이 노출되지 않도록 한다. 이 실행기는 모델 평가를 수행하지 않는다.
3. 생성·수집한 응답의 구조·인용과 의미를 각각 검토한다. 표현이 달라도 같은 뜻일 수 있으므로 G 응답 문자열의 완전 일치로 의미 점수를 매기지 않는다.
4. [기억 품질 기준](../../../../docs/ai-memory-quality.md)에 따라 허구 사실·누락·모순·중복·보존을 판정하고, 합격/불합격/판단 보류/N/A를 기록한다. 원래 기준 응답을 모델 출력으로 덮어쓰지 않는다.

이 자료는 공개된 개발 회귀셋이다. 잠긴 최종 평가셋이나 운영 정확도 추정에 사용하지 않는다. 사례의 의미·정책·기대값을 변경하면 데이터셋 버전과 변경 이유를 함께 관리한다.
