> 짝 문서: `04_AI용_요구사항명세서.md` (기능 ID, API·데이터 계약, 수용 테스트의 상세 기준).

## 0. 읽기 규칙 및 진실성

- **[합의]**: 대화에서 정한 제품 의도와 필수 경험. 구현할 때 임의로 없애거나 2D/퀘스트 전용 게임으로 바꾸지 않는다.
- **[1주 목표]**: **1주 안에 빠르게 구현할 첫 MVP**의 기능. 최종 완성 수준이 아니라 작은 콘텐츠·최소 품질로도 사용자가 처음부터 끝까지 이용할 수 있는 동작을 말한다.
- **[3주 필수]**: 6명+AI 코딩 에이전트 협업으로 **3주 안에 구현·통합·PC 웹 배포를 목표**로 하는 핵심 시스템. NPC 장기 기억·친밀도·일일 퀘스트는 여기에 속하며 단순한 언젠가의 로드맵이 아니다.
- **[4주 조건부]**: PC 웹 배포와 품질이 확보되면 모바일 웹에 **동일한 3D 세계+NPC AI 대화**를 제공한다. 실패하면 PC 안정화.
- **[후속]**: 3주 핵심 범위를 넘어서는 비전·기능(의심도, 경제, 집 꾸미기 등). 비전은 보존하되 현재 개발을 방해하지 않게 한다.
- **[예시]**: Emma/Alex, 카페 주문, 행사 전달, 우유 품절, 월드 오브젝트 등은 대표 구현 사례다. 팀이 같은 학습·세계 반응을 충족하는 다른 콘텐츠로 대체할 수 있다. **샘플 대사·임의 숫자를 고정 콘텐츠/사업 정책으로 오인하지 않는다.**
- **[미확정]**: 엔진/DB/LLM/STT/TTS 벤더·정량 무료 한도·보안과 음성 보관 기간·서비스명/플레이어 배경 설정. 요구사항 문서의 기술 표는 제안 계약이며 임의 확정 금지.
- PoC 결과, 프로토타입, 배포된 MVP는 다른 표현이다. 동작 사실을 검증하지 않았다면 `완료`라고 보고하지 않는다.

## 1. 제품의 출발점과 결코 축소할 수 없는 정체성 [합의]

**문제 발견.** 기존 앱에서 어휘 암기와 정해진 문장 반복은 쉽게 지루해진다. 해외 생활을 하며 언어에 계속 노출되면 자연스럽게 익힐 수 있지만 비용·시간 제약이 있다. 단어를 알더라도 실제 질문 앞에서 막히며, 한국어·영어가 섞인 말도 현실적으로 나온다.

**제품 정의.** 사용자는 미국의 가상 소도시에서 영어를 사용하며 *생활*한다. 자유롭게 걷고, 사물을 살펴보고, 주민과 말하고, 친분을 쌓고, 요청을 받아 퀘스트를 하고, 원하면 복습한다. **언어 학습이 모든 활동을 잠그는 관문이 아니라, 생활의 결과와 피드백으로 이어지는 시스템**이다.

**감성 목표.** 사용자가 “**게임 안에 사람이 있잖아!**”라고 느끼는 것. NPC는 회화 문제를 출제하는 버튼이 아니라 고유 직업·성격·생활 행동·기억·관계·상황 인식을 가진 가상 주민이다. 가상 에이전트가 실제 의식을 가진다고 주장하는 것은 아니다. **일관된 상태·행동·기억으로 실제 존재감을 만드는 게임 설계 목표**다.

### 반드시 지킬 10가지 원칙

1. **미션 없는 자유 탐험 허용.** 동시에 특정 NPC를 만나기 위한 일일 퀘스트도 제공한다. “퀘스트를 위해 NPC를 찾는 흐름”도 정식 플레이 방식이다.
2. **PC 웹 3D**가 시작 플랫폼이며 실행 파일 설치가 기본 배포 방식이 아니다. 3D를 2D 회화 메뉴로 대체하지 않는다.
3. 기본은 **3인칭 자유 이동**, NPC 1:1 대화 중에는 **1인칭 NPC 중심 카메라+이동 잠금**. 사용자가 종료/나가기를 선택하면 복귀한다.
4. NPC와의 대화는 **영어 음성 중심의 자유 회화**다. 날씨나 취미를 묻는 일상 대화를 주문 시나리오의 정답 목록으로 제한하지 않는다. 필요하면 텍스트 보조를 제공한다.
5. 사용자는 영어·한국어·혼용·미완성 발화를 할 수 있다. AI가 **대화 맥락의 의도**를 추론하고 필요할 때 표현을 돕는다. 틀린 영어라도 대화를 멈추게 하지 않는다.
6. 대화 이후 **짧고 부담 없는 자동 피드백**과 선택형 상세 분석·다시 듣기·재발화·표현 저장이 있다. 학습 내역은 다시 열 수 있다.
7. 세상 속 **사물·공간 탐색 자체가 학습**이다. 호버/초점 시 영어 이름·한국어 뜻·간단 예문, 저장; **회상 퀴즈 5회 성공** 시 자동 설명만 숨기고 수동 보기는 유지.
8. **NPC 장기 대화 기억은 3주 필수**, **호감도=친밀도**(하나의 개별 NPC 관계 지표), **선택형 일일 퀘스트도 3주 필수**다. 1주 MVP에 모두 완성해야 하는 것은 아니다.
9. AI는 **대화·요약·후보 의도**를 생성하고, **서버/게임 로직**이 주문 상태·퀘스트 완료·보상·친밀도·세계 사실을 검증 및 변경한다. AI가 마음대로 세계 상태를 갱신하지 않는다.
10. 기술 장애나 무료 AI 한도 소진 시 **탐험·이미 저장한 표현·복습 기능은 계속 가능**하다. 무제한 외부 API 호출, 유료 키 클라이언트 노출 금지.

## 2. 세계의 구체적인 형태와 초반 사용자 경험

### 마을과 시점

- 시작 세계: 미국 느낌의 허구적 소도시. 첫 언어: 미국 영어, 한국어 학습 보조. 마을 공식 명칭/사용자가 새 주민인지 외부 방문객인지는 미확정.
- 첫 수직 슬라이스: **걷는 거리 1개+진입 가능한 카페 1개**, 직원형 NPC(예시 `Emma`), 행인형 NPC(예시 `Alex`), 호버 대상 소수(약 10개는 콘텐츠 제안치).
- 사물: 컵, 메뉴판, 의자, 벤치, 가로수, 횡단보도 등. 이름·의미·예문을 게임 UI에 표시한다. 호버 오브젝트는 어휘 `vocab_id`로 매핑한다.
- 기본 상태: `EXPLORE_THIRD_PERSON` → NPC 접근/행인 선제 이벤트 → `DIALOGUE_FIRST_PERSON`(이동 잠금·음성 UI) → 종료 → 피드백(건너뛰기 가능) → 탐험 복귀. 카페 입장 자체가 곧 대화 시작을 강제하지는 않는다.
- NPC는 대화하지 않을 때도 간단한 루프(걷기/정리/둘러보기)를 수행한다. 장기적으로 일정에 따라 장소가 바뀌도록 확장한다.

### 첫 플레이 장면 — 추천 예시, 강제 순서 아님

1. 이용자는 접속해 3인칭 캐릭터로 거리를 자유롭게 이동한다. 벤치를 호버해 `bench / 벤치 / 예문`을 보고 저장한다.
2. 거리를 걷다 행인이 먼저 말을 걸 수 있다. 사용자는 답하거나 무시하고 지나갈 수 있다. 답한다면 카페와 동일한 대화 엔진으로 1회 이상 자연스럽게 이어갈 수 있다.
3. 카페에 들어가 직원과 인사·주문·잡담을 **자유롭게** 한다. 1인칭 시점, 이동 제한, 대화 종료 버튼 제공.
4. 이용자가 “Can I get... 아, 아이스라떼...”처럼 말하다 막히면 AI는 직전 질문과 장면을 고려해 의도를 이해한다. 요청형 도움을 누르면 단어 → 문장 틀 → 전체 예시 단계의 힌트가 표시된다.
5. NPC가 말한 영어를 이해하지 못하면 다시 듣거나 한국어 뜻을 볼 수 있다. 대화를 끝내면 짧은 피드백을 보고 즉시 나가거나, 상세 평가·모범 음성·자기 음성 다시 듣기·다시 말하기·단어장 저장을 선택한다.
6. 저장한 표현은 회상 문제로 복습한다. 5번 **정답으로 회상한** 해당 단어는 탐색 중 자동 호버 카드만 감춘다. 필요할 때 여전히 확인 가능하다.
7. 2~3주차에는 NPC가 이전 취향·대화를 기억하고, 친밀도 반응이 달라지며, 일일 퀘스트로 특정 NPC를 찾아갈 수 있다. 카페에서 들은 정보가 거리의 다른 NPC 사건에 쓰이는 한 번의 연결 경험을 구현한다.

> **정확한 구현 경계:** 위 4번의 주문/행사·품절 예시는 시스템 검증용 콘텐츠 사례다. 퀘스트/대화가 항상 정해진 순서로 전개되는 것은 아니다. 1주에는 복잡한 사건 연쇄가 없어도 자유 대화가 성립해야 한다.

## 3. 시스템 설계 철학

### 3.1 대화와 사건은 병렬로 존재한다

- `FREE_CHAT`: 퀘스트가 없어도 NPC 성격·직업·현재 상황에 맞춰 자연스럽게 잡담, 요청, 질문에 답한다.
- `AMBIENT_TRIGGER`: 행인이 먼저 말을 거는 이벤트. 사용자가 거절/무시할 수 있고, 수락하면 자연스러운 대화를 이어간다.
- `QUEST_CONTEXT`: 사용자가 일일 퀘스트를 받고 특정 인물을 만나거나 진행 중인 사건을 돕는다. NPC 자유 대화 범위는 유지하고 관련 의도만 미션 판정에 사용한다.
- `SCENE_EVENT`: 품절·길 안내·상황 변화 등 게임 규칙이 바뀌는 경우 서버 시나리오 엔진이 승인된 상태 전환을 수행한다.
- 한 NPC 대화에서도 잡담→퀘스트 관련 질문→다시 잡담 전환이 가능하다. **시나리오 상태 머신이 대화 주제를 전면 검열하지 않는다.**

### 3.2 AI와 게임 서버의 권한 경계

- **AI의 권한:** 원문에 충실한 STT 분석 보조, 사용자 발화 의도·필요 슬롯 후보 추출, 캐릭터에 맞는 NPC 응답, 도움·문장 코칭·피드백 후보, 기억 사실 후보·친밀도 신호 후보 제안.
- **서버의 권한:** NPC/사용자 접근 검사, 대화 상태 및 비용 관리, 시나리오 성공 판정, 월드 상태/아이템/보상 변경, 퀘스트 완료, 실제 기억 저장(민감 정보 제한), 친밀도 증감 검증, 동시성 및 기록 정합성.
- AI가 “네 음료를 지급했다”라고 말했더라도 서버가 주문 완료 이벤트를 승인하지 않았으면 실제 아이템·보상이 생기지 않는다. 자유 잡담은 서버 이벤트 발생 없이 충분히 진행된다.

### 3.3 NPC 유형과 기억

| 유형 | 표현 방식 | 관계·기억 | 1~3주 범위 |
|---|---|---|---|
| 배경 엑스트라 | 배회·한두 마디 고정 대사 | 개인 기억 없음 | 배경 소수, 기존 리소스 재활용 |
| 지속형 주민 | 역할·성격·상황을 지닌 자유 AI 대화 | 사용자별 핵심 기억·친밀도 | 3주 필수: 적어도 직원 NPC 하나 |
| 관계 형성 가능 행인 | 우연한 만남 이후 지속 인물로 전환 가능 | 전환 후 기억/관계 | 단순 행인 이벤트는 1주, 승격은 이후 확장 가능 |

- **단기 맥락(1주):** 같은 대화 안의 최근 발화·NPC 직전 질문·장면을 유지.
- **장기 기억(3주):** 세션이 종료되어도 `(user_id, npc_id)`별 핵심 사실(`favorite_drink` 예시), 지난 대화 요약, 마지막 만남과 횟수를 지속 저장. 관련성 높은 기억만 후속 프롬프트에 전달. 개인별 데이터 혼입 금지.
- **친밀도(3주):** 호감도와 같은 개념. 관계 점수 및 범주를 한 번만 정의한다. 행동·대화·사건 결과에서 서버가 검증된 규칙으로 변경. 영어 문법 실수에 대한 친밀도 페널티 금지.
- **살아 있는 존재감:** 반복 인사/취향 기억, 퇴근·걷기 등 단순 활동, 사건에 대한 자연스러운 언급, 먼저 말 걸기. 모든 NPC를 실시간 자율 에이전트로 실행할 필요는 없다.

### 3.4 자연 노출과 선택형 집중 학습

- 탐험하며 물체 어휘를 배우고, NPC와 실제 의도로 자유롭게 대화한다. 학습하려고 매번 정답 문장만 고를 필요가 없다.
- 대화 도중 **사용자가 원할 때** 단계형 힌트를 보인다. 발화 도중 자동 끼어들어 실시간 완성 문장을 띄우는 기능은 기술 검증 후 고도화한다.
- 대화 후 **짧은 자동 피드백 + 선택형 상세 보기**. 기본 내용: 의도 전달 여부, 잘한 점 1개, 개선 표현 1개. 상세에는 문장별 원문, 더 자연스러운 표현, 모델 음성, 사용자 발화 재생(저장 동의 범위), 재녹음, 단어 저장. **발음 음소별 채점은 별도 검증 전 확정 금지.**
- 단어장은 사물, NPC 대사, 피드백에서 직접 저장하며, 복습은 짧은 회상 문제로 제공한다. 오답 시 5회 성공 카운트 증가 금지. 5회 성공해도 수동 뜻 보기 금지하지 않는다.
- 익혔던 표현은 관련 생활 맥락에 다시 나올 수 있지만, 단어 복습 때문에 이야기를 강제로 틀지 않는다.

### 3.5 활동·퀘스트·성장

- **일일 퀘스트(3주 필수):** NPC 방문·인사, 특정 주민의 부탁, 사물 알아보기, 저장 표현 복습 등 **생활형과 학습형이 모두** 포함된 작은 템플릿. 선택해 수행하거나 자동 추적 가능; 미수행·미접속 페널티는 현 단계에서 도입하지 않는다.
- **상황 이벤트:** 거리 행인이 먼저 말을 걸거나 카페 상태가 달라지는 사건. 사용자 발화·선택에 따라 제한된 세계 상태 변경; 자유 탐험을 영구 차단하지 않는다.
- 언어 능력/생활 경험/개별 친밀도는 의미가 달라 후속 시스템에서도 하나의 점수로 통합하지 않는다. 퀘스트로 보상을 주더라도 AI 유료 API 사용권과 게임 재화를 자동으로 혼용하지 않는다.
- 장기적으로 새로운 관계 이벤트·행동·콘텐츠가 해금되지만 기본적인 걷기, 말하기, 복습을 잠그지 않는다.

## 4. 개발 전략: **1주 MVP → 3주 핵심 완성** [합의]

### 1주 MVP: 작은 월드, 실제 학습 서비스 수직 슬라이스

**사용자가 완료하는 행동**: PC 웹 접속 → 3D 거리 이동 → 행인 선제 발화 경험 → 카페 NPC와 음성 AI 자유 대화 → 사물 호버·단어장 → 코칭·대화 종료 기본 평가 및 상세·듣기/재발화 → 회상 복습. 자동 호버 숨김은 간단 카운트로 동작. 서버 API 비용 통제.

범위를 줄일 때는 **장소 수, 모델·애니메이션의 화려함, 발화 평가의 정교함, 대화 시나리오 콘텐츠 수**를 줄인다. 언어학습 기본 경험 자체를 지우지 않는다. 1주 달성은 기술 PoC와 병렬 통합 성과에 따라 좌우되는 **공격적 목표**이며, 계획을 실제 완료라고 보고하면 안 된다.

### 2~3주: 살아 있는 세계의 핵심 구조를 완성

- NPC **장기 대화 기억(필수)**, **친밀도(필수)**, **일일 퀘스트(필수)**, 기본 NPC 생활 행동, 짧은 연결 사건/분기(대표 사례), 사용자별 재방문 확인, PC 웹 정식 테스트·배포.
- 1주 구현 내용에 대한 AI 답변 자연스러움, 오류 복구, 피드백 품질, 수업·회화 흐름, 입력 지연, 비용 운영을 안정화한다.
- 팀원이 6명이므로 게임, 음성, NPC/코칭, 서버 도메인, 학습 UI/데이터, 통합/QA를 병렬화하되 API·응답 JSON 계약은 처음에 합의한다. AI 코딩 에이전트가 서로 다른 임의 스키마를 만들지 않도록 한다.

### 4주 조건부: PC와 동일한 모바일 3D 서비스

- PC 배포 품질 게이트가 통과하면 QR로 접속 가능한 모바일 웹을 제공. **모바일 전용 퀴즈/대화 페이지만 만들지 않는다.** 3D 이동·카페 출입·NPC 대화·호버 대체 터치·마이크 권한·성능을 동등하게 검증한다.
- PC에서 통합 문제가 남아 있으면 모바일 범위를 시작하지 않고 안정화한다.

### 장기 비전: 개발 초기에 막지 않는 확장 가능성

- NPC 일정·타 NPC 관계망·기억 고도화, 전화/연애/친구, 공동 이벤트.
- 점포/알바/포인트/아바타/집·가구/경제, 작은 가구 배치 시 쿼터뷰 등 특수 카메라.
- 공항·비행기·여러 나라와 언어, 현지 은어·숙어, 학습시설(TOEIC/OPIC 등).
- 멀티플레이, 공간 공유·대여, 모바일 네이티브 앱.
- **의심도**: 낯선 외부인 설정, 주민 경계·경찰/신뢰 이벤트 등은 **후속 검토 아이디어**. 학습 미접속에 따른 자동 불이익, 기본 탐험 제한은 확정하지 않았다. 현재 MVP/3주 필수로 도입하지 않는다.

## 5. AI 비용·안전·접근성·데이터

- 유료 호출은 서버 AI 게이트웨이를 통해서만 수행; 키 클라이언트 노출 금지, 사용자/세션별 속도·길이·사용량·하드캡, 호출 원장과 중복 청구 방지.
- 한도 소진 시 **새 AI 회화 및 새로운 비용 발생 요청만 제한**. 기존 무료 게임 기능(걷기·호버·저장한 단어·복습·이전 피드백)은 계속 쓸 수 있다. 모든 회화를 정답 선택지로 대체하는 것은 제품 철학과 충돌한다.
- 음성 입력 권한 및 사용자 기록 동의 경계 명확화. 자신의 음성 **세션 내 다시 듣기**와 **서버에 장기 저장**은 별개의 권한이다. 기본 정책은 개인정보 최소 보관이고, 기간·법적 준수는 팀 의사결정 항목.
- LLM이 이전 사실을 지어내거나 다른 사용자 기억을 누출하지 못하도록 사용자별 조회 범위와 맥락 검증. 게임 NPC와의 대화는 사용자가 실제 사람과 대화한다고 오인하도록 허위 고지하지 않는다.
- 지연·API 503·JSON 오류·STT 오인식 시 버튼 재시도/전사 확인·텍스트 수정/타임아웃, 비비용 기능으로 복구 가능하게 한다.

### 5.1 AI 사용량이 소진된 이후에도 유지되는 두 활동 영역 [W1 필수 정책]

> **중요:** 'AI 가능 모드/무료 모드'를 서로 다른 **대화 모드**로 정의하지 않는다. 사용자가 세계에서 수행하는 활동에는 **생활·자율학습 영역**과 **유료 연산이 필요한 AI 상호작용 영역**이 있으며, 한도 소진 시 후자의 *새 연산 요청*만 중단된다. 자연스러운 AI 자유 회화와 퀘스트 대화를 미리 작성한 정답 선택지나 무제한 고정 대화로 갈아 끼우지 않는다.

| 활동 영역 | 남은 AI 이용량이 0일 때 | 제품 경험 |
|---|---|---|
| **자유 생활·기초 학습(계속 허용)** | 거리 걷기, 카페 출입·구경, 저장된 오브젝트 정보 호버/수동 열람, 단어장 조회·저장(기존 오브젝트/이미 제공된 문장), 저장된 피드백·대화 기록 열람, 규칙 기반 회상 퀴즈·정답 5회 처리 | 마을은 사라지지 않으며 이미 학습한 것을 계속 복습한다 |
| **이미 만들어진 콘텐츠(계속 허용)** | 이미 저장·캐시된 대사·피드백·음성 재생(보관 및 동의 조건 충족 시), NPC의 사전 제작 배경 대사·애니메이션 | **새 AI 모델 호출이 발생하지 않는 경우에만** 무료로 유지한다 |
| **새 AI 처리(한도 회복 전 제한)** | 카페·행인 NPC의 새로운 AI 자유 응답, STT, 즉석 한국어/영어 번역, 새로운 힌트·코칭·문장 평가, 새 피드백·모범 TTS 생성, AI 기억 추출·요약 | 한도 부족 안내 후 재생성/전송 불가; 화면·카메라 잠금 없이 탐험으로 복귀할 수 있다 |
| **3주 NPC·퀘스트 시스템(상태 보존)** | 기존 NPC 장기 기억·친밀도·완료 퀘스트 조회 가능, 새로운 AI 대화를 요구하는 퀘스트만 *대기*, AI 불필요 활동은 계속 | 부족한 크레딧 때문에 친밀도 초기화·퀘스트 실패·방문 불이익 없음 |

**사용자 흐름 (반드시 구현):** 남은 한도/상태 확인 → 소진 또는 차단 시 이유 표시 → 무료 활동 계속 이용 → 서버에서 사용 가능 여부 회복을 확인한 경우에만 새 AI 대화 버튼 활성화. 진행 중이던 1:1 대화는 오류 화면에 갇히지 않고 정상적으로 닫힌다. 소진 전 승인된 요청의 정산과 이후 신규 요청 차단은 서버가 책임진다. 이전에 생성된 평가가 없는 상황에서 AI 평가를 실제 수행하지 않고 생성된 것처럼 표시하지 않는다.

**정책과 수익화는 구분:** 무료 한도 수치, 지급/갱신 주기, 소진 시 유예 여부, 추가 크레딧 충전·결제/구독·퀴즈 보상 크레딧 지급 여부는 **미확정**이다. 제품 요구는 *어떤 수치를 채택해도 서버 설정만으로 제한할 수 있고, 초과된 AI 요청은 외부 API를 호출하기 전에 거부하며, AI 없는 생활 기능은 계속 제공하는 것*이다. 1주 MVP에 실제 유료 결제 시스템을 구축한다는 뜻이 아니다.

## 6. 효과를 검증하는 방법 (아직 달성하지 않은 지표는 목표로 표시)

- 실사용자가 3D 마을을 자유롭게 탐험하며 호버 단어를 찾는가?
- 행인 선제 발화에서 사용자가 예상 밖 질문에 말로 답하는가?
- NPC와 주제 제한 없이 대화가 이어지는가? 한영 혼용 의도가 보존되는가?
- 피드백→다시 듣기/재발화→복습 과정을 실제로 수행하는가?
- 3주 후 NPC가 *지난 세션의 저장된 사실*을 실제로 언급하는가? 친밀도 변화가 다른 반응으로 체감되는가?
- 퀘스트 없이 탐험하는 경로와 퀘스트를 위해 NPC를 찾는 경로가 모두 가능한가?
- 무효 AI 응답/사용량 소진/마이크 거부에서도 앱이 죽지 않는가? AI 사용량 0에서 무료 생활·복습과 퀘스트 기록 보존이 실제로 동작하는가?
- 모바일 확장을 결정하기 전에 **실제 외부 사용자 PC 웹 배포**가 가능한지 검증했는가?

## 8. 개발 에이전트 작업 지시와 변경 관리

1. 기존 레포/현재 구현과 이 문서의 차이를 먼저 조사하고 `이미 구현됨 / 부분 구현 / 미구현 / 기술 부채`를 구분한다.
2. 작업은 `기능 ID → 의존 API 계약 → UI/서버/AI 책임 → 수용 테스트` 순으로 진행한다. 팀원별로 같은 데이터 모델을 중복 정의하지 않는다.
3. 새로운 아이디어를 발견하더라도 합의 없이 W1/W3 필수 기능을 빼거나, 미확정 콘텐츠·제품명을 확정하지 않는다.
4. **1주 MVP를 검증 가능한 작은 완성품으로** 만들되, 기능 연결을 유지한다. 실패할 위험이 있는 작업은 PoC 결과와 대안 경로를 기록한다.
5. 시연자료·문서에서 `이미 구동되는 기능`, `로컬 PoC`, `정적 데모`, `외부 PC 웹 서비스`를 반드시 분리 표기한다.
