# 3D AI NPC 생활형 외국어 학습 시뮬레이션 — AI 구현 요구사항 명세서

> 버전 **v2.1 · 2026-10-13** · 제품 원칙은 `03_AI용_제품기획안.md` 참조.  
> **W1** = 1주 MVP 목표, **W3** = 3주 PC 웹 필수 완료 목표, **W4-C** = 4주 조건부 모바일 확장. 구현 도중 기능을 로드맵으로 임의 강등하지 않는다.  
> 이 문서의 `REQ-*`는 추적 ID; API/테이블/JSON 이름은 **초기 협업을 위한 권고 계약(미확정)**이다. 기존 레포 규약이 있으면 팀 합의 후 하나로 통일한다.

## 0. AI 에이전트 구현 계약

1. **기능 설계와 컨텐츠를 구분**한다. `Emma`, `Alex`, 우유 품절, 행사 시간 등은 예시. 자유 대화·선제 이벤트·세계 상태 승인·학습 루프가 요구사항이며 문장이나 지명을 하드코딩한 정답만 강요하지 않는다.
2. **W1 목표는 첫 1주일 내 최소 동작 버전**, W3 목표는 이후 2~3주 고도화와 배포. W1에는 기본 학습 기능(피드백, 다시 듣고 재말하기, 단어장, 5회 회상 숙련 등)과 **AI 한도 소진 후 무료 생활 지속(REQ-29·30)**을 포함한다.
3. **6명 병렬 작업**을 전제로 스키마·ID·계약을 선행 합의한다. 엔진, 서버 언어, 모델, 벤더, 기술 선택은 팀 기존 코드와 PoC를 확인한 뒤 결정한다.
4. 사용자 발화는 영어/한국어/혼용/불완전·침묵 가능. NPC는 어떤 정해진 의도에 부합하지 않아도 성격을 유지해 답할 수 있다. 사건 상태 변경은 서버만 승인한다.
5. 개인정보/녹음: `현재 세션 내 재생`과 `서버 장기 음성 저장`을 구분한다. 사용자의 선택과 팀 정책이 없는 장기 원본 음성 저장은 기본 기능으로 가정하지 않는다.
6. 미정 수치는 예시 테스트 픽스처이지 운영 값이 아니다. 실사용 AI 이용량·무료 한도·오디오 보관 기한·성능 임계치를 임의 확정하지 않는다.
7. 기능 '완료'는 **UI 표시 + 실제 서버/AI 흐름 + 새로고침/재접속 또는 예외 케이스 검증(해당 기능 적용 시)**의 조합으로 판단한다. 정적 화면/더미 JSON만으로 완료로 표기하지 않는다.

## 1. 우선순위와 수직 슬라이스 정의

### 1.1 W1 MVP 통합 데모(필수 행동 루프)

`PC 브라우저 진입 → 3인칭 거리 이동 → 행인 선제 발화(응답/무시) → 카페 출입 → 1인칭 NPC 음성 자유 회화(실제 STT/LLM/TTS) → 한국어·혼합 발화 지원과 요청형 힌트 → 대화 종료 → 요약 피드백·상세 문장 평가 → 사용자/모범 음성 듣기·다시 말하기 → 표현 단어장 저장/복습 → 호버 단어 5회 회상 시 자동 숨김 → 다시 자유 탐험`.

기본 화면은 마이크 미허용 때 사용자에게 접근 가능한 재시도·텍스트 대체를 제공한다. 본인 음성은 브라우저 버퍼에 남아 있는 경우 같은 세션에서 재생 가능하며 새로고침 후에도 듣기를 보장하려면 **별도의 명시 동의 기반 업로드·보관 설계**가 필요하다. W1 정확한 학습 평가의 깊이와 자산 종류·개수는 작은 범위부터 시작한다.

### 1.2 W3 통합 데모

`이전에 대화한 NPC와 다시 만남 → 이전 핵심 사실을 적절히 기억 → 행동/대화로 동일한 단일 친밀도 지표 변경 → 다음 NPC 반응이 달라짐 → 일일 생활/학습 퀘스트를 수락하고 NPC를 찾아감 → 선택한 발화가 제한된 세계 사건·퀘스트 상태를 변화 → 학습 기록·피드백 유지 → 외부 PC 웹 사용자 접속`.

W3의 장기 기억·친밀도·일일 퀘스트는 **반드시 개발 대상**. 단, 복잡한 NPC 전체 사회망, 시뮬레이션 경제, 의심도는 이후 확장.

| ID | 단계 | 기능과 처리 | 테스트 가능한 수용 조건 |

### 2.4.1 AI 이용 한도 소진 시의 **필수 동작 계약** (REQ-20·29·30)

**규칙:** 한도 소진은 서비스 로그아웃/게임 오버/마을 폐쇄가 아니다. *두 개의 대화 모드*를 새로 만드는 것이 아니라, **AI 호출이 필요한 작업과 그렇지 않은 생활·학습 작업을 구분하는 접근 정책**이다. AI 자유 회화의 핵심 경험을 무제한 고정 대사로 대체하지 않는다.

| 기능/작업 | `AI_AVAILABLE` | `AI_EXHAUSTED` | 구현 조건 |
|---|---|---|---|
| 3D 이동·카페 출입·카메라 탐색·사물 호버 | 허용 | **허용** | 정적 월드/사전 등록된 어휘 리소스는 새로운 AI 요청 없음 |
| 단어장·회상 퀴즈·5회 정답 숨김·기존 피드백/대화 기록 보기 | 허용 | **허용** | CRUD/규칙 기반 연산은 AI 게이트웨이를 호출하지 않음 |
| 이전에 생성·보관한 모범 음성/본인 음성·NPC 기본 고정 반응 | 허용 | **조건부 허용** | 캐시에 실존하고 재생·보관 동의 충족, **새 TTS 생성 금지**; 자유 AI 회화 대체용 전체 시나리오 제공 아님 |
| 새로운 NPC 자유 응답, STT, 즉석 번역, 신규 추천 힌트·AI 평가·새 피드백·새 TTS | 허용(정책 예산 범위) | **차단** | **클라이언트와 서버 모두** 차단하되 서버 검사 필수; 외부 벤더에 요청하지 않음 |
| NPC 장기 기억·친밀도·세계/퀘스트 기록 조회 | 허용 | **허용** | 저장 상태 보존; 새 AI 추출/요약 호출 불가 |
| AI가 필수인 일일 퀘스트·사건 | 허용 | **현재 상태에서 대기** | 강제 실패·시간 경과 벌점·기록 초기화 금지. 비AI 퀘스트는 계속 진행 가능 |

**상태와 UX 계약**

1. 서버 정책 평가 결과를 권한/사용량과 함께 전달: `AI_AVAILABLE`, `AI_EXHAUSTED`, `AI_TEMPORARILY_UNAVAILABLE`(장애), `AI_RESTRICTED`(운영·안전 제한)는 별도 **접근 상태**이며 NPC의 `conversation_mode`와 무관하다. `AI_EXHAUSTED`를 단순 API 장애나 마이크 권한 거부와 동일하게 처리하지 않는다.
2. 사용자가 AI 대화·새 STT·새 AI 힌트/평가를 요청할 때 서버가 **예상 비용/잔여 정책**을 먼저 검사하고 예산을 예약한다. 클라이언트에서 버튼이 비활성화되어도 직접 API 호출 우회는 서버에서 거절한다. 불충분하면 안정된 `AI_QUOTA_EXHAUSTED` 오류를 반환하고 **비용 있는 모델 호출은 실행하지 않는다**.
3. 클라이언트는 `AI 사용량을 모두 사용했습니다. 마을 탐험, 사물 학습, 단어장·복습은 계속할 수 있습니다.` 같은 메시지와 `탐험 계속`, `단어장`, `복습`, `기존 기록` 접근을 제공한다. 재개 시점은 정책에 명시된 경우에만 표시하며 없는 경우 임의 날짜를 약속하지 않는다.
4. 한도 소진이 **대화 중** 발생하면 이미 승인/예약된 실행 중 요청은 서버 과금 정책에 맞춰 정산하고, **다음 신규 AI 호출부터** 제한한다. 사용자는 종료·취소로 3인칭 상태에 복귀하며 이동 잠금/녹음/로딩 상태가 남지 않는다.
5. 새 AI 결과를 만들 수 없는 경우 기존 결과만 조회한다. 아직 AI 평가가 생성되지 않았다면 가짜 AI 평가를 보여주지 않는다. 이미 받은 사용자 발화 텍스트, 미션 사실 등 **AI 호출 없이 확인 가능한 기록**은 표시할 수 있다.
6. 사용량이 **정책상 갱신 또는 허가된 크레딧 충전**으로 회복되면 서버 확인 뒤 새 AI 처리 재개. 무료 지급량, 주기, 실제 판매/충전 시스템, 광고/복습 보상 크레딧은 팀 결정 전 `TBD`이며 현재 필수 결제 기능으로 자동 구현하지 않는다.

**계측/경합/보안 계약**

- `user_id + request_id + operation_type` 기준 멱등성, 원장 예약→실제 소비 정산→잔여 복구/실패 기록을 명확히 한다. STT·LLM·TTS 등 **모든 과금 대상 단계**를 합쳐 계정과 글로벌 예산 상한을 적용한다. 요청 도중 공급자가 이미 비용을 부과한 경우 '전액 환불'을 무조건 가정하지 말고 **실제 소비 근거에 맞춰 정산**한다.
- 동시 탭·동시 요청이 잔여 한도를 넘지 않게 예약/원장 갱신을 원자적으로 처리한다. 제한을 넘어선 시도는 모델 호출 이전에 차단하며 서버 키가 브라우저 번들에 노출되어서는 안 된다.
- 소진 상태 전환이 기존 저장 데이터 삭제·친밀도 감소·퀘스트 포기·학습 숙련도 초기화를 트리거하지 않게 한다.

## 3. 게임 상태 모델과 흐름

### 3.1 카메라·대화 상태(필수)

```text
EXPLORE_THIRD_PERSON
  ├─ move/inspect/enter_cafe → EXPLORE_THIRD_PERSON or SCENE_TRANSITION
  ├─ interact_with_npc → DIALOGUE_STARTING
  └─ pedestrian_calls + accept → DIALOGUE_STARTING
DIALOGUE_STARTING → DIALOGUE_FIRST_PERSON [camera at NPC, playerMoveLocked=true]
DIALOGUE_FIRST_PERSON → AWAIT_SPEECH → AI_PROCESSING → NPC_SPEAKING → DIALOGUE_FIRST_PERSON
DIALOGUE_FIRST_PERSON → ENDING (user_end / npc_goodbye / abandon)
ENDING → FEEDBACK_OPTIONAL → EXPLORE_THIRD_PERSON [playerMoveLocked=false]
ERROR_RECOVERABLE: AI_PROCESSING failure → retry/edit_input/end; always recover camera lock
AI_QUOTA_EXHAUSTED: before new paid operation → preserve session/world state; no provider call → show free activities or end → EXPLORE_THIRD_PERSON
```

**입장 조건:** player와 npc 간 거리·NPC 활동 가능 여부, 중복 대화 시작 방지. 거리 NPC는 먼저 말하더라도 사용자가 무시하면 강제 카메라 전환/이동 잠금 없음. 대화가 종료되면 녹음·TTS를 중지하고 현재 카메라·입력 상태 복귀.

### 3.2 이벤트/퀘스트의 서버 상태(확장 가능)

- 이벤트 예시: `AVAILABLE → ACTIVE → WAITING_FOR_INTENT → SUCCEEDED | SKIPPED | FAILED_RECOVERABLE`. 퀘스트는 `OFFERED → ACCEPTED → IN_PROGRESS → COMPLETED | ABANDONED`.
- LLM의 `intent_candidate`, `slots_candidate`는 **제안**. 서버는 `(scenario_id, state, allowed_actions, slots)` 검증 후 상태를 원자적으로 변경한다.
- 사용자의 자유 잡담은 `NO_WORLD_ACTION`으로 처리해 NPC 응답을 생성하되 게임 사건을 멈추거나 임의 완료하지 않는다.
- 같은 턴을 중복 전송해도 퀘스트 완료/보상/친밀도·AI 차감이 중복되지 않아야 한다.
- 단순 거절/모르겠다는 답도 정상적인 대화 결과다. 임의의 미션 실패 때문에 마을 기본 활동을 차단하지 않는다.

### 3.3 NPC 기억과 관계 상태

- 세션 중 최근 메시지 N개 + 중요 상황 요약은 대화 컨텍스트에 사용. `N`과 토큰 예산은 환경 설정.
- W3에 `(user_id, npc_id)`별 주목할 만한 사실과 방문 메타데이터를 저장하고 관련성 높은 기억만 맥락에 회수한다.
- 관계 점수는 NPC별 **`affinity_score`** 하나; `호감도`라는 별도 테이블/점수를 만들지 않는다. 점수 범위·단계 경계는 팀 설정값.
- `NPC memory`, `world fact`, `quest record`는 다른 개념. 사적 취향과 공개 사건을 한 테이블로 무분별하게 혼합하지 않는다.

## 4. API 계약 제안(초기 스키마, 확정 기술 아님)

| ID | 경로 제안 | 주요 입력 | 주요 출력 및 검사 |
|---|---|---|---|
| API-01 | `GET /api/v1/bootstrap` | 세션 토큰 | user/session, scene, policy, progress, 401 |
| API-02 | `GET /api/v1/scenes/{id}` | 장면 | npc/object 목록, 상호작용 가능 조건 |
| API-03 | `POST /api/v1/conversations` | `npc_id`, `scene_id`, `trigger` | conversation ID, intro line, NPC/camera state, 제한 초과 오류 |
| API-04 | `POST /api/v1/speech/transcribe` | audio blob, request ID | transcript, detected languages, 오류·길이 제한 |
| API-05 | `POST /api/v1/conversations/{id}/turns` | verified transcript/text, request ID | NPC message, audio reference, intent candidates, client-safe event delta, AI usage |
| API-06 | `POST /api/v1/conversations/{id}/hints` | hint stage, current turn ID | keywords, sentence stem, example (가급적 앞선 생성 결과 재사용) |
| API-07 | `POST /api/v1/conversations/{id}/end` | reason | summary feedback, report ID, camera release instruction |
| API-08 | `GET /api/v1/feedback/{id}` | user auth | detailed report, saved audio eligibility |
| API-09 | `GET/POST/DELETE /api/v1/vocabulary` | vocab/expression ID | saved items, duplicate detection |
| API-10 | `POST /api/v1/reviews/attempts` | question ID, answer, request ID | correct, success count, auto_hide, prevent duplicate |
| API-11 | `GET /api/v1/npcs/{id}/relationship` | user auth | affinity, visit state, relevant public metadata (W3) |
| API-12 | `GET/POST /api/v1/quests/daily` | local date, quest ID, action | offered/accepted/progress/completed (W3) |
| API-13 | `GET /api/v1/usage` | user auth | server-authoritative `ai_access_status`, remaining quota, operation limits, known reset/renewal policy (optional), no keys |
| API-14 | `GET /api/v1/usage/capabilities` | user auth | `can_start_ai_conversation`, `can_generate_new_feedback`, `can_use_non_ai_learning`, `reason_code` (contract proposal) |

**AI 한도 초과 공통 오류 응답 예시** (권고 DTO; HTTP 상태코드/실제 단위는 팀 합의):

```json
{
  "error": {
    "code": "AI_QUOTA_EXHAUSTED",
    "message": "AI 사용량을 모두 사용했습니다. 탐험과 저장된 학습은 계속 가능합니다.",
    "retryable_now": false,
    "can_continue_exploring": true,
    "allowed_features": ["WORLD_EXPLORE", "OBJECT_HOVER", "VOCABULARY", "REVIEW", "SAVED_FEEDBACK"],
    "resume_at": null
  }
}
```

`resume_at: null`은 정책상 갱신 시간이 알려지지 않았다는 뜻이며 '영원히 차단'을 의미하지 않는다. 사용량 단위(분·토큰·크레딧 등)는 실제 공급자별 비용과 서비스 정책이 확정될 때 `usage_policy`에 정의한다. **이 응답은 클라이언트가 외부 모델 사용권을 결정하는 수단이 아니며 최종 승인은 서버에 있다.**

**API 표의 목적**은 병렬 개발 계약 통일이지 REST 경로 강제 아님. WebSocket/streaming을 택해도 이벤트 의미·서버 권한·식별자와 검증이 유지되면 된다.

### 대표 응답 예시: AI 후보 ≠ 게임 상태 확정

```json
{
  "conversation_id": "conv_example_01",
  "turn_id": "turn_example_03",
  "npc": {"id": "emma", "text": "Sure! Would you like it iced?", "language": "en-US"},
  "learner": {"transcript": "I want... 아이스 라떼", "transcript_reviewable": true},
  "analysis_candidate": {
    "intent": "ORDER_DRINK",
    "slots": {"drink": "latte", "temperature": "iced"},
    "confidence": 0.84
  },
  "hint": {
    "keywords": ["iced", "latte", "please"],
    "starter": "I'd like ...",
    "example": "I'd like an iced latte, please."
  },
  "world_event": {
    "status": "NOT_APPLIED",
    "reason": "Pending server-side transition validation"
  },
  "usage": {"request_id": "req_example_03", "status": "RECORDED"}
}
```

예시의 `confidence=0.84`는 **테스트 JSON 샘플**이며 실제 모델 품질 주장/합격 임계치가 아니다. 가능하면 AI 자유형 텍스트와 **검증 가능한 제한된 구조화 출력**을 분리한다. AI는 친밀도 점수·퀘스트 보상·세계 아이템을 직접 지정하지 않는다.

| `ai_usage_ledger` | id, user_id, request_id, model, input_tokens, output_tokens, audio_units, reserved, charged, status | W1 비용 하드캡·중복 차감 방지 |
| `ai_usage_policy` | policy_id, unit_definition, free_allowance, renewal_rule?, operation_caps?, global_cap, status | **운영 수치 미확정**. 환경/관리자 설정으로 변경 가능하고 공개 클라이언트가 수정 불가 |
| `ai_usage_reservations` | user_id, request_id, operation_type, estimated_units, settled_units, status, created_at | 동시 호출의 원자적 예약·정산. 원장과 병합 구현 가능, 멱등성·감사 가능성 유지 |

개인 식별자(user_id)를 NPC 기억·학습·음성 데이터 모든 조회에 전달하고, 서버에서 접근 권한을 검사한다. 음성 원본의 **영구 저장은 결코 묵시적 요구사항이 아님**. 필요한 동의/삭제/보유기간은 배포 전에 팀이 결정한다.

## 6. AI 파이프라인·모듈 책임

```text
PC Web (3D renderer / UI / browser mic & speakers)
   | user/session token, scene, NPC and typed/audio input
   v
Application Backend [authoritative]
   +-- Scene / NPC state and camera triggers
   +-- Conversation and Quest orchestrators
   +-- Scenario state machine (server action approval)
   +-- Learning: vocabulary, reviews, feedback reports
   +-- Memory + Relationship (W3)
   +-- Quota / permission / ledger / durable storage
   |
   +--> AI gateway (key server-side; timeout / schema validation)
           +-- ASR/STT: mixed-language transcript
           +-- LLM: NPC persona reply + intent/hint/feedback/memory candidates
           +-- TTS: en-US NPC/model example speech
```

- 음성 전사 원문과 이용자 수정 전사를 구분 저장한다(평가 기준은 사용자 확인 전사 가능).
- 음성 처리·대화 생성·TTS 단계를 로그에서 구분 측정한다. TTS 완료까지 포함하지 않은 숫자를 '전체 대화 지연'으로 표시하지 않는다.
- 프롬프트에서 타 사용자 기억·관리자/시스템 지시를 노출하지 않고, NPC 배경 정보와 장면 사실을 서버의 안전한 참조 데이터에서 공급한다.
- 게임 클라이언트는 서버가 승인한 이벤트만 애니메이션/아이템/퀘스트 결과로 반영한다. 네트워크 오류 시 이전 유효 상태를 유지하고 재동기화 가능해야 한다.

## 7. 오류·비용·개인정보·성능

**정량 지표:** 처음에는 p50/p95 STT·LLM·TTS·대화 전체 지연, JSON 성공률, intent 보존, 발화 재시도율, 첫 대화 진입률 등을 계측한다. 문서에 특정 초를 **성능 합격 수치로 확정하지 않는다**. 팀 PoC를 통해 결정한다.

## 10. 수락 게이트 및 범위 변경

**W1 MVP 완료 판정:** 핵심 상호작용과 학습 기능이 한 번 이상 **실제 모델 호출을 포함해** 종단간 실행; 해당 화면만 있는 정적 시연은 불충분. 피드백·단어장·퀴즈·5회 숨김은 제한된 데이터로 동작. 음성 재생과 장기 보관은 동의 정책을 구분.

**W3 완료 판정:** 외부 PC 브라우저에서 W1 전체 루프 + **장기 NPC 기억·친밀도·일일 퀘스트·기본 사건 상태**가 재접속 이후에도 동작. API 비용/사용량·권한·오류 복구를 테스트하고 실제 접속 링크를 제공할 수 있어야 한다.

**W4 시작 게이트:** W3 PC 제품의 핵심 회화·AI 연결·외부 배포가 안정적일 때만 모바일 동등 경험으로 확장. 미충족이면 W4도 안정화에 우선 사용.

**후속 범위:** 의심도 게이지·신고/경찰 사건, 가구 배치·주택, 일자리·화폐 경제, 멀티플레이, 출석 페널티, 완전한 NPC 자율 에이전트, 정교한 발음 점수·실시간 자동 부분 힌트, 시험 학습 건물, 국제 여행·앱스토어 배포 등. 합의 없이 W1/W3 요구에 끼워 넣지 않는다.

**변경 절차:** 신규 요구 → 어떤 제품 원칙에 기여하는지 → W1/W3/W4/후속 구분 → 관련 REQ·테스트·API 영향 → 팀 확인 → 문서 4종과 Jira 동기화. 샘플 문장·시나리오를 확정 정책으로 승격할 때도 같은 절차가 필요하다.
