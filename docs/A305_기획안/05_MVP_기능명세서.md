## 0. 읽는 법

### 근거와 우선순위

1. **MVP 기능 범위 문서와 회의 보드의 결정 메모:** MVP에서 무엇을 어떻게 만들지 정하는 기준이다.
2. **ERD v3.1과 MVP API 명세 초안:** 와이어프레임 피드백을 반영한 데이터·API 설계다. 기능별 `데이터` 항목은 ERD v3.1의 테이블·컬럼 이름을, `API` 항목은 API 명세의 ID를 쓴다.
3. **와이어프레임:** 화면 구성 초안이다.
4. **03·04 v2.1:** 제품 원칙, AI와 서버의 권한 경계, AI 한도 소진 계약, `REQ-*`·`T-*` ID를 가져온다.

문서끼리 달랐던 항목은 [5절](#5-문서-간-차이)의 결정이 위 순서보다 우선한다.

### 표기

- 표시가 없는 규칙은 근거 문서에서 결정된 내용이다.
- `(제안)`은 근거 문서에 질문형 메모나 제안으로만 있거나, 이 명세에서 구현을 위해 정리한 초안이다. 팀 검토 후 확정한다.
- `(확인 필요)`는 아직 정하지 않은 내용이다. [6절](#6-결정이-필요한-항목)에 모았으며 구현 전에 결정한다.
- 미션 문구, NPC 대사, 사물 목록은 예시 콘텐츠다. 같은 경험을 주는 다른 콘텐츠로 바꿀 수 있다.
- 기능 ID `F-xx`는 Jira 작업과 테스트의 근거로 쓴다. 연결된 `REQ-*`·`T-*`는 04 문서의 ID다.

## 1. 사용자 흐름과 화면

```text
[진입]      01 사이트 접속 → 02 소셜 로그인 → (처음이면) 닉네임·캐릭터·약관 입력
                  ├─ 첫 방문 → 초기 설정
                  └─ 재방문 → 저장된 진행 단계와 장소로 복귀
[초기 설정]  03 학습 언어 → 04 레벨 테스트(건너뛰기 가능) → 05 NPC 대화 난이도
[튜토리얼]   06 집에서 시작(건너뛰기 가능) → 07 키 조작 → 08 가구 호버 → 09 미션 소개·외출
```

## 2. 공통 규칙

### 2.1 플랫폼과 시점

- PC 웹 브라우저에서 Unity WebGL로 실행한다. 실행 파일 설치를 요구하지 않는다.
- 탐험은 3인칭 자유 이동, NPC 1:1 대화 중에는 NPC 중심 1인칭과 이동 잠금이다.
- 대화가 어떤 이유로 끝나든(사용자 종료, NPC 종료, AI 한도 소진, 오류) 3인칭 시점과 이동을 복원한다.
- 마우스 커서는 화면 가운데에 고정하지 않고 자유롭게 움직인다. 카메라는 마우스 왼쪽 버튼을 누른 채 움직여서 돌린다. 거의 움직이지 않고 뗀 왼쪽 클릭은 사물 카드 고정에 쓴다.

### 2.2 화면 상태

04 문서 3.1절의 상태 흐름을 MVP 기준으로 줄인 것이다. 튜토리얼의 길 안내 대화(F-15)는 대본으로 진행하며 이 흐름과 별도다.

```text
EXPLORE (3인칭)
  ├─ NPC 상호작용 → [E 대화하기] ─────┐
  └─ 행인 말걸기 → [대화하기] ────────┤
                                    ▼
DIALOGUE (1인칭·이동 잠금): 녹음 → 전사 확인 → AI 처리 → NPC 발화 → 녹음 …
  └─ 사용자 종료 / NPC 종료 / 토큰 소진(NPC 작별 대사) / 오류
        ▼
FEEDBACK (짧은 피드백 → 상세 보기 선택, 건너뛰기 가능) → EXPLORE
```

- 진행 중인 대화가 있으면 새 대화를 시작하지 않는다.
- 대화가 끝나면 녹음, 음성 재생, 로딩 표시를 모두 멈춘다.

### 2.3 AI와 서버의 권한

- AI는 NPC 응답, 번역, 추천 표현, 피드백, 미션 완료·대화 종료 **후보**를 만든다.
- 미션 완료, 대화 종료, 사용량 차감은 서버가 검증해 확정한다. NPC가 "완료했다"고 말해도 서버가 승인하지 않으면 상태가 바뀌지 않는다. (`ai_candidates`)
- AI 키는 서버에만 둔다. 모든 AI 호출은 서버를 거치며, 서버는 호출 전에 사용량 한도를 검사한다(F-38).

### 2.4 사용자 데이터와 요청

- 서버는 모든 조회와 저장에서 로그인한 사용자의 권한을 검사한다. 다른 사용자의 대화·피드백·단어장은 존재 여부도 드러내지 않는다.
- AI를 호출하는 요청과 중복 반영되면 안 되는 요청에는 클라이언트가 만든 `requestId`를 붙인다. 같은 요청을 다시 보내면 이전 결과를 돌려주고 저장과 차감은 한 번만 한다. (`turns.request_id`, `ai_requests`)

## 3. 기능 명세

### 3.1 진입·가입

#### F-01 사이트 접속 화면 (화면 01)

- 접속하면 로그인·가입·초기 설정 상태를 조회해 첫 화면을 정한다. 로그인하지 않았으면 접속 화면을 보여준다.
- 상단에 서비스명·로고, 가운데에 "3D 마을에서 영어로 생활하며 대화한다"는 소개, 하단에 [시작하기] [로그인]을 둔다.
- 소셜 로그인만 쓰므로 두 버튼 모두 소셜 로그인으로 이어진다.
- 서비스명은 가칭 Elsehere이며, 소개 문구는 임시다 (확인 필요).
- 게스트 세션이 남은 채 다시 접속한 게스트에게는 게임으로 들어가기 전에 [Google로 가입하고 이어 하기]와 [게스트로 계속하기]를 고르게 한다. 세션이 끝난 게스트는 접속 화면을 본다.
- **API:** BOOT-01, AUTH-01

#### F-02 소셜 로그인·가입 (화면 02)

- 가입과 로그인은 소셜 로그인으로 한다. 지원할 제공자는 (확인 필요).
- 처음 로그인한 사용자는 프로필(F-04)과 약관 동의를 제출해야 계정이 만들어진다. 그 전에는 가입 관련 기능만 쓸 수 있다.
- 가입 화면은 두 단계다. 먼저 약관 동의를 받고([전체 동의]로 한 번에 켜고 끌 수 있고, 필수 약관에 모두 동의해야 [다음]), 다음 단계에서 닉네임·캐릭터를 받아 [가입하기]로 함께 제출한다. 다음 단계의 [뒤로]는 고른 동의를 유지한 채 약관 단계로 돌아간다. 휴대폰을 가로로 눕혀도 두 단계 창이 화면 안에 들어간다.
- 동의 항목은 이용약관, 개인정보 처리방침, 만 14세 이상 확인, 음성 처리 동의다. 앞의 세 항목은 필수이고 음성 처리 동의는 선택이다. 음성 처리에 동의하지 않으면 음성 입력을 쓸 수 없고 글자로 대화한다. 게스트는 시작할 때 음성 처리 동의를 고른다.
- 각 약관의 [보기]는 약관 문서 페이지를 연다. 문구와 버전은 [서비스 API](../api/mvp-api.md#auth-03-get-apiv1authsignup)의 AUTH-03을 따른다.
- 필수 약관이 빠지면 계정을 만들지 않고 빠진 항목을 알려준다.
- 소셜 인증이 실패하거나 취소되면 접속 화면으로 돌아가 다시 시도할 수 있다.
- 게스트가 가입하면 새 계정을 만들지 않고 그 게스트를 회원으로 바꿔, 게스트 때 대화·단어·NPC와의 사이·게임 시간·장소를 그대로 이어 간다. 캐릭터는 게스트 때 것을 쓰고 닉네임과 약관만 받으며, 언어·레벨 화면 없이 게임으로 돌아간다. 이미 가입한 소셜 계정으로 로그인하면 그 계정으로 들어가고 게스트 기록은 합치지 않는다고 알린다.
- **데이터:** `users`(provider, provider_uid, email은 제공자가 줄 때만), `user_consents`
- **API:** AUTH-01 ~ AUTH-04
- **근거:** 회의 보드 01 가입 방식, REQ-01

#### F-03 재방문 복귀

- 로그인하면 `users.onboarding_step`으로 이어갈 화면을 정한다.
  - `LANG`: 학습 언어 선택(화면 03)
  - `LEVEL`: 레벨 테스트(화면 04). 테스트를 마쳤거나 그만뒀거나 건너뛰었으면 난이도 설정(화면 05)
  - `TUTORIAL`: 튜토리얼 처음(화면 06)부터 다시 진행
  - `DONE`: 마지막으로 있던 장소. 없으면 마을
- 진행 중이던 대화가 있으면 대화 기록을 다시 불러온다. 이어서 진행할지 종료 처리할지는 (확인 필요).
- 미션 진행 상태는 그대로 유지한다(F-18).
- **완료 기준:** 새로고침·재접속 후에도 본인의 단어장·피드백·미션 상태가 보인다(T-01). 두 사용자의 기록이 섞이지 않는다(T-02).
- **API:** BOOT-01, CONV-11
- **근거:** 와이어프레임 02, REQ-01·19

#### F-04 프로필 입력 (화면 02)

- 가입 화면에서 닉네임과 캐릭터 기본형을 반드시 입력한다. 닉네임은 NPC가 사용자를 부르는 이름이다.
- 닉네임은 한글 2~8자 또는 영문·숫자 2~16자다. 섞어 쓰면 한글은 2, 영문·숫자는 1로 세어 합계 16 이하다.
- 다른 사용자가 쓰는 닉네임은 쓸 수 없으며, 제출 전에 [중복 확인]으로 확인할 수 있다.
- MVP의 캐릭터 기본형은 성별(여·남)만 고른다.
- 프로필과 약관 동의를 함께 제출해야 계정이 만들어진다.
- 닉네임 금칙어 처리 여부는 (확인 필요).
- **데이터:** `users.nickname`(unique), `users.avatar_type`(F · M)
- **API:** AUTH-04, AUTH-06
- **근거:** 회의 보드 02 닉네임·캐릭터 기본형

### 3.2 초기 설정

#### F-05 학습 언어 선택 (화면 03)

- 상단에 초기 설정 진행 표시, 가운데에 "배우고 싶은 언어를 선택하세요"와 언어 카드, 하단에 [다음]을 둔다.
- MVP에서 고를 수 있는 언어는 영어(미국 영어)뿐이다. 다른 언어는 "준비 중" 카드로 보여줄 수 있다.
- **데이터:** `users.current_language`(en-US), `user_language_profiles`
- **API:** ONB-01, ONB-02
- **근거:** 회의 보드 02 학습 언어

#### F-06 레벨 테스트 (화면 04)

- 레벨 확인 안내 → 문항 풀기("문항 3 / N" 진행률) → 결과 확인 → 난이도 설정 순서로 진행한다.
- [건너뛰기]를 누르면 테스트 없이 1단계(초급)로 시작하고, 더 높은 난이도의 대화를 원하면 레벨 테스트를 보라고 안내한다.
- [그만하기]를 누르면 일부만 푼 상태로 멈추고 추천 레벨 없이 난이도 설정으로 넘어간다.
- MVP에서는 화면과 흐름만 만들고, 적용하는 난이도는 초급(1단계)뿐이다.
- MVP의 첫 화면에는 [레벨 테스트 진행하기]와 [건너뛰기]를 두되 [진행하기]는 "준비 중"으로 막아 둔다. 서버에는 예시 선택형 5문항과 초급 고정 결과로 흐름을 만들어 두어, 막아 둔 버튼을 열면 바로 쓸 수 있다.
- 실제 문항 형식, 문항 수, 채점 기준, 문항 하나만 건너뛰는 기능은 (확인 필요).
- **데이터:** `level_tests`(IN_PROGRESS · DONE · QUIT · SKIPPED), `level_test_answers`, `user_language_profiles.recommended_level`
- **API:** ONB-03 ~ ONB-07
- **근거:** 회의 보드 02 레벨 테스트·건너뛰기

#### F-07 NPC 대화 난이도 설정 (화면 05)

### 3.3 집 튜토리얼

#### F-09 튜토리얼 진행 틀

- 튜토리얼은 집 안(화면 06~09)에서 시작해 집 밖 행인 길 안내(화면 10~12)로 끝난다.
- 튜토리얼은 미리 작성한 대본으로 진행한다. 대본, NPC 대사·음성, 사용자가 말할 대사는 Unity 콘텐츠이고, 서버는 음성 인식과 튜토리얼 완료·건너뛰기 기록만 맡는다.
- 상단에 진행 단계(예: "튜토리얼 1/5")를 보여준다. 안내를 놓쳤으면 [이전 단계]로 다시 본다.
- 화면 06에서 [튜토리얼 건너뛰기]를 누르면 튜토리얼을 마친 것으로 기록하고 마을에서 시작한다. 건너뛴 사용자에게 튜토리얼을 다시 볼 방법을 줄지는 (확인 필요).
- 마치기 전에 접속을 끊으면 다음 접속 때 튜토리얼을 처음(화면 06)부터 다시 진행한다. 마치거나 건너뛴 뒤에는 다시 시작하지 않는다.
- 튜토리얼을 마치면 일일 미션을 연다(F-17).
- **데이터:** `users.onboarding_step`(튜토리얼을 마치거나 건너뛰면 `DONE`). 튜토리얼 대화와 튜토리얼 미션은 DB에 기록하지 않는다.
- **API:** TUT-01, TUT-02
- **근거:** 범위 문서 4절, 회의 보드 03 재시도/다시 보기, 회의 보드 04 막힘·오류, 5.1절 12번

- 거울 앞에 선 캐릭터를 보여주고, 안내 캐릭터가 대사창으로 설명하는 연출을 쓴다 (제안).
- 서비스 설명은 몇 문장으로 핵심 경험을 알린다(예: "우리 서비스는 ~ 이런 거야"). 문구는 (확인 필요).

#### F-11 키 조작 안내 (화면 07)

- 집 안에서 직접 움직이며 조작을 익힌다. 다루는 조작은 이동(방향키), 달리기, 점프, 카메라 회전, 시점 전환, 확대·축소다. 조작을 직접 해 보면 체크 표시를 한다.
- 카메라는 마우스 왼쪽 버튼을 누른 채 움직여서 돌리고, 마우스 커서는 고정하지 않는다.
- 정확한 키 배치는 조작 설계에 맞춰 정한다 (확인 필요).
- [이해했어요]를 누르면 가구 호버 실습으로 넘어간다.
- 튜토리얼 밖에서도 장소 화면 오른쪽 아래의 작은 조작법 카드로 이동·달리기·점프·카메라 회전·확대·축소·시점 전환과 사물·NPC 클릭을 보여준다. 휴대폰·태블릿에서는 조이스틱·화면 끌기·사물·NPC 탭을 보여준다. 카드는 X로 닫으면 그 기기에 기억해 다시 띄우지 않고, 오른쪽 위 메뉴(≡)의 [조작법]으로 다시 연다.

#### F-12 사물 호버 카드 (화면 08, 공통)

- 호버 대상 사물에 마우스를 올리면 카드가 뜨고, 벗어나면 사라진다. 집·마을·카페·호텔에서 같은 방식으로 동작한다.
- 카드에는 영어 이름, 한국어 뜻, 발음 듣기를 보여준다. 단어장에 저장한 단어는 예문과 예문 뜻까지 보여준다.
- 카드에는 [단어 저장]과 [보이지 않기] 버튼을 둔다. [단어 저장]은 단어장에 저장하고(F-33), [보이지 않기]는 그 사물의 카드를 더 이상 자동으로 띄우지 않는다(F-36).
- 발음 음성은 사물 어휘를 등록할 때 TTS로 한 번 만들어 두고, 들을 때 AI를 호출하지 않는다 (제안).
- 사물 정보는 미리 등록한 어휘를 쓰므로 AI를 호출하지 않는다. AI 한도가 소진돼도 동작한다.
- 튜토리얼 실습 대상(예시)은 TV, 냉장고, 에어컨, 소파, 책장이다. "가구에 마우스를 올려보세요"라고 안내하고 [다음]을 누르면 미션 소개로 넘어간다.
- 튜토리얼에서 [다음]이 열리는 조건(확인할 사물 수 등)은 (확인 필요).
- **데이터:** `world_objects`(unity_key → vocab_id), `vocabularies`(example, example_ko, pronunciation_audio_key), `user_vocab`, `user_object_prefs`
- **API:** WORLD-02, WORLD-04, VOCAB-02(OBJECT), WORLD-03
- **완료 기준:** 어휘가 연결된 사물에 마우스를 올리면 카드가 뜨고 벗어나면 사라진다(T-11의 표시·숨김).
- **근거:** 회의 보드 03 가구 호버, 와이어프레임 08, REQ-06, 5.1절 1·4번

#### F-13 미션 소개·외출 (화면 09)

- 호버 실습이 끝나면 튜토리얼 미션 "길 잃은 사람 돕기"를 띄우고 "집 밖으로 나가 사람을 만나세요"라고 안내한다. 출구와 이동 동선을 보여준다.
- 튜토리얼 미션은 수락 버튼 없이 바로 시작한다.
- 문을 지나가면 장면을 전환해 집 밖 마을로 나간다. 전환 중에 실내와 실외가 동시에 보이지 않게 한다.
- **API:** WORLD-05
- **근거:** 회의 보드 03 미션 안내·집 밖 전환, 와이어프레임 09

### 3.4 행인 길 안내 튜토리얼

#### F-14 행인 선제 접근 (화면 10)

- 집 밖으로 나오면 바로 플레이어 조작을 잠그고, 행인 NPC가 다가오는 장면을 짧게 보여준 뒤 대화 제안 팝업을 띄운다.
- 팝업에는 행인이 말을 거는 이유가 담긴 제안(예: "잠깐 도와줄 수 있나요?")과 [대화하기]를 둔다.
- 튜토리얼에서는 무조건 수락한다. 거절하거나 지나갈 수 없다.
- [대화하기]를 누르면 NPC 중심 1인칭과 이동 잠금으로 바뀐다(F-15).
- **근거:** 회의 보드 04 접근 트리거·응답 선택·카메라·이동, REQ-04·05

#### F-15 길 안내 튜토리얼 대화 (화면 11)

- 행인이 카페 위치를 묻는 대본으로 진행한다. 이후의 NPC 자유 대화(F-23~F-28)와 구분한다.
- 화면에 대본의 NPC 대사와 사용자가 말할 대사를 보여준다. 안내할 목적지는 카페(또는 호텔)로 고정한다.
- 입력은 [말하기]를 한 번 눌러 녹음을 시작하고 다시 눌러 끝내는 방식이고 최대 녹음 시간을 둔다. 마이크를 쓸 수 없으면 텍스트로 입력한다.
- 음성 인식 결과를 대본의 대사와 비교해 맞으면 다음 대사로 넘어간다. 비교 기준(키워드 포함 여부 등)은 클라이언트 콘텐츠에서 정한다. 대본의 대사를 모두 말하면 길 안내를 완료한 것으로 본다.
- 추천 단어, 힌트, 대화 종료 버튼은 두지 않는다.
- 최대 녹음 시간, 사용자가 아무 말도 하지 않을 때의 처리, 튜토리얼 음성 인식을 AI 사용량에 포함할지는 (확인 필요).
- **API:** CONV-02(`purpose: TUTORIAL`)
- **근거:** 범위 문서 4-7, 회의 보드 04 대화 방식·추천 표현·길 안내 판정·막힘·오류, 5.1절 12번

#### F-16 튜토리얼 피드백·종료 (화면 12)

- 실제 AI 피드백이 아니라, 대화가 끝나면 이런 피드백(잘한 점, 개선 표현)을 받는다는 예시와 피드백 표현을 단어장에 저장하는 방법을 보여준다. AI를 호출하지 않는다.
- 하단에 [단어장 보기] [마을로 가기]를 둔다. 어느 쪽을 눌러도 튜토리얼을 마친 것으로 기록한다 (제안).
- **API:** TUT-01
- **근거:** 범위 문서 4-8·4-9, 와이어프레임 12, 5.1절 12번

### 3.5 미션

#### F-17 미션 목록 (화면 13)

- 튜토리얼이 끝나면 일일 미션을 제시해 카페나 호텔 NPC를 만나도록 이끈다.
- 미션 목록은 화면 왼쪽에 기본으로 열려 있고, 열고 닫을 수 있다. 진행 중인 미션 제목은 화면 위에 표시하고, 다음 갱신 시각을 보여준다.
- 미션은 2개를 제시한다. 범위 문서의 "2~3개" 중 회의 보드에서 2개로 정했다.
  - 예시 1: "카페에 가서 우유를 두유로 바꾼 카페라테를 주문하세요."
  - 예시 2: "카페에 가서 디저트를 파는지 물어보세요."
- 일일 미션은 카페와 호텔에 하나씩 둔다(카페 음료 주문, 호텔 체크인).
- 미션 카드에는 제목, 설명, 대상 장소·NPC, 진행 상태를 보여준다.
- 시설 위치를 어떻게 안내할지는 (확인 필요). 지도와 자세한 설명이 있는 미션 상세 화면은 MVP에 넣지 않는다.
- **데이터:** `missions`(title, description, npc_id)
- **API:** MIS-01
- **근거:** 회의 보드 05 미션 목록·목표·안내, 와이어프레임 13

#### F-18 미션 선택·진행 상태

- 미션은 사용자가 골라서 수락한다. 미션을 고르지 않아도 자유 탐험과 NPC 대화를 할 수 있다.
- 상태는 시작 전 → 진행 중 → 완료 순서로 바뀐다. 진행 중에 그만두면(중단) 시작 전으로 돌아간다.
- 나갔다가 다시 들어와도 진행 상태는 유지된다.
- 여러 미션을 동시에 진행할 수 있는지는 (확인 필요).
- **데이터:** `user_missions.status`. ERD v3.1은 자동 시작 기준(RUN · DONE, 수락 시각 없음)이므로 시작 전 상태(IDLE)와 수락 시각(accepted_at)을 다시 넣어야 한다.
- **API:** MIS-01. 자동 시작 기준이므로 수락·중단 API를 더해야 한다([5.2절](#52-mvp-api-명세-초안과-다른-점)).
- **근거:** 회의 보드 05 선택·수락·진행 상태·저장·재접속·거절·포기, 5.1절 13번

#### F-19 미션 완료 판정

- AI가 대화 턴마다 미션 완료 후보를 제안하고, 서버가 확인해서 확정한다. 수락한 미션만 판정한다 (제안).
- 서버는 미션에 등록한 판정 키워드가 사용자 발화와 NPC 대사에 나왔는지 확인한다 (제안). AI 의도 판정과 키워드 일치를 둘 다 요구할지, 하나만 요구할지는 (확인 필요).
- 확정하면 미션을 완료로 바꾸고, 미션을 완료한 대화를 함께 기록한다. 한 대화에서 여러 미션을 함께 완료할 수 있다. 같은 턴을 다시 보내도 완료는 한 번만 처리한다.
- MVP의 미션 완료 행동은 대상 NPC와의 대화다. 장소 방문, 단어 저장 같은 다른 행동으로 완료하는 미션이 필요한지는 (확인 필요).
- 미션 완료 여부와 관계없이 NPC와의 대화는 자유롭게 이어진다.
- **데이터:** `missions.keywords`, `missions.intent_rule`, `ai_candidates`(kind MISSION_DONE, decision PENDING · APPROVED · REJECTED), `user_missions.conversation_id`
- **API:** CONV-03(missionUpdates), CONV-08(completedMissions)
- **근거:** 회의 보드 05 완료 판정, 03 3.2절

#### F-20 일일 미션 갱신

- MVP에는 간단한 일일 미션만 넣는다. 자정에 새 미션으로 바뀐다.
- 자정은 한국 시간(Asia/Seoul) 기준으로 한다 (제안). 새 미션을 고르는 규칙(정해진 목록을 순서대로, 무작위 등)은 (확인 필요).
- 수행하지 않은 미션에 불이익을 주지 않는다(03 3.5절).
- 보상은 MVP 이후에 다룬다.
- **데이터:** `missions`(일일 미션 정의), `user_missions.mission_date`(사용자·미션·날짜 조합은 하나만)
- **API:** MIS-01
- **근거:** 회의 보드 05 MVP 경계·보상, 5.1절 7번

### 3.6 시설 이동·NPC 상호작용

#### F-21 장면 이동 (화면 14)

- 장면은 집(HOME), 마을(TOWN), 카페(CAFE), 호텔(HOTEL)이다. 건물 문을 지나가면 장면을 전환해 출입한다.
- MVP에서 들어갈 수 있는 시설은 카페와 호텔이다. ERD·API 명세와 시드에 호텔 개방과 호텔 직원 NPC(`HOTEL_STAFF`)를 반영했다.
- 출입을 여러 번 눌러도 전환은 한 번만 일어난다.
- 장소를 옮기면 재접속 위치로 현재 장소를 저장한다. 장소 안의 정확한 위치까지 복원할지는 (확인 필요).
- **데이터:** `scenes`, `users.last_scene_id`
- **API:** WORLD-01, WORLD-05
- **완료 기준:** 마을에서 카페를 찾아 들어가고 다시 나올 수 있다(T-03).
- **근거:** 범위 문서 4-6, 와이어프레임 14, REQ-02·03, 5.1절 9번

#### F-22 NPC 상호작용·대화 시작 (화면 14)

- 대화할 수 있는 NPC에게 다가가면 이름표와 상호작용 표시가 뜬다. [E 대화하기]로 자유 대화를 시작하고, 뒤로 가면 마을 탐색으로 돌아간다.
- NPC가 많은 곳에서도 원하는 NPC에게 말을 걸 수 있도록, 8m 안의 NPC는 몸이나 머리 위 이름표를 클릭·탭해도 대화를 시작한다. PC에서는 말을 걸 수 있는 NPC나 그 이름표에 커서를 올리면 NPC 몸에 테두리를 그린다.
  - 이름표는 바탕 전체가 클릭을 받고, 이름표를 누르면 그 NPC 몸을 누른 것과 같다. 이름표가 겹치면 가까운 NPC 이름표를 위에 그리고 그 NPC에게 말을 건다. 이름표 위에서는 뒤 사물의 사물 카드가 뜨지 않고, 메뉴·창이 이름표를 덮었으면 반응하지 않는다.
  - 다가와 제안하는 NPC를 누르면 [대화하기]를 누른 것과 같다. 다른 NPC가 제안하는 중이면 그 제안을 거절한 것으로 닫고, 누른 NPC와 대화한다. 거절할 수 없는 제안(튜토리얼)이 떠 있으면 반응하지 않는다.
  - 대화를 다 쓴 게스트가 누르면 가입 안내 창을 띄운다(F-39).
  - 8m보다 멀거나 다른 대화·창·튜토리얼 진행이 막고 있으면 반응하지 않는다. 벽이나 사물 카드가 뜨는 사물이 앞을 가리면 그 사물을 누른 것으로 본다.
- 대화를 시작하려면 플레이어가 NPC 가까이 있고, NPC가 대화할 수 있는 상태이며, 진행 중인 다른 대화가 없고, 한 턴과 짧은 피드백에 쓸 AI 사용량이 남아 있어야 한다(F-38).
- 카페나 호텔에 들어가는 것만으로 대화를 시작하지 않는다.
- 튜토리얼이 끝난 뒤에는 거리의 행인이 먼저 말을 걸 수 있다.
  - 미리 작성한 첫 말을 말풍선으로 보여주고 [대화하기] [지금은 괜찮아요]를 둔다.
  - 수락하면 그 첫 말을 첫 NPC 턴으로 삼아 대화를 시작한다. 거절하거나 무시하면 아무 일도 일어나지 않는다.
  - 말을 거는 조건(거리, 반복 간격, 횟수)은 클라이언트 콘텐츠 설정이며 값은 (확인 필요).
  - AI를 쓸 수 없는 상태에서는 말을 걸지 않는다.
- 직원 NPC의 첫 인사를 미리 작성할지 AI로 만들지는 (확인 필요).
- MVP의 NPC는 길 안내 행인, 카페 바리스타, 호텔리어를 기본으로 한다 (제안). 아트 제작 목록의 최초 배치 제안과 같다. 더 둘 NPC 수는 (확인 필요).
- **데이터:** `npcs`(npc_type PASSERBY · STAFF, can_initiate, approach_line, approach_audio_key), `conversations`(initiated_by USER · NPC)
- **API:** WORLD-02, CONV-01
- **근거:** 범위 문서 4-7, 와이어프레임 14, REQ-05, 03 2절

### 3.7 NPC AI 자유 대화 (화면 15)

#### F-23 대화 화면·종료

- NPC 중심 1인칭이며 이동을 잠근다. 대화창에 NPC 대사와 내 발화가 차례로 쌓이고, 상단에 이 NPC가 대상인 진행 중 미션을 보여준다.
- 미션과 관계없는 주제로도 대화를 이어갈 수 있다. 정해진 답을 요구하지 않는다.
- [대화 종료 (Esc)]로 언제든 끝내고 3인칭 탐색으로 돌아간다. 오류 화면에서도 종료할 수 있다.
- NPC가 대화를 마무리할 수도 있다. AI가 종료 후보를 내고 서버가 확정하면 NPC가 작별 인사를 한 뒤 대화를 끝낸다.
- AI 사용량이 떨어지면 NPC의 작별 대사로 대화를 끝낸다(F-40).
- 오랫동안 요청이 없으면 서버가 대화를 만료로 닫고 예약한 사용량을 푼다. 시간 값은 서버 설정값이다. 대화 중 새로고침했을 때 이어서 진행할지 종료 처리할지는 (확인 필요).
- 대화가 끝나면 짧은 피드백(F-29)으로 넘어간다.
- **데이터:** `conversations.status`(ACTIVE · ENDED_BY_USER · ENDED_BY_NPC · EXPIRED), `conversations.end_reason`(USER_ENDED · NPC_ENDED · QUOTA_EXHAUSTED · EXPIRED), `ai_candidates`(kind CONVO_END)
- **API:** CONV-01, CONV-08, CONV-11
- **완료 기준:** 대화 중 이동 키를 눌러도 캐릭터가 움직이지 않고, 종료하면 3인칭과 이동이 복원된다(T-04). 주문 뒤 날씨처럼 관계없는 질문에도 자연스럽게 답한다(T-06).
- **근거:** 회의 보드 06 대화 자유도·종료·복귀, REQ-04·08

#### F-24 음성·텍스트 입력

- 기본 입력은 마이크 [말하기]다. 한 번 누르면 녹음을 시작하고 다시 누르면 끝낸다. 녹음 중 목소리가 들리면 버튼의 초록불이 켜진다. 마이크를 쓸 수 없으면 [텍스트로 입력]을 쓴다.
- 음성은 외부 음성 인식 업체로 보내므로 음성 처리에 동의한 사용자만 말하기를 쓴다(F-02). 동의하지 않았으면 [말하기]를 회색으로 보이고, 누르면 음성을 어디에 쓰는지 알리는 동의 창([문서 보기]·[닫기]·[동의하고 켜기])을 띄운다. 그 자리에서 동의하면 바로 말할 수 있고, 동의하지 않아도 글자로 대화한다. 게스트와 회원이 같다.
- 녹음이 최대 시간을 넘으면 자동으로 끝낸다. 녹음 형식과 최대 길이는 STT 벤더 입력 형식에 맞춰 정한다 (확인 필요).
- 녹음이 끝나면 인식된 문장을 보여주고 [보내기] 또는 [다시 녹음]을 고른다. 인식된 문장을 직접 고치는 기능은 두지 않는다.
- 아무 말도 인식되지 않으면 다시 녹음하라고 안내한다.
- 한국어와 영어를 섞어 말해도 언어를 따로 고르지 않는다.
- 받은 음성은 전사한 뒤 보관하지 않는다. 음성으로 보낸 턴에는 STT 원문을 함께 저장한다.
- **데이터:** `turns`(input_type VOICE · TEXT, stt_raw_text, text, request_id)
- **API:** CONV-02(`purpose: TURN`), CONV-03
- **완료 기준:** 잘못 인식된 발화를 다시 녹음하거나 텍스트로 입력해 대화를 이어간다. 04 T-10은 전사 수정을 기준으로 해서 갱신이 필요하다.
- **근거:** 회의 보드 06 음성·텍스트 입력·전사 확인, REQ-09·12, 5.1절 11번

#### F-25 NPC 응답

- 사용자 발화 → LLM → TTS 순서로 처리해 NPC의 음성과 자막을 출력한다.
- NPC 응답에는 NPC의 성격·직업·장소, 같은 대화의 최근 맥락, 적용 난이도를 반영한다.
- 한영 혼용이나 불완전한 발화도 의도를 추론해 대화를 이어간다. 틀린 영어 때문에 대화를 멈추지 않는다.
- 응답을 기다리는 동안 처리 중임을 보여준다.
- NPC 대사 옆에 [다시 듣기]를 둔다. 만들어 둔 음성을 다시 재생하며 TTS를 새로 만들지 않는다.
- 읽지 않고 들어서 이해하는 연습을 위해 NPC 대사 자막은 꺼진 채 시작한다. 자막을 끄면 대사를 단어마다 회색 막대로 가려 띄어쓰기만 보이고, [자막]으로 언제든 켜고 끌 수 있다. 설정은 기기에 저장한다. [뜻 보기]를 펼친 동안과, 음성을 재생할 수 없는 대사(생성 실패·만료)는 자막을 꺼 두었어도 보여준다.
- 음성 생성에 실패하면 자막은 그대로 보여주고 음성만 다시 만들 수 있게 한다.
- NPC 턴 음성은 생성 후 최대 30일, 개발·운영 각각 합계 5GB까지 보관한다. 매일 정리에서 만료 파일을 먼저 정리하고 상한을 넘으면 오래된 음성부터 삭제한다(정리 사이에는 상한을 넘을 수 있다). 삭제한 음성은 다시 만들지 않으며, 음성이 없거나 조회에서 404를 받으면 재생 버튼을 숨기고 자막을 유지한다. 최초 생성 실패의 재시도는 유지한다. 세부 기준은 [NPC 음성 저장 운영](../npc-audio-storage.md#보관삭제-정책)을 따른다.
- **데이터:** `npcs.persona`, `npcs.voice_id`, `turns`(speaker NPC, npc_audio_key, npc_audio_created_at, npc_audio_deleted_at)
- **API:** CONV-03, CONV-06, CONV-07
- **완료 기준:** 실제 음성으로 왕복하고 이전 질문을 반영해 답한다(T-07). 한국어, 영어, 혼용 발화의 의도를 각각 이해한다(T-08).
- **근거:** 회의 보드 06 NPC 응답, REQ-08·09·10

#### F-26 NPC 대사 뜻 보기·단어 뜻

- [뜻 보기]를 누르면 NPC 대사 전체의 한국어 뜻을 보여준다.
- NPC 대사 안의 단어에 마우스를 올리면 그 단어의 뜻을 보여준다.
- 뜻은 처음 요청할 때 만들어 저장하고, 다시 볼 때는 AI를 호출하지 않는다.
- 대사의 단어나 문장을 단어장에 저장할 수 있다(F-33). 저장 버튼의 위치는 와이어프레임에 없어 (확인 필요).
- **데이터:** `turns.meaning_ko`, `turns.glossary`
- **API:** CONV-04, VOCAB-02(NPC_LINE)
- **근거:** 회의 보드 06 NPC 발화 표시, 회의 보드 08 저장 출처, REQ-10

#### F-27 추천 단어

- NPC 응답과 함께 지금 대화에 쓸 만한 추천 단어 3개를 만들어 대화창 상단에 늘 보여준다. 힌트 버튼(F-28)과 별개다.
- 힌트 1단계 키워드와 같은 단어를 쓸지는 (확인 필요).
- **데이터:** `turns.suggest_words`
- **API:** CONV-01·CONV-03 응답
- **근거:** 회의 보드 06 추천 단어

#### F-28 3단계 힌트

- [힌트]를 누를 때마다 한 단계씩 연다: 1단계 키워드 → 2단계 문장 시작 → 3단계 전체 예문.
- 답할 방향이 여럿이면 AI가 대화 맥락과 진행 중인 미션을 보고 가장 자연스러운 방향 하나를 골라 보여준다.
- [다른 답 보기]를 누르면 다른 방향으로 바꾸고 1단계부터 다시 보여준다.
- 힌트를 보지 않아도 대화를 계속할 수 있고, 하나의 정답을 강요하지 않는다.
- 처음 [힌트]를 누를 때 방향 2~3개의 3단계 힌트를 한꺼번에 만들어 저장하고, 단계를 열거나 방향을 바꿀 때는 다시 요청하지 않는다 (제안).
- 어느 방향의 몇 단계까지 열었는지 기록한다.

예시:

```text
NPC: What can I get for you today?
[힌트] 1번   1단계  iced · latte · please
[힌트] 2번   2단계  I'd like ...
[힌트] 3번   3단계  I'd like an iced latte, please.
[다른 답 보기] → '추천 묻기' 방향으로 1단계부터 다시
```

- **데이터:** 지금 ERD에는 추천 문장 하나(`turns.hint_text`)와 힌트를 연 시각(`turns.hint_opened_at`)만 있다. 방향별 3단계 내용과 연 단계를 담도록 바꿔야 한다 (확인 필요).
- **API:** CONV-05. 추천 문장 하나를 돌려주는 2단계 기준이므로 바꿔야 한다([5.2절](#52-mvp-api-명세-초안과-다른-점)).
- **완료 기준:** 키워드 → 문장 시작 → 전체 예문을 단계별로 열 수 있다(T-09). [다른 답 보기]로 방향을 바꾸면 1단계부터 다시 보인다.
- **근거:** 5.1절 3번, REQ-11

### 3.8 피드백

#### F-29 짧은 피드백 (화면 16)

- 대화가 끝나면 바로 보여준다: 대화한 NPC·장소·발화 수, 완료한 미션, 대화 요약, 잘했어요·아쉬워요 칩, 개선 표현(내 발화 → 더 자연스러운 표현).
- 칩은 지도 앱의 방문자 리뷰 키워드처럼 짧은 문구로 보여준다. 이번 대화에서 실제로 한 말을 근거로 쓴다(예: "예약 이름을 먼저 말했어요", "정중하게 요청했어요"). "숙어 표현이 부족해요"처럼 대화와 상관없이 붙는 고정 부족 항목은 쓰지 않는다.
- 개선 표현은 단어장에 저장할 수 있다(F-33).
- 하단에 [상세 보기] [마을로 돌아가기]를 둔다. 닫으면 3인칭 탐색으로 돌아간다.
- 대화를 시작할 때 예약한 사용량으로 만들므로, 사용량이 떨어져 NPC가 대화를 끝낸 경우에도 피드백을 받는다.
- 사용자 발화가 없는 대화의 피드백을 만들지는 (확인 필요).
- **데이터:** `conversation_feedback`(summary, reviews `{ good, improve, suggestion }`, status DONE · FAILED · SKIPPED)
- **API:** CONV-08, FB-01
- **완료 기준:** 대화를 정상 종료하면 짧은 피드백이 뜨고, 바로 닫아 탐색으로 돌아갈 수 있다(T-12).
- **근거:** 회의 보드 07 짧은 요약, 와이어프레임 16, REQ-13

#### F-30 상세 피드백 (화면 17)

- 대화에서 사용자가 한 문장마다 보여준다: 내 발화, 더 자연스러운 표현, 이유(한국어), 숙어와 그 뜻. 맞는 문장에는 교정 대신 더 자연스러운 대안이나 숙어를 대화 전체에서 최대 1개만 보이고 원문도 맞다고 알린다. 억지 숙어는 넣지 않는다. 장면에 맞는 관용표현·숙어는 "이 상황에서 자주 써요"(상황 표현)로 따로 보인다.
- [모범 음성 듣기]로 더 자연스러운 표현의 원어민 발음(TTS)을 듣는다. 한 번 만든 음성은 저장해 다시 쓴다. 마지막 재생 뒤 30일이 지나거나 전체 상한(5GB)을 넘으면 서버가 지우고, 다시 누르면 새로 만든다.
- 내 음성 다시 듣기는 MVP에 넣지 않는다. 음성 보관 정책과 함께 이후에 검토한다.
- 듣고 다시 말하는 연습 기능은 두지 않는다. 사용자가 스스로 따라 말한다.
- 표현과 숙어를 단어장에 저장할 수 있다(F-33).
- 평가는 사용자가 보낸 문장을 기준으로 한다. STT 오인식을 발음 오류로 평가하지 않고, 음소별 정밀 발음 점수는 MVP에 넣지 않는다.
- [상세 보기]를 처음 누를 때 만들고, 이미 만들었으면 저장된 평가를 보여준다. 대화 종료 때 미리 만들지는 (확인 필요).
- **데이터:** `turn_feedback`(better_text, reason, idiom, idiom_meaning_ko, model_audio_key)
- **API:** FB-03, FB-01, FB-04, VOCAB-02(FEEDBACK)
- **완료 기준:** 상세 피드백을 만든 뒤 재접속해도 다시 열람할 수 있다(T-13). T-14에서 내 음성 재생과 재녹음 항목은 제외한다.
- **근거:** 회의 보드 07 상세 평가·다시 듣기·모범 음성·재발화·표현 저장, 와이어프레임 17, REQ-14·15, 5.1절 2·16번

#### F-31 피드백 건너뛰기

- 대화를 끝낼 때 피드백을 건너뛰고 바로 탐색으로 돌아갈 수 있다.
- 건너뛰면 피드백을 만들지 않고 `SKIPPED`로 기록하며, 피드백용으로 예약한 사용량을 푼다.
- 건너뛰어도 NPC 호감도에는 반영하지 않는다(5.1절 6번).
- 건너뛰기 버튼의 위치는 (확인 필요).
- **API:** CONV-08(`skipFeedback`)
- **근거:** 회의 보드 07 건너뛰기, REQ-13

#### F-32 피드백 다시 열람·생성 실패

- 지난 대화의 피드백과 대화 기록은 [단어장] 옆 [피드백 목록] 창에서 다시 본다. 새로고침·재접속 후에도 볼 수 있다.
- 피드백 생성에 실패해도 대화는 정상 종료한다. 결과를 지어내지 않고 [다시 만들기]와 [대화 기록 보기]를 보여준다.
- AI 한도가 소진된 상태에서는 새 피드백을 만들지 않고 이미 만든 피드백만 보여준다(F-39). 대화 텍스트 기록은 AI 없이 볼 수 있다.
- **데이터:** `conversation_feedback.status`(FAILED)

- **완료 기준:** AI 한도가 0이어도 저장된 피드백과 대화 기록을 볼 수 있고, 만들지 않은 평가를 표시하지 않는다(T-30).
- **근거:** 회의 보드 07 다시 열람·생성 실패, 04 2.4.1절

### 3.9 단어장 (화면 18)

#### F-33 표현 저장·중복 처리

- 사물 호버 카드, NPC 대사, 피드백 세 곳에서 저장할 수 있다. 단어, 숙어, 문장을 모두 저장한다.
- 이미 저장한 표현을 다시 저장하면 새로 만들지 않고 중요도를 올려 목록 위쪽으로 옮긴다.
- 피드백에서 저장하는 표현은 그 대화의 피드백에 실제로 있는 표현만 받는다.
- 뜻이 없는 표현(NPC 대사의 일부 등)을 저장할 때 뜻을 AI로 만들지, 이미 만든 대사 뜻·숙어 뜻을 쓸지는 (확인 필요). AI를 호출하지 않는 저장은 AI 한도가 소진돼도 할 수 있다.
- **데이터:** `vocabularies`(type WORD · IDIOM · SENTENCE, source), `user_vocab`(source_type OBJECT · NPC_LINE · FEEDBACK, source_turn_id). ERD v3.1은 중요도 컬럼을 지웠으므로 다시 넣어야 한다.
- **API:** VOCAB-02. 이미 저장한 표현은 그대로 돌려주는 기준이므로 중요도를 올리도록 바꿔야 한다([5.2절](#52-mvp-api-명세-초안과-다른-점)).
- **완료 기준:** 저장, 중복 저장 처리, 삭제, 조회가 동작한다(T-15).
- **근거:** 회의 보드 08 저장 출처·저장 단위·중복 처리, REQ-16, 5.1절 14번

#### F-34 단어장 목록·상세·메모·삭제

- 상단에 유형 필터(전체·단어·숙어·문장)와 유형별 개수를 보여준다.

- [단어장에서 삭제]는 내 단어장에서만 지운다.
- 지난 대화의 피드백과 기록은 단어장 옆 [피드백 목록] 창에서 본다(F-32).

- **근거:** 회의 보드 08 목록·상세·삭제·수정, 와이어프레임 18, 5.1절 14·15번

### 3.10 AI 한도·오류 (화면 19)

#### F-37 AI 사용량 조회

- 서버는 사용자별 AI 이용 상태를 알려준다. 상태는 사용 가능, 소진, 일시 장애, 운영 제한으로 나눈다.
- HUD에 AI 사용 가능 여부를 표시한다. 남은 양과 갱신 시점은 정책이 정해진 경우에만 보여주고, 정해지지 않았으면 갱신 시점을 약속하지 않는다.
- 사용량은 토큰으로 센다. 한도 수치와 갱신 주기는 서버 설정값으로 바꿀 수 있어야 하며 값은 (확인 필요).
- **데이터:** `user_ai_usage`
- **API:** AI-01, BOOT-01
- **근거:** 회의 보드 09 AI 사용량 확인, REQ-29

#### F-38 한도 사전 차단·정산 (서버)

- 대화가 도중에 갑자기 끊기지 않도록 대화 단위로 사용량을 예약한다.
  - 대화를 시작할 때 한 턴과 짧은 피드백에 쓸 양이 남아 있어야 하고, 피드백용 양을 미리 예약한다.
  - 턴마다 예상 사용량을 예약하고 AI를 호출한 뒤 실제 사용량으로 정산한다.
- 그 밖의 AI 요청(STT, 뜻 보기, 힌트, 상세 피드백, 모범 음성)도 외부 AI를 호출하기 전에 한도를 검사한다. 부족하면 `AI_QUOTA_EXHAUSTED`로 거절하고 외부 AI를 호출하지 않는다.
- 클라이언트에서 버튼을 막더라도 서버 검사는 반드시 한다.
- 서버 쪽 실패로 결과를 전달하지 못하면 사용자 한도에서 차감하지 않고, 실제로 쓴 양은 비용 근거로 기록한다.
- 같은 `requestId`로 다시 보내면 이전 결과를 돌려주고 한 번만 차감한다. 여러 탭에서 동시에 보내도 한도를 넘지 않도록 예약을 원자적으로 처리한다.
- 한 턴 예상 사용량과 피드백 예약량은 서버 설정값이며 값은 (확인 필요).
- **데이터:** `ai_requests`(kind STT · LLM · TTS · FEEDBACK, status RESERVED · OK · FAILED · BLOCKED), `user_ai_usage`(used_tokens, reserved_tokens)
- **API:** API 명세 1.3·1.4절, AI를 호출하는 모든 API
- **완료 기준:** 같은 요청 ID를 두 번 보내도 중복 차감이 없다(T-18). 한도 0에서 AI 요청이 외부 호출 없이 거절된다(T-28). 동시 요청이 한도를 넘지 않는다(T-33).
- **근거:** 회의 보드 09 한도 사전 차단, REQ-20·29

#### F-39 소진 안내·비AI 기능 유지

- 한도가 소진되면 이유와 계속할 수 있는 활동을 안내한다. 예: "AI 사용량을 모두 사용했습니다. 마을 탐험, 사물 카드, 단어장은 계속할 수 있습니다." [탐색 계속] [단어장] [지난 기록]으로 바로 이동할 수 있게 한다.
- 소진 후에도 쓸 수 있는 기능: 3D 이동과 장면 출입, 사물 카드와 발음 듣기, 단어장 조회·저장·메모·외웠어요·퀴즈, 저장된 피드백·대화 기록 보기, 이미 만든 NPC 음성·모범 음성 재생
- 소진 후 막히는 기능: 새 NPC 대화, STT, 새로 만드는 뜻 보기, 힌트, 새 피드백·상세 평가, 새 TTS
- 소진 상태에서는 행인이 먼저 말을 걸지 않는다.
- 게스트가 대화 횟수를 다 쓰면 [말 걸기]·택시 버튼 자리에 "게스트 대화를 모두 썼어요"와 [가입하고 계속 대화하기]를 보이고, 누르면 가입 안내 창([닫기]·[Google로 가입하기])을 띄운다. 다시 말을 걸지 않고 나가는 게스트도 보도록, 마지막 대화를 마치고 그 대화의 피드백을 닫을 때도 같은 창을 띄운다([피드백 목록]에서 다시 연 피드백은 제외). 가입하면 게스트 기록을 이어 계속 대화한다(F-02). 창이 열릴 때 화면 위 가운데에서 설문 카드("잠깐! 이용해 보니 어땠나요?", [설문 하러 가기]·[닫기])가 내려온다. 설문은 새 탭에서 열린다. 설문 카드는 가입 안내 창과 따로 있어, 첫 호텔 퀘스트를 끝낸 회원에게도 같은 카드를 띄운다.
- 서버가 사용 가능 상태로 돌아왔다고 확인한 뒤에만 새 AI 대화를 다시 연다.
- 한도가 소진돼도 미션 기록, 단어장 등 저장된 데이터를 지우거나 초기화하지 않는다. 진행 중인 미션은 그 상태로 둔다.
- **API:** AI-01, API 명세 1.5절 오류 응답
- **완료 기준:** 한도 0에서 이동·출입·호버·단어장이 정상 동작한다(T-29). 사용량이 회복되면 새 AI 대화가 다시 열린다(T-34).
- **근거:** 회의 보드 09 소진 안내·비AI 기능 유지·상태 회복, 회의 보드 06 한도·장애, REQ-29·30

#### F-40 대화 중 사용량 소진

- 대화 도중 다음 턴에 쓸 양이 부족하면 AI를 호출하지 않고, NPC가 미리 만든 작별 대사(예: "앗, 급한 일이 생겼어요. 다음에 또 얘기해요!")로 대화를 끝낸다. 오류가 아니라 정상 종료다.
- 대화를 시작할 때 예약한 양으로 짧은 피드백을 받는다.
- 대화가 끝나면 3인칭 탐색으로 돌아가고 이동 잠금, 녹음, 로딩 표시가 남지 않는다.
- 진행 중인 미션은 실패로 처리하지 않고 그 상태로 둔다.
- 작별 대사와 음성은 NPC마다 미리 만든다. 대사 내용은 (확인 필요).
- **데이터:** `npcs.farewell_line`, `npcs.farewell_audio_key`, `conversations.end_reason`(QUOTA_EXHAUSTED)
- **API:** CONV-03, CONV-08
- **완료 기준:** 대화 중 사용량이 떨어져도 대화가 정상 종료되고 3인칭으로 돌아간다(T-32).
- **근거:** 회의 보드 09 대화 중 소진, 04 2.4.1절

| AI 한도 소진 | F-39의 안내를 보여준다. 대화 중이면 F-40을 따른다. |

- 응답 실패, 무음·인식 실패, 한도 소진은 서로 다른 오류 코드와 안내를 쓴다. 마이크 문제는 브라우저에서 판단한다. 장애를 한도 소진으로 보여주지 않는다.
- 어떤 오류에서도 카메라와 이동 잠금을 풀고, 저장된 데이터를 잃지 않는다.
- **API:** API 명세 1.5절 오류 응답
- **완료 기준:** 권한 거부·503·응답 형식 오류 뒤 UI와 카메라가 복구된다(T-19). 장애·마이크 거부·한도 소진이 서로 다르게 안내된다(T-35).
- **근거:** 회의 보드 09 마이크·STT 오류·AI 응답·TTS 장애, 와이어프레임 19, REQ-21

## 6. 결정이 필요한 항목

### 진입·초기 설정

- 소셜 로그인 제공자 (F-02)
- 서비스명(가칭 Elsehere)과 접속 화면 소개 문구 (F-01)
- 닉네임 금칙어 처리 (F-04)
- 레벨 테스트 문항 형식·문항 수·채점 기준, 문항 하나만 건너뛰기 (F-06)
- NPC 대화 난이도 단계 수와 단계별 차이, 설정을 바꾸는 화면 (F-07)
- 마이크 권한을 요청하는 초기 설정 단계 (F-08)

### 튜토리얼

- 건너뛴 사용자에게 튜토리얼을 다시 볼 방법을 줄지 (F-09)
- 시작 연출(거울, 안내 캐릭터)과 서비스 설명 문구 (F-10)
- 키 배치 (F-11)
- 호버 실습의 다음 단계 조건 (F-12)
- 대본 대사 비교 기준, 침묵 처리, 최대 녹음 시간, 튜토리얼 음성 인식의 AI 사용량 포함 여부 (F-15)

### 미션

- 시설 위치 안내 방식 (F-17)
- 동시에 진행할 수 있는 미션 수 (F-18)
- 미션 완료 판정에서 AI 의도 판정과 키워드 일치의 조합, 대화 외 완료 행동 (F-19)
- 일일 미션 선정 규칙 (F-20)

### 시설·대화·피드백

- 장소 안 위치 복원 (F-21)
- 기본 NPC 외에 더 둘 NPC 수, 행인 말걸기 조건 값, 직원 첫 인사 작성 방식 (F-22)
- 대화 중 새로고침 처리 (F-23)
- 녹음 형식과 최대 길이 (F-24)
- NPC 대사 저장 버튼 위치 (F-26)
- 힌트 1단계 키워드와 상단 추천 단어의 관계, 힌트를 담을 데이터 구조 (F-27, F-28)
- 사용자 발화가 없는 대화의 피드백 (F-29)
- 상세 피드백 생성 시점 (F-30)
- 피드백 건너뛰기 버튼 위치 (F-31)

### 단어장

- 뜻이 없는 표현을 저장할 때 뜻을 만드는 방법 (F-33)
- 퀴즈 형식, 정답 결과의 쓰임(정답 횟수 규칙, 호버 카드 자동 숨김 연동), 퀴즈 기록 데이터 (F-35)

### AI 한도·음성

- 무료 한도 수치, 갱신 주기, 한 턴 예상 사용량, 피드백 예약량 (F-37, F-38)
- NPC별 작별 대사 내용 (F-40)
- 음성 보관 동의와 보관 기간 (F-24, F-30)
- 추가 충전·결제는 MVP 이후 (범위 문서 3절)

## 7. MVP 이후 범위

범위 문서 3절을 기준으로 하고, 이 명세에서 MVP에 넣지 않기로 정리한 기능을 더했다.

- 카페·호텔 외 추가 시설, 미션 상세 화면(지도·자세한 설명)
- 2단계 이상의 NPC 대화 난이도와 레벨 테스트 결과 적용
- 정밀 발음 평가, 모바일 웹, 결제·크레딧 충전
- 다시 말하기 연습, 상세 피드백의 내 음성 다시 듣기(음성 보관 정책과 함께)
