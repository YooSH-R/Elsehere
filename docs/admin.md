# 운영자 어드민

운영자가 게임 콘텐츠를 고치고 서비스 사용량을 보는 관리 화면입니다. 백엔드가 Thymeleaf로 화면을 그리고, 저장은 화면의 스크립트가 관리 API를 호출합니다. 지금은 **NPC 페르소나 편집** 화면, 조회만 하는 **이용 현황**·**AI 사용량** 화면과 화면 없는 **사물 단어 발음 만들기** API만 제공합니다. 장소·NPC 기본 정보·사물·어휘·미션 관리는 Jira 에픽 S15P31A305-287의 후속 스토리에서 다룹니다.

## 주소

| 구분 | 개발 | 운영 |
| --- | --- | --- |
| 어드민 화면 | `https://dev.elsehere.kr/admin/` | `https://elsehere.kr/admin/` |
| 관리 API | `/api/v1/admin/**` | `/api/v1/admin/**` |

게임과 같은 출처에서 제공하지만 로그인은 게임의 Google 로그인과 따로인 어드민 계정으로 합니다([접근 권한](#접근-권한)). 웹 컨테이너의 Nginx([web.conf](../infra/nginx/web.conf))가 `/admin`을 백엔드로 넘깁니다.

| 화면 | 주소 | 하는 일 |
| --- | --- | --- |
| NPC 목록 | `/admin/npcs` | NPC 코드·이름·역할 이름·장소를 보고 페르소나 화면으로 이동 |
| NPC 페르소나 | `/admin/npcs/{npcCode}` | 페르소나(role·facts·scene)를 고쳐 저장 |
| 이용 현황 | `/admin/usage?days=7` | 최근 1~90일(기본 7일)의 활동 사용자·재방문·가입 전환·대화·학습 기록·진행 단계를 전체로 보고, 활동한 사용자 목록에서 사용자별 화면으로 이동 |
| 사용자 이용 현황 | `/admin/usage/user?userId={사용자 ID}&days=7` | 사용자 한 명의 개요(구분·시작·가입 전환·진행 단계·플레이 시간)와 같은 기간의 활동. 찾기 칸(`/admin/usage/find?user={이메일 또는 사용자 ID}`)에서 들어올 수 있음 |
| AI 사용량 | `/admin/ai-usage?days=7` | 최근 1~90일(기본 7일)의 AI 호출을 날짜·종류·모델·게스트/가입자·사용자별로 묶어 봄 |
| 로그인 | `/admin/login` | 어드민 아이디·비밀번호로 로그인. 로그인하지 않고 다른 화면을 열면 여기로 옴 |

| API | 하는 일 |
| --- | --- |
| `PUT /api/v1/admin/npcs/{npcCode}/persona` | 페르소나 저장. 본문 `{ "role", "facts", "scene" }`, 응답은 저장한 값 |
| `POST /api/v1/admin/login` | 어드민 로그인. 본문 `{ "loginId", "password" }`, 성공하면 `204` |
| `POST /api/v1/admin/logout` | 어드민 로그아웃. 로그인하지 않았어도 `204` |
| `GET /api/v1/admin/pronunciations` | 사물 단어 발음 진행 상황 |
| `POST /api/v1/admin/pronunciations` | 발음 파일이 없는 사물 단어의 발음을 백그라운드에서 만들기 시작. `202`와 진행 상황 |

## 접근 권한

어드민은 게임의 Google 로그인과 관계없는 **어드민 계정**(아이디·비밀번호)으로만 씁니다. 계정은 환경(개발·운영)마다 하나이며 백엔드 환경변수로 정합니다. 팀이 같은 계정을 함께 씁니다.

| 환경변수 | 기본값 | 설명 |
| --- | --- | --- |
| `ADMIN_LOGIN_ID` | 없음 | 어드민 아이디 |
| `ADMIN_PASSWORD` | 없음 | 어드민 비밀번호. 12자 이상, UTF-8로 72바이트 이하. 비어 있으면 어드민 로그인을 끕니다 |

- 서버는 시작할 때 비밀번호를 BCrypt 해시로 바꿔 메모리에만 둡니다. 비밀번호가 12자보다 짧거나 72바이트보다 길거나, 비밀번호만 있고 아이디가 비어 있으면 서버가 시작하지 않습니다.
- 개발·운영 비밀번호는 따로 정하고 서버의 배포 환경 파일에만 둡니다. 코드·Git·Jira에 적지 않습니다. 로컬에서는 `backend/.env`에 적습니다([백엔드 README](../backend/README.md#어드민-로그인)).
- 비밀번호를 바꾸려면 환경변수를 고치고 백엔드를 다시 시작합니다. 세션이 서버 메모리에 있어 다시 시작하면 모두 로그아웃됩니다.
- 예전에 관리자를 정하던 `users.role`(`ADMIN`)과 Google 이메일로 관리자를 지정하던 화면은 쓰지 않습니다. `users.role` 칼럼은 후속 작업에서 지웁니다.

### 로그인과 세션

- 로그인하지 않고 어드민 화면을 열면 로그인 화면(`/admin/login`)으로 보냅니다. 관리 API는 로그인하지 않았으면 `401 UNAUTHENTICATED`입니다.
- 아이디나 비밀번호가 틀리면 `401 ADMIN_LOGIN_FAILED`입니다. 무엇이 틀렸는지는 알려 주지 않습니다.
- 어드민 아이디로 연속 5번 틀리면 15분 동안 맞는 비밀번호로도 로그인하지 못합니다(`429 ADMIN_LOGIN_LOCKED`). 로그인에 성공하면 틀린 횟수를 처음부터 셉니다. 없는 아이디로 틀린 것은 세지 않습니다. 횟수와 잠금은 서버 메모리에만 있어 백엔드를 다시 시작하면 풀립니다.
- 게임과 같은 세션 쿠키를 쓰지만 로그인은 세션 안의 다른 칸에 둡니다. Google로 게임에 로그인했어도 어드민에 들어오지 못하고, 어드민 로그인으로는 게임 API를 쓰지 못합니다. 로그인하면 세션 ID를 바꿉니다.
- 어드민의 [로그아웃]은 어드민 로그인만 끝내고 같은 브라우저의 게임 로그인은 남깁니다. 반대로 게임에서 로그아웃하면 세션이 통째로 끝나 어드민도 다시 로그인해야 합니다.
- 세션 유지 시간은 게임 세션 설정을 따릅니다([백엔드 README](../backend/README.md#인증과-오류-응답)).
- 로그인·저장 요청에도 게임 API와 같은 요청 위조 방지 헤더(`X-Requested-With`)를 붙입니다. 화면의 버튼이 붙여 보냅니다. 헤더가 없으면 `403 CSRF_HEADER_REQUIRED`이므로 다른 사이트가 로그인이나 저장을 시킬 수 없습니다.
- 로그인 성공·실패·잠금은 백엔드 로그 `admin_login_succeeded`·`admin_login_failed`·`admin_login_locked`로 남습니다. 넣은 아이디·비밀번호는 남기지 않습니다.

### 처음 설정하기

새 환경도 DB에 쓰지 않고 환경변수만 정합니다.

1. 그 환경의 배포 환경 파일에 `ADMIN_LOGIN_ID`·`ADMIN_PASSWORD`를 넣습니다. 백엔드 컨테이너가 두 값을 받으려면 Compose의 backend `environment`에 두 변수가 있어야 합니다(인프라 담당).
2. 백엔드를 다시 배포하거나 다시 시작합니다.
3. `/admin/login`에서 로그인합니다.

## NPC 페르소나

페르소나는 대화할 때 AI 워커에 보내는 NPC 설명입니다([AI 워커 명세](api/ai-worker.md)의 `npc`). 영어로 적습니다.

| 칸 | 필수 | 최대 길이 | 내용 |
| --- | --- | --- | --- |
| `role` | O | 200자 | NPC가 누구인지 한 문장. 워커가 이름 뒤에 붙입니다(예: `Mia, the barista at the corner cafe.`) |
| `facts` | | 2,000자 | 가격, 파는 물건, 지켜야 할 규칙처럼 대화에서 지켜야 할 사실 |
| `scene` | | 300자 | NPC가 있는 곳의 설명 |

- 저장하면 다음 대화 요청부터 바로 반영됩니다. 진행 중인 대화도 다음 턴부터 바뀐 값을 씁니다.
- 앞뒤 공백은 지우고, 비운 칸은 빈 문자열로 저장합니다.
- 이름·역할 이름·장소·목소리·먼저 말 걸기 대사는 화면에 보여 주기만 합니다. 이 값은 시드(`world.sql`)가 관리합니다.
- 인격 카드([NPC 설정 v2 인격 구조](api/npc-ai-contracts/01_npc_configuration_spec_v2.md)의 성격·가치관·말투 등)는 이 화면에서 다루지 않습니다. 카드는 시드가 `content/npc-configurations.json`에서 넣습니다([백엔드 README](../backend/README.md#시드-데이터)).
- 인격 카드가 있는 NPC는 카드와 `facts`·`scene`을 함께 써서 대답합니다. `role`은 무례·의도 판정, 번역, 힌트·추천 단어, 뜻 보기, 기억 카드에서 NPC를 짧게 소개할 때 씁니다. 카드가 없는 NPC는 세 칸으로 대답합니다. NPC별 현재 근무지는 [NPC 생활·관계 설계](npc-life-design.md#일과와-교대)의 교대표를 참고합니다.

### 시드와의 관계

서버가 시작할 때 `WorldSeedLoader`가 `world.sql`을 실행합니다. NPC의 다른 값은 시드 값으로 갱신하지만 **페르소나는 NPC를 처음 넣을 때만** 시드 값을 씁니다. 그래서 어드민에서 고친 페르소나는 배포 뒤에도 남습니다.

- 새 NPC는 지금처럼 `world.sql`에 추가합니다. 처음 페르소나는 시드 값이 들어가고, 그 뒤로는 어드민에서 고칩니다.
- 이미 있는 NPC의 페르소나를 `world.sql`에서 고쳐도 반영되지 않습니다. 어드민에서 고칩니다.
- 인격 카드는 카드가 비어 있는 NPC에 시드에서 채우고, `ai/npcs/`의 카드 `profileVersion`이 DB 카드보다 높으면 다음 서버 시작 때 새 카드로 바꿉니다. 카드를 고칠 때는 `ai/npcs/`에서 수정하고 `profileVersion`을 올린 뒤 다시 내보냅니다.
- 새로 만든 DB(로컬 DB 초기화 등)에는 시드의 처음 값이 들어갑니다. 환경 사이에 페르소나를 옮기는 기능은 없습니다.

## 이용 현황

서비스를 얼마나 쓰는지 보고 부족한 부분을 찾으려고, DB에 있는 기록을 묶어 보여 줍니다. 이용 현황을 위해 따로 모으는 기록은 게임 시계 신호로 쌓는 일별 접속 기록(`user_daily_activities`)뿐입니다. 로그인 전 방문은 GA4 방문 통계로, 오류·응답 시간은 [로그와 지표](observability.md)로 봅니다.

- **기간:** 최근 1·7·30·90일 가운데 고릅니다. 1~90일을 벗어나면 `400 VALIDATION_FAILED`입니다. 날짜는 한국 날짜로 묶습니다.
- **보여 주는 정보:** 가입자는 이메일로, 이메일이 없는 게스트·탈퇴한 사용자는 `게스트 #57`·`탈퇴 #12`처럼 사용자 ID로 보여 줍니다. 닉네임·대화 내용은 보여 주지 않습니다.
- **게스트·가입자:** 지금 계정 기준입니다. 게스트에서 가입한 사용자는 게스트였던 날의 활동도 가입자로 셉니다.
- **팀 사용 제외:** 팀 기기에서 쓴 계정(`users.team_account`)은 전체 집계에서 뺍니다. 사용자를 골라 보는 사용자별 화면에서는 팀 계정도 보여 줍니다.
  - 팀원은 쓰는 브라우저마다 한 번 `https://elsehere.kr/?team=1`(개발은 `https://dev.elsehere.kr/?team=1`)로 엽니다. 웹 템플릿이 그 브라우저에 팀 기기 쿠키(`elsehere_team=1`, 2년)를 남기고 주소에서 `team`을 지웁니다. `?team=0`으로 열면 쿠키를 지웁니다.
  - 팀 기기에서는 GA4 태그를 불러오지 않습니다([Unity 설정](unity/setup.md)).
  - 팀 기기로 게임에 들어오면(BOOT-01, 게스트 시작·Google 로그인 뒤에도 부름) 로그인한 계정을 팀 계정으로 표시합니다. 표시는 계정 단위라 표시하기 전의 기록도 함께 빠지고, 되돌리는 화면은 없습니다.
  - 쿠키를 남기기 전에 다른 브라우저에서 만든 계정은 팀 기기로 다시 들어오기 전까지 집계에 남습니다.

### 활동 사용자

로그인 기록 표는 없으므로, 그날 아래 기록 중 하나라도 있으면 그 사용자가 그날 활동했다고 봅니다.

| 활동 흔적 | 기록 |
| --- | --- |
| 계정 만들기(게스트 시작·가입) | `users.created_at` |
| 가입 전환 | 아래 [가입 전환](#가입-전환)의 시각 |
| NPC 대화 시작 | `conversations.started_at` |
| AI 호출 | `ai_requests.created_at` (예약만 하고 끝내지 않은 `RESERVED`와 사용자 없는 어드민 호출은 뺌) |
| 단어 저장 | `user_vocab.saved_at` |
| 오늘의 미션 완료 | `user_missions.completed_at` |
| 게임 시계 마지막 신호 | `user_game_clocks.last_beat_at` |
| 장소 화면에 들어온 날 | `user_daily_activities`(일별 접속 기록, 그날 마지막 신호 시각) |

- 일별 접속 기록은 게임 시계 신호(WORLD-07, 30초마다)를 받을 때마다 그날(한국 날짜)의 첫·마지막 접속과 장소 화면에 머문 시간을 쌓습니다. 이 기록이 생기기 전 기간은 게임 시계 마지막 신호 시각만 남아, 대화·저장 없이 돌아다니기만 한 날은 마지막 접속일만 활동으로 잡힙니다.
- **다시 온 사용자:** 기간 안에 서로 다른 한국 날짜 이틀 이상 활동한 사용자입니다.
- **평균 누적 플레이 시간:** 활동 사용자의 `user_game_clocks.play_seconds` 평균입니다. 기간과 관계없이 지금까지 쌓인 값이고 대화 중 시간은 빠집니다([게임 시간](api/mvp-api.md#게임-시간)).
- **하루 평균 머문 시간:** 기간 안 일별 접속 기록의 머문 시간 합을 활동한 하루(사용자 한 명의 한 날) 수로 나눕니다. 머문 시간은 장소 화면에 있던 실제 시간이라 대화·피드백 화면을 보는 시간도 들어가고, 탭을 숨기거나 닫아 신호가 60초 넘게 끊긴 사이는 빠집니다. 날짜별 표에도 그날 머문 시간(분)을 보여 줍니다.

### 재방문

기간 안에 계정을 만든 사용자(게스트 시작·바로 가입)가 그 뒤 다시 왔는지 봅니다. 계정을 만든 한국 날짜를 0일째로 셉니다. 다시 온 것은 위 활동 흔적(일별 접속 기록 포함)이 그날 하나라도 있는 것입니다.

| 기준 | 다시 온 사용자 | 대상 |
| --- | --- | --- |
| D1 | 1일째(다음 날)에 활동 | 1일째가 다 지난 사용자 |
| D7 | 7일째에 활동 | 7일째가 다 지난 사용자 |
| 7일 안 | 1~7일째 중 하루라도 활동 | D7과 같음 |

- 오늘은 아직 끝나지 않아 확인할 날로 치지 않습니다. 그래서 최근 7일을 고르면 D7·7일 안 대상이 없고, 최근 30·90일에서 보입니다.
- 일별 접속 기록이 생기기 전에 계정을 만든 사용자는 돌아다니기만 한 날이 빠져 실제보다 적게 잡힐 수 있습니다.

### 가입 전환

게스트로 시작해 Google로 가입한 사용자 수입니다. 전환 여부를 적는 칸이 없어 다음 규칙으로 추정합니다.

- 게스트는 약관(`TERMS`)에 동의하지 않고, 바로 가입한 회원은 계정과 약관 동의가 같은 요청에서 생깁니다. 그래서 **첫 약관 동의가 계정 생성보다 1분 넘게 늦은 회원**을 전환으로 보고, 그 동의 시각을 전환 시각으로 씁니다.
- 게스트 세션에서 Google로 가입하면 게스트 행이 그대로 회원으로 바뀌므로([백엔드 README](../backend/README.md#게스트로-시작하기)) 이 규칙으로 셀 수 있습니다. 이 방식이 배포되기 전에 가입한 게스트는 새 회원 행이 따로 생겨 전환으로 세지 않습니다. 게스트가 이미 가입한 Google 계정으로 로그인하면 합치지 않으므로 전환이 아닙니다.
- 정확한 전환 수가 필요하면 백엔드 로그 `user_signed_up`의 `from_guest=true`를 함께 봅니다([관측성](observability.md)).

### 대화와 학습 기록

| 표 | 세는 것 |
| --- | --- |
| 대화가 끝난 방식 | 기간 안에 시작한 대화를 `end_reason`으로 묶음. 끝내지 않고 나간 대화는 따로 기록하지 않아 진행 중인 대화와 함께 '끝내지 않음'으로 묶임 |
| NPC별 대화 | 기간 안에 시작한 대화를 NPC 이름·역할 이름으로 묶음 |
| 대화 중 행동 | 학습자가 음성·글로 보낸 말(`turns.input_type`), 힌트·추천 단어·뜻 보기 요청(`ai_requests`의 `HINT`·`MEANING`) |
| 단어 저장 | 저장한 곳(사물 카드·NPC 대사·피드백) |
| 대화 피드백 | 받음·실패·사용자가 건너뜀·평가할 말이 없어 건너뜀 |
| 진행 단계 | 기간 안에 계정을 만든 사용자의 초기 설정 단계, 활동 사용자의 첫날 미션·마을 여정 지금 단계(아무도 없는 단계도 0명으로 보여 줌) |

- 끝낸 대화 비율은 기간 안에 시작한 대화 가운데 끝낸 대화의 비율이고, 1인당 대화 수는 대화한 사용자 기준입니다.
- 게스트는 마지막 활동 하루 뒤, 탈퇴한 사용자는 탈퇴할 때 보낸 말·저장 단어·피드백이 지워지므로([게스트 정리](../backend/README.md#게스트로-시작하기)) 음성·글로 보낸 말, 단어 저장, 대화 피드백은 그만큼 적게 잡힙니다. 사용자·대화·AI 호출·미션·게임 시계 기록은 남아 그대로 셉니다.

### 사용자별 화면

- 전체 화면 아래에 기간 안에 활동한 사용자를 마지막 활동이 늦은 순서로 100명까지 보여 줍니다. 사용자 이름(가입자는 이메일)을 누르거나, 찾기 칸에 가입 이메일(대소문자 무시)이나 사용자 ID를 적어 사용자별 화면을 엽니다. 숫자만 적으면 사용자 ID로 봅니다.
- 사용자별 화면은 사용자 이름, 구분(게스트·가입자·탈퇴), 시작 시각, 가입 전환 시각, 초기 설정·첫날 미션·마을 여정 단계, 누적 플레이 시간, 게임 시계 마지막 신호와 같은 기간의 활동(날짜별·대화·학습 기록)을 보여 줍니다.
- 없는 사용자 ID나 가입하지 않은 이메일이면 `404 NOT_FOUND`입니다.

## AI 사용량

AI 호출 기록(`ai_requests`)을 묶어 보여 줍니다. 호출 한 번이 한 줄이며 사용자, 대화, 호출 종류, 상태, 모델, 입력·출력 토큰, 음성 길이가 남습니다.

- **기간:** 최근 1·7·30·90일 가운데 고릅니다. 1~90일을 벗어나면 `400 VALIDATION_FAILED`입니다.
- **묶는 기준:** 날짜(한국 날짜), 호출 종류, 모델, 게스트/가입자입니다. 토큰을 많이 쓴 사용자는 상위 10명까지 이용 현황과 같은 이름(가입자는 이메일, 게스트·탈퇴는 사용자 ID)으로 보여 줍니다. 닉네임은 보여 주지 않습니다.
- **팀 계정:** 실제로 쓴 비용이므로 팀 계정도 그대로 셉니다.
- **실패:** 워커 오류로 끝난 호출입니다. 모든 AI 호출은 실패해도 기록됩니다(`AiGateway`).
- **세지 않는 것:** 예약만 하고 끝내지 않은 기록(`RESERVED`), 모델을 부르지 않는 관계 갱신(`/v1/npc/relationship`)
- **모델 "없음":** 워커 오류로 끝난 호출과 음성 합성(TTS)은 모델과 토큰을 알리지 않아 "없음"으로 묶입니다.
- **사용자 없는 호출:** 어드민이 실행한 [사물 단어 발음 만들기](#사물-단어-발음-만들기)는 게임 사용자가 없어(`user_id` 없음) 합계·날짜·종류·모델에는 들어가고 게스트/가입자 구분과 사용자별 목록에는 들어가지 않습니다. 이용 현황의 활동 흔적에도 세지 않습니다.
- **금액:** 모델별 단가가 정해지지 않아 보여 주지 않습니다.

## 사물 단어 발음 만들기

사물 카드의 [발음 듣기](api/mvp-api.md)(WORLD-04)가 쓰는 WAV를 AI 워커 TTS(`af_heart`, 속도 1.0)로 만듭니다. 파일은 음성 볼륨의 `pronunciation/` 폴더에 `{wordKey}.wav`로 저장합니다([NPC 음성 저장 운영](npc-audio-storage.md)). 발음 파일이 없는 사물 단어는 카드에서 발음 버튼이 숨겨집니다(`hasPronunciation: false`).

- 발음 파일이 없는 단어만 만들므로 여러 번 실행해도 됩니다. 합성에 실패한 단어는 건너뛰고 결과의 `failedWordKeys`에 남기며, 다시 실행하면 그 단어만 다시 만듭니다.
- 한 번에 하나만 실행합니다. 진행 중에 다시 시작하면 새로 시작하지 않고 진행 상황만 돌려줍니다. 실행 상태와 마지막 결과는 서버 메모리에만 있어 서버를 다시 시작하면 사라집니다(만든 파일은 남습니다).
- 개발·운영 볼륨은 따로이므로 환경마다 실행합니다. 새 사물 단어를 Unity에서 추가해 배포한 뒤에도 다시 실행합니다.
- 영어 표현을 바꾸는 경우에는 공용 단어 키를 유지하고 Unity 에셋의 `pronunciationAudioKey`에 새 WAV 이름을 지정합니다. 생성기는 이 이름을 우선 사용하므로 예전 표현의 `{wordKey}.wav`를 재사용하지 않습니다. 명시한 발음 키는 파일 생성 전에도 카드에 연결되므로, 콘텐츠 배포 직후 발음 생성을 실행해 `missing`이 0인지 확인해야 합니다.
- AI 워커에 TTS 모델이 준비되어 있어야 합니다. 준비되지 않았으면 모든 단어가 `failedWordKeys`에 남습니다.
- 합성 호출은 사용자 없이(`user_id` 없음) `ai_requests`(`kind: TTS`)로 기록합니다. 어드민 계정은 게임 사용자가 아니기 때문입니다.

화면은 따로 없습니다. 어드민으로 로그인한 브라우저에서 어드민 화면(`/admin/`)을 열고 개발자 도구 콘솔에서 실행합니다.

```js
// 시작
await (await fetch("/api/v1/admin/pronunciations", {
  method: "POST", headers: { "X-Requested-With": "ElsehereAdmin" }
})).json();
// 진행 상황: { total, ready, missing, running, lastRun: { created, failedWordKeys } }
await (await fetch("/api/v1/admin/pronunciations")).json();
```

`running`이 `false`가 되고 `missing`이 0이면 끝난 것입니다.

## 화면을 바꿀 때

- 화면 템플릿은 `backend/src/main/resources/templates/admin/`에 있고, 공통 머리글·메뉴는 `layout.html`입니다.
- 화면은 조회만 하고, 상태를 바꾸는 요청은 관리 API를 부릅니다. HTML 폼을 바로 전송하면 요청 위조 방지 헤더가 없어 거절됩니다.
- 새 관리 API는 `/api/v1/admin/` 아래에 둡니다. 어드민 보안 설정(`AdminSecurityConfig`)이 이 경로와 `/admin/**`에 어드민 로그인 검사를 적용합니다. 컨트롤러는 로그인한 어드민을 `@AuthenticationPrincipal AdminLogin`으로 받습니다.
