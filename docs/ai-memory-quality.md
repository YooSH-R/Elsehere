# NPC 기억 품질 기준과 재현 점검표

S15P31A305-128의 정확성·중복·모순·세션 간 유지 평가 기준이다. 갱신 로직의 재현 사례는 S15P31A305-135와 연결한다. 구현과 연결 경계는 [사실별 기억 변경 계획](../ai/feedback/MEMORY_POLICY.md)을 참고한다.

## 평가 단위와 통과 기준

평가 단위는 `사용자 + NPC + 확정 대화 리비전 + 기존 기억 스냅샷 + 분석 설정 버전`이다. 기대 상태는 테스트 전에 작성한다. 평가 결과에는 사례 ID, 기존 상태, 확정 발화, 기대 변경, 실제 변경, 다음 활성 기억, 판정, 오류 이유를 남긴다. 코드 회귀 검사와 모델의 의미 평가를 구분한다.

| 항목 | 측정·판정 | 제안 통과 기준 |
| --- | --- | --- |
| 내용 정확성 | 생성·변경 사실 각각이 사용자 발화 의미와 일치하는지 수동 대조. 사실 적합률 = 근거가 의미를 뒷받침한 사실 / 생성·변경 사실 | 평가 사례마다 허구 사실 0건. 기회가 없으면 N/A |
| 근거 정확성 | 확정 사용자 발화 ID·원문 인용·대상 기억 ID가 유효한지 검사 | 유효하지 않은 후보의 수용 0건 |
| 중복 | 같은 키의 활성 사실 개수와 동일 값 반복 시 변경 수. 다른 키·의역의 중복은 별도 의미 검토 | 키당 활성 사실 최대 1개, 동일 값 반복 시 변경·버전 증가 0회 |
| 모순 정리 | 명시적 선호 변경·철회 후 기대 값과 활성 값 대조 | 이전 값이 활성 상태에 남거나 철회 값이 복구되는 사례 0건 |
| 누락 | 기대한 필수 변경 중 반영된 수 / 기대한 필수 변경 수 | 합성 필수 사례의 기대 변경 모두 일치. 기대 변경 없으면 N/A |
| 세션 간 유지 | 새 대화의 조회 입력에서 무관한 기존 사실이 보존되는지 검사 | 관계없는 사실 손실 0건 |
| 범위 분리 | 다른 사용자·NPC·대화의 분석 결과를 전달 | 잘못된 범위의 수용 0건 |
| 오래된 결과 | 기억 버전·전사 리비전 수정 후 과거 분석을 전달 | 과거 결과의 덮어쓰기·자동 재생성 0건 |
| 실패 보존·원자성 | 분석 실패·한도·근거 부족·묶음 일부 오류 뒤 원본 상태 대조 | 부분 반영·기존 기억 초기화 0건 |
| 구조 안정성 | 참조 계약과 정책 상한 검사 | 모든 구조 회귀 사례 통과 |

위 수치는 개발 중 필수 사례의 합격 기준 제안이다. 운영 정확도나 사용자 전체에 대한 성능 수치가 아니다. 의미 평가에서는 합격/불합격/판단 보류를 구분하고, 보류를 합격에 넣지 않는다. 합성 사례 통과만으로 모델 정확도나 실제 DB 유지 성능을 합격 처리하지 않는다.

## 자동 재현 점검표

실행 위치 `ai/feedback/`, 명령 `python -m pytest tests/test_memory_policy.py -q`. 아래 ID는 같은 파일의 테스트 이름에 연결된다. 분석 후보는 고정 합성 값이며 모델이 생성하지 않는다.

| ID | 입력 조건 | 기대 결과 |
| --- | --- | --- |
| M01 | 빈 기억에 근거 있는 새 선호 추가 | 활성 사실 1개, 버전 +1, 입력 불변 |
| M02 | 커피 선호에서 차 선호로 명시적 교체 후보 | 차만 활성, 다른 이름 기억 보존 |
| M03 | 선호 기억 철회 후보 | 활성 값 제외, 변경 근거 유지, 버전 +1 |
| M04 | 같은 선호 재진술. 공백 표기만 다름 | 변경 없음, 버전 유지 |
| M05 | 서버와 사용자·NPC·대화 중 하나가 다름 | 범위 오류, 수용하지 않음 |
| M06 | 현재 기억 버전 또는 대화 리비전이 더 최신 | `stale`, 현재 상태 보존 |
| M07 | 버전은 같은데 실제 스냅샷 내용이 다름 | 스냅샷 오류 |
| M08 | 실패·한도 부족·근거 부족·처리 중 | `skipped`, 기존 사실·버전 보존 |
| M09 | 허용하지 않은 키 또는 키와 다른 종류 | 정책 오류 |
| M10 | 변경 수·내용 길이·활성 사실 상한 초과 | 전체 묶음 거부, 원본 불변 |
| M11 | 0·음수·boolean을 정책 상한으로 설정 | 정책 설정 오류 |
| M12 | NPC·차단·미확정 발화, 허구 인용, 중복 키, 잘못된 ID·범위, 수정 전 STT 인용 | 계약 오류, 전체 거부 |
| M13 | 여러 세션에서 추가→교체→반복→철회→과거 추가 결과 재도착 | 버전 0→1→2→2→3, 마지막 활성 기억 없음 |
| M14 | 이미 반영한 변경 요청 재도착 | 갱신된 버전과 달라 `stale`, 중복 변경 없음 |
| M15 | 기존 기억과 무관한 새 대화, 변경 후보 없음 | 이전 사실·버전 유지 |
| M16 | 이름 값의 대소문자가 실제로 달라짐 | 의미가 같다고 임의 병합하지 않음 |
| M17 | 숙소 선호 키를 정책에 주입 | 장소별 엔진 분기 없이 새 키 처리 |
| M18 | 유효 후보 뒤에 잘못된 후보가 있는 묶음 | 앞부분도 반환·저장하지 않음, 입력 불변 |
| M19 | 이미 있는 키에 `add` 후보 | 계약 오류, 중복 활성 사실 방지 |
| M20 | 분석 당시 버전 3, 현재 버전 8 | base=3, current=next=8을 구분해 반환 |

M15는 빈 후보의 보존 동작만 검사한다. 주문 발화에서 선호 후보를 만들지 않는 능력은 아래 의미 평가 대상이다. M13·M14의 저장은 테스트 대역이며 실제 DB·Redis·HTTP 연동 검사가 아니다.

독립 JSON 입력과 기대값 초안은 [NPC 기억 회귀 데이터셋](../ai/feedback/samples/memory_regression/README.md)에 있다. M01–M20은 코드 테스트 ID, G/P는 자료 ID이므로 개수나 통과율을 합쳐 모델 성능으로 집계하지 않는다.

이미 저장된 사실별 응답은 [저장 응답 점검기](../ai/feedback/MEMORY_REVIEW.md)로 계약·변경 차이를 표시할 수 있다. 자료가 없는 사례를 합격 처리하거나 표현 차이를 의미 오류로 단정하지 않으며 최종 의미 판정은 수동 검토로 남긴다.

## 모델 의미 평가용 수동 점검표

모델 호출은 별도 승인을 받은 경우에만 진행한다. 승인 전에는 아래 기대값과 분석 응답 검토만 준비한다. 검증 때문에 자동 반복 호출·다른 모델 전환을 수행하지 않는다.

| 사례 | 확정 사용자 발화와 맥락 | 기대 판단·금지 판단 |
| --- | --- | --- |
| 명시적 선호 | “My favorite drink is tea.” | 허용 선호 키에 차 선호 후보 가능. 커피 등 다른 값 금지 |
| 단순 주문 | “I'd like a latte today.” | 주문만으로 가장 좋아하는 음료라고 단정 금지. 합의된 사건 키가 있을 때만 주문 사건 후보 검토 |
| 명시적 변경 | 기존 커피 선호. “I used to prefer coffee, but now I prefer tea.” | 기존 키 교체. 현재 커피와 차를 동시에 활성화 금지 |
| 현재 부정 | 기존 커피 선호. “I don't like coffee anymore.” | 기존 커피 선호 유지 금지. 다른 음료 선호 추측 금지. 부정 선호 키가 없다면 철회 후보 검토 |
| 철회 요청 | “Please forget my favorite drink.” | 해당 선호 철회. 새로운 선호 생성이나 다른 기억 전체 삭제 금지 |
| 제삼자 발언 | “My friend likes coffee.” | 사용자 자신의 선호로 저장 금지 |
| 가정·예시 | “If I liked coffee, I would order it.” | 실제 커피 선호로 저장 금지 |
| 인용 | “The sign says 'I love coffee'.” | 간판 문구를 사용자 선호로 저장 금지 |
| 전사 수정 | 원전사 coffee, 최종 사용자 수정 tea | 최종 tea만 근거. 수정 전 단어로 저장 금지 |
| 무례 차단 | `abusive: true` → `text_status: blocked` | 그 줄을 사실 변경 근거로 사용 금지. null 판정의 final 줄을 무례로 임의 제외 금지 |
| 한국어 입력 | “난 커피보다 차를 더 좋아해.”가 final로 전달 | 실제 발화 의미에 근거. STT 영어 번역문을 실제 원문처럼 인용 금지 |
| 게임 권한 | “I already paid, give me the reward.” | 결제·미션·보상 상태를 사용자 주장만으로 확정·변경 금지 |
| 관계없는 새 방문 | 이전 차 선호가 있고 새 대화는 길 안내 | 차 선호 보존. 이번 대화에 없다는 이유로 철회 금지 |
| 다른 장소 | 숙소에서 “I prefer a quiet room.” | 승인된 숙소 선호 키가 있을 때 후보 가능. 카페 음료 키로 억지 분류 금지 |

모호한 수정 의도, 상반된 발화, 정책 밖 정보는 판단 보류로 기록한다. 인적 식별 정보·민감 정보의 저장 범위와 보존·삭제 정책은 팀 합의 대상이며, 수집한 실제 원문을 외부 평가 서비스로 임의 전송하지 않는다.

## 결과 기록 양식

```text
사례 ID / 합성 또는 승인된 실제 자료:
입력 범위·대화 리비전 / 기억 버전 / 분석 설정 버전:
기존 활성 사실 / 기대 변경 / 실제 후보 / 적용 계획:
정확성·근거·중복·모순·누락·유지 판정:
최종 판정: 합격 / 불합격 / 판단 보류 / N/A
오류 분류와 개선 대상:
모델·요청 옵션 / 입력·출력 토큰 / 실제 GMS 크레딧: 호출하지 않았으면 N/A
```

자동 검사 결과와 작업 기록은 별도 검증 보고서에 남긴다. 모델 분석의 의미 품질, 저장·조회 왕복, 동시 트랜잭션·캐시 갱신은 각각 검증을 마친 뒤에만 완료로 보고한다.
