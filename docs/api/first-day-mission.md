# 첫날의 작은 소동: 연계 미션

작업 이슈: S15P31A305-318. 기본 미션 UI(194)의 후속 확장이다. 튜토리얼을 마치거나 건너뛰면(TUT-01·02) 서버가 바로 시작하는 한 번의 연계 여정이며 일일 미션 API는 유지한다. 건너뛴 사용자는 튜토리얼 마지막의 퀘스트 카드 안내를 보지 못해 퀘스트가 있는지 모르므로, 마치는 방법과 상관없이 시작해 왼쪽 위 카드와 길 안내가 바로 보이게 한다.

완료한 이용자는 수첩에서 별도로 저장되는 [첫날 이후 마을 여정](town-story.md)을 시작할 수 있다. 첫날 완료 기록은 유지하고, 코인은 두 퀘스트의 진행에서 함께 계산한다.

## 화면과 진행

게임 공간과 NPC를 중심에 두고 왼쪽 위에 지금 하는 퀘스트를 한 줄 알약으로 접어 두며, 알약을 누르면 현재 상황·해결 목표를 담은 퀘스트 카드를 펼친다. 오른쪽 위는 메뉴(≡)가 쓴다. 퀘스트 카드를 누르면 퀘스트 수첩이 펼쳐지고 마을 지도, 전체 단계, 완료한 목표, 소지품과 여행용 예산을 확인한다. 지도는 TownScene의 실제 도로와 HOME·CAFE·HOTEL·DRUGSTORE 출입문 위치로 그리며, 마을에서는 내 위치와 방향을, 건물 안에서는 그 건물 출입문을 표시하고 지금 가야 할 건물에 빨간 테두리를 두른다. 수첩은 대화 중에 열어도 대화창의 추천 단어 카드나 피드백·단어장 화면에 가려지지 않게 가장 위에 그리고, 닫으면 원래 순서로 돌아간다. 수첩을 닫아도 현재 목표는 유지한다. 마을에서는 화면 왼쪽 아래에 모서리를 크게 둥글린 하늘색 유리 미니맵을 고정해, 수첩 지도와 같은 배치 위에 내 위치·방향(흰 테두리의 파란 화살표)과 지금 갈 건물(은은하게 밝아지는 금색 이름표)을 실시간으로 보여 준다. 판은 큰 지도와 같은 맑은 하늘색 유리이고, 지도 바탕과 인도는 거의 비워 뒤 거리가 비치며 차도·건물은 진하게 둔다. 미니맵을 끌면 지도가 따라 움직여 주변을 둘러볼 수 있고, 손을 떼고 3초 뒤 내 위치로 돌아온다. 끌고 놓았을 때는 큰 지도를 열지 않는다. 미니맵이나 폰 메뉴의 [마을 지도]를 누르면 같은 유리 판에 미니맵과 같은 지도 그림 전체를 보이는 큰 마을 지도를 화면 가운데에 펼치며(제목 '마을 지도'와 닫기 버튼, 내 위치·목적지 범례, 길 안내 켬/끔), 닫기 버튼·Esc·바깥 누르기로 닫는다. 큰 지도는 열려 있는 동안 다른 화면보다 위에 그린다. 수첩이나 큰 지도가 열려 있거나 건물 안에서는 미니맵을 숨긴다. 튜토리얼 중에는 기존 기본 미션 UI를 쓰고 완료·건너뛰기 뒤 새 퀘스트 UI를 표시한다. 퀘스트는 앞으로 여러 개가 되므로 화면 문구에는 '첫날'·'여정'을 쓰지 않는다. 수첩 제목은 '퀘스트', 시작 버튼은 '퀘스트 시작'이고, 시작 전 안내는 '마을에서 일어난 작은 소동을 해결해 볼까요?'와 '왼쪽 위 지도 버튼에서 퀘스트를 시작하세요.'다. 시작 전 화면은 자동 시작 전에 튜토리얼을 끝낸 사용자와, 튜토리얼 저장이 늦어진 잠깐 동안 보인다.

왼쪽 위 안내는 지금 상황 아래에 '호텔 직원에게 요청하세요. (대화 상대: Jake)'처럼 누구에게 무엇을 할지 알리고, 이번 단계 목표를 체크리스트로 보여 준다. 아직 하지 않은 목표 아래에는 말해야 할 정보(`goals[].hint`)를 작게 보인다. 예약자 이름은 게임 닉네임(게스트는 '내 이름'), 찾을 가방은 '파란색 숄더백, 빨간 열쇠고리'와 '여권 지갑과 책'처럼 학습자가 따로 알 수 없는 정보를 그대로 적는다. 마을 이야기 목표도 같다. 아침 주문은 '음식과 음료를 함께'처럼 필요한 내용만 안내하며, 퀘스트에는 영어 예문을 반복하지 않는다. 학습자가 목표를 말해 서버가 달성을 알리면 그 항목이 초록 ✓로 바뀐다. 미션 NPC는 첫 인사에서 인사와 무엇을 도와줄지만 묻고, 예약 확인·짐 보관·카페 안내(0단계), 가방 분실(2단계), 찾은 가방(3단계), 우산·드럭스토어(4단계), 우산 권유·가격(5단계, 결제 방법은 사겠다고 한 뒤에 묻는다), 체크인·예약 확인·캐리어 반환(6단계)은 학습자가 먼저 꺼냈을 때만 답한다. 학습자가 직접 요청해야 말할 기회가 생기기 때문이다. 카페 직원도 음료를 나열하거나 권하지 않고 무엇을 마실지만 묻는다. 학습자가 요청한 뒤에는 그 요청을 마치는 데 필요한 질문(음료 크기·결제 방법·가방 생김새 등)만 한다.

| stage | 장소·NPC | 완료할 행동 |
| --- | --- | --- |
| 0 | HOTEL / HOTEL_STAFF | 예약 확인, 큰 캐리어 맡기기, 카페 위치 문의. 객실이 아직 준비되지 않아 NPC는 체크인을 끝내지 않고 얼리 체크인이 어렵다고 안내한다 |
| 1 | CAFE / CAFE_STAFF | 음료 주문, 옵션 하나 선택, 매장 이용 선택. 대화 종료 뒤 카페 의자나 소파에서 **5초 쉬기** |
| 2 | HOTEL / HOTEL_STAFF | 작은 가방을 두고 왔다고 설명, 찾아온 뒤 돌아오겠다고 말하기 |
| 3 | CAFE / CAFE_STAFF | 분실물 문의, 가방 외형·내용물 설명, 소유 확인 |
| 4 | TOWN / TOWN_PASSERBY | 우산 판매처와 드럭스토어 가는 길 문의 |
| 5 | SHOP / SHOP_STAFF | 우산 가격 문의, 구매 의사, 결제 방법 선택 |
| 6 | HOTEL / HOTEL_STAFF | 가방을 찾았다고 말하기, 체크인·예약 확인·캐리어 수령 요청 |
| 7 | 전체 완료 | 재접속·다시 시작 요청에도 완료 상태 유지 |

호텔 예약은 학습자의 게임 닉네임으로 되어 있다. 0단계 예약 확인과 6단계 예약 정보 확인은 학습자가 그 이름을 말해야 완료되며, 한글 닉네임을 영어로 읽은 이름이나 성·이름 하나만 말해도 인정한다. 다른 이름을 대면 목표로 세지 않고, 호텔 직원은 그 이름으로 된 예약을 찾지 못했다며 다시 확인해 달라고 한다. 게스트 계정의 닉네임(`guest-000123`)은 사람 이름이 아니어서 대조하지 않는다.

큰 캐리어는 호텔에 보관한다. 잃어버린 물건은 **빨간 열쇠고리가 달린 작은 파란 숄더백**이며, 안에는 **여권 지갑과 책**이 있다. 외형은 파란색과 함께 숄더백 또는 빨간 열쇠고리 중 하나, 내용물은 여권이나 여권 지갑과 책을 말하면 인정한다. 우산은 퀘스트 코인 8개를 한 번 차감한다. 거리의 비는 가방을 찾은 뒤 마을 씬에서 표시하고 여정 완료 시 해제한다. Unity는 마을에서 응답의 날씨에 맞춰 빗방울과 함께 하늘·해·안개·구름을 어둡게 바꾸며, 흐린 날씨도 같은 방식으로 표시한다. 흐림은 3단계(카페에서 가방 찾기)에 쓴다.

카드에는 각 목표에 필요한 정보를 보여 준다. 판정은 의미가 같은 직접·간접 요청, 앞 질문에서 뜻이 분명한 짧은 응답, 여러 턴에 나누어 제공한 정보를 인정한다. 목표마다 독립적으로 판정하므로 일부만 충족해도 그 목표는 기록된다. NPC 답변에는 남은 목표의 조건을 전달하며, 학습자가 꺼낸 요청에서 빠진 정보 하나만 묻게 한다. 예를 들어 `A latte, please.`는 주문 목표를 충족하고, 직원은 `Hot or iced?`처럼 옵션만 먼저 묻는다.

## API

모든 경로는 로그인 세션을 사용한다. POST에는 공통 `X-Requested-With: ElsehereClient` 헤더가 필요하다. 사용자 ID는 로그인에서 얻고 요청 본문으로 받지 않는다.

| 메서드 | 경로 | 본문 | 동작 |
| --- | --- | --- | --- |
| GET | `/api/v1/missions/first-day` | 없음 | 진행 조회. 시작 전에도 200과 `started:false` |
| POST | `/api/v1/missions/first-day/start` | 없음 | 없으면 생성, 있으면 기존 진행 반환 |
| POST | `/api/v1/missions/first-day/visit` | `{"scene":"CAFE"}` | 현재 씬 보고와 진행 조회. 미션 완료 권한을 주지 않음 |
| POST | `/api/v1/missions/first-day/rest` | 없음 | 카페 주문 목표를 모두 마치고 대화 종료한 경우에만 stage 1→2 |

`scene`은 HOME/TOWN/CAFE/HOTEL/SHOP이다. 허용되지 않은 씬은 400 `VALIDATION_FAILED`. 잘못된 휴식 시도는 409 `MISSION_NOT_READY`이며 진행을 바꾸지 않는다. stage 2에서 같은 휴식을 재전송하면 기존 상태를 반환한다. 인증·요청 확인 헤더 오류는 공통 API 규칙을 따른다.

모든 성공 응답 형식:

```json
{
  "started": true,
  "stage": 3,
  "completed": false,
  "scene": "CAFE",
  "canRest": false,
  "raining": false,
  "weather": "CLOUDY",
  "balance": 96,
  "lastPurchase": "카페 음료",
  "situation": "카페 직원에게 분실물을 물어보세요. 작은 파란색 가방에는 빨간 열쇠고리가 달려 있어요.",
  "direction": "카페 직원에게 가방을 찾아 달라고 하세요. 가방 안에는 여권 지갑과 책이 있어요. (대화 상대: Mia)",
  "steps": [
    {
      "index": 3,
      "title": "카페에서 가방을 찾아요",
      "scene": "CAFE",
      "npcCode": "CAFE_STAFF",
      "status": "CURRENT",
      "goals": [{"id":"ask_lost_bag","title":"분실물 문의","completed":false,"hint":"잃어버린 가방이 들어왔는지"}]
    }
  ]
}
```

예시의 `steps`·`goals`는 축약했다. 실제 응답은 7개 단계를 모두 포함하며 `status`는 UPCOMING/CURRENT/DONE이다. 진행 중에는 현재 단계의 담당 NPC 이름을 NPC 정보에서 찾아 퀘스트 카드에 함께 표시한다. 목표 장소에 있으면 `direction`에, 다른 장소에 있으면 이동할 곳을 설명하는 `situation`에 표시한다. NPC 이름을 찾을 수 없으면 기존 안내를 유지한다. Unity의 카페 의자는 미션 단계와 상관없이 카페에서 대화·요청 중이 아니면 몇 번이든 앉을 수 있다. `canRest`가 true일 때 앉아서 쉰 휴식만 서버에 휴식으로 보낸다. 마을 벤치와 호텔 소파에도 같은 조작으로 앉지만 미션 휴식으로 보내지 않는다.

`raining`은 4~6단계에 마을에 있을 때 true다. `weather`는 마을 날씨 이름이며 장소와 상관없이 현재 단계로 정한다. 시작 전과 여정 완료 뒤는 `CLEAR`다.

| 단계 | weather |
| --- | --- |
| 시작 전, 0~2 | `CLEAR` |
| 3 (카페에서 가방 찾기) | `CLOUDY` |
| 4~6 | `RAIN` |
| 완료 | `CLEAR` |

`weather`는 문자열이며 서버는 허용 값을 enum이나 검증으로 막지 않는다. 단계별 값은 `FirstDayStage`에 있고 DB 컬럼은 없다. 눈 같은 날씨를 더할 때는 값 이름을 Unity 날씨 정의와 먼저 맞춘 뒤 그 단계의 값만 바꾼다. Unity는 `weather`가 없거나 Unity 날씨 목록에 없는 값이면 `raining`으로 비와 맑음을 정하므로, 백엔드와 WebGL은 따로 배포해도 된다.

## 대화·AI·피드백 경계

기존 턴 처리의 `/v1/judge`에 현재 단계의 허용 의도를 전달한다. 예문 문자열이나 영어 철자 일치로 완료하지 않는다. 판정할 수 없거나 오류인 결과, 다른 NPC, 지난 단계의 결과는 적용하지 않는다. 현재 단계 목표는 여러 턴과 대화에 걸쳐 누적한다. NPC 대답 생성과 턴 저장이 성공한 트랜잭션에서만 서버가 목표를 적용하며, 이미 저장된 요청 ID 재전송은 기존 턴을 반환한다.

현재 단계 담당 NPC의 첫 인사와 매 턴 지시문에만 현재 사건·남은 목표·캐리어와 가방 구분을 넣는다. 다른 NPC(이전 단계 NPC 포함)에게는 다음 목적지와 그곳에서 만날 NPC 이름(`npcs.name`)을 알려, 지금 할 일이나 갈 곳을 물으면 모른다고 하지 않고 그 NPC에게 가 보라고 안내하게 하고, 자기 역할 안에서 길 안내만 하라는 지시를 보내며, 담당 NPC의 판매·분실물 보관 등 행동 지시는 전달하지 않는다. 매 턴 이미 완료한 목표와 이번에 인식한 목표를 빼고 남은 목표를 알려 주되, 담당 NPC가 남은 목표·필요한 물건·겪은 일을 먼저 꺼내거나 권하지 않고 학습자가 먼저 말하기를 기다리게 한다(`LEARNER_LEADS`). 학습자가 머뭇거리면 할 일을 말하지 않고 "Is there anything else I can help you with?"처럼 열린 질문만 한다. 모두 답했으면 미션 질문을 반복하지 않는다. 카페 주문을 마쳤지만 아직 쉬지 않은 상태로 다시 말 걸어도 재주문을 권하거나 휴식을 마쳤다고 말하지 않는다.

미션 시작 전은 기존 자유 대화와 동일하다. 퀘스트를 위해 별도 모델 호출을 추가하지 않는다. 기존 NPC 대답·TTS·피드백·기억 생성의 사용량은 그대로 발생하며, 자동 검증에서는 모두 대체한다.

`conversations.first_day_stage`는 대화 시작 시점의 단계이며, `first_day_goal_ids`는 그때 남아 있던 목표 ID 목록이다. 종료 피드백과 복습은 저장된 목록만 사용하므로 다시 말을 걸어도 이전 대화에서 완료한 목표를 요구하지 않는다. 다음 단계로 이동해도 지난 대화의 평가 범위는 유지한다. 빈 목록은 카페 주문을 마친 뒤 휴식 전에 다시 말 거는 경우처럼 새 목표가 없는 대화다. `NULL`은 목표 정보를 저장하기 전의 기록으로, 피드백은 실제 발화만 평가하고 복습은 저장된 요약을 사용하며 당시 목표를 추측하지 않는다. 이미 생성된 피드백은 자동으로 다시 만들지 않는다. NPC 기억은 기존 갱신 경로를 쓰며 미션의 소지품·결제·완료 상태를 덮어쓸 수 없다.

## 저장과 배포

`first_day_missions`에 사용자당 한 행을 저장한다. 업데이트 시 행 잠금을 사용하며 버전도 기록한다. 새로 시작할 때는 사용자 행 잠금으로 중복 생성을 막는다. 자정 초기화·재시작·삭제 API는 제공하지 않는다. ERD는 `docs/erd.dbml`을 따른다.

백엔드 시드에 SHOP·SHOP_STAFF가 추가되고 Unity Build Settings에 ShopScene이 추가된다. **백엔드와 WebGL을 같은 변경 묶음으로 배포**한다. 기본 테이블과 단계 컬럼은 `V1__create_schema.sql`, 대화별 남은 목표 컬럼은 `V29__add_conversation_first_day_goals.sql`에 정의되어 Flyway가 백엔드 시작 시 반영한다. 기존 진행 상태는 유지하고 과거 대화의 목표 목록은 채우지 않는다. 비밀 환경변수나 패키지 추가는 없다.

Unity 에셋은 **Tools → A305 → Mission → Build First Day Journey**로 생성·연결한다. 기존 씬 아트는 유지하고 없는 상점 실내만 만든다. 이미 있는 간판은 글자만 DRUGSTORE로 맞추고, 수첩의 마을 지도는 실행할 때마다 TownScene 배치로 다시 그린다. 우산 공용 단어와 상점 단어 목록은 ObjectHover 내보내기로 생성한다.

상점은 미국 소도시의 드럭스토어(DRUGSTORE)다. 미국에서는 갑자기 비가 오면 CVS·Walgreens 같은 드럭스토어에서 우산을 사는 일이 흔해 이 형태로 정했다. 실내는 **Tools → A305 → World → Apply Drugstore Interior**가 꾸미며 Build First Day Journey도 같은 작업을 실행한다. 입구 우산 통·음료 냉장고 벽·과자·식료품·약 선반·커피 코너·과일 상자를 두고, 조각과 실내 프리팹은 `Assets/Prefabs/World/Drugstore/`에 없을 때만 만든다. 우산 통은 기존 우산 공용 단어를 그대로 쓴다.

## QA

1. 개발 환경에서 새 계정으로 로그인해 튜토리얼을 완료하거나 건너뛴다. [퀘스트 시작]을 누르지 않아도 왼쪽 위에 첫 단계의 퀘스트 알약(누르면 카드가 펼쳐짐)이 보이고 호텔 출입문에 길 안내가 켜지는지 확인한다.
2. 표의 순서로 장소를 이동하며 대화한다. 정해진 예문을 따라 읽을 필요는 없다. 현재 목표 여러 개를 한 문장에 말하거나 여러 대화로 나누어도 누적되는지 확인한다.
3. 카페에서는 음료·옵션·매장 이용을 답한 뒤 대화를 마치고 카페 의자에 앉아 쉬어 간다. 주문 전이나 쉰 뒤에도 의자에는 다시 앉을 수 있지만, 주문 전 휴식은 미션 진행으로 인정되지 않아야 한다.
4. 분실물 외형·내용물을 일부만 답하면 아직 반환되지 않아야 한다. 우산은 결제 방법까지 선택한 뒤 코인이 8만큼 한 번만 줄어야 한다.
5. 중간에 씬을 이동하고 새로고침·재접속해도 진행이 유지되는지, 다른 사용자에게 진행이 공유되지 않는지 확인한다.
6. 대화 종료·피드백 표시와 미션 완료는 별개다. 현재 NPC 대화가 끝났다는 이유만으로 목표가 완료되면 안 된다.
7. 화면에는 NPC가 보이고 왼쪽 위 안내만 유지되어야 한다. 퀘스트 카드를 눌러 수첩을 열고, 퀘스트 카드가 오른쪽 위 메뉴(≡) 버튼과 겹치지 않아야 한다. 드럭스토어 입구는 카페 옆 빈 건물의 **DRUGSTORE** 간판이고, 지도에서 지금 갈 건물과 내 위치가 실제 거리 배치와 맞아야 한다.
8. 카페 주문 단계와 분실물 찾기 단계에서 호텔 Jake에게 다시 말 건다. 음료를 먼저 권하거나 카페에서 발견한 가방을 호텔이 보관 중이라고 말하지 않아야 한다. 나머지 단계에서도 담당이 아닌 NPC는 자기 역할을 유지하며 요청 시 길 안내만 해야 한다.
9. 첫 호텔 대화에서 Jake는 인사와 무엇을 도와줄지만 묻고, 예약 확인·짐 보관·카페 안내를 먼저 꺼내지 않아야 한다. 학습자가 요청하면 그 요청에 답한다. 체크인을 요청하거나 대화를 길게 이어 가도 체크인을 끝내거나 객실 번호·키를 주거나 신분증·카드·결제를 요구하지 않고, 얼리 체크인이 어렵다고 안내해야 한다.
10. 호텔에서 예약을 확인할 때 닉네임과 다른 이름을 대면 예약 확인 목표가 완료되지 않고 Jake가 이름을 다시 확인해 달라고 해야 한다. 닉네임을 말하면 완료되어야 한다.
11. 주문·옵션·매장 이용 답변을 마치면 추가 주문 질문을 강요하지 않아야 한다. 쉬기 전 카페 직원에게 다시 말 걸어도 재주문을 권하지 않아야 한다. 각 단계 마지막 목표를 답한 직후에도 이미 답한 질문을 반복하거나 다음 단계가 끝났다고 말하지 않아야 한다.

실제 모델 의미 판정과 말하기·피드백 품질 검증은 별도 승인 후 플레이하며 확인한다. 고정 응답 HTTP 테스트는 모델 품질 근거로 쓰지 않는다. `dev` 대상 MR 업로드, 병합, 배포 성공, 대표 주소의 새 화면 확인은 각각 구분한다.
