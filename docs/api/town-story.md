# 첫날 이후: 마을에서 보내는 하루

첫날의 작은 소동을 마치고 수첩에서 시작하는 연속 대화 여정이다. 식당에서 음료를 쏟은 뒤 빨래를 맡기고, 기다리는 동안 이발을 하며, 도움받은 사람들에게 감사를 전한 후 마을을 둘러본다. 첫날 여정과 새 여정의 진행은 별도 저장한다.

| 순서 | 장소와 상대 | 이야기와 대화 목표 |
| --- | --- | --- |
| 1 | 식당 Rosa | 아침을 주문하고 옷에 음료를 쏟은 상황을 설명한다. |
| 2 | 빨래방 Gus | 세탁 방법과 가격을 묻는다. |
| 3 | 은행 Henry | ATM 위치와 현금 인출 방법을 묻는다. PIN이나 비밀번호는 묻지 않는다. |
| 4 | 빨래방 Gus | 돌아와 세탁을 요청한다. |
| 5 | 이발소 Tony | 기다리는 동안 이발을 요청하고 원하는 스타일을 설명한다. |
| 6 | 꽃집 Lily | 마음에 드는 이발에 대한 감사 선물을 고르고 포장을 요청한다. |
| 7 | 이발소 Tony | 돌아가 꽃을 선물한다고 말하고 감사한다. |
| 8 | 빵집 Grace | 빨래방 주인에게 전할 간식을 고른다. |
| 9 | 빨래방 Gus | 세탁물 찾기를 요청하고 감사를 전한다. |
| 10 | 생활용품점 Nina | 램프를 구경하고 포장이나 배송을 문의한다. 매장 배송은 약속하지 않는다. |
| 11 | 오락실 Max | 우체국에 가는 길에 게임 방법을 묻는다. |
| 12 | 우체국 Linda | 소포 발송 방법과 가격을 묻는다. |

마을 미니맵, 미니맵을 눌러 여는 큰 지도, 여행 수첩 지도에서 지금 갈 가게를 빨간 테두리로 표시한다. 큰 지도 머리줄 범례에는 가게 이름도 나온다. 새 여정의 모든 단계는 `TOWN`에서 진행되므로 현재 단계의 `npcCode`로 가게를 찾는다. 재방문이나 재접속 때도 같은 기준을 쓰며, 여정을 마치면 테두리를 지운다.

세탁·이발·물건 구매와 선물은 **대화 연습**이다. 실제 결제, 소지품 거래, 캐릭터 머리 변경, 오락기 플레이와 배송 처리는 제공하지 않는다. 첫날 우산 구매 후 예산은 그대로 보여 주며 새 여정 대화에서 차감하지 않는다.

## 서버 계약

모든 요청은 로그인 세션을 사용한다. 상태 변경 요청에는 `X-Requested-With: ElsehereClient`가 필요하다.

| 메서드 | 경로 | 동작 |
| --- | --- | --- |
| GET | `/api/v1/missions/town-story` | 사용자별 시작 여부·현재 단계·목표를 조회한다. |
| POST | `/api/v1/missions/town-story/start` | 첫날 미션을 완료한 이용자의 새 여정을 시작하거나 기존 진행을 돌려준다. 미완료면 `MISSION_NOT_READY`다. |
| GET | `/api/v1/missions/quests` | 퀘스트 목록(제목·설명·들르는 곳·보상·상태)과 보상까지 더한 코인 잔액을 조회한다. |

응답은 첫날 미션과 같은 필드(`started`, `stage`, `completed`, `situation`, `direction`, `steps` 등)를 쓴다. stage 0~11이 진행 중이고 12가 완료다. 사용자별 목표는 대화와 저장이 성공한 경우에만 반영되며, 다른 NPC·지난 단계·판정 실패는 진행을 바꾸지 않는다. 중복 시작과 진행 반영은 기존 사용자 기록의 잠금을 이용한다. 대화 시작 시 기록한 여정 단계는 나중에 피드백을 만들 때 사용한다.

서버의 `town_stories`는 첫날 완료 행과 별도로 유지한다. 게스트 정리·탈퇴 시 사용자 진행만 남기는 기존 첫날 미션 정책을 따른다. 서버와 WebGL을 함께 배포하고 Flyway 마이그레이션을 먼저 적용한다. 운영 반영 여부는 배포에서 따로 확인한다.

현재 단계와 그 단계의 목표를 숫자와 비트로 저장하므로 이미 배포된 단계나 목표의 순서를 바꾸면 기존 진행이 다른 내용으로 해석된다. 순서를 바꿔야 한다면 저장된 진행을 함께 이전한다.

## 퀘스트 목록과 보상

화면의 퀘스트 목록은 첫날 연계 미션과, 마을 이야기 12단계를 네 장으로 나눈 퀘스트 다섯 개다(`Quest`). 장은 따로 저장하지 않고 마을 이야기 단계 범위로 정한다.

| 퀘스트 | 단계 | 보상 |
| --- | --- | --- |
| 호텔 체크인과 잃어버린 가방 | 첫날 0~6 | 10코인 |
| 옷에 쏟은 아침 | 마을 이야기 0~3 (식당·빨래방·은행·빨래방) | 6코인 |
| 새 머리와 꽃 선물 | 4~6 (이발소·꽃집·이발소) | 6코인 |
| 고마운 마음 전하기 | 7~8 (빵집·빨래방) | 4코인 |
| 마을 구경과 소포 | 9~11 (생활용품점·오락실·우체국) | 6코인 |

- 상태는 `LOCKED`(앞 퀘스트를 아직 끝내지 않음)·`AVAILABLE`(시작할 수 있음)·`IN_PROGRESS`·`DONE`이다. 앞 퀘스트를 끝내야 다음이 열린다. 마을 이야기를 시작하면 첫 장부터 이어서 진행하므로, 다음 장은 앞 장을 끝내는 즉시 `IN_PROGRESS`가 된다.
- 들르는 곳(`stops`)은 진행 단계마다 하나다. 장소 이름, NPC 이름(`npcs.name`), 할 일(목표 제목), 지나온 곳(`done`), 지금 갈 곳(`current`)을 준다.
- 보상은 끝낸 퀘스트로 계산해 첫날 예산(20코인, 우산을 사면 12코인)에 더한다. 지급 기록을 따로 남기지 않으므로 같은 보상을 두 번 받지 않는다. 첫날 미션·마을 이야기 응답의 `balance`도 같은 방식으로 보상을 더한다. 실제 결제나 서비스 재화와는 연결하지 않는다.

## 검증

서버는 단계·NPC별 판정, 실패·중복, DB 저장·복원, 첫날 미션과 피드백 회귀를 검증한다. Unity는 첫날 완료 전후의 여정 선택과 조회·시작 요청을 검증한다. 자동 테스트에서는 실제 STT·LLM·TTS를 호출하지 않는다. 실제 모델 대화와 화면 흐름은 테스트 환경에서 별도로 확인한다.
