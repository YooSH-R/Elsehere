# 비 오는 저녁 시연 퀘스트

기존 첫날·마을 이야기와 진행 및 결제를 분리한 시연 경로다. 기본값은 꺼져 있다. 이 기능은 Draft MR에서 검토하며, 별도 승인 없이 dev에 병합하거나 개발 서버에서 활성화하지 않는다.

## 실행과 복구

시연 브랜치의 백엔드와 Unity 클라이언트를 함께 사용한다. 전용 로컬 백엔드에서만 환경 변수 `ELSEHERE_SHOWCASE_ENABLED=true`(또는 `backend/.env`에 `elsehere.showcase.enabled=true`)를 설정한다. 진행은 계정마다 각자의 DB에 저장되므로, 팀원이 브랜치를 바꿔 자기 로컬 서버로 해 봐도 다른 사람의 진행이 보이지 않는다. DB는 Flyway V42가 시연 진행 테이블과 대화의 시연 상황 필드를 추가한다. dev의 V41(표현 카드 요청 종류) 이후에 적용한다. 기존 퀘스트 행은 변경하지 않는다.

퀘스트 창의 [이야기] 목록 맨 앞의 **비 오는 저녁, 햄버거 한 끼**를 열어 시작한다. 시연 서버에서는 이것만 열려 있고, 나머지 퀘스트는 진행 중이던 것까지 잠겨 있다. 계정에 진행 중이던 다른 퀘스트가 있어도 진행 중으로 보이지 않고, NPC도 그 퀘스트 목표로 대화하지 않는다. 기존 이야기 카드·지도·단계 UI를 그대로 사용한다. 시연 서버에서는 새 계정이 튜토리얼 방을 거치지 않고, 시연을 하는 중이 아니면 접속할 때 마지막 장소와 상관없이 호텔에서 시작한다. 시연을 하는 중에 다시 접속하면 마지막 장소로 돌아간다. 시연 서버(`ELSEHERE_SHOWCASE_ENABLED=true`)에서는 튜토리얼을 마치거나 건너뛰어도 첫 퀘스트를 미리 시작하지 않으므로, 호텔에 들어가면 진행 중인 퀘스트 없이 시연자가 퀘스트 창을 둘러보고 직접 눌러 시작한다. 시작하면 왼쪽 위 퀘스트 카드를 펼치고, 시연을 하는 동안 저절로 접지 않는다.

Jake에게 감사 인사를 전해 완료해도 진행을 즉시 초기화하지 않는다. 완료 안내와 같은 대화의 시연 맥락은 유지하고, 호텔에서 대화 노트 → Rosa의 햄버거 주문 대화 → [다시 연습]으로 이어 간다. 이때 카드의 복습 안내와 시연 대화창(최대 다섯 줄, 음성과 함께 자막 표시)은 유지된다. 복습을 끝내도 자동으로 초기화하지 않는다. 퀘스트 목록의 시연 카드만 `AVAILABLE`로 표시하고 지난 단계·현재 단계 표시는 숨긴다. 대화를 끝내고 시연 카드를 다시 눌러 시작할 때에만 진행·우산·시연 결제·택시 요청·날씨를 처음 상태로 되돌린 뒤 시작한다. 중간에 중단한 시연은 기존 진행을 재개한다. 저장된 대화·피드백·기억·복습 기록은 지우지 않는다.

| 경로 | 동작 |
| --- | --- |
| `GET /api/v1/missions/showcase` | 내 시연 상태 |
| `POST /api/v1/missions/showcase/start` | 새 시연 시작, 중단한 진행 재개, 완료한 시연은 처음부터 다시 시작 |
| `POST /api/v1/missions/showcase/reset` | 시연 진행·시연 결제만 처음으로 초기화하고 시작 전 상태로 둔다. 시연자가 퀘스트 창에서 눌러야 다시 시작된다. |
| `POST /api/v1/missions/showcase/stop` | 일반 퀘스트로 복귀 |
| `POST /api/v1/missions/showcase/taxi-arrival` | 인식된 목적지에 실제 하차한 Unity 이벤트 수신 |

모든 요청은 로그인 세션을 사용한다. POST에는 공통 `X-Requested-With` 헤더가 필요하다. 시작·중단·초기화는 진행 중인 대화를 먼저 끝내야 한다. 설정이 꺼져 있으면 시연 경로는 사용할 수 없고, 목록과 일반 진행에 영향을 주지 않는다. 시연을 중단해도 대화 기록·실제 기억·호감도는 지우지 않는다. 같은 계정에서 완료한 시연을 반복할 수 있으며, 학습 기록까지 없는 시연이 필요하면 별도 시연 계정을 사용한다.

시연 진행은 기존 첫날·마을 이야기와 같은 진행 메타데이터 보존 기준을 따른다. 탈퇴·게스트 정리에서 대화 원문·피드백·기억·복습 내용은 기존 삭제 경로로 지운다.

## 진행

1. 호텔 Jake에게 햄버거 가게 위치를 묻는다. Jake는 비가 오니 택시를 권하고 우산을 빌려준다. 우산 반환 약속은 목표가 아니어서, 길만 물으면 이 단계를 마치고 우산을 빌린 상태가 된다.
2. Jake와 대화를 마치면 빌린 우산을 접어 손에 쥐고 호텔 안을 걸어 나온다. 비 오는 거리에 나오면 우산을 펴 쓴다. 호텔 앞에 기다리는 택시는 **택시 타기**로 안내한다. 탑승 후 기사는 쉬운 말로 목적지를 묻고, 목적지 요청·이동 시간 질문 표현은 추가 생성 대기 없이 바로 보여 준다. 우산은 차량 안에서는 숨긴다. 손님을 태운 택시가 달리는 동안에는 교차로 본길 신호를 초록으로 붙잡아 신호에 서지 않는다. 빨간불을 지나치는 것이 아니라 신호 자체가 초록이고, 내리면 원래 주기로 돌아간다. 단순 목적지 발화·취소·다른 곳 하차로는 다음 단계가 열리지 않는다.
3. 시연을 시작해 끝낼 때까지 Maple Burger에는 직원과 John만 있다. 여가로 들르는 다른 NPC(행인, 쉬는 다른 가게 직원)는 들어오지 않고, 이미 있던 손님은 걸어 나간다. Maple Burger에 들어가면 장면 전환이 늦게 끝나는 것을 감안해 1.5초 뒤에 John의 저장된 랩이 재생된다. 랩을 시작한 자리에서 한 걸음 이동하면 공연을 멈추고 다가와 기존 대화 제안을 띄운다. 입장부터 이 제안에 답할 때까지 가게 생활소음을 끄고, 거절하거나 무시하면 다시 낸다. 수락해 대화하는 동안에는 평소 대화처럼 낮춘 크기로 낸다. Rosa에게 치즈버거·양파 빼기·감자튀김과 콜라·매장/포장 여부를 말한다. 조건은 큰 중복 설명 대신 체크리스트 아래에 표시하며, 정해진 힌트를 그대로 읽을 필요는 없다. Rosa는 단골 기억(늘 시키는 메뉴)이 있으면 인사에서 늘 드시던 것인지 물을 수 있고, 학습자가 다른 것을 고르면 새 주문을 받는다. Rosa는 `Are you eating here?`처럼 물으며 학습자가 할 `to go`를 먼저 말하지 않는다. 주문 완료 시 시연 잔액에서 7코인을 한 번만 차감하고 즉시 음식을 건네며, 일반 서비스의 받을 것·착석 타이머는 만들지 않는다. 원래 퀘스트 잔액은 유지한다.
4. 주문을 마치면 날씨가 맑아진다. 접은 우산을 들고 호텔로 돌아가면 Jake가 돌아온 것을 반기고 비를 피했는지 묻는다. 우산 감사 인사를 전한 뒤 호텔 안에서 대화 노트를 열어 주문 대화를 다시 연습해도 된다. 다시 연습하는 동안 왼쪽 위 카드에는 주문 조건 네 가지가 펼친 채로 보이고, 말한 조건에 체크된다. 대화 위 '이번에 써 볼 표현'은 주문 대화 중에 뜬 추천 문장만 주문 조건 차례(버거 → 재료 → 사이드·음료 → 매장·포장)로 놓이고, 같은 뜻의 표현은 하나만 두며, 모든 표현 아래에 뜻을 보인다.

호텔로 돌아왔을 때의 기억과 호감도는 기존 대화·기억 기능의 실제 기록을 사용한다. 시연 대사나 기억을 성공한 것처럼 미리 저장하지 않는다. 대화 노트도 기존 전역 기록을 사용하며, 시연 때문에 장소를 제한하지 않는다.

주문 대화에는 시연 상황 스냅샷을 저장한다. 복습은 그 상황의 새 주문으로 시작하며, 이전 주문의 감사 인사나 원래 아침 식사·커피 쏟기·세탁소 퀘스트로 이어지지 않는다. 대화 중 보여 준 대체 표현은 저장된 문장 그대로 피드백과 복습에 함께 쓰며, 짧지만 적절한 답을 오류로 바꾸거나 별도로 모델을 호출하지 않는다. 햄버거 주문의 [다시 연습]에서는 포장 답변에 대해 저장된 추천 문장을 ‘이번에 써 볼 표현’ 맨 위에 두고 나머지 표현도 유지한다. 복습 중 체크와 종료 결과도 같은 목록을 사용한다.

시연 중에는 자동 설문 안내를 띄우지 않는다. 대사 칸은 발화 수 대신 실제 줄바꿈 기준 최대 다섯 줄로 제한하며, 긴 내용·뜻·가사는 기록을 지우지 않고 안에서 스크롤한다. 시연의 임시 스트림 글자는 바로 표시하지 않고 음성과 함께 받은 문장부터 보여 준다. 음성이 없는 경우에는 저장된 최종 대사를 표시한다.

시연 NPC는 쉬운 말로 한 번에 한 질문만 하고, 대답은 1~2개의 짧은 문장·22단어 이내로 요청한다. 학습자가 할 말을 먼저 대신하거나 다음 퀘스트를 설명하지 않는다. 이는 모델 지시 기준이며 긴 입력·음성 합성 실패를 막는 서버 보장과는 구분한다. 대화창의 다섯 줄·스크롤 상한은 별도로 적용한다.

시연 거리에는 호텔·햄버거 가게가 있는 동쪽 보도를 비워 두고, 반대편 서쪽 보도에서만 주민 두 명이 짧은 구간을 왕복한다. 이들은 먼저 다가오거나 대화를 제안하지 않는다. 호텔에는 Jake 외에 리셉션 보조 직원과 벨보이를 남기되 각각 프런트 뒤와 로비 가장자리의 지정 위치에 머물게 한다. 중앙 출입 통로에는 직원을 두지 않는다. 햄버거 가게에는 시연 시간과 무관하게 주문 담당 Rosa와 John만 둔다. 시연 중 시설 방문객은 생성하지 않으며, 일반 퀘스트로 전환하면 기존 NPC 일과와 방문을 다시 적용한다.

## 낮과 밤을 보여 주는 로컬 시간

서비스 시계는 실제 600초가 게임 하루이므로 실제 1초에 게임 2.4분이 흐른다. 대화·학습 화면을 보고 있는 동안은 시계가 멈춘다. 따라서 전체 시연 영상 길이만으로 일몰을 계산하면 안 된다.

로컬의 새 시연 계정은 오후 5시 29분 무렵으로 준비한다(누적 플레이 237초: 오전 8시 + 237×2.4분). 기본 일몰 오후 7시까지 이동·탐색 시간 약 38초가 필요하며, 약 50초가 흐르면 오후 7시 30분으로 해가 진 상태가 된다. 날씨는 햄버거 주문 완료에 맞춰 맑아진다. 사용자가 대화에 쓰는 시간에는 밤이 빨리 되지 않으므로 호텔 이동·택시·매장 이동을 포함한 실제 이동 시간으로 확인한다. 일반 계정·서버 공용 시계는 변경하지 않는다.

## 검증 경계

자동 검사는 AI·음성 공급자를 테스트 대역으로 바꾼다. 시연 계정으로 실제 대화·번역·음성·기억·피드백을 확인하는 것은 모델 호출이 필요한 별도 수동 검증이다. 호출 승인을 받기 전에는 실행하지 않는다.

실차 위치와 카메라·우산, 퀘스트 카드·목록·지도는 Unity에서 확인한다. PC와 모바일 화면에서 글자·아이콘 정렬, 안쪽 여백, 이웃 HUD와 겹침·잘림을 함께 점검한다. 전체 대화 노트·복습장은 기존 UI를 재사용한다.
