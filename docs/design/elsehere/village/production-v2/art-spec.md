# Elsehere B안 제작 규격 v2

> 이미지·ZIP·검수 기록은 Git에서 제외한 로컬 자료다. 아래 `artifacts/...` 경로는 로컬 보관본을 가리킨다.

브릭 메인스트리트 v3-B의 공간감을 구현하기 위한 제작 규격이다. **캐릭터 키는 1.6m로 확정하며, 건물은 폭·깊이·높이를 키운 확대안을 적용한다.** 캐릭터는 리틀 멍 v7의 현재 `tripo-turnaround-v1` 4방향 이미지를 기준으로 제작한다.

- B안 기준 이미지 (`artifacts/village/brick-mainstreet-v3/b-3p0m/street-height.png`, 로컬 보관) · 전체 배치와 재질 참고 (`artifacts/village/brick-mainstreet-v2/town-overview.png`, 로컬 보관)
- [리틀 멍 v7 비율과 시트](../../mascot/little-mung-v7/README.md) · [에셋 목록](asset-list.md) · [Unity 적용 순서](unity-application-plan.md)

이 규격은 production-v1을 대체한다. 이전 2m 층고·1.8m 문·4.4m 상점 건물과 이전 치수도는 현재 제작에 사용하지 않는다. **마을 B안과 캐릭터 B/Cluster는 서로 다른 선택 항목**이다.

## 1. 유지할 디자인

미국 소도시의 연속된 벽돌 상점, 평지붕과 파라펫, 쇼윈도, 카페 어닝, 세로 호텔 간판, 보도와 교차로를 유지한다. 형태는 넓은 면과 부드러운 모서리로 표현한다. 벽돌·피부·직물·나뭇잎의 사실적인 미세 질감은 생략한다.

캐릭터는 큰 머리, 작은 몸, 넓은 얼굴 여백, 작고 단순한 눈, 얇고 낮은 코, 작은 입을 공유한다. 눈매와 표정은 움직이는 요소로 두고, 공통 비율·얼굴 조형 방식·재질로 통일감을 만든다. 성별·피부색·직업에 따라 리그를 따로 만들지 않는다.

## 2. 단위와 기준면

1 Unity unit = 1m를 기준으로 크기를 맞춘다. 가져온 모델의 단위와 Scale Factor를 확인하고 기능 프리팹 루트 Scale은 (1,1,1)을 유지한다. [Unity Model Import](https://docs.unity3d.com/6000.3/Documentation/Manual/FBXImporter-Model.html)

- 방향: +Y 위, +Z 정면. 캐릭터 원점은 양발 사이 바닥, 벽은 바닥 중앙이다.
- 치수 표기는 너비×깊이×높이(m). 출입문만 유효 폭×유효 높이로 쓴다.
- 수평 기본 격자는 2m, 세부 배치는 0.1m. 회전은 90도 단위로 시작한다.
- 차도 윗면 Y=0, 보도와 건물 1층 완성 바닥 Y=0.1m. 출입구에 단차를 만들지 않는다.
- 층고와 건물 높이는 해당 건물 1층 완성 바닥에서 잰다. 바닥·슬래브 두께를 다시 더하지 않는다.

| 카페·일반 상점 외관 | 8.00×8.00×7.40m | 전면: 4m 출입구 조립 + 2m 창 두 칸 |
| 호텔 외관 | 10.00×10.00×7.40m | 전면: 4m 출입구 조립 + 2m 창 세 칸 |
| 집 외관 | 8.00×8.00×5.20m | 단층 4m + 박공지붕 높이 1.2m |
| 집·카페·호텔 로비 실내 | 6×6 / 8×8 / 8×8m | 유효 바닥 크기 후보; 기존 분리 씬 구조 사용 |
| 어닝 | 돌출 약 1.4m, 최저점 약 2.37m | 출입문 상단·카메라·간판을 가리지 않게 조정 |
| 보도 | 총폭 4.00m | 가로수·가구 띠 1m + 연속 통행 폭 3m |
| 차도 | 총폭 6.00m | 양방향 거리 표현. 차량 시뮬레이션 기능과 별개 |
| 건물 사이 통로 | 유효 폭 2.00m 이상 | 장식과 처마를 포함한 실제 통과 폭 검사 |
| 가로등·나무 | 높이 약 3.4 / 4.35m | 나무 수관은 큰 덩어리 3~5개 |

같은 기준으로 마을 좌표의 2층 바닥은 Y=4.1m, 지붕 기준면은 Y=7.1m, 파라펫 상단은 Y=7.5m가 된다. 별도 실내 씬에서는 바닥을 Y=0으로 두어도 바닥 기준 높이는 동일하게 유지한다.

### 출입구 접합

4m 전면의 중앙에 폭 2m 개구부를 둔다. 양옆 1m 영역은 각각 0.9m 벽과 0.1m 프레임으로 구성한다. 높이는 2.2m 개구부 + 0.1m 상단 프레임 + 1.7m 상부 벽 = 4m다. 문 프레임 안으로 벽 Collider가 넘어오지 않도록 분리한다.

문 Visual, 통행을 막는 Collider, 씬 전환 Trigger는 별개다. 전환용 문 앞을 닫힌 문짝 Collider로 막지 않는다. 열리는 문 연출을 추가할 때도 Trigger까지 실제로 접근할 수 있어야 한다. 새 문 여닫기 기능을 이 규격만으로 구현 범위에 포함하지 않는다.

직선 접합면은 평평하게 두고 노출된 모서리만 둥글린다. 건물 bevel은 0.03~0.06m부터 시험하며, 코너는 외곽 치수가 유지되는 전용 부품으로 처리한다. 구역 끝에는 차도 6m + 양쪽 보도 4m의 동일한 연결 단면을 남긴다.

## 4. 캐릭터 비율과 가구

리틀 멍 v7은 v4 B의 대두 비율을 계승한다. 아래 값은 2D 이미지의 인상을 제작용으로 근사한 시작값이다. 전체 키를 1.6m로 확정하고 머리 약 60%·턱 아래 몸 약 40%를 공통 기준으로 시험한다.

| 항목 | 리틀 멍 v7 기준 |
| --- | --- |
| 전체 높이 | 1.60m 확정 |
| 기본 헤어 포함 정수리~턱 | 약 0.96m |
| 턱 아래~신발 바닥 | 약 0.64m |
| 머리 비중 | 약 60% |
| 시각적 인상 | 큰 머리와 함께 옷과 짧은 팔다리가 보임 |
| 의자 좌판 높이 시험 | 0.27~0.29m |
| 탁자 상판 높이 시험 | 약 0.60m; 카운터는 대화·손 도달 별도 검사 |

가구 치수는 v7 베이스의 앉기·손 도달·턱 간섭을 검사한 뒤 공통 세트로 고정한다. 외관과 실내 크기가 다르더라도 문 디자인, 장소의 색, 가구의 사용 높이는 이어져야 한다.

헤어 포함 외곽은 우선 최대 폭 1.6m·깊이 약 1.14m 안에서 시험한다. 눈높이는 원본에서 임의로 고정하지 않고 최종 메시의 눈 중심을 발 기준으로 측정한다. 이 범위는 통행 검사에 쓰는 예산이며 모든 머리를 같은 외곽으로 만들라는 뜻은 아니다.

### 모듈과 표정

- v7 비율을 바탕으로 몸·관절 위치·본 계층·bind pose·목 접합부를 검증하고 고정한다. 공통 베이스에서 헤어·의상을 교체해 스킨 호환성을 확인한 뒤 인물 조합을 늘린다.
- 원본 B/Cluster의 가운데 모인 이목구비와 양쪽 볼의 넓은 여백을 유지한다. 같은 공통 베이스에서 얼굴 인상·헤어·피부색·복장·표정을 변형하며, 인물마다 별도 전신 리그를 만들지 않는다. A/Wide는 현재 제작 기준이 아니다.
- 현재 정면은 중앙 이동 전 B의 시선을 복원한 배치다. 둥근 느낌의 눈동자가 각 흰자 안에서 코 쪽에 조금 붙은 위치를 유지하며, 흰자 중앙으로 강제 이동하지 않는다. 후속 작업은 현재 `tripo-turnaround-v1/front.png`를 직접 참고한다. 실제 중립 시선과 시선 애니메이션은 메시와 대화 카메라에서 확인한다.
- 얼굴 프리셋은 같은 토폴로지의 제한된 변형을 우선한다. 눈·코·입을 무조건 분리 메시로 만들지 않는다. 헤어는 Head 부착점, 움직이는 의상은 같은 베이스의 스킨과 바인드 포즈를 사용한다.
- 초기 표정: 중립, MouthOpen, MouthRound, MouthWide, BlinkLeft, BlinkRight. 입 내부와 눈꺼풀 변형을 실제 메시에서 검사한다. 이 채널 구성만으로 음성 립싱크가 완성되는 것은 아니다. [Unity Blend Shapes](https://docs.unity3d.com/6000.3/Documentation/Manual/BlendShapes.html)
- 초기 동작: Idle, Walk, Run, Talk, Wave. 기존 점프 입력을 유지하는 동안 Jump/Fall/Land도 확인한다. Sit은 가구 검증용으로 먼저 시험한다.
- Humanoid 애니메이션 재사용은 유효한 Avatar가 전제이며, 짧은 팔다리에서 자연스럽게 움직이는지는 별도 확인한다. 본 이름이 같다는 이유만으로 스킨 교체 호환성을 보장하지 않는다. [Unity Retargeting](https://docs.unity3d.com/6000.3/Documentation/Manual/Retargeting.html)

## 6. 제작 예산과 통과 조건

| 대상 | 최초 예산·검증 기준 |
| --- | --- |
| 캐릭터 한 명 | 헤어·옷 포함 8k~15k triangles, 재질 슬롯 2~3개부터 |
| 조립 건물 외관 한 동 | 5k~12k triangles, 공유 재질 2~4종 |
| 나무 / 보통 소품 | 0.5k~1.5k / 0.1k~1k triangles |
| 텍스처 | 캐릭터·환경 아틀라스별 1024px부터; 대화 확대 화면으로 필요성 판단 |
| Web 화면 | 지정한 팀 PC·브라우저, 1080p, 1→4→8명 비교 |
| 성능 목표 | 평균 30fps 이상부터 검토. 프레임 시간 중앙값·95백분위, 메모리, 장비·브라우저를 함께 기록 |

이는 프로젝트의 초기 제작 예산이며 측정 성능이 아니다. Renderer·재질·투명 오브젝트·조명 비용을 함께 본다. 문 정면·대각선 통과, 벽 코너의 머리 관통, 카메라 최소·최대 줌, 대화 중 얼굴 가림, 입출입 후 재전환, 의상 교체 후 스킨 변형을 통과한 뒤 에셋을 늘린다.

## 7. 저장 위치와 적용 범위

제작 문서·프롬프트는 `docs/design/elsehere/`, 생성 시안은 `artifacts/`에 둔다. Unity 원본 외부 에셋은 `Assets/ThirdParty/<에셋 이름>/`, 팀 가공 결과는 `Assets/Art/<기능>/`, 기능 프리팹은 `Assets/Prefabs/<기능>/`, 조절 설정은 `Assets/Data/<기능>/` 규약을 따른다. 공통 인물과 공유 건축은 `Assets/Art/Common/` 후보로 묶는다.

최신 [MVP 기능 범위](../../../../A305_기획안/3D%20AI%20언어학습%20서비스%20—%20MVP%20기능%20범위.md)의 방 튜토리얼·행인 길 안내·카페·숙소 대화를 유지한다. 구체 적용은 [Unity 적용 순서](unity-application-plan.md)와 [Unity 개발 규약](../../../../unity/conventions.md)을 따른다. 메인스트리트는 별도 작업 브랜치의 Unity Sandbox에서 크기 대체물과 외관 모듈로 조립한다. 실제 v7 메시·리그·립싱크, Production 씬 연결과 Web 성능 검증은 별도 단계다.
