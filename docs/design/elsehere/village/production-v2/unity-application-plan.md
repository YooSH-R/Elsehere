# Elsehere B안 Unity 적용 순서

목표는 브릭 메인스트리트 v3-B와 리틀 멍 v7 비율을 기존 방·마을·카페·숙소 흐름에 적용하는 것이다. **v7 비율과 통행을 먼저 시험하고, 공통 베이스 한 체와 카페 한 구간이 통과한 뒤 전체 공간으로 확장한다.** 이 문서는 실행 계획이며 아래 단계가 이미 완료됐다는 뜻은 아니다.

[제작 규격](art-spec.md) · [에셋 목록과 ID](asset-list.md) · [캐릭터 v7 기준](../../mascot/little-mung-v7/README.md)

[메인스트리트 씬 디자인 v1](../../scenes/mainstreet-v1/README.md)은 집·앞마당·카페·호텔을 연결하는 배치 초안이다. 거리 콘셉트와 좌표가 있는 평면도를 크기 시험과 MVP 조립에 참고한다. 확대 배치와 1.6m 비율 대체물은 `Assets/Scenes/Sandbox/TownMainstreetSandbox.unity`에서 확인한다. 제작한 외관·조명과 무료 소품 프리팹의 사용법은 [Unity 아트 문서](../../../../unity/mainstreet-art.md)를 따른다. Production 씬 연결은 후속 단계다.

## 1. 현재 프로젝트에 맞출 기준

프로젝트 루트는 `frontend/UnityClient`다. 저장소의 설정 파일은 Unity 6000.3.26f1, URP 17.3.0을 지정한다. 패키지 추가 없이 현재 구성에서 시작한다.

| 현재 소스에서 확인한 항목 | 적용 시 확인할 일 |
| --- | --- |
| PlayerSandboxBuilder 신규 캡슐 기본값: 높이 1.8m, 반지름 0.3m | 1.6m 모델을 넣은 뒤 시각 외곽·실제 충돌 범위를 따로 검사 |
| PlayerCameraSettings 기본값: pivot 1.5m, eye 1.6m, 거리 5m, pitch 20도 | 해당 값은 새 캐릭터 눈높이가 아님. 별도 시험 설정으로 비교 |
| SpaceSceneBuilder 신규 문 Trigger: 1.4×2.4×0.7m | 2.0×2.2m 개구부의 정면·대각선 접근을 감지하도록 크기와 위치 검사 |
| 기존 문 대체 Visual: 1.2×2.2m | 기능 루트·연결은 보존하고 Visual 아래의 문 모델 교체 |
| HomeScene ↔ TownScene ↔ CafeScene / HotelScene | 씬 이름·Doorway Id·Destination 연결을 유지 |
| 기존 Builder는 디자인 Visual과 이미 조절한 값을 보존하는 구조 | 재실행으로 새 규격이 자동 반영된다고 가정하지 않음 |

이 표는 C# 기본값이며 저장된 프리팹·ScriptableObject의 현재 Inspector 값과 다를 수 있다. 실제 적용 전에 사용할 객체를 확인한다. 근거: [Player Builder](../../../../../frontend/UnityClient/Assets/Scripts/Editor/Player/PlayerSandboxBuilder.cs), [Camera Settings](../../../../../frontend/UnityClient/Assets/Scripts/Player/PlayerCameraSettings.cs), [World Builder](../../../../../frontend/UnityClient/Assets/Scripts/Editor/World/SpaceSceneBuilder.cs), [World 사용 설명](../../../../../frontend/UnityClient/Assets/Scripts/World/README.md).

### 1단계 크기 시험장

실제 게임 캐릭터를 생성하기 전에 구·상자 등 단순 대체물로 v7의 높이·외곽을 재현한다. 이 대체물은 실제 공간의 크기를 재는 도구다.

1. 전체 키 1.6m 확정, v7 머리/몸 약 0.96/0.64m로 대체물 하나를 만든다. 크기 시험 뒤 플레이어와 NPC를 같은 비율·리그 기준으로 제작한다.
2. E02 벽 2×0.2×4m와 E04 출입구 조립 4×0.2×4m를 붙인다. 개구부 2×2.2m, 보도·문 바닥 높이, 상층 벽 3m와 파라펫 0.4m를 함께 확인한다.
3. CharacterController는 기존 설정을 복제한 시험 프리팹에서 조절한다. 높이 1.6m·중심 Y=0.8m를 출발점으로 보고, 반지름은 실제 통행감과 머리 외곽을 함께 보며 정한다. 작은 캡슐에 큰 머리를 붙였다는 이유만으로 충돌 검증을 끝내지 않는다.
4. Mainstreet Sandbox의 아트 검토 카메라는 pivot 2.5m, 거리 6.2m, pitch 6도, 세로 FOV 55도를 사용한다. pivot은 구도 조절값이며 실제 눈높이가 아니다. 현재 대체물의 eye는 약 1.074m이며 최종 v7 메시의 눈 중심을 측정해 다시 확인한다. Build And Verify Reference Look 메뉴는 Sandbox 전용 카메라와 색 보정을 적용한다. Production 카메라는 별도 검증 후 반영한다.
5. 문 정면·대각선 이동, 벽 코너 회전, NPC와 교행, 보도 턱, 최소·최대 줌, 1인칭·대화 화면을 시험한다. 카메라 벽 충돌과 플레이어 머리 관통은 따로 검사한다.
6. 문 앞 3×2.4m를 비워 두고 ArrivalPoint를 Trigger 밖에 둔다. 플레이어 충돌체 전체가 겹치지 않는지 확인한다. 도착 직후 다시 이전 씬으로 이동하면 이 단계를 통과하지 못한 것이다.
7. v7 기준 의자 좌판 0.27~0.29m, 탁자 상판 약 0.60m를 실제 Sit·손 동작·대화 시점에서 확인한다. 카운터는 손 도달과 턱 가림을 별도로 검사한다. 무료 소품의 현재 프리팹 크기를 사용 동작에 맞는 최종 치수로 간주하지 않는다.

### 2단계 모델 확보와 모듈 검사

Tripo를 사용할 경우 선택한 인물 한 명의 정면·측면·후면 자료와 분리할 파트를 준비한다. 여러 사람이 담긴 비교 시트를 그대로 입력하지 않는다. 후보 생성 뒤 DCC에서 실제 크기, 축, 피벗, 면 누락, UV, 텍스처, 토폴로지, 입 내부, 리그·스킨을 정리한다. 원본과 가공본을 구분해 보관한다.

첫 결과의 수정량이 크면 원인을 고치거나 베이스 확보 방법을 바꾼다. 같은 문제를 가진 전신 캐릭터를 다량 생성하지 않는다. 자동 리깅 성공이나 파일 가져오기 성공은 모듈 교체·표정·성능 통과와 별개다.

FBX와 텍스처를 기존 가져오기 경로에서 먼저 시험한다. 다른 포맷 때문에 새 패키지가 필요하면 필요성과 호환성을 확인하고 프로젝트의 패키지 변경 절차를 따른다. 최종 베이스 위에서 헤어 2종·의상 2종을 교체하며 B 얼굴의 인물별 변형에서 눈감기·입벌리기·대화 동작을 검사한다. 애니메이션과 이동 코드가 동시에 위치를 움직여 이중 이동을 일으키지 않는지도 확인한다.

### 3단계와 4단계 공간 적용

카페 전면 8m를 **4m 출입구 조립 + 2m 창 두 칸**으로 완성하고 동일 조명에서 캐릭터와 비교한다. 이 한 구간이 통과하면 호텔 10m·상점 8m·집 8m를 같은 규격으로 조립한다. 실내는 공통 가구와 재질을 재사용한다.

- 아트는 `Environment`, NPC는 `Characters`, 조명은 `Lighting`에 둔다.
- 플레이어와 출입구 기능 루트를 지우지 않고 `Visual` 아래를 교체한다. 기존 참조 연결과 문 앞 도착 방향을 유지한다.
- 방의 호버 사물, 마을 행인의 접근·대화 요청, 카페·호텔 직원의 대화 위치가 큰 머리·간판·카운터에 가리지 않도록 검사한다.
- 일반 상점 외관은 배경이다. 실내와 기능이 없는 건물은 영업 중인 가게로 오인되는 상품 진열·입간판·쇼윈도 조명을 배치하지 않는다. 실제 이용 장소의 출입구와 이동 연결을 먼저 확인하고 그 장소에 맞는 장식을 적용한다. 외관을 추가했다고 새로운 상점 기능을 만들지 않는다.

## 3. Editor와 Builder 실행 순서

모든 적용 작업은 [프론트엔드 지침](../../../../../frontend/AGENTS.md)과 [Unity 개발 규약](../../../../unity/conventions.md)을 따른다. 씬·프리팹·데이터 에셋·머티리얼은 Editor 또는 Builder로 생성하고 `.meta`를 함께 관리한다. 직렬화 YAML을 직접 작성하지 않는다.

1. 새 환경을 처음 구성할 때 기존 메뉴를 **Tools → A305 → Player → Build Sandbox → UI → Set Up Fonts → World → Build Spaces** 순서로 실행한다. 이미 구성된 프로젝트를 아트 교체 때문에 초기화하지 않는다. 각 메뉴는 경로를 줄여 표시한 것이며, UI와 World도 Tools → A305 아래에 있다.
2. 아트 검증은 `Assets/Scenes/Sandbox/TownMainstreetSandbox.unity`에서 이어간다. TownMainstreetBuilder가 외관 모듈을 조립한다. 다른 Sandbox를 새로 늘리지 않는다. Player Builder는 자신의 Sandbox를 덮어쓰므로 디자인 작업을 PlayerSandbox에 저장하지 않는다.
3. 모델은 `Assets/Art/Common/` 또는 장소별 `Art/`에, 기능 프리팹은 기존 `Prefabs/` 규약에 맞춰 넣는다. 공유 Data 원본에 시험값을 바로 덮어쓰지 않고 시험용 설정에서 비교한다.
4. Production 반영 전에는 프로젝트 규약대로 최신 dev 반영과 팀 채널의 씬 수정 선언을 담당자가 수행한다. 같은 씬을 동시에 편집하지 않는다. 이 계획 작성 자체로 메시지를 전송하지는 않는다.
5. 해당 Production 씬에서 공간 프리팹을 교체하고 **Tools → A305 → World → Set Up Open Scene**으로 기존 기능 연결을 맞춘다. 도구가 아트나 수치를 자동으로 B안으로 바꾸는 것은 아니다.
6. Prefab Mode에서 저장한 디자인, Collider 설정, 출입구 짝과 카메라 연결이 Builder 재실행 후에도 유지되는지 확인한다. 변경한 에셋과 Unity가 생성한 `.meta`를 함께 리뷰한다.

기존 Builder와 설정을 수정해야 할 때는 별도 코드 변경으로 다룬다. 동작 변경에는 TDD 절차를 적용하며, 새 Builder는 재실행해도 디자인을 덮어쓰지 않아야 한다.

## 4. 완료 판정

| 영역 | 확인할 결과 |
| --- | --- |
| 크기 | 실제 Bounds로 키·문·층고 확인, 문틀 접합·발 접지·상하층 연결 정상 |
| 이동·시점 | 직진·대각선 통과, 대두의 벽 관통과 카메라 가림, 최소/최대 줌 정상 |
| 캐릭터 | 남녀·피부색·헤어·직업 변경 후 같은 베이스 유지, 표정과 의상 변형 정상 |
| 기능 | Home/Town/Cafe/Hotel 왕복, ArrivalPoint, 호버, 행인 요청·대화 진입/종료 정상 |
| 회귀 | 영향받는 기존 EditMode·PlayMode 테스트 실행; World 연결 테스트 포함 |
| Web | 같은 장면·카메라에서 1/4/8명 비교, 프레임 시간·메모리·장비 기록 |

시각 요소는 Play와 실제 브라우저로 확인한다. 문서와 시안 작성 단계에서는 Unity 실행이나 3D 모델 호환성 검사를 통과한 것으로 기록하지 않는다. 기능 테스트 실행 방법은 [Unity 개발 환경](../../../../unity/setup.md)과 [프론트엔드 지침](../../../../../frontend/AGENTS.md)에 따른다.
