# Jira와 GitLab 연동

Jira는 작업 범위와 진행 상태를 관리하고, GitLab은 해당 작업의 코드 변경과 리뷰 이력을 관리합니다. 이슈 키를 기준으로 작업과 구현 이력을 연결합니다.

## 연동 구성

GitLab의 Jira issues 연동을 사용합니다.

| 항목 | 설정 |
| --- | --- |
| Jira 주소 | `https://ssafy.atlassian.net` |
| 연동 이벤트 | Commit, Merge request |
| 이력 기록 | 커밋·MR 링크 및 댓글 |
| 자동 상태 전환 | 비활성화 |

## 이슈 키 작성

브랜치·커밋·MR에 실제 Jira 이슈 키를 포함합니다. 아래 예시의 `S15P31A305-123`은 해당 작업의 이슈 키로 바꿉니다.

```text
브랜치: feat/S15P31A305-123-cafe-order
커밋: feat(frontend): 카페 주문 화면 추가 [S15P31A305-123]
MR 제목: [S15P31A305-123] 카페 주문 화면 추가
```

커밋 메시지와 MR 제목에 포함된 이슈 키로 해당 Jira 이슈에 변경 이력을 기록합니다. 로컬 커밋의 이슈 키 자동 입력은 [개발 및 협업 규칙](development.md)의 Git 훅 설정을 따릅니다.

## 작업 상태 관리

- 담당자는 작업을 시작할 때 Jira 상태를 진행 중으로 변경합니다.
- 구현, 리뷰, 반영 및 이슈별 검증이 끝나면 완료 조건을 점검하고 완료로 변경합니다.
- 상위 스토리는 연결된 작업의 결과와 통합 검증을 기준으로 완료 처리합니다.
- 커밋 Push나 MR 병합만으로 Jira 상태를 자동 변경하지 않습니다.

## 연동 설정 관리

Maintainer는 `Settings → Integrations → Jira issues`에서 연동을 관리합니다.

- 연동 계정에는 대상 이슈 조회와 링크·댓글 작성 권한을 부여합니다.
- API 토큰은 GitLab 연동 설정에서 관리하며 문서·코드·커밋에 기록하지 않습니다.
- 설정을 변경하면 커밋·MR 이벤트, 다중 이슈 키, 중복 이벤트 처리를 검증합니다.
- 연동 오류가 발생하면 이벤트 설정과 계정 권한을 점검하고, 누락된 이력을 해당 이슈에 기록합니다.
