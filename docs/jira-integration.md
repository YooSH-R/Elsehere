# Jira와 GitLab 연동

Jira는 작업 범위와 진행 상태를 관리하고, GitLab은 해당 작업의 코드 변경과 리뷰 이력을 관리합니다. 이슈 키를 기준으로 작업과 구현 이력을 연결합니다.

## 연동 구성

GitLab for Jira Cloud 앱으로 Jira 이슈의 개발 탭에 브랜치·커밋·MR·파이프라인을 연결합니다. 같은 내용을 웹링크나 댓글로 다시 생성하는 기존 Jira issues 연동은 사용하지 않습니다.

| 항목 | 설정 |
| --- | --- |
| Jira 주소 | `https://ssafy.atlassian.net` |
| 연동 방식 | GitLab for Jira Cloud 앱 |
| 이력 기록 | Jira 개발 탭의 브랜치·커밋·MR·파이프라인 |
| 중복 링크 | 커밋·MR 웹링크를 수동 추가하지 않음 |
| 작업 상태 | 완료 조건 확인 후 담당자가 관리 |

## 이슈 키 작성

이슈 키로 해당 Jira 이슈의 개발 정보와 연결합니다. 작업 이슈 키의 위치·명명 예시와 로컬 커밋 자동 입력은 [개발 및 협업 규칙](development.md#브랜치)을 따릅니다.

개발 탭에 이미 표시되는 커밋·MR은 이슈 설명이나 웹링크에 중복 등록하지 않고, Jira에는 범위·결정·검증 결과와 남은 작업을 기록합니다.

## 작업 상태 관리

- 담당자는 작업을 시작할 때 Jira 상태를 진행 중으로 변경합니다.
- 구현, 반영 및 이슈별 검증이 끝나면 완료 조건을 점검하고 완료로 변경합니다.
- 상위 스토리는 연결된 작업의 결과와 통합 검증을 기준으로 완료 처리합니다.
- 커밋 Push나 MR 병합만으로 Jira 상태를 자동 변경하지 않습니다.

## 연동 설정 관리

GitLab의 `Settings → Integrations → GitLab for Jira Cloud app`에서 개발 정보 연동 상태를 확인합니다. 그룹 연결과 Jira 앱 설정은 해당 권한이 있는 담당자가 관리합니다.

- 기존 Jira issues 연동을 함께 활성화하면 커밋·MR 웹링크가 다시 생성될 수 있으므로 중복 활성화를 피합니다.
- 인증값은 앱·GitLab 설정에서 관리하며 문서·코드·커밋에 기록하지 않습니다.
- 설정을 변경하면 실제 이슈의 개발 탭에서 브랜치·커밋·MR과 상태가 연결되는지 확인합니다.
- 개발 정보가 누락되면 이슈 키와 그룹 연결·동기화 상태를 점검합니다. 같은 링크를 반복 생성하는 방식으로 보완하지 않습니다.
