# NPC 음성 파일 저장 운영

NPC가 생성한 턴 전체 WAV 파일은 백엔드가 저장하고, DB의 `turns.npc_audio_key`에는 파일 키를 기록합니다. 클라이언트는 기존 인증된 음성 API로 조회합니다. 파일 폴더를 Nginx 정적 경로로 공개하지 않습니다. 사용자 원본 녹음의 보관은 이 설정의 범위가 아닙니다.

이 문서는 음성 저장 설정이 포함된 앱 이미지와 Compose를 적용하는 환경의 운영 기준입니다. 저장소의 구성 준비, 실제 서버의 볼륨 연결, 음성 API 동작 검증은 구분해서 확인합니다.

## 저장 위치와 환경 분리

| 항목 | 기준 |
| --- | --- |
| 저장 장치 | 앱 서버의 EBS 디스크를 사용하는 Docker named volume |
| 백엔드 설정 | `NPC_AUDIO_DIR=/app/data/npc-audio` |
| 컨테이너 경로 | `/app/data/npc-audio` |
| Compose 논리 볼륨 | `npc-audio-data` |
| 개발 프로젝트·볼륨 | `a305-dev` · `a305-dev_npc-audio-data` |
| 운영 프로젝트·볼륨 | `a305-prod` · `a305-prod_npc-audio-data` |
| 파일 이름 | 백엔드가 생성한 UUID와 `.wav` 확장자 |

[앱 Compose](../infra/compose/compose.app.yaml)는 백엔드 경로에 환경별 named volume을 연결합니다. 프로젝트 이름으로 볼륨을 분리하므로 개발·운영에서 전역 볼륨 이름을 공유하지 않습니다. 운영 앱이 배포되기 전에는 운영 볼륨·음성 API가 실제로 준비됐다고 판단하지 않습니다.

[백엔드 이미지](../infra/docker/backend.Dockerfile)는 저장 폴더를 만들고 실행 계정 `app`이 쓸 수 있도록 소유권을 설정합니다. 새 named volume은 이미지의 해당 경로를 바탕으로 초기화합니다. 이미 사용 중인 볼륨의 권한은 기존 데이터를 보존하면서 실제 실행 UID·GID와 함께 확인합니다.

애플리케이션의 저장·조회는 [NpcAudioStore](../backend/src/main/java/com/elsehere/conversation/service/NpcAudioStore.java)가 담당합니다. 저장 위치를 바꾸면 Compose 마운트와 `NPC_AUDIO_DIR`, 배포 검증·운영 문서를 함께 갱신합니다.

## 배포·복구와 데이터 보존

- 이미지 교체와 컨테이너 재생성에서도 같은 프로젝트 이름·논리 볼륨·마운트 경로를 유지합니다.
- 배포와 롤백에서 기존 `npc-audio-data` 볼륨을 제거하거나 새 빈 볼륨으로 대체하지 않습니다.
- 개발 자동 배포 수신기는 저장 경로·쓰기 가능한 마운트·개발 전용 볼륨 이름을 검사하고, 실행 중인 백엔드의 실제 볼륨과 다르면 앱 교체 전에 거절합니다. 저장 위치를 이전할 때는 DB의 파일 키와 WAV를 함께 옮기는 별도 절차를 먼저 준비합니다.
- 볼륨을 삭제하는 `down --volumes`·`docker volume rm`·일괄 정리는 실제 개발·운영 프로젝트에 사용하지 않습니다. 폐기용 검사 프로젝트는 실제 프로젝트와 이름을 분리합니다.
- DB의 파일 키와 해당 WAV를 함께 보존합니다. 서버 이전·저장소 변경·데이터 복원 시 두 항목이 일치하는지 확인합니다.
- 저장 위치와 별개로 백업 주기·보관 기간·복원 기준은 담당자와 합의해 관리합니다. 컨테이너 재생성 후 보존 확인은 백업 성공을 뜻하지 않습니다.

## 적용 상태 확인

서버 관리 계정으로 개발 백엔드의 연결을 확인합니다. 실제 비밀값이 포함되는 전체 환경 파일이나 전체 Compose 해석 결과는 출력하지 않습니다.

```bash
sudo docker volume inspect a305-dev_npc-audio-data --format '{{.Mountpoint}}'
sudo docker inspect --format '{{range .Mounts}}{{println .Type .Name .Destination .RW}}{{end}}' a305-dev-backend-1
sudo docker exec a305-dev-backend-1 sh -ec 'id; test "$NPC_AUDIO_DIR" = /app/data/npc-audio; test -w "$NPC_AUDIO_DIR"'
```

볼륨이 존재하고 백엔드의 해당 경로에 읽기·쓰기로 연결되어 있어야 합니다. 운영은 실제 앱 배포 후 `a305-prod` 이름으로 확인합니다. 디스크는 OS·DB·로그·CI와 함께 사용하므로 호스트의 여유 공간과 음성 볼륨 사용량을 함께 확인합니다.

보존 검증은 외부 AI를 호출하거나 사용자 대화를 만들지 않고 작은 합성 WAV로 수행합니다. 다음 결과를 구분해서 남깁니다.

1. 후보 이미지의 일반 실행 계정이 파일을 저장·조회할 수 있는지 확인합니다.
2. 작성 컨테이너를 제거하고 같은 볼륨을 연결한 새 컨테이너에서 내용·해시를 확인합니다.
3. 개발·운영용 폐기 볼륨에 같은 파일명을 사용해 서로 다른 내용이 유지되는지 확인합니다.
4. 실제 서버 적용 후 마운트·권한·health를 확인하고, 실제 음성 API와 재배포 이후의 보존 결과를 별도로 확인합니다.

검사 파일에는 임의의 UUID를 사용하며 검사 후 해당 검사 자료만 정리합니다. 실제 사용자 파일의 내용이나 경로 목록을 로그·MR·Jira에 첨부하지 않습니다.

## 보관·삭제 정책

보관 기간·자동 삭제 기준·용량 상한은 아직 미정입니다. 영구 저장 연결에서 자동 삭제나 임의의 차단 상한을 추가하지 않습니다. 정책을 정할 때 대화·계정 삭제, 저장 용량 부족, 음성 재생성, 백업·복원과 [음성 API 계약](api/mvp-api.md)을 함께 맞춥니다.
