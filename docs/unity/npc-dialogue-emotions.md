# NPC 대화 감정 표정

## 대사에서 표정까지

NPC의 성격·기분·대화 이력을 받는 기존 `/v1/npc/reply` 요청에서 대사와 표정 종류·강도를 함께 생성한다. 감정을 분석하기 위한 별도 LLM 요청은 만들지 않는다. 내부 표시는 `[[curious:0.6]]` 형식이며 워커가 제거한 순수 대사만 자막·TTS·대화 기록으로 보낸다. 단어 일치 규칙으로 감정을 선택하지 않는다.

감정 종류는 평온, 인자한 미소, 의문, 당황, 찡그림, 놀람, 장난기, 웃음, 걱정/공감, 슬픔, 폭소, 무신경, 분노, 격한 분노, 쑥스러움, 누그러짐이다. `EmotionExpressionProfile`의 16종 조합으로 기존 얼굴 블렌드셰이프를 제어한다. 강한 슬픔·폭소는 맥락이 뒷받침할 때만 선택하도록 지시한다. 실제 모델의 선택 품질은 모의 응답을 이용한 연결 검사와 별도로 확인해야 한다.

## 무례·칭찬·사과의 구분

Spring이 기존 무례 판정과 대화의 누적 횟수, 의도 판정의 사건을 이용해 선택적 `reaction`을 같은 대사 생성 요청에 넣는다. 추가 판정 요청은 없다. 횟수는 사용자의 문장이나 LLM 추측에서 읽지 않는다. 현재 발화의 무례 판정이 칭찬·사과보다 우선한다.

| 확정된 상황 | 전달 값 | 얼굴 반응 |
| --- | --- | --- |
| 첫 번째 무례 | `rude_warning` | `frown`: 눈썹을 내리고 입꼬리를 낮춘 경고 |
| 두 번째 무례 | `rude_repeated` | `angry`: 눈썹·입꼬리 최대 찡그림과 더 강하게 좁힌 눈매 |
| 세 번째 이상 무례 | `rude_final` | `furious`: 눈을 크게 뜬 강한 분노. 기존 세 번째 무례의 대화 종료 규칙 유지 |
| 무례 이후 사과 사건 | `apology_after_rude` | `relieved`: 눈썹의 긴장은 일부 남기고 입꼬리가 약간 풀리는 반응 |
| 칭찬 사건 | `compliment` | 기존 `laugh`의 확실한 웃음 또는 `shy`; 크게 즐거워하는 맥락에는 기존 `big_laugh` |
| 일반 인사·그 외 | 생략 | 기존 맥락별 감정과 인자한 미소 유지 |

무례 단계와 사과 반응은 워커가 표정 표시를 정규화하여 실시간 음성·저장 구절·전체 다시 듣기에 동일하게 적용한다. 칭찬에 일상 미소를 반환하거나 표시를 누락하면 기존 `laugh`를 사용한다. 칭찬의 쑥스러움·웃음 선택은 기존 대사 모델이 NPC 성격과 맥락을 보고 고른다. 단순히 칭찬 단어가 등장한 모든 문장을 칭찬으로 취급하지 않는다.

무례 뒤에 평범한 말을 하면 계속 분노를 강제하지 않는다. 사과로 누적 무례 횟수를 초기화하거나 기존 호감도 규칙을 바꾸지 않는다. 같은 최종 반응으로 정규화되는 감정 표시는 TTS 구절을 추가로 나누지 않는다. 대사 길이와 기존 문장 분할 기준은 유지한다.

대사 길이·학습 수준 규칙을 유지하면서 내부 감정 표시를 위한 최대 64 출력 토큰을 추가한다. 상한은 초급 154, 일반 184, 고급 234토큰이다. 추가 요청은 없지만 입력 지시문과 실제 출력한 감정 정보만큼 토큰 사용량이 늘어난다.

## 음성 구간과 저장

감정이 바뀌는 위치에서 TTS 구절을 나누고 실제 PCM 길이로 구간을 만든다. 모델에 초 단위 시간을 추측하게 하지 않는다. 음성 속도는 기존 NPC TTS 설정을 따른다.

WAV의 기존 `a305` 발음 시간표와 별개로 `e305` RIFF 청크에 표정 시간표를 저장한다. PCM 자체는 바꾸지 않는다.

```json
{
  "version": 1,
  "duration": 2.4,
  "pcmSha256": "해당 PCM의 SHA-256",
  "cues": [
    {"start": 0, "end": 2.4, "emotion": "curious", "intensity": 0.6}
  ]
}
```

`emotion`은 `calm`, `warm_smile`, `curious`, `confused`, `frown`, `surprised`, `playful`, `laugh`, `concerned`, `sad`, `big_laugh`, `indifferent`, `angry`, `furious`, `shy`, `relieved` 중 하나다. 강도는 0~1, 구간은 시간순이며 서로 겹치지 않는다. 턴 전체 WAV를 만들 때 각 조각의 실제 길이만큼 시간을 옮겨 합친다. Spring은 기존 음성 저장·반환 경로에서 WAV 바이트를 그대로 보존한다.

저장된 음성의 다시 듣기는 같은 표정 시간표를 재생한다. 워커는 음성 성공 여부와 별개로 `done.speech_phrases`에 구절별 `text`·`emotion`·`intensity`를 반환하고, Spring은 NPC 턴의 `speech_phrases`에 보존한다. 시간 초과 뒤 `/v1/tts`로 음성을 다시 만들 때도 저장된 구절을 `phrases`로 보내 같은 감정을 유지한다. 초 단위 시간과 PCM 해시는 재합성한 실제 음성에 맞춰 새로 계산하며, 감정을 정하기 위한 LLM 재호출은 없다.

이 정보가 없던 이전 대화나 미리 만든 고정 대사는 기본 표정으로 재생한다. 누락된 과거 감정을 임의로 추정하지 않는다. 보관 정책으로 삭제된 음성의 재생 정책은 바꾸지 않는다.

## Unity 재생과 오류 처리

`DialogueSpeechWav`가 PCM 해시·길이·감정 종류·강도·구간을 검사하고, `DialogueServerLink`가 스트리밍 조각과 다시 듣기에 시간표를 전달한다. `CharacterSpeechPlayer`는 오디오 재생 위치로 입 모양과 표정을 함께 계산한다.

실제 대화 재생에서는 검증한 감정 시간표의 종류·시점을 유지하고 강도를 1로 변환한다. 서버가 보낸 0.4~0.6을 다시 곱해 표정이 흐려지지 않도록 각 감정의 완성된 프리셋을 사용한다. 모든 블렌드셰이프를 100으로 설정하는 것은 아니며, 인자한 미소 등 프리셋 안의 부위별 비율과 발음 보호는 유지한다. 저장 음성의 원본 메타데이터와 직접 조절하는 검수 재생의 강도는 변경하지 않는다.

칭찬의 웃음은 기존 `Laugh`·`BigLaugh`의 입과 볼 변형을 사용한다. `eyeSquintOpening`은 웃는 눈의 곡면 보정을 유지하면서 눈꺼풀 닫힘만 줄인다. 웃음은 0.45, 폭소는 0.4를 사용해 눈동자가 보이게 하며, 실제 깜빡임과 직접 눈 감기는 계속 완전히 닫힌다. 기존 인자한 미소는 이 보정을 사용하지 않는다.

Ben의 파생 표정 메시에서는 `cheekRaise`로 아래 눈꺼풀과 애교살 중앙을 함께 올리고 양끝으로 갈수록 변형을 줄인다. 얼굴 피부·눈 접합부·눈꺼풀에는 같은 변형장을 적용하여 공유 경계가 벌어지지 않게 한다. 중립 메시·골격·발음·깜빡임 채널은 유지하며, 웃는 눈과 애교살 채널만 제작 자료와 Unity 에셋에 함께 반영한다. 이 형상은 공통 제작 스크립트로 만들지만 다른 NPC의 기존 메시에는 재제작과 외관 검수 전까지 자동 반영되지 않는다.

장난기 표정의 한쪽 눈 감기는 고정 자세가 아니라 짧은 윙크로 재생한다. 얼굴 전환 뒤 0.1초 동안 감고 0.06초 유지한 뒤 0.18초 동안 다시 뜬다. 동일한 감정이 이어지는 구절·음성 조각에서는 한 번만 실행하며, 윙크 도중 대사가 끝나도 눈은 다시 뜨고 미소는 유지한다. 새 대답·중단·상대 변경에서는 윙크의 이어 재생 상태도 초기화한다. 직접 프리셋을 표시하는 정지 검수는 완전히 감은 윙크 자세를 확인할 수 있다.

현재 대사의 첫 음성 합성이 실패하면 `NpcSpeechRecovery`가 대화 요청이 끝난 뒤 한 번 재합성을 요청하고, 음성이 준비되면 다시 듣기 버튼을 누르지 않아도 재생한다. 이미 음성 조각을 들은 대사와 보관 기한이 지난 음성은 자동 복구에서 제외한다. 대사당 자동 시도는 한 번이며, 새 대사·녹음·대화 종료로 취소한 뒤 늦게 도착한 음성은 재생하지 않는다. 자동 복구도 실패하면 기존 수동 다시 듣기를 유지한다. 이 처리는 합성 자체의 지연을 줄이지 않으므로 서버의 GPU 연결과 합성 시간을 별도로 확인한다. Windows 개발 PC의 GPU 연결은 [GPU 음성 합성](../../ai/gpu_tts/README.md#windows-개발-pc의-nvidia-gpu)을 따른다.

같은 대답의 다음 조각은 직전 표정에서 0.24초 동안 연결하고 깜빡임의 재생 시각을 이어 간다. 실제 대화와 다시 듣기는 음성이 끝나면 발음 입 모양을 닫고 마지막 감정을 유지한다. 답변을 고르는 동안에도 같은 재생기가 깜빡임을 합성하므로 별도 대기 깜빡임이 감정 눈매를 덮어쓰지 않는다. 새 대답·다시 듣기·취소·녹음 시작·대화 종료·상대 변경에는 연결 상태를 초기화한다. `CharacterSpeechPlayer.Play`의 `holdEmotionAfterSpeech` 기본값은 `false`이므로 대화 밖의 독립 검수 재생은 기존 종료 동작을 유지한다.

발음에 필요한 입 모양을 우선하고, 감정은 눈썹·눈·볼·입꼬리에 혼합한다. 깜빡임은 별도로 합성한다. 대화 중단·NPC 변경 시 재생과 표정을 초기화한다. 감정 정보가 없는 기존 음성은 NPC에 지정된 기본 기분(기본값 인자한 미소)으로 재생한다. 감정 메타데이터가 잘못돼도 정상 음성과 발음 시간표는 유지하며 `EmotionNotice`에 원인을 남긴다.

찡그리는 눈썹과 약한 `eyeSquint`가 함께 있으면 Base 눈꺼풀이 안구 뒤 준비 구간에 머물지 않도록 닫힘 이동량을 보강한다. 직접 눈 감기·기존 인자한 미소의 닫힘 값과 발음 시간표는 유지하며, 웃음의 닫힘은 위의 `eyeSquintOpening`으로 별도 조절한다. 이 재생 보정은 눈썹 변형 자체를 추가하거나 원본 모델을 바꾸지 않는다.

카페 남자 파생 표정 메시에는 찡그림 눈썹·슬픔 입꼬리 변형을 보강하고, 이 변형의 노멀 변화는 줄여 피부가 접힌 듯한 음영을 완화한다. `ServiceNpcEmotions/author_emotions.py --smooth-eye-shading`은 눈 접합부의 드문 기존 노멀을 그대로 보간하는 대신 주변 피부 곡면으로 노멀을 계산한다. 적용 시 중립 정점·면·UV·가중치와 기존 발음·미소 정점 변형은 유지한다. 강한 측광의 표면 흔적과 표정 강도는 자동 검사와 별도로 정면·사선에서 검수한다.

감정 표정은 음성 억양을 바꾸는 기능이 아니다. TTS의 감정 연기, 사용자 발화를 듣고 새 감정을 추론하는 기능, 몸 전체 웃음 동작은 별도 기능이다. 음성 종료 뒤 유지하는 것은 마지막 대사의 감정이다.

## 검증 기준

- 감정 표시가 어느 스트리밍 글자 경계에서 잘려도 자막·TTS에 노출되지 않는다.
- 별도 감정 분석 LLM 요청 없이 구절별 감정과 순수 대사를 얻는다.
- 스트리밍·지연 합성·턴 전체 다시 듣기의 감정과 시간 오프셋이 일치한다.
- 다른 음성의 해시, 알 수 없는 감정, 잘못된 시간·강도는 표정 적용을 거부하며 음성은 유지한다.
- 실제 NPC에서 표정 변화와 입 모양 유지, 다시 듣기, NPC 변경과 취소 초기화를 검사한다.
- 두 번째 무례는 모델이 미소를 제안해도 분노로 재생하고, 세 번째의 종료·호감도·중복 요청 규칙은 유지한다.
- Ben의 실제 프리팹에 지정된 공통 프로필로 새 감정을 읽고 발음 입 모양을 유지하는지 검사한다. 공통 프로필은 `CafeEmotionBuilder.AddMissingReviewPresets`로 누락된 프리셋만 추가하여 기존 조절값을 보존한다.
- 보통 강도 찡그림의 눈꺼풀 노출, 음성 종료 후 발음 입 모양 닫힘·감정 유지, 대기 깜빡임과의 제어 충돌을 검사한다.
- 유료 API를 쓰지 않는 검증은 연결·타이밍 검증이다. 실제 대화의 감정 선택 적절성은 별도로 검수한다.
