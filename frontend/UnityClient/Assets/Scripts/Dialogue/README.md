# Dialogue 모듈

대화 화면은 아래쪽 대화창과 왼쪽 단어·문장 카드를 따로 표시합니다. 대화창은 NPC 이름과 이번 대화의 대사를 말한 사람(NPC 이름·나)과 함께 처음부터 표시합니다. 가장 최근 대사가 보이게 맨 아래로 내려 두며, 지난 대사는 위로 스크롤해 다시 봅니다. 긴 대사는 줄을 바꾸고, 넓은 화면에서는 대사 줄 수에 맞춰 대화창을 좁은 화면 높이까지 위로 키우며, 그보다 긴 대사·뜻은 스크롤합니다. [넣기]는 추천 문장을 입력창에 옮기며 전송하거나 모델을 호출하지 않습니다. 서버 대화에서 [뜻]을 펼치면 뜻을 받은 NPC 대사 안의 단어 풀이(CONV-04 `glossary`)에 밑줄이 생기고, 밑줄 단어를 누르면 대사 안의 그 단어가 반투명 주황으로 칠해지고, 사물 호버 카드처럼 그 단어 바로 위(자리가 없으면 아래)에 단어·뜻과 [단어장에 저장]·닫기(X)가 있는 카드가 뜹니다. 카드는 대화창 안에서만 움직여 그 위쪽의 NPC 얼굴을 가리지 않고, 대사 위에 겹쳐 떠서 대사 칸 크기는 그대로이며, 대사 칸을 스크롤하면 단어를 따라갑니다. 저장은 그 대사의 턴 출처(VOCAB-02 `NPC_LINE`)로 하며 단어장에 NPC 이름과 함께 남습니다. `to go` 같은 숙어도 같은 방법으로 저장합니다(서버 어휘 종류 `IDIOM`). 지난 대사도 뜻을 받았으면 밑줄 단어를 이어서 누를 수 있고, X를 누르거나 뜻을 접거나 문장을 보내면 카드를 닫습니다. 듣기·뜻·힌트 같은 보조 버튼은 입력창 위 한 줄에 바로 놓고, 대화 종류에 따라 숨는 버튼은 자리를 비우지 않고 당겨 붙입니다. 보내기·말하기·대화 종료도 바로 사용할 수 있습니다. NPC 얼굴은 대화창보다 위쪽에 오도록 화면 비율을 반영해 카메라 구도를 맞춥니다.

**Tools → A305 → UI → Apply Approved Dialogue Design**은 기존 대화 기능과 입력 연결을 유지하며 승인된 하단 배치·글꼴·여백을 프리팹에 적용합니다. 카페의 카운터와 소품 높이, 직원 방향, 마을 드럭스토어 출입구와 퀘스트 지도도 Unity Builder로 갱신합니다. 외부 AI 호출은 하지 않습니다.

NPC와의 대화를 시작하고 끝냅니다. 대화가 시작되면 NPC를 바라보는 1인칭 시점으로 바꾸고 이동을 잠그며, 끝나면 직전 시점과 이동을 되돌립니다. 대화는 한 번에 하나만 진행합니다.

튜토리얼 길 안내처럼 정해진 흐름이 있는 NPC는 확인용 대본(`MockDialogueScripts`)으로, 그 밖의 NPC는 서버 AI와 자유 대화로 진행합니다. 대화 화면 프리팹의 `DialogueServerLink`에서 서버를 끄면 모든 대화를 확인용 대본으로 진행하며, 이때 자유 대화는 키워드로 답하는 대본이 흉내 냅니다. 지금 화면은 흐름 확인용 초안입니다.

## 구성

| 파일 | 역할 |
| --- | --- |
| `DialogueSession` | 대화 중인 NPC 키(ERD `npcs.code`)를 기억하고 대화가 겹쳐 시작되지 않게 막습니다. Unity 객체 없이 테스트합니다. |
| `DialogueConversation` | 대화 한 번의 진행. 사용자가 보낸 문장 뒤에 대본에 따라 NPC 대사를 붙이고, 정해진 흐름의 읽을 대사·완료 여부를 알려 줍니다. Unity 객체 없이 테스트합니다. |
| `DialogueScript`, `GuidedTurn`, `KeywordReply`, `DialogueLine` | 대본과 대사. 정해진 턴이 있으면 정해진 흐름, 없으면 키워드 응답 규칙과 기본 응답으로 답합니다. 서버 대화의 NPC 대사는 [뜻 보기]로 받은 뜻과 풀이 단어(`Glossary`)를 함께 가집니다. |
| `GlossaryWord` | NPC 대사의 단어 풀이 하나(풀이를 받은 턴 ID·대사에 있는 단어나 숙어·뜻). Unity 객체 없이 테스트합니다. |
| `GlossaryWordCard`, `WordCardPlacement` | 누른 단어의 호버 카드 상태와 자리. `GlossaryWordCard`는 저장 안내(저장하는 중, 저장 결과, 실패 이유)와 [단어장에 저장]을 보일지·누를 수 있을지 정합니다. 같은 단어를 다시 누르면 닫고, 이번 대화에서 저장한 단어는 다시 눌러도 저장했다고 보입니다. 단어장 서버가 없으면 저장 버튼을 숨깁니다. `WordCardPlacement`는 카드를 단어 가운데 바로 위에 두고, 위에 자리가 없으면 아래에, 둘 다 안 되면 카드 위쪽을 대화창 안에 맞춥니다. Unity 객체 없이 테스트합니다. |
| `TextLinkClicks` | 대사 칸 글자의 `<link>`를 누르면 링크 ID를 알립니다. 링크가 아닌 곳은 무시합니다. |
| `DialogueRecord` | 끝난 대화의 기록. 피드백·미션·튜토리얼이 대화 결과를 판단할 때 씁니다. |
| `DialogueScriptSource`, `MockDialogueScriptSource` | NPC 키로 대본을 찾는 곳과 서버 연동 전 확인용 대본입니다. |
| `ServerConversation`, `IConversationApi`, `ConversationApi` | 서버 AI 자유 대화 한 번. 대화 시작(CONV-01)·발화(CONV-03)·녹음 전사(CONV-02)·뜻 보기(CONV-04)·힌트(CONV-05)·종료(CONV-08)를 부릅니다. 가짜 API로 Unity 객체 없이 테스트합니다. |
| `ConversationStanding` | 서버 대화의 NPC 호감도와 무례 경고 칸(3아웃) 값. CONV-01·03 응답의 `conversation`(`affinity`, `rudeCount`, `rudeLimit`)으로 바뀌며, 무례로 센 턴에는 호감도 변화량(예: -6)과 "무례한 말 1/3 · 3번이면 대화가 끝나요" 문구를 한 번 냅니다. 이 칸을 보내지 않는 서버면 `IsKnown`이 false입니다. Unity 객체 없이 테스트합니다. |
| `ConversationStandingDisplay` | 대화창 NPC 이름 옆 한 줄 "♥ 12   ○○○". 새 상태를 받은 뒤 4초 동안 변화량(깎이면 빨강, 오르면 초록)과 무례 경고 문구를 붙였다가 지웁니다. 글자는 서비스 글꼴(NanumSquareRound)에 있는 ♥·●·○를 씁니다. Unity 객체 없이 테스트합니다. |
| `ConversationAllowance`, `IAiStatusApi`, `AiStatusApi` | 새 NPC 대화를 시작할 수 있는지와 게스트의 남은 대화 수(AI-01). 공간에 들어올 때와 대화가 끝날 때 다시 받고, 받지 못하면 직전 상태를 둡니다. 받기 전이나 서버를 끈 때는 막지 않습니다(최종 확인은 CONV-01). 가짜 API로 Unity 객체 없이 테스트합니다. |
| `VoiceInputNotice` | 말하기 안내 문구. 녹음 중, [종료]를 누르기 전에 녹음이 끝난 이유(최대 시간·말 멈춤·창 이동), 마이크를 쓸 수 없는 이유(권한 거부·장치 없음·미지원)를 나눠 알립니다. 음성 처리에 동의하지 않아 [말하기]가 회색인 대화에서는 다른 상태 안내가 없을 때 도구 줄 위 상태 줄에 "[말하기]를 눌러 음성 처리에 동의해 주세요"를 보입니다. |
| `TalkButtonRules` | [말하기]를 보일지, 쓸 수 있는 모양으로 그릴지, 누르면 녹음 시작·끝·동의 묻기 중 무엇을 할지 정합니다. 정해진 대본 대화는 아직 음성을 받지 않아 숨기고(S15P31A305-422 뒤에 붙임), 서버 대화에서 동의하지 않았으면 회색으로 두되 누르면 동의 창을 엽니다. Unity 객체 없이 테스트합니다. |
| `VoiceConsentDialogView`, `VoiceConsentAgreement`, `IVoiceConsentApi`, `VoiceConsentApi` | 회색 [말하기]를 누르면 뜨는 음성 처리 동의 창. 음성을 어디에 쓰는지 알리고 [문서 보기](`VoiceConsent.DocumentUrl`)·[닫기]·[동의하고 켜기]를 둡니다. [동의하고 켜기]는 USER-03(`PUT /api/v1/me/consents`, `VOICE` 켜기)을 부르고, 저장되면 게임 전체의 `VoiceConsent`를 켜고 지금 대화의 [말하기]도 바로 씁니다(`ServerConversation.AllowTalk`). 저장하지 못하면 창 안에 이유를 보이고 다시 누를 수 있습니다. 창 요소는 **Tools → A305 → Dialogue → Apply Voice Consent Dialog**로 대화창 프리팹에 더합니다. 저장 처리는 가짜 API로 Unity 객체 없이 테스트합니다. |
| `NpcSpeechSlot` | [다시 듣기]로 재생할 NPC 음성. 지금 대사의 음성만 가지며, 새 대사의 음성 합성이 실패하면 지난 대사의 음성을 버려 [다시 듣기]가 음성을 다시 만들게(CONV-07) 합니다. Unity 객체 없이 테스트합니다. |
| `FeedbackRegenerator` | 만들지 못한 짧은 피드백을 다시 만들고(FB-02), 새로 만들면 상세 평가(FB-03)도 받습니다. 피드백 화면의 [다시 만들기]가 씁니다. |
| `DialogueController` | 대화 시작·종료 때 카메라 시점, 이동 잠금, 대화 화면을 바꾸고 대화 진행을 화면과 연결합니다. 대화 중 Esc를 누르면 [대화 종료]와 같이 끝냅니다. |
| `DialoguePanelLayout` | 대사 길이에 맞춘 대화창 높이와 대사 칸·상태 줄 위치. 대사와 뜻이 길면 창을 위로 키우고(넓은 화면 최대 560), 그보다 길면 대사 칸 안에서 스크롤합니다. 상태 줄은 도구 줄 바로 위에서 창 안쪽 폭 전체를 써 도구 버튼과 겹치지 않고, 대사 칸은 그 위에서 끝나 마지막 줄이 버튼에 걸리지 않습니다. 창 크기가 바뀌어도 대사 칸 스크롤은 아래 기준 위치를 지켜 가장 최근 대사와 단어 풀이가 가려지지 않습니다. Unity 객체 없이 테스트합니다. |
| `DialogueWait`, `LoadingSpinner` | 대화창이 크게 보여 줄 기다림. NPC 첫 대사(`Opening`)와 대답(`NpcReply`)을 기다리는 동안은 대사 칸을 덮는 로딩(도는 고리 + "Jake의 대답을 기다리고 있어요")을, 대화를 끝내고 피드백(`Feedback`)을 기다리는 동안은 화면 전체를 어둡게 덮는 가운데 로딩 창을 보이고 상태 줄은 숨깁니다. 뜻·힌트·음성 다시 만들기·음성 인식처럼 짧은 기다림은 지금처럼 상태 줄에만 알립니다. 로딩 고리는 게임 시간이 멈춰도 실제 시간으로 돕니다. 대화창 전체 Builder를 다시 돌리지 않고 로딩만 더할 때는 **Tools → A305 → Dialogue → Apply Waiting Views**를 씁니다. |
| `DialogueLinesText` | 대화창 대사 칸의 글자. 이번 대화의 대사를 말한 사람과 함께 순서대로 보이고, [뜻 보기]를 펼치면 가장 최근 NPC 대사 바로 아래에만 뜻과 단어 풀이를 붙입니다. 뜻을 펼친 동안 풀이를 받은 NPC 대사의 풀이 단어는 `<link="대사 번호/풀이 번호"><u>단어</u></link>`로 감싸고(대소문자 무시, `good` 속 `go`처럼 다른 단어의 일부는 제외), `FindWord`로 누른 링크의 풀이 단어를 찾습니다. 단어 카드에 보이는 단어는 `<mark=#F982564D>`로 칠해 카드가 어느 단어의 것인지 보이게 합니다. 대사에서 찾지 못한 풀이는 아래 단어 풀이 줄에만 보입니다. Unity 객체 없이 테스트합니다. |
| `DialoguePanelView` | 대화 중 화면. 이번 대화의 대사, 이번에 읽을 대사, 추천 단어·추천 문장, 텍스트 입력과 [보내기]·[예시 문장]·[뜻 보기]·[대화 종료 (Esc)], 누른 풀이 단어 근처의 호버 카드(`WordCard`: 단어·뜻·저장 안내와 [단어장에 저장]·닫기), 서버 대화의 [말하기]·[다시 듣기]·[힌트]·[다시 시도], NPC 이름 옆 호감도·무례 경고 칸(`Standing`, 이름 색을 따르고 서버가 보내지 않으면 숨김)이 있습니다. 음성 처리에 동의하지 않았으면 [말하기]를 흐리게(투명도 0.45) 그리고 누르면 동의 창을 엽니다. |

## 서버 대화의 오류와 안내

상태 문구 아래에 사용자가 다음에 할 일을 함께 보여 줍니다(기능 명세 F-41). 서버가 준 오류 문구는 그대로 보여 줍니다.

| 상황 | 안내 |
| --- | --- |
| 연결 실패·시간 초과, 서버·AI 장애(5xx), 요청 속도 제한 | 대화 시작이나 발화가 실패했으면 [다시 시도]를 보여 줍니다. 발화는 같은 문장을 같은 요청 ID로 다시 보냅니다. |
| AI 사용량 소진(`AI_QUOTA_EXHAUSTED`) | 다시 시도하지 않고 [대화 종료]로 탐험에 돌아가라고 안내합니다. 게스트가 대화 횟수를 다 썼으면 서버가 "게스트는 NPC와 3번까지 대화할 수 있어요…"를 보냅니다. 보통은 그 전에 [말 걸기]가 막혀 이 화면까지 오지 않습니다. |
| 대화 중 사용량 소진(`endReason: QUOTA_EXHAUSTED`) | 오류가 아닌 정상 종료지만, NPC가 왜 대화를 마쳤는지와 계속 쓸 수 있는 기능을 알립니다. |
| 무례 누적으로 종료(`endReason: RUDE`) | "무례한 말이 쌓여 (NPC)이(가) 대화를 마쳤어요."와 함께 [대화 종료]로 피드백을 볼 수 있다고 알립니다. |
| 무음·인식 실패(`STT_NO_SPEECH`) | 다시 말하거나 텍스트로 입력하라고 안내합니다. |
| 음성 처리 미동의(BOOT-01 `voiceConsent: false`, 전사의 `VOICE_CONSENT_REQUIRED`) | 녹음하지 않고 [말하기]를 회색으로 둡니다. 상태 줄에 [말하기]를 눌러 동의하라고 안내하고, 누르면 동의 창이 뜹니다. 동의하면 안내를 지우고 바로 녹음할 수 있습니다. |
| NPC 음성 삭제·만료(`EXPIRED`), 음성 정보 없음, 음성 조회의 `404` | [다시 듣기]를 숨기고 자막을 유지합니다. 삭제된 음성은 다시 합성하지 않습니다. |
| 최초 NPC 음성 생성 실패(`FAILED`) | [다시 듣기]에서 음성 생성만 재시도합니다. |
| 저장 음성의 일시적인 다운로드 실패 | [다시 듣기]를 유지하고 같은 음성을 다시 받습니다. 음성 재생성 API를 부르지 않습니다. |
| 녹음 중·녹음 뒤 | [말하기]를 한 번 누르면 녹음을 시작하고 버튼이 [종료]로 바뀝니다. 다시 누르면 녹음을 끝내고 전사합니다. 녹음 중에는 도구 줄 위 상태 줄에 "듣고 있어요"와 최대 녹음 시간을 안내하고, 목소리가 들리는 동안 버튼의 불이 초록색으로 켜집니다(조용하면 흐린 흰색). 최대 시간·말 멈춤으로 저절로 끝나도 버튼은 [말하기]로 돌아옵니다. 전사 뒤에는 들은 문장이 맞으면 [보내기]를 누르라고 안내하고, 입력칸에 보낼 문장이 있으면 [보내기]를 강조합니다. 말하지 않고 [종료]를 눌러 녹음에 말소리가 거의 없으면(`RecordedVoice.HasSpeech`) STT에 보내지 않고 말한 뒤 [종료]를 누르라고 알립니다. 이런 녹음을 보내면 엉뚱한 문장이 입력칸에 들어오기 때문입니다. 대화를 끝내면 녹음도 멈추고 전사하지 않습니다. |

## 다른 기능에서 쓰는 API

| API | 설명 |
| --- | --- |
| `DialogueController.TryStart(string npcCode, Transform lookTarget, ConversationInitiator initiatedBy = Npc)` | 대화를 시작합니다. 이미 대화 중이면 false를 돌려줍니다. 플레이어가 [말 걸기]로 먼저 건 대화는 `ConversationInitiator.User`로 넘기고, 서버 대화 시작(CONV-01)에 `initiatedBy: USER`로 보냅니다. NPC가 제안한 대화는 기본값(`NPC`)입니다. |
| `DialogueController.End()` | 대화를 끝내고 시점과 이동을 되돌립니다. [대화 종료] 버튼과 Esc도 이 동작을 합니다. |
| `DialogueController.RegenerateFeedbackAsync(ServerFeedback)` | 만들지 못한 피드백을 다시 만듭니다. 서버 대화가 아니거나 대화 ID가 없으면 받은 피드백을 그대로 돌려줍니다. |
| `DialogueController.IsTalking` | 대화 중인지 |
| `DialogueController.Allowance` | 새 NPC 대화를 시작할 수 있는지(`CanStartConversation`)와 게스트의 남은 대화 수(`RemainingConversations`). 행인 말걸기와 [말 걸기]가 씁니다. |
| `DialogueController.FindNpcName(string npcCode)` | 대화 대본에 적힌 NPC 이름. 대본이 없으면 null입니다. 행인 제안 화면의 머리말에 씁니다. |
| `DialogueController.Started` | 대화가 시작되면 NPC 키를 알립니다. |
| `DialogueController.Ended` | 대화가 끝나면 끝난 NPC 키를 알립니다. |
| `DialogueController.NpcResponded` | 서버가 NPC 턴을 확정하면 알립니다. 첫날 연계 미션 UI가 서버 진행을 다시 읽을 때 사용합니다. |
| `DialogueController.ConversationEnded` | 대화가 끝나면 `DialogueRecord`를 알립니다. 시점과 이동을 되돌린 뒤 가장 마지막에 알리므로, 받는 쪽이 화면을 열며 이동을 잠가도 풀리지 않습니다. |
| `DialogueController.WordSaveRequested` | 대화창 단어 카드에서 [단어장에 저장]을 누르면 그 `GlossaryWord`(턴 ID·단어)를 알립니다. 단어장 저장은 받는 쪽(Learning 모듈)이 합니다. |
| `DialogueController.ShowWordSaveResult(GlossaryWord, bool saved, string message)` | 저장 결과를 단어 카드에 보입니다. `saved`면(이미 있던 단어 포함) 저장 버튼을 숨기고, 아니면 이유와 함께 다시 누를 수 있게 둡니다. 결과를 기다리는 사이 다른 단어를 골랐으면 지금 카드는 바꾸지 않습니다. |
| `DialogueController.SetWordSaveAvailable(bool)` | [단어장에 저장]을 보여 줄지. 단어장 서버가 없으면 끄고 뜻만 보입니다. |

## NPC 얼굴과 음성 재생

대화 시작 시 `LookTarget`의 부모 `DialogueSpeaker`가 선택된 NPC의 얼굴·재생기를 준비합니다. `NpcIdentity`가 화자 컴포넌트를 자동으로 제공하므로 NPC별 Builder 연결을 반복하지 않습니다. 얼굴 채널이 부족하면 `LipSyncNotice`에 이유를 남기고 기존 음성 재생을 유지합니다. 지원되는 모델은 같은 WAV의 음소 시간표와 AudioSource 샘플 위치를 사용하며, 화자 변경·종료·늦은 음성 응답 취소는 기존 수명 처리를 따릅니다. 표정 메시 생성이나 LLM 감정 추론 기능은 아닙니다.

새 대사에 음성이 없으면 `ForgetSpeech`가 이전 음성과 발음 시간표를 함께 버리고 얼굴을 중립으로 되돌립니다. 화자 연결은 유지하므로 다음 정상 음성은 같은 NPC에서 재생됩니다. 대화 종료는 화자 연결도 해제합니다. 내려받는 중 대사가 바뀌거나 종료되면 이전 응답을 재생하지 않습니다.

음성 보관 정책은 [NPC 음성 저장 운영](../../../../../docs/npc-audio-storage.md)을 따릅니다. 대사가 바뀌거나 대화를 끝내면 이전 음성과 진행 중인 다운로드를 무효화합니다. EditMode 대화 테스트는 실제 대화 프리팹의 상태별 버튼 표시, 404 후 자막 유지, 최초 실패 재시도, 일시적인 다운로드 실패와 이전 턴의 늦은 응답을 검증합니다.

현재 음성의 404는 `ServerConversation`에 전달해 만료 상태로 바꾸고 다시 듣기를 숨긴다. 대화가 끝난 뒤 도착한 이전 음성의 404는 무시하므로 새 대화의 상태를 바꾸지 않는다.
