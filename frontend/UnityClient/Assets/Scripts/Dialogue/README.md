# Dialogue 모듈

대화 준비·진행 중에는 게임 시간을 멈추고, 대화창을 닫으면 대화에 의한 정지를 해제합니다. 피드백·단어장·튜토리얼의 정지는 각 화면과 진행 흐름이 별도로 유지합니다. 준비 중 Esc로 닫은 뒤 시작 응답이 늦게 도착하면 그 서버 대화를 피드백 없이 종료하고, 정리 전의 시간 정지 응답을 버리도록 시계를 재동기화합니다. 취소한 대화를 다시 표시하거나 추천 단어를 요청하지 않습니다. 취소 직후 다시 말을 걸면 이전 준비 요청의 서버 정리가 끝난 뒤 새 대화를 요청해 두 대화의 정리가 섞이지 않게 합니다.

한국어·한영 혼합 발화의 응답(CONV-03)에 `userTurn.translation.english`가 있으면 대화 옆의 작은 카드에 표시합니다. 제목은 “방금 한 말의 영어 표현이에요.”입니다. 원 발화를 유지하고 번역문을 다시 보내지 않으며, 다음 발화를 보내면 이전 표현을 비웁니다. 무례 판정과 관계없이 영어 번역이 있으면 표시하고, 번역이 없는 응답에서는 카드를 숨깁니다. 좁은 화면에서는 대사 위에 쌓고 긴 문장은 카드 안에서 스크롤합니다. [듣기]는 기기 영어 음성을 사용하며 추가 AI 요청을 만들지 않습니다. `DialogueTranslationBuilder`가 프리팹과 연결을 갱신합니다.

NPC 음성을 다시 합성하거나 내려받아 재생을 준비하는 동안에는 `DialogueWait.NpcSpeech`로 대사 칸을 로딩 상태로 유지합니다. 준비가 끝나면 자막 설정을 적용하므로 자막이 음성보다 먼저 노출되지 않습니다. 생성 실패·만료가 확정된 음성의 자막 대체와 다시 듣기 재시도는 유지합니다. 이전 대사의 늦은 음성 응답은 현재 대사의 표시를 바꾸지 않습니다.

첫 합성에 실패한 대사는 `NpcSpeechRecovery`가 서버 응답 처리가 끝난 뒤 한 번 자동으로 재합성하고, 준비된 음성을 바로 재생합니다. 자동 복구도 실패하면 반복 요청하지 않고 기존 다시 듣기를 유지합니다. 녹음 시작·대화 종료·화자 교체로 취소한 대사의 늦은 음성은 자동으로 재생하지 않습니다. 모든 문장 조각을 받은 턴과 만료된 음성은 자동 복구 대상에서 제외합니다. 일부 조각이 빠졌으면 뒤 조각을 먼저 읽지 않고 전체 음성으로 복구합니다. 이미 받은 조각의 PCM이 전체 음성의 시작과 일치하면 그 뒤부터 이어 읽습니다. 재합성 결과가 달라 일치하지 않으면 발화를 누락하지 않도록 전체를 다시 읽습니다.

대화 화면은 상자 없는 아래쪽 대화창과 오른쪽 위 추천 단어 카드를 따로 표시합니다. 추천 단어 카드는 대화창 이름 줄 위 남는 높이(최대 600)에 다 들어가도록 묶음째 줄이고(`DialogueHelpFit`, 0.7배까지), 그보다 길 때만 칸 안에서 스크롤해 아래가 잘려 보이지 않습니다. 대화창은 화면 아래 전체 폭에 어두운 그라데이션을 깔고, 가운데 열에 아래부터 입력 줄 → 상태 줄 → 대사 → 코랄 이름표와 도구 줄을 쌓습니다. 대화창은 NPC 이름과 이번 대화의 대사를 말한 사람(NPC 이름·나)과 함께 처음부터 표시합니다. 대사 칸에는 가장 최근 네 대사와 펼친 뜻만 보이는 높이를 주고 맨 아래로 내려 두며, 그 전 대사는 위로 스크롤해 다시 봅니다. 지난 대사가 있으면 대사 칸을 최근 네 대사에 딱 맞춰 지난 대사가 반쯤 비치지 않게 합니다. 지난 대사가 있으면 대사 칸 오른쪽 끝에 가는 흰 세로 스크롤바를 보이고, 스크롤할 대사가 없으면 숨깁니다. 대사는 마우스 휠, 손가락 끌기, 스크롤바 손잡이 끌기로 넘깁니다. 손잡이는 휴대폰에서도 잡기 쉽게 누르는 자리를 막대보다 넓게(36) 둡니다(`DialogueDockBuilder`). 긴 대사는 줄을 바꾸고, 최근 네 대사와 뜻이 최대 600 또는 현재 화면의 남은 높이보다 길면 대사 칸 안에서 스크롤합니다. 대사는 크고 흰 둥근 글자로, 뜻은 그 아래 한 단계 작고 옅은 글자로 씁니다. 말한 사람 이름은 대사와 구분되게 NPC는 밝은 코랄(이름표 계열), 나는 밝은 하늘색으로 칠합니다. 이름 길이와 상관없이 모든 문장과 그 아래 뜻은 더 긴 이름 뒤 같은 자리에서 시작하고, 긴 문장이 줄을 바꿔도 그 자리에 맞춥니다. 코랄 이름표는 끝이 둥글어 대사와 같은 자리에서 시작하면 안쪽으로 들어가 보이므로, 대사 글자 줄보다 8만큼 앞으로 냅니다. [힌트]로 받은 추천 문장은 입력창에 바로 들어가며, 사용자가 수정하거나 전송할 수 있습니다. 이미 받은 뒤 [힌트]를 다시 누르면 서버에 다시 묻지 않고 같은 문장을 입력창에 다시 넣습니다. 서버 대화에서 [뜻]을 펼치면 뜻을 받은 NPC 대사 안의 단어 풀이(CONV-04 `glossary`)에 밑줄이 생기고, 밑줄 단어를 누르면 대사 안의 그 단어가 반투명 주황으로 칠해지고, 사물 호버 카드처럼 그 단어 바로 위(자리가 없으면 아래)에 단어·뜻과 [단어장에 저장]·[닫기]가 있는 카드가 뜹니다. 카드는 오른쪽 위 도움 카드와 같은 밝은 유리 카드라 어두운 대화창 위에서 떠 보이고, 안쪽이 불투명해 뒤 대사가 비치지 않습니다. 카드는 대화창의 이름·호감도 줄 아래에서만 움직여 호감도·경고 표시와 NPC 얼굴을 가리지 않고, 대사 위에 겹쳐 떠서 대사 칸 크기는 그대로이며, 대사 칸을 스크롤하면 단어를 따라갑니다. 저장은 그 대사의 턴 출처(VOCAB-02 `NPC_LINE`)로 하며 단어장에 NPC 이름과 함께 남습니다. `to go` 같은 숙어도 같은 방법으로 저장합니다(서버 어휘 종류 `IDIOM`). 지난 대사도 뜻을 받았으면 밑줄 단어를 이어서 누를 수 있고, [닫기]를 누르거나 뜻을 접거나 문장을 보내면 카드를 닫습니다. 자막·다시 듣기·뜻·힌트 같은 보조 버튼과 [다시 시도]·[대화 종료]는 이름표 줄 오른쪽에 반투명한 흰 테두리 버튼으로 놓고, 대화 종류에 따라 숨는 버튼은 자리를 비우지 않고 오른쪽으로 당겨 붙입니다. 입력 줄은 반투명 입력칸, 둥근 [보내기], 코랄 [말하기]를 같은 높이로 둡니다. [말하기]는 한 번 눌러 녹음을 시작하고 다시 누르면([종료]) 끝냅니다. 서버 대화는 듣고 이해하는 연습을 위해 NPC 대사 자막을 끈 채 시작합니다. 자막을 끄면 NPC 대사 글자는 투명하게 자리만 차지하고 단어마다 둥근 회색 막대로 덮여, 띄어쓰기와 줄바꿈만 보입니다. NPC 대답을 기다리는 로딩이 대사 칸을 덮는 동안은 막대도 감춰 로딩 위로 비치지 않게 합니다. [자막 켜기]·[자막 끄기]는 누르면 실행할 동작을 보이며(켜진 상태면 강조색) 누를 때마다 바뀌고, 이 기기(Web 빌드는 브라우저)에 저장해 다음 대화에도 이어집니다. [뜻]을 펼친 동안과, 지금 NPC 대사의 음성을 재생할 수 없을 때(음성 생성 실패·만료)는 자막을 꺼 두었어도 대사를 보입니다. 음성이 없는 대본 대화에는 [자막]이 없고 대사를 그대로 보입니다. NPC 얼굴은 대화창보다 위쪽에 오도록 화면 비율을 반영해 카메라 구도를 맞춥니다.

**Tools → A305 → UI → Apply Approved Dialogue Design**은 기존 대화 기능과 입력 연결을 유지하며 승인된 하단 배치·글꼴·여백을 프리팹에 적용합니다. 카페의 카운터와 소품 높이, 직원 방향, 마을 드럭스토어 출입구와 퀘스트 지도도 Unity Builder로 갱신합니다. 외부 AI 호출은 하지 않습니다.

NPC와의 대화를 시작하고 끝냅니다. 대화가 시작되면 NPC 얼굴 앞에서 얼굴을 비추는 대화 시점으로 바꾸고 이동을 잠급니다. 끝나면 플레이어를 대화하던 NPC 쪽으로 돌리고, 직전 시점(카메라는 플레이어 뒤)과 이동을 되돌립니다. 대화는 한 번에 하나만 진행합니다.

튜토리얼 길 안내처럼 정해진 흐름이 있는 NPC는 확인용 대본(`MockDialogueScripts`)으로, 그 밖의 NPC는 서버 AI와 자유 대화로 진행합니다. 대화 화면 프리팹의 `DialogueServerLink`에서 서버를 끄면 모든 대화를 확인용 대본으로 진행하며, 이때 자유 대화는 키워드로 답하는 대본이 흉내 냅니다. 지금 화면은 흐름 확인용 초안입니다.

정해진 흐름의 대화도 [말하기]로 말할 수 있고, 빈 입력칸에는 이번에 말하거나 입력할 대사를 회색 안내로 미리 보입니다. 글자로 보낸 문장은 대사와 같아야 넘어가지만, 말로 한 대사는 무엇을 말했든 정해진 대사로 이어 갑니다. 음성 처리에 동의했으면 튜토리얼 용도(CONV-02 `purpose=TUTORIAL`, 대화 ID 없음)로 알아듣고, 대사와 다르거나 알아듣지 못했거나 동의하지 않아 알아듣지 않았으면 "튜토리얼은 정해진 흐름대로 진행돼요…"를 상태 줄에 보입니다. 서버를 끄면(`DialogueServerLink`) 녹음기가 연결되지 않아 말하기 버튼을 두지 않습니다.

## 구성

| 파일 | 역할 |
| --- | --- |
| `DialogueSession` | 대화 중인 NPC 키(ERD `npcs.code`)를 기억하고 대화가 겹쳐 시작되지 않게 막습니다. Unity 객체 없이 테스트합니다. |
| `DialogueConversation` | 대화 한 번의 진행. 사용자가 보낸 문장 뒤에 대본에 따라 NPC 대사를 붙이고, 정해진 흐름의 읽을 대사·완료 여부를 알려 줍니다. 정해진 흐름에서 읽을 대사와 다른 문장은 대화에 남기지 않고 다시 입력하라고 안내하고, 말로 한 대사(`SendSpoken`)는 무엇을 말했든 정해진 대사로 이어 갑니다. 정해진 흐름은 대사마다 쓸 만한 추천 단어(`SuggestWords`)를 보입니다. Unity 객체 없이 테스트합니다. |
| `GuidedLineMatcher` | 정해진 흐름에서 보낸 문장이 읽을 대사와 같은지 봅니다. 대소문자·띄어쓰기·문장부호(아포스트로피 포함)는 보지 않고, 글자 8개마다 한 글자 정도의 오타는 같은 대사로 봅니다. Unity 객체 없이 테스트합니다. |
| `DialogueScript`, `GuidedTurn`, `KeywordReply`, `DialogueLine` | 대본과 대사. 정해진 턴(할 대사·뜻·추천 단어·NPC 대답)이 있으면 정해진 흐름, 없으면 키워드 응답 규칙과 기본 응답으로 답합니다. 서버 대화의 NPC 대사는 [뜻 보기]로 받은 뜻과 풀이 단어(`Glossary`)를 함께 가집니다. |
| `GlossaryWord` | NPC 대사의 단어 풀이 하나(풀이를 받은 턴 ID·대사에 있는 단어나 숙어·뜻). Unity 객체 없이 테스트합니다. |
| `GlossaryWordCard`, `WordCardPlacement` | 누른 단어의 호버 카드 상태와 자리. `GlossaryWordCard`는 누른 자리를 덮는 풀이(누른 단어, 그 단어가 든 숙어)를 짧은 말부터 보이고, 풀이마다 저장 안내(저장하는 중, 저장 결과, 실패 이유)와 [단어장에 저장]을 보일지·누를 수 있을지 정합니다. 같은 자리를 다시 누르면 닫고, 이번 대화에서 저장한 단어는 다시 눌러도 저장했다고 보입니다. 저장을 기다리는 단어는 카드를 닫았다 열어도 다시 보내지 않습니다. 단어장 서버가 없으면 저장 버튼을 숨깁니다. `WordCardPlacement`는 카드를 단어 가운데 바로 위에 두고, 위에 자리가 없으면 아래에, 둘 다 안 되면 카드 위쪽을 대화창 안에 맞춥니다. 풀이가 여럿이라 높인 카드는 `FitHeight`로 단어 위나 아래 중 넓은 쪽 자리에 맞춰 줄여 누른 단어를 가리지 않게 합니다(풀이 한 줄 높이보다는 줄이지 않음). Unity 객체 없이 테스트합니다. |
| `TextLinkClicks` | 대사 칸 글자의 `<link>`를 누르면 링크 ID를 알립니다. 링크가 아닌 곳은 무시합니다. |
| `DialogueRecord` | 끝난 대화의 기록. 피드백·미션·튜토리얼이 대화 결과를 판단할 때 씁니다. |
| `DialogueScriptSource`, `MockDialogueScriptSource` | NPC 키로 대본을 찾는 곳과 서버 연동 전 확인용 대본입니다. |
| `ServerConversation`, `IConversationApi`, `ConversationApi` | 서버 AI 자유 대화 한 번. 대화 시작(CONV-01)·발화(CONV-03)·녹음 전사(CONV-02)·뜻 보기(CONV-04)·힌트(CONV-05)·종료(CONV-08)를 부릅니다. 끝내지 못한 대화가 남아 있으면 같은 NPC와의 대화는 이어서 하고(CONV-11의 턴으로 지난 대사를 다시 보임), 다른 NPC와의 대화는 피드백 없이 끝내고 새로 시작합니다. 종료 응답의 `followUp`은 `FollowUpStore`에 남기고, 시작 응답의 `deliveredFollowUpId`는 지웁니다. 발화는 스트리밍(CONV-03 `Accept: text/event-stream`)으로 받아, 대사 글자가 오기 시작하면 로딩을 걷고 보낸 문장과 온 만큼의 NPC 대사를 보이며 문장 조각 음성(`NpcSpeechChunk`)을 넘깁니다. 저장된 턴을 받으면 그 줄들을 저장된 턴으로 다시 그리고, 실패하면 지웁니다. 스트림이 저장된 턴 없이 끊기면 `ConversationApi`(`TurnEventReader`)가 같은 요청 ID로 JSON 요청을 한 번 더 보내 서버가 끝까지 저장한 턴을 받습니다. 가짜 API로 Unity 객체 없이 테스트합니다. |

## 서버 대화의 오류와 안내

상태 문구 아래에 사용자가 다음에 할 일을 함께 보여 줍니다(기능 명세 F-41). 서버가 준 오류 문구는 그대로 보여 줍니다.

| 상황 | 안내 |
| --- | --- |
| 연결 실패·시간 초과, 서버·AI 장애(5xx), 요청 속도 제한 | 대화 시작이나 발화가 실패했으면 [다시 시도]를 보여 줍니다. 발화는 같은 문장을 같은 요청 ID로 다시 보냅니다. |
| AI 사용량 소진(`AI_QUOTA_EXHAUSTED`) | 게스트가 대화 횟수를 다 쓰면 서버가 "게스트는 NPC와 3번까지 대화할 수 있어요…"를 보냅니다. 보통은 그 전에 대화 시작이 막혀 이 화면까지 오지 않습니다. 진행 중인 대화의 종료 피드백은 사용할 수 있습니다. |
| 대화 중 사용량 소진(`endReason: QUOTA_EXHAUSTED`) | 오류가 아닌 정상 종료지만, NPC가 왜 대화를 마쳤는지와 계속 쓸 수 있는 기능을 알립니다. |
| 무례 누적으로 종료(`endReason: RUDE`) | "무례한 말이 쌓여 (NPC)이(가) 대화를 마쳤어요."와 함께 [대화 종료]로 피드백을 볼 수 있다고 알립니다. |
| 용건이 끝나 NPC가 마무리(`endReason: NPC_ENDED`) | 미션 목표를 마쳤거나 작별·용건 끝냄을 말한 턴에 서버가 대화를 끝냅니다. "(NPC)이(가) 대화를 마쳤어요."와 함께 [대화 종료]로 피드백을 볼 수 있다고 알립니다. |
| 무음·인식 실패(`STT_NO_SPEECH`) | 다시 말하거나 텍스트로 입력하라고 안내합니다. |
| 음성 처리 미동의(BOOT-01 `voiceConsent: false`, 전사의 `VOICE_CONSENT_REQUIRED`) | 녹음하지 않고 [말하기]를 회색으로 둡니다. 상태 줄에 [말하기]를 눌러 동의하라고 안내하고, 누르면 동의 창이 뜹니다. 동의하면 안내를 지우고 바로 녹음할 수 있습니다. |
| NPC 음성 삭제·만료(`EXPIRED`), 음성 정보 없음, 음성 조회의 `404` | [다시 듣기]를 숨기고 자막을 유지합니다. 삭제된 음성은 다시 합성하지 않습니다. |
| 최초 NPC 음성 생성 실패(`FAILED`) | [다시 듣기]에서 음성 생성만 재시도합니다. |
| 저장 음성의 일시적인 다운로드 실패 | [다시 듣기]를 유지하고 같은 음성을 다시 받습니다. 음성 재생성 API를 부르지 않습니다. |
| 녹음 중·녹음 뒤 | [말하기]를 한 번 누르면 녹음을 시작하고 버튼이 [종료]로 바뀝니다. 대화를 시작할 때 마이크를 미리 열어 두므로 누르는 즉시 녹음됩니다. 마이크가 아직 열리는 중이면(처음 권한을 받는 대화 등) 버튼이 [준비 중]을 보이고 불을 끈 뒤, 소리를 받기 시작하면 [종료]로 바뀝니다. [준비 중]을 눌러도 녹음을 그만둡니다. 다시 누르면 녹음을 끝내고 전사합니다. 녹음 중에는 도구 줄 위 상태 줄에 "듣고 있어요"와 최대 녹음 시간을 안내하고, 목소리가 들리는 동안 버튼의 불이 초록색으로 켜집니다(조용하면 흐린 흰색). 최대 시간·말 멈춤으로 저절로 끝나도 버튼은 [말하기]로 돌아옵니다. 전사 뒤에는 들은 문장이 맞으면 [보내기]를 누르라고 안내하고, 입력칸에 보낼 문장이 있으면 [보내기]를 강조합니다. 말하지 않고 [종료]를 눌러 녹음에 말소리가 거의 없으면(`RecordedVoice.HasSpeech`) STT에 보내지 않고 말한 뒤 [종료]를 누르라고 알립니다. 이런 녹음을 보내면 엉뚱한 문장이 입력칸에 들어오기 때문입니다. 대화를 끝내면 녹음도 멈추고 전사하지 않으며 미리 연 마이크를 닫습니다. |

| `DialogueController.RegenerateFeedbackAsync(ServerFeedback)` | 만들지 못한 피드백을 다시 만듭니다. 서버 대화가 아니거나 대화 ID가 없으면 받은 피드백을 그대로 돌려줍니다. |

| `DialogueController.FindNpcName(string npcCode)` | 대화 대본에 적힌 NPC 이름. 대본이 없으면 null입니다. 행인 제안 화면의 머리말에 씁니다. |
| `DialogueController.Started` | 대화가 시작되면 NPC 키를 알립니다. |

| `DialogueController.NpcResponded` | 서버가 NPC 턴을 확정하면 알립니다. 첫날 연계 미션 UI가 서버 진행을 다시 읽을 때 사용합니다. |
| `DialogueController.ConversationEnded` | 대화가 끝나면 `DialogueRecord`를 알립니다. 시점과 이동을 되돌린 뒤 가장 마지막에 알리므로, 받는 쪽이 화면을 열며 이동을 잠가도 풀리지 않습니다. |
| `DialogueController.WordSaveRequested` | 대화창 단어 카드에서 [단어장에 저장]을 누르면 그 `GlossaryWord`(턴 ID·단어)를 알립니다. 단어장 저장은 받는 쪽(Learning 모듈)이 합니다. |
| `DialogueController.ShowWordSaveResult(GlossaryWord, bool saved, string message)` | 저장 결과를 단어 카드에 보입니다. `saved`면(이미 있던 단어 포함) 저장 버튼을 숨기고, 아니면 이유와 함께 다시 누를 수 있게 둡니다. 결과를 기다리는 사이 다른 단어를 골랐으면 지금 카드는 바꾸지 않습니다. |
| `DialogueController.SetWordSaveAvailable(bool)` | [단어장에 저장]을 보여 줄지. 단어장 서버가 없으면 끄고 뜻만 보입니다. |
| `FollowUpStore.Shared` | NPC가 준비해 건네기로 한 것의 목록. `Items`(먼저 되는 것부터), `Changed`(늘거나 줄거나 바뀜), `FindReady(npcCode)`(그 NPC가 건넬 것 가운데 다 된 것), `TakeNewlyReady()`(다 됐는데 아직 알리지 않은 것). [Mission 모듈](../Mission/README.md#기다리는-카드)의 기다리는 카드와 [Npc 모듈](../Npc/README.md#동작-규칙)의 부르기가 씁니다. |

`DIALOGUE_PREVIEW_OUTPUT`에 출력 폴더를 지정해 `A305.EditorTools.Dialogue.DialogueLayoutPreview.CaptureWords`를 batchmode로 실행하면 카페 씬의 실제 대화창으로 풀이 단어 호버 카드(기본, 저장 뒤, 숙어, 숙어 안의 단어를 눌러 단어와 숙어를 쌓은 카드와 아래로 스크롤한 카드, 세로 화면)를 고정 대사로 찍습니다. `Capture`는 같은 방식으로 대화 구도와 도움 카드를 찍습니다. 서버·모델을 호출하지 않고 씬도 저장하지 않습니다.

공간 씬의 대화 처리와 화면은 [World 모듈의 공간 기능 연결](../World/README.md#새-공간-씬-만들기)이 붙이므로 씬마다 직접 배치하지 않습니다. 화면 프리팹과 확인용 대본은 **Tools → A305 → Dialogue → Build**(`Scripts/Editor/Dialogue/DialogueBuilder.cs`)로 준비합니다. 화면은 없는 요소만 만들고, 이미 있는 요소의 디자인은 유지합니다.

## NPC 얼굴과 음성 재생

공통 감정을 적용한 12종 NPC 외형은 실제 대화 WAV의 구절별 감정 시간표로 새 음성 대사를 재생합니다. AI 워커가 기존 대사 요청에서 감정을 함께 생성하며 연결 방식은 [NPC 대화 감정 표정](../../../../../docs/unity/npc-dialogue-emotions.md)을 따릅니다. 시간표가 없으면 `ConfigureMood` 또는 Inspector의 기본 기분·강도를 사용합니다(기본값 인자한 미소). 지원 외형과 검수 씬은 [말하기 중 NPC 감정 표정 검수](../../../../../docs/unity/npc-speaking-emotions.md)를 참고합니다.

대화 시작 시 `LookTarget`의 부모 `DialogueSpeaker`가 선택된 NPC의 얼굴·재생기를 준비합니다. `NpcIdentity`가 화자 컴포넌트를 자동으로 제공하므로 NPC별 Builder 연결을 반복하지 않습니다. 얼굴 채널이 부족하면 `LipSyncNotice`에 이유를 남기고 기존 음성 재생을 유지합니다. 지원되는 모델은 같은 WAV의 음소 시간표와 AudioSource 샘플 위치를 사용하며, 화자 변경·종료·늦은 음성 응답 취소는 기존 수명 처리를 따릅니다. 얼굴 메시 제작은 별도이며 감정 선택은 AI 워커가 담당합니다.

스트리밍으로 받은 문장 조각 음성은 `DialogueServerLink.QueueSpeechChunk`가 받은 순서대로 이어 재생합니다(앞 조각이 끝나면 다음 조각, 같은 립싱크 경로). 새 대답의 조각이 오면 지난 대사의 음성과 지난 대답의 남은 조각을 버리고, 녹음 시작처럼 음성을 멈추면 남은 조각도 버립니다. 조각으로 들려준 턴은 저장된 턴을 받은 뒤 턴 전체 음성을 다시 자동 재생하지 않으며, [다시 듣기]는 턴 전체 음성(CONV-06)을 받아 재생합니다.

새 대사에 음성이 없으면 `ForgetSpeech`가 이전 음성과 발음 시간표를 함께 버리고 얼굴을 중립으로 되돌립니다. 화자 연결은 유지하므로 다음 정상 음성은 같은 NPC에서 재생됩니다. 대화 종료는 화자 연결도 해제합니다. 내려받는 중 대사가 바뀌거나 종료되면 이전 응답을 재생하지 않습니다.

음성 보관 정책은 [NPC 음성 저장 운영](../../../../../docs/npc-audio-storage.md)을 따릅니다. 대사가 바뀌거나 대화를 끝내면 이전 음성과 진행 중인 다운로드를 무효화합니다. EditMode 대화 테스트는 실제 대화 프리팹의 상태별 버튼 표시, 404 후 자막 유지, 최초 실패 재시도, 일시적인 다운로드 실패와 이전 턴의 늦은 응답을 검증합니다.

현재 음성의 404는 `ServerConversation`에 전달해 만료 상태로 바꾸고 다시 듣기를 숨긴다. 대화가 끝난 뒤 도착한 이전 음성의 404는 무시하므로 새 대화의 상태를 바꾸지 않는다.

추천 문장을 기다리는 동안 직접 수정한 입력은 보존합니다. 힌트를 누른 시점의 초안과 같을 때만 받은 힌트로 교체하며, 튜토리얼은 명시적으로 요청한 힌트만 채웁니다. 전송하면 해당 입력 요청을 해제해 이전 문장이 다음 입력을 대신하지 않게 합니다. 이미 받은 힌트를 다시 누르기와 서버 전송 실패 문장 복원은 유지합니다.

착석으로 받는 카페·식당 주문은 미션 타이머가 `SetSeatedWaitRemaining`으로 남은 시간을 맞추며, 5초 완료 시 `CompleteSeatedWaitAsync`가 해당 NPC의 주문만 숨기고 CONV-14로 저장합니다. 완료 ID는 세션 동안 기억해 늦게 도착한 목록·종료 응답으로 카드가 되살아나지 않게 하고, 서버 저장 실패는 다음 `RefreshAsync`에서 재시도합니다. 다른 NPC의 대기와 새 주문 ID에는 적용하지 않습니다.

복습 중 오른쪽 참고 카드는 대화창 위의 여유 높이(최대 440) 안에 고정합니다. 긴 상황 설명과 목표 표현은 카드 안의 스크롤·스크롤바로 읽으며, 글자를 축소하거나 입력창까지 카드를 늘리지 않습니다. 복습이 끝나면 일반 추천 단어 카드의 배치와 글자 크기로 복원합니다.
