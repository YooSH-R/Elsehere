# Tripo Asset Workbench

Unity에서 API로 생성하거나 Studio·로컬 파일에서 초안을 가져와,
기본 구조 검사, 필요한 Blender 수정, 사람의 외형 승인과 새 버전 프리팹 등록을 처리한다.
메뉴는 **Tools → A305 → Assets → Tripo Workbench**다.
Unity 6000.3 LTS와 Animation Rigging 1.4.1을 사용하며 Editor 전용 도구다.

생성된 정적 모델에 표정 데이터가 저절로 생기지는 않는다. 기준 캐릭터의 공통 골격,
가중치와 얼굴 Shape Keys는 Blender에서 제작·검수해야 한다. 도구는 이 데이터를
연결하고 미리보기·왕복 보존·검증을 돕는다. 원본 생성 완료와 대화용 캐릭터 완성은 구분한다.

## 화면과 작업 흐름

처음에는 **API 생성 / 웹·파일 가져오기** 중 작업 방식을 선택한다.
API 생성은 **이미지 → 생성 설정 → 비용 확인 후 생성** 순서로 입력한다.
작업 기록이 생기면 **생성·가져오기 → 모델·골격 → 검증·등록** 탭을 사용할 수 있다.
이전 기록은 상단 **기존 작업 불러오기**에서 선택한다.
표정·립싱크와 부품·소켓은 **고급 작업**을 켜면 사용할 수 있다.

면 수·높이는 **세부 설정**, 계정·보너스·Bridge 안내는 **도움말**에 모았다.
예상 크레딧·API 잔액 확인과 실제 사용량은 접힌 도움말 밖에 표시한다.
본 매핑·Blender 연결·검사 기준 편집은 각 단계의 설정을 펼쳐 사용한다.
검사 오류·수동 검수 항목은 계속 표시하며, 수정 후보 적용·제외 및 이전 버전 복원은 대상이 있을 때만 표시한다.
초기화 메뉴는 **Tools → A305 → Development → Tripo → Create Workbench Defaults**에 있다.
일반 작업에서는 기록을 만들 때 기본 검사 프로파일이 준비되므로 먼저 초기화 메뉴를 실행할 필요가 없다.
고급 화면을 숨겨도 기존 작업 기록의 얼굴 매핑·부품·검사 조건은 삭제하거나 무시하지 않는다.
몸 애니메이션 생성과 자동 리타기팅은 이 제작 흐름에 포함하지 않는다.
확보한 모션은 Unity의 별도 애니메이션 작업에서 적용하고, 그 결과를 모델의 동작 검수에 활용한다.

| 탭 | 주요 동작 | 결과와 확인할 사항 |
| --- | --- | --- |
| 생성·가져오기 | API 이미지 생성 또는 웹·파일 가져오기 선택 | API 생성은 API 크레딧 사용, 파일 가져오기·검사는 API 키 불필요 |
| 모델·골격 | 공통 기준 모델, 연결 방식, 기준 높이·전체 크기 설정 / Scene 조작 핸들 열기 | 유효한 Humanoid에 팔·다리 IK와 머리 회전 핸들 생성 |
| Blender 수정 | 실행 파일 선택 / 최초 원본 준비·열기 / 저장된 수정본 가져오기 | 기존 `.blend`를 보존하고 새 FBX 후보 생성 |
| 표정·립싱크 | 이름 기반 키 매핑 / 6개 빠른 모습 / 감정·발음·눈 감기 / 105조합 / 기존 클립 / 음성 시간표 | 실제 모델의 Shape Keys를 구동하고 누락·중복 매핑 확인 |
| 부품·소켓 | 머리·옷·좌우 귀걸이·기타 슬롯 / 부품 가져오기 안내 / 모델 연결 | 강체 소켓 또는 공통 골격에 스킨 부품 장착 |
| 검증·등록 | 프로파일 조정 / 자동 검사 / 시각 검수 / 후보 적용·이전 모델 복원 / 프리팹 등록 | 현재 모델·설정에 대한 검사 통과와 사람의 승인 후 새 파일 등록 |

이미 생성한 모델은 **생성·가져오기 → 웹·파일 가져오기 → 가져온 모델 → 작업 시작**으로 연다. 작업 기록은
`Assets/Data/Tripo/`에 저장되며, 다시 열어도 모델·매핑·슬롯·검수 상태를 유지한다.
검사 오류와 수동 확인 항목도 작업 기록에 저장된다. 모델·설정을 변경한 뒤 보이는 이전 결과는
참고용이며 다시 검사해야 승인할 수 있다. 신규 Character 기록은 Humanoid 필수 검사를 기본으로 켠다.
기존 기록의 설정은 유지하며, 얼굴 준비 여부는 별도로 확인한다.
기본 검증값은 `DefaultValidation.asset`에서 조정한다.

### 생성 진행 상태와 완료 결과

작업 상태와 오류는 창 상단에 고정 표시된다. 업로드는 완료 이미지 수, 원격 생성·리깅은
서버가 마지막으로 응답한 단계별 진행률을 표시한다. 전체 완료율이나 남은 시간은 추정하지 않는다.
중지 후의 진행률은 마지막 조회값이며 원격 작업이 중지됐다는 뜻은 아니다.

생성 없이 연결·업로드 오류만 확인하려면 **이미지 업로드만 테스트 · 생성 안 함**을 사용한다.

1. API 생성 화면에서 테스트할 이미지 1장 또는 4장을 선택하고 API 키를 입력한다.
2. API 키 아래의 **이미지 업로드만 테스트 · 생성 안 함**을 누른다.
3. 상단의 완료 이미지 수를 확인한다. 실패하면 **오류 내용 복사**로 상세 응답을 확인한다.
4. 성공하면 해당 이미지 업로드에서 종료한다. 생성·리깅·변환 요청과 기존 작업 재개는 실행하지 않는다.

테스트는 업로드 함수만 전달받는 독립 실행이며 생성 파이프라인과 작업 JSON에 연결하지 않는다.
테스트용 파일 토큰은 생성 작업에 자동으로 재사용하지 않는다. 이후 생성은 별도 유료 작업이다.
테스트 중 **업로드 테스트 중지**로 취소할 수 있다. 이미 서버에 전달한 이미지를 삭제하는 기능은 아니다.
실제 서버 원인은 업로드 테스트에서 반환되는 상세 메시지로 판단하며 오류 코드만으로 단정하지 않는다.

오류가 나면 단계와 상세 메시지를 확인하고 **오류 내용 복사**로 전달한다. 서버가 반환한
`message`, `suggestion`, `request_id`를 표시하며 현재 요청의 API 키는 가린다.
서버가 상세 정보를 보내지 않은 오류는 원인을 단정할 수 없다. 창을 닫기 전 오류를 복사해 둔다.
**저장된 작업 재개**는 저장한 단계부터 이어가며 이미 받은 작업 ID를 다시 제출하지 않는다.
아직 제출하지 않은 생성·리깅 단계에 도달하면 해당 유료 요청이 실행된다.
재개를 업로드만 시험하는 기능으로 사용하지 않는다.

생성 완료 후 **검증·등록** 화면에서 모델을 드래그하여 회전하고 휠로 확대한다.
자동 검사 결과, 외형·동작 수동 항목을 확인하고 문제는 **Blender 수정**에서 처리한다.
생성 완료는 품질 승인이나 최종 등록을 의미하지 않는다.

저장 위치는 완료 결과에 절대 경로로 표시되며 파일·폴더를 열 수 있다.

- 다운로드 원본: `UserSettings/Tripo/Downloads/<작업 식별자>.fbx`
- Unity 모델: `Assets/Art/Characters/Tripo/<이름>_<식별자>/Source.fbx`
- 생성 프리팹: `Assets/Prefabs/Characters/Tripo/<이름>_<식별자>.prefab`
- 작업·검수 기록: `Assets/Data/Tripo/<모델 GUID>.asset`
- 최종 검수 프리팹: 등록할 때 선택한 프로젝트 내 경로

화면을 다시 열었을 때 결과가 선택되어 있지 않으면 **생성 결과 검수하기**로 기존 모델의
작업 기록을 다시 연다. 이 동작에는 API 호출이 없다.

### 저장 폴더 설정과 생성 후 검수 순서

API 생성 화면의 **저장 위치**에서 모델·프리팹 폴더를 각각 선택한다.
프로젝트 `Assets/` 아래의 폴더만 허용하며 각 작업의 고유 이름과 다운로드 원본 경로는 유지한다.
새 생성 확인창에서 실제 저장할 모델·프리팹 경로를 확인한다.
이미 저장된 미생성 작업은 **저장된 미생성 작업에도 이 경로 적용**을 눌러야 변경된다.
생성 시작 이후의 작업 경로와 기존 파일은 자동으로 이동하지 않는다.

1. 생성 완료 후 **검증·등록**에서 모델을 확인한다. 다시 열 때는 **생성 결과 검수하기**를 누른다.
2. **기준 자세**에서 정면·좌측·우측·후면과 얼굴 확대를 확인한다. 드래그 회전, 휠 확대를 지원한다.
3. 자동 검사 오류를 먼저 확인한다. Humanoid 매핑 오류가 있으면 **모델·골격 → FBX Inspector에서 본 매핑 설정**으로 해결한다.
4. **검수 동작 → 플레이어 걷기 / 플레이어 달리기**를 선택해 **반복 재생**한다.
   점프는 실제 Controller에서 사용하는 **상승 / 하강 / 착지** 클립을 각각 확인한다.
   실제 모션은 원래 클립 길이를 기준으로 1배속이며, 0.25배속까지 낮출 수 있다.
   **일시정지**와 **동작 구간** 슬라이더로 발이 뒤집히거나 손이 몸에 들어가는 구간을 확인한다.
5. **골격 연결 표시**를 켜 본 위치를 함께 보고 정면·양측면·후면에서 확인한다.
   걷기·달리기는 발 방향, 무릎, 소매·바지와 손/몸 관통을 본다. 착지는 손이 몸에 숨는지 확인한다.
   팔 올리기·팔꿈치 굽히기·무릎 굽히기는 추가 관절 검수용이며 한 주기 4초다.
6. **모델·골격**에서 검증 프로파일의 최소·기준·최대 전체 크기로 같은 검수를 반복한다.
7. 문제가 있으면 승인하지 않고 해당 동작과 구간을 기록한다. 자동 재생성이나 Blender 보정은 실행하지 않는다.
   직접 수정한 후보가 있을 때만 **Blender 수정**으로 별도 복사본을 왕복하고 같은 구간을 비교한다.
8. 자동 검사 통과와 수동 확인을 마친 뒤 새 검수 프리팹을 등록한다. 미확보 모션은 검수했다고 처리하지 않는다.

실제 플레이어 모션은 `Assets/Art/Player/LittleMung/Walk.anim`, `Run.anim`,
`Motions/Jump.fbx`의 Rise/Fall/Land를 재사용한다. 모델 자체 Humanoid Avatar에 리타기팅하며
리틀 멍의 Avatar·골격·가중치를 새 모델에 덮어쓰지 않는다. **재사용 모션** 필드에서 원본 클립을 확인할 수 있다.
Avatar가 유효해도 필수 본, 스킨 본의 연결 대상, 본/바인드 포즈 개수가 잘못되면 오류를 표시하고 동작 검수를 막는다.
이 연결 검사는 **현재 모델·설정 검증**에도 포함된다. 발끝 본은 선택 항목이며 누락 시 수동 확인을 안내한다.

자세는 미리보기 복사본에만 적용되고 **기준 자세로 복원**하거나 미리보기를 닫으면 복원된다.
카메라 구도와 회색 발밑 기준면은 기준 자세에 고정해 변형에 따라 화면이 들썩이지 않게 한다.
골격 선은 메시 위에 겹쳐 표시하므로 선 자체가 보이는 것은 관통 판정이 아니다.
원본 FBX·Avatar·본·가중치·기존 Controller는 변경하지 않는다. 로컬 검수에는 API 키나 크레딧이 필요 없다.

**연결 통과와 외형 승인은 별개다.** 기준면은 실제 물리 지면이 아니며, 점프 클립 검수는
게임의 점프 궤적이나 상태 전환까지 재현하지 않는다. 루트 이동, 발 IK, 리틀 멍 전용 접지·팔 보정,
천 시뮬레이션은 적용하지 않는다. 실제 게임에서의 이동·접지·전환 검증은 별도다.
생성/등록 프리팹을 Production의 플레이어 외형이나 캐릭터 목록에 자동 덮어쓰지 않는다.
자동 구조 검사는 모든 프레임의 옷·피부 관통이나 귀여운 인상 유지까지 보증하지 않는다.

### 로컬 FBX 검사와 Blender 왕복

외부 생성 서비스 없이 다운로드한 파일만으로 진행할 수 있다.

1. **웹·파일 가져오기**에서 카테고리를 고르고 **로컬 FBX 복사해서 가져오기 · 자동 검사**를 누른다.
   FBX와 같은 폴더의 이미지 및 같은 이름의 `.fbm` 폴더를 새 버전 폴더에 복사한다.
   다른 위치를 참조하는 텍스처는 먼저 함께 내려받거나 FBX에 포함시킨다.
   다운로드 원본은 수정하지 않는다. 이미 Project에 있는 모델은 **작업 시작**을 누른다.
2. **검증·등록** 탭에서 검사 대상 경로, 자동 오류와 수동 검수 항목을 확인한다.
   얼굴 Shape Key나 접합 샘플이 없으면 해당 검사가 준비되지 않았다고 표시한다.
   정지 구조 검사에는 애니메이션 전체 프레임의 틈·관통·변형 판정이 포함되지 않는다.
3. **문제 수정 · Blender 단계로 이동** 후 **연결 설정**에서 실행 파일을 선택한다. 경로가 없으면 설정이 자동으로 표시된다.
   **Blender에서 열기 · 최초 원본 준비**는 현재 적용 FBX로 편집 파일을 만들고 연다.
   기존 `.blend`가 있으면 덮어쓰지 않는다. 별도 파일은 **기존 .blend 연결**로 지정한다.
4. Blender에서 수정하고 저장한 뒤 **저장된 수정본 가져오기**를 누른다.
   저장 파일의 스냅샷을 새 FBX 후보로 내보내며 후보마다 재질·텍스처 폴더를 분리한다.
   가져온 후보는 자동 재검사하고 현재 모델과 본 계층·Shape Key·등록된 소켓을 비교한다.
   원본, 현재 적용 모델과 편집 파일은 내보내기 과정에서 변경하지 않는다.
5. 오류가 있거나 외형이 마음에 들지 않으면 **후보 제외 · 현재 모델 재검사**를 누른다.
   후보 파일은 삭제하지 않고 작업 대상에서 제외한다. 현재 적용 모델은 유지한다.
   **이전 모델 버전 복원**은 직전에 적용했던 버전으로 돌아가며 다시 검사한다.
6. 검사 통과 후 사람이 수동 항목을 확인해야 **검증한 수정본 적용**을 사용할 수 있다.
   적용 후에는 승인 상태가 초기화되므로 다시 검사·확인하고 새 프리팹으로 등록한다.

왕복 내보내기는 미터·센티미터 변환을 FBX 단위 정보에 기록한다. 단위 변환을
Armature의 100배 스케일로 남기지 않아 본 아래 소켓의 위치와 크기를 유지한다.
기존에 내보낸 후보 FBX는 자동 수정되지 않는다. 보존한 `.blend`에서
**저장된 수정본 가져오기**로 새 후보를 만들고 다시 검사한다. 기존 편집 파일 자체의
본 배율·기준 자세가 바뀌었다면 검사 오류를 확인하며 소켓 오프셋으로 덮어 보정하지 않는다.

왕복은 편집 메시·본·가중치·Shape Key를 대상으로 한다. Blender의 몸 애니메이션,
제약·드라이버와 메시 Modifier 결과는 FBX에 포함하지 않는다. 본 개수와 이름이 같아도
좌표축·기준 자세·소켓 방향은 달라질 수 있으며 경고와 소켓 편차를 별도로 검수해야 한다.
표정의 이름 보존은 표정의 외형 품질을 보장하지 않는다. 모델을 자동 수선하거나
얼굴 표정을 자동 제작하는 흐름은 아니다.

### Pro와 공식 DCC Bridge 준비

기본 경로는 **Studio Pro 웹 생성 → 자동 리깅 → DCC Bridge → 작업대**다.
Studio 월간 크레딧과 개발자 API 크레딧은 서로 다르다. 이 경로는 API 키나 별도 API 충전을 요구하지 않는다.
웹에서 생성·리깅할 때는 Studio가 표시하는 크레딧과 Pro 잔액을 확인한다.
계정에 제공되는 API 보너스가 있더라도 Studio 월간 잔액을 공유하는 것은 아니다.

저장소 루트에서 다음을 실행한 뒤 Unity의 패키지 가져오기가 끝날 때까지 기다린다.

```powershell
./infra/scripts/install-tripo-bridge.ps1
```

설치 스크립트는 공식 ZIP의 SHA-256과 패키지 ID·버전(1.0.14)을 확인한다.
`Packages/com.tripo3d.unitybridge/`에 로컬 embedded package로 설치하고 기존 설치를 덮어쓰지 않는다.
원본 ZIP·소스는 `Library/TripoTools/UnityBridge-1.0.14/`에 보존한다.
공식 배포물의 `StartupCleanup`이 오래된 `Assets/ImportedModels` 폴더를 삭제하므로,
설치 사본의 `[InitializeOnLoad]`만 제거해 자동 정리를 비활성화한다. 다른 원본 코드는 변경하지 않는다.
패키지 원본은 저장소에 재배포하지 않는다. 다른 PC에서도 위 스크립트로 설치한다.
다운로드 원본이 바뀌어 해시가 다르면 설치가 중단되며 새 배포물을 검토한 뒤 갱신한다.

### MVP 제작 전략: 완성형 개별 캐릭터 우선

초기 남/여/바리스타/호텔리어/행인 5종은 **머리·복장을 포함한 개별 캐릭터**를 우선 권장한다.
같은 얼굴 인상·대두 비율·포즈·높이를 입력에서 맞추되, 동일 골격이나 동일 얼굴 토폴로지가
생성된다고 가정하지 않는다. 한 캐릭터의 생성·검사·보정을 먼저 끝내고 나머지를 진행한다.
완성형도 옷 관통·얼굴 경계·가중치 문제를 피할 수 있는 것은 아니다.

다음 비교는 모든 결과를 새로 생성하고, 현재 도구의 표준 텍스처·삼각형·FBX 경로를
각각 한 번 성공한다고 가정한 **API 견적**이다. Studio Pro 크레딧과 합산하지 않는다.

| 구성 | 생성 결과 수 | H v3.1 | P2 Preview |
| --- | ---: | ---: | ---: |
| 완성형 5명, 각 자동 리깅 | 5 | 5 × 55 = 275 | 5 × 135 = 675 |
| 기준 몸 1개 자동 리깅 + 헤어 5개 + 복장 5개, 부품은 리깅 없이 FBX 변환 | 11 | 55 + 10 × 40 = 455 | 135 + 10 × 120 = 1,335 |

부품 경로는 Blender에서 공통 골격 가중치·피팅을 따로 준비하는 가정이다. 부품에도 Tripo 리깅을
요청하면 비용은 달라지며, 독립 리깅만으로 장착 호환성이 보장되지 않는다. 이미 확보한 몸이나
부품은 신규 비용에서 제외한다. 이미지 제작, 재시도, 추가 가공, 수작업 비용은 위 표에 없다.
완성형 5종이 모두 한 번씩 재생성·리깅된다면 H는 550, P2는 1,350이므로 재시도 예산을 남겨 둔다.

조합 수가 많아지거나 같은 얼굴의 표정·립싱크 데이터를 여러 외형에 재사용해야 하면
공통 몸체와 교체 부품이 유리해질 수 있다. 반대로 완성형 캐릭터는 얼굴 토폴로지가 서로 달라
각 캐릭터의 얼굴 변형 제작·검수가 반복될 수 있다. 부품 기능은 보존하고, 실제 재사용 수와
보정 시간을 확인한 뒤 기본 경로 전환을 결정한다.

### 고급 경로: 공통 얼굴·골격과 교체 부품 준비

교체 부품 경로를 선택할 때는 **LittleMungBase 한 몸체·공통 얼굴·공통 골격 + 교체 헤어·복장**을 사용한다.
이 경로에서는 각 조합마다 얼굴·몸체·얼굴 Shape Keys를 새로 생성하지 않는다.

| 카테고리 | 입력 이미지와 생성 초안 | Blender에서 맞출 내용 |
| --- | --- | --- |
| Character | 리틀 멍 얼굴·대두 비율, 중립 표정, 머리카락·장신구 없음, 몸에 붙는 단색 기본복, 전신 A/T 포즈 | 공통 골격·rest pose·가중치와 눈꺼풀·입 안·얼굴 Shape Keys |
| Hair | 머리카락 부품만, 기준 머리 크기·헤어라인을 따른 정면·측면·후면 | 머리에 맞는 안쪽 면·pivot, 강체 소켓 또는 공통 골격 스킨 연결 |
| Clothing | 몸·얼굴을 포함하지 않는 의상, 기준 몸체와 같은 비율·포즈 | 원하지 않는 내부 몸체 제거, 체형 맞춤, 공통 골격 가중치와 접합부 |
| Accessory | 장신구 단품 | 착용 방향·크기, 왼쪽/오른쪽 등 소켓 위치 |

기준 몸체를 나체로 생성할 필요는 없다. 장식·큰 주름 없는 밀착 기본복으로 형태를 드러내고,
머리카락 없는 두피 전체를 만들어 헤어 아래 빈 공간이 생기지 않게 한다.
헐렁한 직업복·모자·머리카락을 기준 몸체와 한 덩어리로 생성하지 않는다.
기본복과 교체 의상이 겹치는 부분은 Blender에서 정리한다. 도구가 의상 아래 몸체를 자동으로 숨기거나
별도 생성한 옷을 자동 재봉·피팅하는 기능은 아직 없다.

Tripo 초안에 머리·옷이 붙어 나오거나 부품 안에 몸이 생기면 Blender에서 분리·수정한다.
캐릭터 자동 리깅은 공통 기준 골격을 만드는 출발점이며, 옷마다 별도 골격을 자동 생성해 쓰지 않는다.
기준 얼굴의 29개 컨트롤과 15개 발음 상태를 한 번 준비해 조합 전체에 재사용한다.
중립·미소·눈 감기·입 벌리기·F/V·TH 6개 빠른 모습으로 인상을 먼저 확인하고,
머리·복장 교체 후 같은 표정·포즈·전체 크기에서 틈·관통·소켓 연결을 다시 검수한다.
### 리틀 멍 첫 모델 만들기

1. 이 분리된 Unity 프로젝트 하나만 실행하고 Play를 끈다. 작업대의 **공식 DCC Bridge 열기**를 누른다.
   `Tools → Tripo Bridge`와 같은 창이다. 서버가 실행 중이고 Render Pipeline이 URP인지 확인한다.
   전송이 끝날 때까지 Bridge 창을 열어 둔다.
2. Chrome 또는 Edge에서 [Tripo Studio](https://studio.tripo3d.ai/)를 열고 Pro를 결제한 계정으로 로그인한다.
   작업대의 **Tripo Studio 열기** 버튼도 같은 페이지를 연다.
3. 웹 상단 **3D 작업 공간**에서 **Smart Mesh / 깔끔한 토폴로지**의 이미지 입력을 연다.
   Multi-view를 선택하고 정면·좌측·우측·후면을 각 슬롯 안내에 맞춰 넣는다.
   같은 캐릭터·포즈·비율·조명을 유지하고 손발이 잘리지 않은 중립 표정, 팔과 몸이 떨어진 A/T 포즈를 쓴다.
   편집 화면과 모델 종류에 따라 다중 이미지 지원·슬롯 이름이 다르므로 제공되는 슬롯을 확인한다.
4. 모델 이름은 **LittleMung_Barista_01**처럼 외형·역할을 구분한다. 공통 몸체를 만드는 경우에만 **LittleMungBase**를 사용한다. 면 수를 지정할 수 있으면 **15,000**부터 시작한다.
   면 수는 표면 폴리곤 개수이며 생성 목표와 실제 결과는 다를 수 있다.
   면이 많아도 눈·입 변형용 토폴로지, 피부 가중치, 표정 데이터가 자동으로 완성되지는 않는다.
5. 웹의 예상 Studio 크레딧을 확인하고 **생성 / Generate**를 누른다.
   생성 후 얼굴 인상·뒷면·손발·옷과 몸의 붙음 상태를 먼저 돌려 본다.
6. 모델을 열어 **Rig / Auto Rig**를 실행한다. Tripo 모션 적용은 별도 크레딧이 들 수 있으므로 필수 단계로 실행하지 않는다.
   확보한 외부 모션이 있으면 Unity의 별도 애니메이션 작업에서 어깨·팔꿈치·다리를 확인한다.
   내보낼 때는 리깅 결과가 선택되어 있어야 한다. 필요한 경우 **Include rig**를 켠 FBX를 사용한다.
7. 웹 상단 **DCC Bridge → Unity**를 켜 연결 상태가 녹색인지 확인한다.
   리깅된 모델의 **Export → Send to Unity**를 누른 뒤 Unity로 돌아온다.
   공식 Bridge는 첫 Unity 인스턴스에 연결하며 Play 중 전송하지 않는다.
8. Project 창의 **Assets/TripoModels/<모델 이름>/**에서 FBX를 선택한다.
   Inspector의 **Model → Read/Write Enabled**, **Blend Shapes**를 켜고 **Apply**한다.
   본·가중치 검사용 읽기와 표정 가져오기를 위한 설정이며, 없는 표정을 새로 만드는 설정은 아니다.
9. 작업대의 **웹·파일 가져오기 → 가져온 모델**에 FBX를 넣고 **모델 카테고리 → Character → 작업 시작**을 선택한다.
   **검증·등록**에서 기본 검사를 실행하고, 오류나 외형 문제가 있으면 **Blender 수정** 후 재검사한다.
   표정·부품을 사용하는 캐릭터는 고급 작업에서 해당 데이터를 준비·검수한다.

Bridge가 연결되지 않을 때는 웹에서 FBX와 텍스처를 함께 내려받아 프로젝트의 새 폴더로 가져온다.
원본 FBX, 텍스처, `.fbm` 폴더를 함께 보관한다. Blender 왕복은 FBX를 입력으로 사용한다.
Bridge는 전송 도구다. Unity 이미지 입력으로 Studio의 생성 버튼을 대신 호출하거나,
자동 리깅만으로 29개 얼굴 변형·공통 골격·교체 부품 호환성을 완성하지 않는다.

### 웹 Pro와 Unity API 생성 함께 사용

**생성·가져오기 → API 생성**에서 이미지 입력·API 키·자동 리깅 설정을 사용한다.
웹 Pro+DCC Bridge와 함께 사용할 수 있으며, 웹은 Studio 잔액, Unity 직접 생성은 API 잔액을 사용한다.
두 경로로 가져온 모델 모두 같은 Blender·표정·립싱크·부품·소켓·검증 작업대를 사용한다.
API 작업 재개는 이미 제출한 API 작업에만 해당하며 경로를 바꾸는 것만으로 새 생성을 시작하지 않는다.

[공식 API 보너스 안내](https://studio.tripo3d.ai/cli)에 따르면 활성 Pro/Max 구독자는
Studio와 같은 이메일의 API 계정으로 1회 1,000 API 크레딧을 신청할 수 있다.
미수령 계정만 대상이며 매월 갱신되지 않는다. 계정별 자격·수령 상태와 현재 정책은 신청 페이지에서 확인한다.

1. 작업대의 **도움말 → Pro/Max API 보너스 안내**를 열고 Pro 계정으로 로그인한다.
2. 같은 이메일의 API 계정이 있는지 확인한 뒤 **Claim your API credits**를 선택한다.
3. API 콘솔에서 실제 지급과 잔액을 확인한다. 도구는 지급 완료를 자동으로 판정하지 않는다.
4. **API 생성**을 선택하고 해당 API 계정의 키와 이미지를 입력한다.
5. 생성·리깅에 필요한 API 크레딧을 확인한 뒤 생성한다. 잔액 부족 시 추가 충전 대신 웹 Pro 경로를 사용한다.

이 Unity 도구는 API를 직접 호출하므로 Tripo CLI 설치가 필요하지 않다.
도구에는 API 크레딧 구매·자동 충전 기능이 없다. 개인 계정의 결제·자동 충전 설정을 대신 변경하지 않는다.

#### API 이미지에서 초안 만들기

1. **API 생성 → 1. 이미지**에서 단일 이미지 또는 4뷰를 선택한다.
   캐릭터도 단일 이미지를 사용할 수 있다. 4뷰는 같은 외형·포즈의 정면·좌측면·우측면·후면을 넣는다.
   PNG/JPEG, 파일당 20MB 이하이며 손발이 잘리지 않은 전신을 사용한다.
2. **2. 생성 설정**에서 영문 이름, Character/Hair/Clothing/Accessory 카테고리와
   **H v3.1** 또는 **Smart Mesh / P2 Preview**를 선택한다. Character는 자동 리깅을 선택할 수 있다.
3. 면 수와 높이를 바꾸려면 **세부 설정 · 면 수 / 높이**를 펼친다.
   현재 생성 경로는 삼각형 메시이며 요청 면 수와 결과 실측값은 다를 수 있다.
   가져오기 높이는 전체 배율이다. 프로젝트의 최종 기준 높이는 첫 모델 검수 후 정한다.
4. **3. 비용 확인 후 생성**에서 API 키를 입력하거나 Unity 실행 환경에 `TRIPO_API_KEY`를 설정한다.
   키는 작업 JSON·프로젝트·Player에 저장하지 않는다. **API 콘솔 · 잔액 확인**으로 잔액을 별도 확인한다.
5. 예상 크레딧을 확인하고 **새 에셋 생성…**을 누른 뒤 확인창에서 **생성 시작**을 선택한다.
   정상 완료 시 작업 기록·프리팹을 만들고 자동 검사 후 **검증·등록**으로 이동한다.
   작업 ID·생성 파일 열기는 **작업 상세 · 모델 / 작업 ID**에서 확인한다.
   실제 요금은 서버 응답과 공급자 정책을 따른다.
6. 기본 흐름은 정적 생성 → FBX 변환 → Generic 초안이다. 자동 리깅을 선택하면
   리깅 가능 여부 검사 → 자동 리깅 → Humanoid 확인을 거친다.
   Tripo 자동 리깅 결과가 프로젝트 공통 골격과 같다고 가정하지 않는다.

UI 방향과 달리 API에는 정면·좌측·후면·우측 순서로 전달한다.
생성은 선택한 `v3.1-20260211` 또는 `P2-20260801`을 사용한다. 두 경로 모두 표준 텍스처·PBR·삼각형 메시를 요청한다.
P2의 별도 Quad 옵션은 이 도구에서 제공하지 않는다. 기존 작업은 저장한 모델로 재개하며 새 선택으로 바뀌지 않는다.
선택적 리깅은 `v3.0-20260909`, `spec=unity`를 사용한다.
원본 FBX·재질은 `Assets/Art/Characters/Tripo/`, 초기 프리팹은
`Assets/Prefabs/Characters/Tripo/`의 새 경로에 저장한다.
URP 변환은 기본 색·노멀·메탈릭/스무스니스 연결이며 눈·머리 투명도,
roughness 패킹·법선·텍스처 경계는 실제 모델로 확인한다.

#### 생성 전 예상 API 크레딧

모델과 자동 리깅 선택을 바꾸면 입력 화면과 **새 에셋 생성** 확인창에 같은 예상 합계가 표시된다.
아래는 표준 텍스처·PBR·삼각형 메시로 새 작업 1회를 완료하는 예상값이다. 단일 이미지와 4뷰 요금은 같다.

| 선택 모델 | 이미지 생성 | 자동 리깅 포함 완료 | 리깅 없이 PNG FBX로 완료 |
| --- | ---: | ---: | ---: |
| H v3.1 | 30 | 30 + 25 = **55** | 30 + 10 = **40** |
| Smart Mesh / P2 Preview | 110 | 110 + 25 = **135** | 110 + 10 = **120** |

리깅 검사는 무료이며 리깅 결과를 FBX로 직접 받으므로 변환비를 더하지 않는다.
리깅 없는 경로는 PNG 텍스처를 요청하므로 Basic 5가 아닌 Advanced 변환 10을 계산한다.
1,000 API 크레딧으로 생성·리깅을 모두 성공한다고 가정하면 H는 18회, P2는 7회다.
새 생성, 실패 후 별도 복구, 추가 가공 비용은 따로 계산한다.

견적은 계정 잔액이나 공급자의 확정 청구액이 아니다. UI에 요금표 기준일을 표시하며
[공식 요금표](https://developers.tripo3d.ai/en/pricing),
[P2 요금](https://developers.tripo3d.ai/en/models/p2),
[변환 옵션](https://developers.tripo3d.ai/en/docs/models-convert)이 바뀌면 `TripoCreditEstimate`와 요청 옵션·테스트를 함께 갱신한다.
작업 하단의 **확인된 사용량**은 저장된 작업의 서버 응답이며 새 생성 견적과 별도로 표시한다.
가격 정보가 없는 모델은 낮은 가격으로 대체하지 않고 견적을 거부한다.
### 중단과 복구

작업 상태는 Git에서 제외되는 `UserSettings/Tripo/`에 저장하고 이전 작업은 `History/`에 보존한다.
일시정지는 로컬 처리를 멈춘다. 이미 제출한 원격 작업은 계속 실행되거나 과금될 수 있다.
**저장된 작업 재개**는 기존 ID를 조회한다. 다운로드 재시도도 기존 작업의 새 URL을 조회한다.
제출 응답이 유실되면 자동 재제출을 차단한다. Tripo 콘솔에서 해당 모델·단계의 작업 ID를
확인한 뒤 **기존 작업 ID 연결**로 복구한다. 서버 응답만으로 작업의 동일성을 완전히 증명할 수는 없다.
리깅 실패 시 성공한 생성 작업을 확인하고 정적 FBX 초안으로 복구할 수 있다.

요청 제한은 120초, 로컬 연속 처리는 30분이다. 인증·사용량·연결 문제를 해결한 뒤 재개한다.
다른 이미지로 새로 생성하면 별도 유료 작업이므로 자동 반복하지 않는다.

### Blender에서 본·가중치·얼굴 수정

Blender는 무료 별도 프로그램이다. 설치한 실행 파일을 도구에서 지정한다.
Windows 테스트용 portable 배포본을 `Library/TripoTools/blender-4.5.14-windows-x64/`에 두면
기본 경로로 찾는다. `Library` 삭제 시 이 설치도 사라지므로 상시 사용은 별도 설치 경로를 권장한다.
실행 파일 경로는 개인 EditorPrefs에 보관하며 프로그램 바이너리는 Git에 넣지 않는다.

1. **Blender에서 열기 · 최초 원본 준비**로 FBX를 `.blend`로 준비한다.
   기본 위치는 Unity 프로젝트 밖 `frontend/ArtSources/Tripo/<작업 GUID>/Editable.blend`다.
   기존 `.blend`가 있으면 덮어쓰지 않으며 직접 만든 `.blend`도 연결할 수 있다.
2. 공통 Armature와 rest pose, 얼굴 변형용 토폴로지, Weight Paint, Shape Keys를 수정한다.
   눈코입은 공통 얼굴 메시의 변형으로 만들고, 입 안·눈꺼풀·치아·혀는 필요한 형태로 준비한다.
   이 첫 기준 모델 제작은 자동 생성 결과에 따라 사람의 조형·검수가 필요하다.
3. Blender에서 **Ctrl+S**로 저장한 뒤 Unity의 **저장된 수정본 가져오기**를 누른다.
   저장된 파일의 같은 폴더에 임시 스냅샷을 만들고 새 FBX 후보로 내보낸다.
   저장하지 않은 Blender 변경은 반영되지 않는다.
4. 내보내기는 Armature·Shape Keys를 유지하고 메시 Modifier와 애니메이션을 굽지 않는다.
   Modifier 적용이나 토폴로지 변경이 필요하면 Blender에서 Shape Key 호환성을 먼저 확인한다.
5. 후보에서 키·본·소켓과 접합 샘플을 재검사하고 외형을 확인한 뒤 **후보 적용**한다.
   **이전 모델 버전**은 모델 파일 버전을 되돌리는 기능이며 모든 작업 설정의 전체 롤백은 아니다.

본·키는 이름과 계층 경로로 다시 찾으므로 가져오기 순서에 의존하지 않는다.
본 이름·계층 또는 얼굴 메시 경로를 바꿨다면 연결도 다시 지정해야 한다.
공통 골격 조작 핸들은 별도 미리보기 Scene에서 포즈를 시험한다.
손잡이 조작은 원본 rest pose나 스킨 가중치를 편집하는 기능이 아니다.

### 표정·립싱크

추천 시작안은 감정 7종(중립·미소·기쁨·걱정·슬픔·놀람·단호함),
발음 상태 15종(`SIL PP FF TH DD KK CH SS NN RR AA E IH OH OU`)이다.
중립은 별도 메시 복제 없이 가중치 0으로 표현한다.

논리 제어 채널은 다음 29개다. 실제 Shape Key 이름은 매핑에서 다르게 연결할 수 있다.

- 눈: `eyeBlinkLeft/Right`, `eyeWideLeft/Right`, `eyeSquintLeft/Right`
- 눈썹: `browInnerUp`, `browDownLeft/Right`, `browOuterUpLeft/Right`
- 입꼬리: `mouthSmileLeft/Right`, `mouthFrownLeft/Right`
- 발음: `viseme_PP`부터 위 목록의 `viseme_OU`까지 14개 (`SIL` 제외)

완성된 얼굴 준비 검사에서는 29개 연결, 실제 정점 변형, 누락·중복을 검사한다.
필요 없는 외형 보정 키는 별도로 유지할 수 있다. 기존 AnimationClip의 blendShape 곡선은
논리 제어명 또는 연결한 Shape Key 이름으로 재생한다. 클립만 붙여 없는 Shape Keys를 만들 수는 없다.
발화 중에는 입 모양을 우선하고 입꼬리 감정의 강도를 줄이며 눈·눈썹 감정과 눈 감기를 함께 구동한다.
턱 Shape Key와 턱 본을 동시에 같은 목적으로 구동하지 않도록 원본을 준비한다.

6개 빠른 모습(중립·미소·눈 감기·AA·FF·TH), 감정×발음 105조합,
15발음 무음 순서 검수로 귀여운 인상이 유지되는지 확인한다.
무음 순회는 음성 동기화 합격 판정에 사용하지 않는다.

검수 음성과 아래 형식의 JSON TextAsset을 연결하면 음성 재생 위치에 맞춰 발음을 구동한다.
시간 단위는 초, 강도는 0~1이며 구간은 오름차순·비중첩이어야 한다.

```json
{"cues":[{"start":0.1,"end":0.3,"viseme":"FF","weight":1},{"start":0.3,"end":0.6,"viseme":"AA","weight":0.8}]}
```

P95·최대 오차는 **음성 미리보기 시계 대비 Editor의 구동 시점**이다.
누락된 구간·불완전한 얼굴 매핑에는 합격을 주지 않는다. 음소 정답, 실제 스피커 출력 지연과
자연스러움은 별도 청각·시각 검수 대상이다. TTS 타임라인 생성과 게임 실행 중 대화 연동은 후속 런타임 작업이다.
Editor 오디오는 Unity 6000.3의 미리보기 API를 사용하는 격리된 어댑터이며 버전 변경 시 다시 확인한다.

### 개별 부품과 소켓

카테고리는 처음 만들 때 지정하고 작업 기록에 보관한다. 소켓 슬롯에서 부품 생성 화면으로
이동할 때 카테고리가 따라간다. 생성 후 결과 모델을 해당 슬롯에 연결한다.

- 짧은 머리·장신구는 기본 강체 연결이다. 본 경로와 위치·회전·양수 균일 크기를 지정한다.
- 좌우 귀걸이는 독립 슬롯이다. 한쪽만 넣거나 같은/다른 모델을 양쪽에 넣을 수 있다.
  음수 스케일 복제 없이 각 방향의 위치·회전을 설정한다.
- 옷·변형 머리는 스킨 연결로 전환한다. 기준 몸체와 본 경로·bind pose가 일치해야 하며
  같은 골격으로 연결한다. 독립 생성한 의상의 자동 재봉·자동 가중치 제작은 지원하지 않는다.
- 얼굴 표면을 따라 변형되는 액세서리 부착은 아직 지원하지 않는다. 머리 소켓에 붙이는 것과 구분한다.

전체 크기는 몸체와 연결된 부품을 한 루트에서 함께 변경한다. 개별 신체 비율 변경은 초기 범위에서 제외한다.

## 검증 기준과 등록

H는 기준 몸체 높이다. 아래 값은 첫 실제 모델을 보며 조정할 수 있는 시작값이다.

| 항목 | 시작값 | 현재 확인 범위 |
| --- | --- | --- |
| 전체 크기 | 0.85~1.15 | 범위·유효 수치 검사, 대표 크기의 포즈·외형은 수동 |
| 재질 연결 | 누락 0개 | 비어 있는 재질 슬롯·재질 없는 Renderer 차단. 텍스처 픽셀 품질은 수동 |
| UV0 구조 | 누락·비정상 값 0건 | 텍스처 연결 모델의 UV0 누락, NaN/Infinity, 읽기 불가를 차단. 단색 모델의 누락은 수동 확인 |
| UV0 배치 | 범위·퇴화·겹침 검수 | 0~1 이탈, UV 면적이 거의 없는 면, 같은 서브메시 내부 겹침을 수동 항목으로 표시 |
| 메시 경계 | 의도한 경계와 결함 구분 | 같은 위치의 UV·법선 분리 정점을 검사 중에만 묶어 열린 경계·다중 면 공유 경계 표시. 옷 입구는 정상일 수 있어 자동 불합격 아님 |
| 가중치 | 합계 1±0.0001 | 전체 influence를 검사, 연결 안 된 본·빈 가중치 차단 |
| 접합 틈 | 0.001H 이하 | 지정한 정점 쌍 거리 검사 |
| 금지 관통 | 깊이 경고 0.0005H | 지정한 정점과 표면 법선 기준 검사, 전 메시 충돌 판정 아님 |
| 소켓 보존 | 위치 0.0005H / 회전 0.5도 / 크기 차이 0.0001 이하 | 같은 자세의 왕복 전후 본 경로·위치·회전·크기 비교. 오프셋이 0이어도 크기 검사 |
| 립싱크 구동 | P95 40ms / 최대 80ms | 위 Editor 타임라인 측정 |
| 발화 종료 | 150ms 이내 복원 | 미리보기 입 모양 복원 |
| 감정×발음 | 105조합 | 자동 순회, 시각 합격은 사람이 판단 |

의도하지 않은 보이는 관통과 눈·입을 닫았을 때 1px 이상 열린 틈의 목표는 0건이다.
의도한 숨은 겹침은 금지 관통 샘플에서 제외한다. 이는 실제 대화 카메라에서 확인하며
현재 자동 픽셀 검사는 제공하지 않는다.

접합 샘플은 조립된 모델의 메시 경로와 **Unity가 가져온 메시의 정점 번호**로 지정한다.
Blender의 번호와 같다고 가정하지 않는다. 첫 지정이나 메시 연결 구조 변경 후
**접합 샘플 경로·정점 번호 재확인 완료**를 눌러야 검사할 수 있다.
정점 번호의 의미까지 모든 변경을 감지할 수는 없으므로 토폴로지 편집 후 샘플을 다시 확인한다.
샘플 없는 영역, 애니메이션 전체 구간, 모든 의상 조합의 틈·관통을 자동 보증하지 않는다.

공통 기준 모델이 없으면 부품 간 호환성 검사는 미확인으로 남는다. 완성형 개별 캐릭터는
공통 기준 모델을 반드시 지정할 필요는 없다. 신규 Character는 Humanoid 검사를 기본으로 요구하며,
기존 기록과 대화용 얼굴 준비는 해당 필수 옵션을 직접 확인한다. 준비 검사를 끈 채 등록한 것은 초안 검수 프리팹이다.
모델, 프로파일, 키 매핑, 부품·접합 설정이 바뀌면 이전 승인은 무효화된다.
자동 검사 통과와 시각 검수 표시가 모두 현재 내용에 대응할 때만 **새 버전** 프리팹을 등록한다.

WebGL의 면 수·머티리얼·텍스처 예산과 실제 대화 품질은 첫 기준 모델 및 장면에서 확정한다.

## 검사 결과를 확인하고 다시 작업하기

1. **검증·등록 → 현재 모델·설정 검증**을 누른다. UV0 검사는 가져오기와 Blender 후보 재가져오기에도 자동 실행되며, 오류·수동 항목은 작업 기록에 저장된다. UV 검사 도입 전 승인은 재검사가 필요하다.
2. 오류는 먼저 수정한다. UV0 누락/비정상 값은 텍스처를 배치할 좌표가 없거나 깨졌다는 뜻이다. **현재 검사 모델 Inspector에서 확인**으로 대상을 확인하고, **문제 수정 · Blender 단계로 이동** 후 UV Editing에서 해당 메시를 확인한다.
3. 수동 항목의 메시 이름·서브메시·정점/삼각형 번호를 확인한다. 번호는 Unity 가져오기 결과 기준이며 Blender 번호와 같다고 가정하지 않는다. 범위 이탈은 반복 무늬/UDIM, 겹침은 대칭/스택 UV로 의도했을 수 있다. 동일 서브메시의 면적 있는 교차만 세며 공유 모서리·꼭짓점은 겹침으로 세지 않는다. 비교 상한에 도달하면 검사 미완료를 명시한다.
4. Blender의 UV Editing에서 UV 배치와 실제 텍스처를 함께 확인한다. UV0만 검사하며 다른 UV 채널, 재질의 UV 채널 선택·타일링 변환, 서로 다른 메시/서브메시 사이 겹침, 텍스처 픽셀의 빈 테두리·색 번짐·해상도·섬 간 여백은 자동 검증하지 않는다. UV 면적이 거의 없는 면도 단색 샘플링 의도일 수 있어 수동 검수로 남긴다.
5. Unity 모델 미리보기/별도 검수 장면에서 정면·좌우·후면과 얼굴 확대를 보고 눈썹·입술 테두리, 옷 틈, 관통, 대표 동작과 표정을 확인한다. 작업대의 자세 핸들·표정 미리보기를 사용하고, 전체 동작 검수에는 확보한 애니메이션이 필요하다. 자동 검사는 모든 프레임의 충돌이나 미적 품질을 보증하지 않는다.
6. 마음에 들지 않으면 승인하지 않는다. **후보 제외 · 현재 모델 재검사**로 되돌리거나 Blender에서 수정·저장 후 **저장된 수정본 가져오기**로 새 후보를 검사한다. 검사 결과가 모두 현재 모델에 대응하고 외형까지 확인했을 때만 **표시된 수동 검수 항목까지 확인했습니다**를 체크한다.

### 재검사·수정·재생성 비용

| 행동 | Tripo API 크레딧 |
| --- | --- |
| 로컬 검사 반복·후보 제외·기존 로컬 파일 가져오기 | 소비하지 않음 |
| Blender에서 UV/모델 수정 후 왕복 | 소비하지 않음 |
| API로 새 모델 생성 | 새 생성 비용 발생. 같은 이미지라도 새 요청은 새 작업 |
| API 자동 리깅·텍스처 재생성·Smart UV | 각 서버 작업 비용 발생. 현재 로컬 검사 버튼이 호출하는 기능은 아님 |
| 웹 Studio에서 다시 생성 | API 잔액과 별도. 웹 생성 버튼의 표시 요금과 구독 혜택을 확인 |

검사 실패나 외형 미승인은 자동으로 API 재생성을 실행하지 않는다. 기존 작업의 상태 조회/다운로드 재개와 새 생성을 구분한다. 생성 후 외형이 마음에 들지 않는다는 이유로 무료 재생성이 보장되는 것은 아니다.
현재 공식 가격표 기준으로 작업대의 표준 텍스처 생성+자동 리깅 예상은 H 30+25=55, P2 110+25=135 API 크레딧이다. 모델 옵션·처리 단계가 달라지면 요금도 달라진다. 서버 Rig Check는 키가 필요하지만 현재 무료로 안내된다. [API 요금](https://developers.tripo3d.ai/en/pricing), [P2 요금](https://developers.tripo3d.ai/en/models/p2), [Studio/API 잔액 구분](https://www.tripo3d.ai/help/api-plugins/tripo-studiotripo-api)을 확인한다.

## 개발 검증

EditMode 테스트는 `Assets/Tests/EditMode/Tripo/`에 있다.
요청 중복 방지·재개·API 경계, 정적 변환, 파일/버전 보존, 얼굴 혼합·매핑·클립,
스킨·소켓 연결, IK 평가, 스케일·접합·왕복 검사, 승인 후 등록을 검증한다.
Blender 통합 테스트는 실제 실행 파일이 있으면 절차적 테스트 메시로 `.blend → FBX → Unity`를 검사한다.
네트워크 테스트는 대역을 사용하며 유료 Tripo 호출은 자동 테스트에 포함하지 않는다.

로컬 FBX 가져오기, 구조·소켓·표정 매핑 검사, Blender 왕복·재검사에는 Tripo API 키를
사용하지 않는다. API 생성 경로의 이미지 업로드, 생성, 서버 리깅 가능 여부 검사,
자동 리깅, 변환·작업 조회는 Tripo 서버 요청이므로 API 키를 사용한다.
서버 리깅 가능 여부 검사와 가져온 모델의 로컬 품질 검사는 다른 단계다.

Unity Test Runner의 EditMode 또는 Unity 명령줄 `-runTests -testPlatform EditMode`를 사용한다.
Blender 스크립트는 저장소 루트에서 다음과 같이 실행한다.

```powershell
& '<Blender 실행 파일>' --background --factory-startup --disable-autoexec --python-exit-code 1 --python infra/tests/tripo/test_blender_bridge.py
```

운영 모델의 조형·텍스처·음성 품질과 Editor의 실제 클릭·청취 검수는 별도로 수행한다.
연결된 설계와 진행 상태는 Epic **S15P31A305-183**, Story **204·209** 및 연결 태스크에서 관리한다.

[리깅](https://developers.tripo3d.ai/en/docs/animations-rig),

### 텍스처 자동 준비와 방향 기준

API 다운로드와 로컬 FBX 가져오기는 Blender를 백그라운드로 실행해 재질을 준비한다.
Blender 설치 경로는 연결 설정을 우선 사용하고 Windows 표준 설치 경로를 자동 검색한다.
API 새 생성 전에 실행 파일이 있는지 확인한다. 경로 지정은 생성 도움말에서도 가능하다.
이 처리는 로컬 작업이며 Tripo API 요청이나 크레딧을 사용하지 않는다.

- 격리한 FBX 복사본에서 내장 이미지와 동반 텍스처를 읽고 색상·노멀을 PNG로 저장한다.
- 이미지의 잘못된 확장자에 의존하지 않고 Blender가 읽은 재질 연결을 사용한다.
- 색상 이미지와 바이트가 동일한 노멀 입력은 해제한다. 정상 노멀은 Normal Map 설정으로 가져온다.
- 모델별 `Textures/materials.json`에 대응 관계와 자동 수정 내용을 남긴다.
- 여러 재질의 이름 대응이나 이미지 읽기에 실패하면 가져오기를 중단한다. 새 API 생성으로 해결하려 하지 않는다.
- FBX 원본 바이트와 이미 편집된 Unity 재질은 덮어쓰지 않는다. 수정 파일은 새 후보 폴더로 가져온다.

미리보기 정면은 Humanoid의 좌우 다리 본으로 정한다. 캐릭터 본인 기준 좌·우이며,
리깅되지 않은 모델은 루트 축을 사용한다. 카메라를 돌려도 처음 골격에서 잡은 기준을 유지한다.
URP 렌더와 카메라 기준 조명을 사용한다. 텍스처 연결 복구는 메시 결함·관통·표정 준비 완료를 뜻하지 않는다.
