# Mission 모듈

퀘스트 목록에서 시작 버튼으로 시연 퀘스트를 선택하거나 일반 퀘스트로 돌아가는 것은 완료로 세지 않습니다. 시작 요청이 성공하면 목록을 닫고 선택한 퀘스트의 목표 카드를 펼칩니다. 실패하면 기존 진행과 목록을 유지하고 오류를 표시합니다. 대화·방문 등으로 실제 퀘스트를 완료했을 때만 완료 화면과 그에 연결된 게스트 가입 안내를 표시합니다.

이야기·장소 연습 머리줄의 이전 버튼 그림(`QuestBackRound.png`)은 **Tools → A305 → Mission → Align Quest Back Arrow**에서 생성합니다. 흰 원과 화살표는 같은 중심 좌표를 사용하며, 그림자 여백과 글꼴 기준선에 영향을 받지 않습니다. **Apply Quest Board**도 이 그림을 함께 갱신합니다. **Capture Quest Navigation**(`FirstDayMissionPreview`)은 `QUEST_NAV_PREVIEW_OUTPUT` 폴더에 두 머리줄의 PC·모바일 Unity 캡처를 저장하며 서버를 호출하지 않습니다.

첫날의 작은 소동을 완료하면 수첩에서 [마을에서 보내는 하루](../../../../../docs/api/town-story.md)를 시작할 수 있습니다. 새 여정은 첫날과 별도로 진행을 저장하고, 세탁·이발·선물 등은 실제 결제나 아이템 전달 없이 대화로 연습합니다. 새 여정 시작 전에는 첫날의 소지품과 예산을 그대로 보여 줍니다.

새 여정의 가게 9곳은 모두 마을 씬 안에 있습니다. `TownMapArt.Shops`는 담당 NPC를 가게 이름과 지도 그림의 건물 칸에 연결합니다. **Tools → A305 → Mission → Refresh Town Maps**는 이 칸과 마을 도로를 읽어 수첩·큰 지도를 함께 갱신합니다.

튜토리얼 뒤에는 **첫날의 작은 소동** 연계 미션을 진행합니다. 튜토리얼을 마치거나 건너뛰면 서버가 이 퀘스트를 바로 시작하므로([TUT-01·02](../../../../../docs/api/mvp-api.md)), 건너뛴 사용자도 [퀘스트 시작]을 찾지 않고 첫 단계 카드를 봅니다. 왼쪽 위 모서리에는 책 [퀘스트] 버튼(`Content/QuestIcon`)을 늘 둡니다. 오른쪽 위 휴대폰 버튼·시계·코인 칩과 같은 64 크기이고, 배경에 묻히지 않게 흰 테두리와 넓은 흰 빛 번짐을 함께 렌더링한 그림(`Art/UI/Hud/QuestBookButton.png`)이며, 혼자 있을 때는 넓고 밝게 빛나고, 옆에 알약·카드가 뜨면 그 창에 빛이 비치지 않게 작고 옅은 빛(`QuestBookButtonSoft.png`)으로 바꿉니다. 누르면 퀘스트 창을 엽니다. 튜토리얼의 [오늘의 목표] 안내도 이 버튼을 가리킵니다. 그 오른쪽 12에는 지금 하는 퀘스트를 한 줄 알약(`Content/QuestPill`: '이야기'·단계마다 한 칸인 진행 칸·⌄)으로 접어 둡니다(시안 1-B). 알약을 누르면 그 자리에 퀘스트 카드를 펼치고, 펼친 카드 오른쪽 위의 접기 버튼(⌃)을 누를 때까지 그대로 둡니다. 카드 본문을 누르면 퀘스트 창을 엽니다. 퀘스트를 시작할 때만(시작 전·끝낸 뒤 상태에서 이야기가 진행 중으로 바뀔 때, [연습하기]로 장소 연습을 시작할 때) 카드를 5초 펼쳐 카드 아래 줄어드는 막대로 남은 시간을 보이고 저절로 접습니다(`QuestCardFold`). [다시 연습]은 연습하는 동안 말할 조건을 보도록 펼친 채로 두고 저절로 접지 않습니다. 하던 이야기를 불러올 때는 알약으로 둡니다. 시연 퀘스트(비 오는 저녁)는 시작할 때와 장면을 옮겨 불러올 때 카드를 펼치고 저절로 접지 않습니다. 이 퀘스트는 정해진 순서대로만 진행하지만, 화면에 '시연'이라고 쓰지 않고 다른 이야기 퀘스트 카드와 같은 모양(요청 한 줄·상황 설명·목표 줄)으로 보입니다. 따라갈 순서는 퀘스트 창의 도장 지도에서 봅니다. 하는 동안에는 지금 단계에 나오는 사람만 말을 걸 수 있습니다(`FirstDayMissionState.ShowcaseStepNpcs`, [Npc 모듈](../Npc/README.md)의 `ShowcaseTalkLock`). 한 번에 하나만 보입니다. 장소 연습 방문 중([연습하기]부터 그 대화가 끝날 때까지, World의 `PracticeVisit`)에는 이야기 대신 그 연습을 알약('장소 연습'·목표마다 한 칸인 파란 진행 칸)과 펼친 카드(파란 '장소 연습' 칩·장소 · 상황·상황 설명·목표 진행과 목표 줄)로 보이고, 방문이 끝나면 이야기 알약으로 돌아옵니다. 세로 휴대폰처럼 좁은 화면에서는 카드·알약을 글자까지 같은 비율로 통째로 줄여 오른쪽 위 시계·코인 칩과 겹치지 않게 합니다. 책 버튼·알약·접기 버튼·파란 칩·막대는 **Tools → A305 → Mission → Apply Quest Pill**(`QuestCardBuilder`)이 시안을 렌더링한 `Art/UI/Hud/Quest*.png`로 만듭니다. 펼친 카드는 단계 번호·전체 제목·담당 NPC·상황·목표를 보여 줍니다. 긴 제목은 줄바꿈하며, 목표가 없는 휴식 단계에서는 지금 할 행동을 보입니다. 목표 아래에는 해야 할 내용만 적고 영어 예시는 대화 화면의 추천 단어·힌트를 사용합니다. **Tools → A305 → Mission → Apply Quest Card Readability**로 기존 프리팹의 접기 버튼을 제거하고 제목 줄바꿈을 적용합니다. 오른쪽 위 메뉴 버튼 왼쪽에는 게임 시계 칩(`GameClockText`: "1일차 · 오후 1:40")과 코인 칩(미션 잔액)을 둡니다. 지도의 길과 건물 칸은 `TownMapBuilder`가 TownScene 배치에서 그리고, `TownMapView`는 내 위치와 목적지 표시만 바꿉니다. 서버가 `/v1/judge`의 의미 판정 제안을 현재 NPC·단계에 맞춰 적용하고 사용자별 진행을 저장합니다. 새로고침과 씬 이동 후에도 서버 상태를 읽어 복원합니다. 퀘스트가 여러 개가 되므로 화면 문구에는 '첫날'·'여정'을 쓰지 않습니다(수첩 제목 '퀘스트', 시작 버튼 '퀘스트 시작'). 이미 만든 프리팹과 튜토리얼 안내의 옛 문구는 **Tools → A305 → Mission → Apply Quest Wording**(`QuestWordingBuilder`)이 바꿉니다.

퀘스트 창(`Content/QuestBoard`, `QuestBoardView`)을 열면 같은 크기 판의 가운데에 [장소 연습](장난감 건물 다섯 채)·[이야기](접힌 퀘스트 지도)를 왼쪽부터 큰 그림과 이름으로 고르는 쪽(시안 2-B ①)부터 보입니다. 두 그림은 시안보다 가운데로 30씩 당겨 사이를 좁혔고, 누르는 칸은 가운데 세로 줄에서 나뉩니다. 고른 쪽 머리줄 왼쪽의 둥근 ‹ 를 누르면 고르기 쪽으로 돌아갑니다. [이야기]는 퀘스트 목록(시안 c4)입니다. 목록은 서버 `GET /api/v1/missions/quests`([마을 이야기 문서](../../../../../docs/api/town-story.md#퀘스트-목록과-보상))의 퀘스트를 한 줄에 세 장씩 카드로 보이고, 쪽이 여럿일 때만 아래 가운데에서 쪽을 넘깁니다. 들르는 곳 알약이 카드 폭을 넘으면 다음 줄로 넘깁니다. 카드에는 아이콘·상태 칩(진행 중·새 퀘스트)·제목·설명·들르는 곳 알약(처음 들르는 순서로 한 번씩, 가 본 곳은 코랄)·보상과 도장 수를 두고, 끝낸 퀘스트는 '완료' 도장, 잠긴 퀘스트는 카드째 흐리게 하고 가운데 자물쇠로 표시합니다. 서버가 잠긴 까닭(`lockReason`: 마쳐야 할 앞 퀘스트 이름, 정해진 순서대로 하는 퀘스트를 하는 중이라 잠금)을 주면 자물쇠 아래에 따옴표로 묶은 퀘스트 이름을 한 줄에 두고 그 뒤와 문장마다 줄을 바꿔 흐리지 않게 쓰고, 겹치지 않게 그 카드의 들르는 곳 알약은 숨깁니다(`QuestBoardText.LockReason`). 카드를 누르면 그 퀘스트의 도장 지도로 갑니다. 진행 중인 퀘스트가 있으면 왼쪽 위 퀘스트 카드를 눌렀을 때 고르기 화면 대신 그 퀘스트의 도장 지도가 바로 열립니다(`QuestBoardView.Open(questId)`, 목록을 받기 전이면 받는 대로 엽니다. 장소 연습 중에는 고르기 화면부터). 도장 지도는 목록과 같은 폭에 높이만 지도 카드에 맞춰 줄인 판(`QuestBoardView.MapSheetHeight`)에 머리줄(퀘스트 이름과 그 아래 퀘스트 설명·도장 수·[퀘스트 시작] 또는 [퀘스트 그만두기]), 왼쪽 순서 목록, 오른쪽 흰 카드(`MapCard`)에 담은 마을 전체 지도 한 장을 둡니다. 순서 목록은 들르는 곳 칸(번호, 지나온 곳은 도장, '장소 · 사람', 할 일)을 위아래로 넘기고 넘치면 지금 할 칸이 보이게 넘겨 둡니다. 스크롤 막대는 칸이 넘칠 때만 보입니다. 지금 할 칸은 코랄 테두리에 옅은 코랄 바탕, 시작 전 퀘스트의 첫 칸은 바탕 없이 코랄 테두리만, 아직 차례가 안 된 칸은 따뜻한 아이보리 바탕에 갈색 기운 글자·번호와 자물쇠로 보입니다. 칸은 누르지 않습니다. 지도는 마을 지도를 회색으로 바꾼 그림(`Art/UI/Quest/QuestMapGray.png`, Builder가 없을 때만 만듦)을 카드 안에 꼭 맞게 깔고, 퀘스트에서 들르는 건물 칸만 원래 색 지도(`QuestMap.png`)를 가장자리를 흐리게 잘라 보입니다(`QuestStampMap.Tiles`). 다른 색을 넣지 않고 나머지를 회색으로 눌러 코랄 핀과 도장이 살아나게 합니다. 가 본 곳마다 잉크 도장을 작게 한 번 찍고, 다음에 갈 곳(하는 중이면 지금, 시작 전이면 처음 들를 곳)에 번호 핀을 지붕 위로 띄워 꽂고 퍼지는 코랄 빛(`QuestPinPulse`)과 '지금 갈 곳' 칩(시작 전이면 옅은 '처음 갈 곳' 칩)을 붙입니다(`QuestStampMap.Pin`, 택시 기사는 호텔 앞, 칸이 없는 거리 행인은 지도에 두지 않음). 지도 그림에 남은 옛 '식당' 이름표 자리에는 흰 알약 '햄버거 가게' 이름표(`Art/UI/Quest/QuestPlaceLabel.png`, Builder가 없을 때만 만듦)를 덮습니다. 머리줄 오른쪽에는 시작할 수 있는 퀘스트에 [퀘스트 시작]을, 하는 중인 퀘스트에는 같은 자리에 [퀘스트 그만두기]를 둡니다. [퀘스트 그만두기]는 확인 창(`QuestConfirmView`: [계속하기]·[그만두기])을 거쳐 서버에 그만두기(`POST /api/v1/missions/quests/{questId}/cancel`)를 보내고, 서버가 그 퀘스트를 처음으로 되돌립니다. 그만둔 것은 완료가 아니라 팡파레를 띄우지 않습니다. 다른 퀘스트를 하는 중에 [퀘스트 시작]을 누르면 서버가 하던 퀘스트를 처음으로 되돌리므로 같은 확인 창([그만두고 시작])으로 먼저 묻습니다. 확인 창은 Esc나 바깥을 눌러도 [계속하기]처럼 닫힙니다. 정해진 순서대로만 하는 퀘스트(비 오는 저녁)를 하는 중에 장소 연습의 [연습하기]를 누르면 바로 가지 않고 같은 확인 창([그만두고 연습])으로 그 퀘스트를 그만둘지 묻습니다. 화면 글자는 `QuestBoardText`가 만들고, 그림 조각은 시안을 렌더링한 `Art/UI/Quest`입니다. **Tools → A305 → Mission → Apply Quest Board**(`QuestBoardBuilder`)가 만들고 퀘스트 카드 버튼을 목록 열기에 연결합니다.

[장소 연습]은 이야기와 따로 한 가게에서 한 상황만 골라 연습하는 쪽(시안 `mock.html #place`, `PracticeBoardView`)입니다. 고르기·이야기·장소 연습 쪽은 시안의 흰 유리 판(`.panel` 1520×800)을 함께 쓰고, 이야기·장소 연습 쪽 머리줄은 둥근 ‹·쪽 아이콘(코랄 책·파란 가게)·쪽 이름·옅은 '퀘스트'·둥근 닫기입니다. [이야기] 쪽 카드는 줄인 시안 카드(400×420)를 판 폭에 사이 60씩 고르게 벌려 그립니다. 판 바깥은 어둡게 칠하지 않고 누르면 닫습니다. 도장 지도도 같은 흰 판 그림을 쓰되 폭은 같고 높이만 지도 카드에 맞춰 줄입니다. 연계 퀘스트가 열리는 띠는 판 위에 자리가 없어 머리줄 가운데 빈 곳으로 내려옵니다. 장소 연습 쪽을 열 때마다 서버 장소 연습 목록(PRC-01 `GET /api/v1/practice-places`, `PracticeBoardState`)을 다시 읽어 방금 끝낸 상황도 보입니다. 왼쪽에는 12개 장소를 아이콘·이름·앞 두 상황·끝낸 수("1 / 3", 모두 끝내면 초록)로 보이고, 넘기는 목록 아래는 흐리게 덮습니다. 장소를 고르면(코랄 테두리) 오른쪽 판만 그 장소의 큰 아이콘·이름·직원 칩(예: Rosa · 식당 직원)과 상황 세 줄로 바뀝니다. 고른 장소는 목록을 다시 받아도 유지합니다(`PracticeBoard`). 아직 끝내지 않은 상황은 번호와 [연습하기], 한 번이라도 끝낸 상황은 초록 체크·'완료' 칩·[다시 하기]를 보이며, 몇 번이든 다시 할 수 있습니다. 코인·도장은 없습니다. [연습하기]·[다시 하기]를 누르면 창을 닫고 World 모듈의 `PracticeVisit`로 그 가게 직원에게 연습하러 가자고 알립니다. 이동·대화·결과 알림은 [Learning 모듈](../Learning/README.md#장소-연습-방문)이 맡습니다. 고르기 쪽과 이야기 목록은 `QuestBoardBuilder`, 쪽마다의 머리줄과 장소 연습 쪽은 `QuestBoardBuilder`가 부르는 `PracticeBoardBuilder`가 만들고, 그림은 시안을 2.4배로 렌더링한 `Art/UI/Quest/QuestPick*.png`·`QuestHeader*.png`·`Practice*.png`입니다. 장소·상황·직원 이름은 Jua·Pretendard 글자로 씁니다.

하는 퀘스트가 없으면(시작 전, 퀘스트를 끝내고 다음 퀘스트를 시작하기 전) 왼쪽 위에는 책 [퀘스트] 버튼만 있습니다(**Apply Quest Icon**, `QuestCardBuilder`). 퀘스트를 끝내면(`FirstDayMissionState.QuestFinishedSince`) 대화가 끝난 뒤 '퀘스트 완료!' 팡파레(시안 f1, `Content/QuestComplete`, `QuestCompleteView`)를 띄웁니다. 화면이 살짝 어두워지며 팡파레 소리(`Audio/UI/QuestComplete.wav`, 직접 합성)와 색종이가 터지고, 카드가 튀어 오르며 리본이 펼쳐진 뒤 큰 '완료' 도장이 찍힙니다. 보상 코인은 코인 칩으로 날아가고, 닿을 때 코인 칩에 "+10"과 "퀘스트 보상 +10코인"이 보입니다(그때까지 보상은 더하지 않음). [다음]을 누르면 퀘스트 목록이 열리고 "연계 퀘스트가 열렸습니다!" 띠와 함께 다음 퀘스트 카드의 자물쇠가 깨지며 카드가 노랗게 빛나고 카드 위에 [퀘스트 시작]이 나타납니다(시안 f2, `QuestUnlockEffect`). 시연 퀘스트는 연계 퀘스트가 아니므로 끝내도 이 연출을 하지 않고 [다음]은 팡파레만 닫습니다. 게스트(`PlayerAccount.IsGuest`)가 첫 호텔 퀘스트(`CHECK_IN`)를 끝낸 팡파레의 [다음]을 누르면 가입 안내 창도 띄웁니다(`GuestSignupPrompt.RequestAfterQuest`, [Api](../Api/README.md)). 팡파레는 **Tools → A305 → Mission → Apply Quest Complete**(`QuestCompleteBuilder`)가 만듭니다.

`FirstDayMissionApi`는 공용 API 클라이언트를 사용하고, `FirstDayMissionController`는 씬 진입·NPC 응답·대화 종료 후 상태를 읽습니다. `FirstDayMissionView`는 화면과 수첩만 담당합니다. 왼쪽 위 퀘스트 카드는 확정 시안(g1)과 같은 크기·여백·글꼴(시안 px × 1.2)로, 위에서부터 단계 칩(`StepChip`: 지금 단계 / 전체, 시작 전에는 숨김)과 장소 이름(시안 문구: "호텔에 도착", "비 오는 거리" 등), 서버의 짧은 요청 안내(예: "호텔 직원에게 요청하세요."), 상황 한 줄, 단계마다 한 칸인 진행 칸, 이번 단계 목표 줄을 보입니다. 목표는 한 줄에 하나씩 동그라미 체크와 이름이고, 끝낸 목표는 초록 체크·옅은 글자·취소선입니다. 카페에서 쉴 차례에는 의자에 앉으라는 안내만 보이고 목표 줄은 숨깁니다. 단계 칩·진행 칸·체크·코인처럼 그림인 부분은 시안 HTML을 그대로 렌더링한 그림(`Art/UI/Hud`)입니다. 오른쪽 위 시계·코인 칩은 높이 64의 둥근 유리 알약입니다. 시계는 글자 양옆에 시안 기준 24px 여백과 최소 216px 폭을 확보하며, 긴 날짜에 맞춰 왼쪽으로 넓어집니다. 시각 글자는 일정한 자리를 써서 분이 바뀌어도 밀리지 않습니다. 대화 중에는 시계·코인 칩과 미니맵을 숨기고 대화가 끝나면 해당 장소에 맞춰 다시 표시합니다. 카드와 시계·코인 칩은 **Tools → A305 → Mission → Apply Quest Card**(`QuestCardBuilder`)가 만듭니다. 시계 칸만 갱신하려면 **Apply Game Clock Layout**을 실행합니다. 서버 상태를 받기 전 카드의 할 일 문구(한 줄에 들어가는 "카드를 눌러 퀘스트를 확인하세요.")만 맞출 때는 카드를 다시 만들지 않는 **Apply Quest Card Placeholder**를 씁니다. 마을에서는 왼쪽 아래에 시안(g1)과 같은 유리 미니맵(`Content/MiniMap`, `TownMiniMapView`)을 둡니다. 터치 조작을 보이는 기기(휴대폰·태블릿)에서는 왼쪽 아래 이동 조이스틱과 겹치지 않게 미니맵을 오른쪽 위, 시계·코인 칩과 코인 바뀜 알약 아래로 옮깁니다(`FirstDayMissionView.PlaceMiniMap`). 둥근 창 안에 시안 스타일로 그린 마을 지도 그림(`Art/UI/Map/TownMap.png`)을 깔고, 내 위치가 창 가운데 오도록 그림을 움직이며 위에 내 위치 화살표와 장소 이름표를 얹습니다. 판은 큰 지도와 같은 맑은 하늘색 유리(뒤를 흐리지 않는 유리, 불투명도 0.43)와 흰 테두리이고, 지도 그림은 옛 유리 미니맵처럼 바탕(흰색 0.12)과 인도(흰색 0.28)를 거의 비워 뒤 거리가 비칩니다. 차도(0.7)와 건물·가로수는 진하게 둡니다. 미니맵을 커서나 손가락으로 끌면 지도가 따라 움직여 주변을 둘러볼 수 있고 지도 가장자리에서 멈춥니다. 손을 떼고 3초가 지나면 내 위치로 돌아옵니다(`MiniMapPan`). 끌고 놓았을 때는 큰 지도를 열지 않습니다. 지도 그림은 실제 마을 배치(미션 장소 4곳, 경찰서·빵집·우체국·은행 등 가게, 공원, 가로수, 횡단보도)를 1m = 20단위로 그렸고 북쪽이 오른쪽입니다. 마을 좌표와 그림 좌표 변환, 장소 칸과 출입문 자리는 `TownMapArt`가 정하므로, 마을 배치를 바꾸면 그림과 `TownMapArt`를 함께 고칩니다. 미니맵은 범례 글자 없이 오른쪽 위 펼치기 버튼만 두고, 판 어디를 눌러도 큰 마을 지도(`Content/MapOverlay`, 시안 g7)를 화면 가운데에 펼칩니다. 폰 메뉴의 [마을 지도]도 같은 큰 지도를 엽니다. 큰 지도는 미니맵과 같은 맑은 유리 판과 마을 지도 그림, 내 위치 화살표와 장소 이름표를 쓰고(`TownMiniMapView`, `MiniMapBuilder.MapLayers`), 지도 그림 전체(2.5:1)를 판 폭에 맞춰 한눈에 보입니다. 머리줄에는 하늘색 지도 앱 아이콘(`Art/UI/Map/MapHeaderIcon.png`)·제목·내 위치와 목적지 범례를 두고, 닫기 버튼·Esc·바깥 누르기로 닫습니다. 머리줄 오른쪽의 [길 안내 켬/끔] 버튼(`GuideRouteToggle`)으로 도로 위 길 안내를 켜고 끕니다. 길 안내와 닫기 버튼은 제목 줄의 같은 높이에 나란히 두고, 닫기 버튼의 오른쪽 여백은 지도 내용과 맞춥니다. 길 안내 버튼은 코인 표시처럼 양 끝이 완전한 반원인 알약 모양이며, 두 버튼만 갱신할 때는 **Tools → A305 → Mission → Apply Map Header Controls**를 실행합니다. 퀘스트 카드를 갱신할 때마다 지금 단계의 장소(`FirstDayMissionState.Destination`)를 [길 안내](../Wayfinding/README.md)에 알려(`GuideDestination`), 마을에서 그 건물 출입문 앞이 빛나고 도로 위에 길이 깔립니다. 미션 화면을 끄면(튜토리얼 중) 안내도 멈춥니다. 수첩이나 큰 지도가 열렸거나 마을 밖이면 미니맵을 숨깁니다. 가운데 창이 열리면 펼친 수첩·큰 지도는 닫습니다. 미니맵은 **Tools → A305 → Mission → Apply Mini Map**(`MiniMapBuilder`), 큰 지도까지 함께는 **Apply Live Mini Map**(`FirstDayMissionBuilder.ApplyLiveMiniMap`)이 지우고 다시 만듭니다. 수첩을 열면 캔버스 그리기 순서를 다른 화면(대화창 120, 피드백 130, 단어장 135)보다 높은 1000으로 올려 대화 중에도 가장 위에 보이고, 닫으면 원래 순서(108)로 돌립니다. 마을에서는 상태를 읽을 때마다 서버 `weather`(`CLEAR`/`CLOUDY`/`RAIN` 등)와 `FirstDayMissionState.FallbackWeather`를 [Weather 모듈](../Weather/README.md)의 `WeatherPresenter`에 넘겨 하늘·조명과 날씨 효과를 바꿉니다. `weather`가 없거나 Unity 날씨 목록에 없는 값이면 `FallbackWeather`(`raining`이면 `RAIN`, 아니면 `CLEAR`)를 보여 줍니다. 같은 때 `FirstDayMissionState.OpensUmbrellaIn(sceneCode)`로 플레이어 우산을 펴거나 접습니다. 우산은 드럭스토어 단계(5단계)를 지나면 생기고, 비 오는 마을(`TOWN`)에서만 플레이어가 손에 쥐고 펴 씁니다([Player 모듈](../Player/README.md)의 `UmbrellaHold`). 시연 퀘스트에서는 호텔 직원에게 빌린 우산을 호텔 안과 비가 그친 거리에서는 접어 들고(`CarriesFoldedUmbrellaIn`), 비 오는 거리에서는 펴 씁니다. 시연에서는 택시 안에서 접은 우산도 편 우산도 숨깁니다. 계약·7단계 내용·배포·QA 기준은 [연계 미션 API](../../../../../docs/api/first-day-mission.md)에 있습니다.

지금 단계에서 만나야 하는 행인은 그 단계 동안 정한 자리에서 기다립니다(`QuestNpcWaitSpot`). 비 오는 거리 단계(5/7)의 Ben은 카페에서 나오면 바로 보이도록 카페 출입문 밖 큰길 쪽 보도(`Systems/BenRainWaitSpot`)에서 문을 보고 기다리고, 그날 이미 말을 걸었어도 다가와 대화를 제안합니다. 단계를 마치면 평소 생활로 돌아갑니다. 자리는 **Tools → A305 → Mission → Apply Quest NPC Spots**(`QuestNpcSpotBuilder`)가 둡니다. 다른 장소에 있으면 퀘스트 카드가 갈 곳과 만날 사람("마을 거리에서 행인 Ben에게 물어보세요.")을 보이고, 담당이 아닌 NPC에게 물으면 그 NPC가 지금 만날 사람과 장소를 알려 줍니다.

**Tools → A305 → Mission → Build First Day Journey**가 다섯 공간의 기능 연결, 수첩 프리팹, 상점과 출입구를 준비합니다. 기존 씬 디자인은 유지합니다. `SpaceSceneSetup`도 같은 기능을 연결하므로 공간을 다시 구성해도 연결이 남습니다.

미니맵과 큰 지도는 건물과 공원에 같은 TextMeshPro 이름표를 표시합니다. 그림 좌표 기준 32 크기의 굵은 글씨와 연한 하늘색의 둥근 바탕, 얇은 테두리와 약한 그림자를 사용합니다. 이름표 폭은 32 크기로 잰 글자 폭에 좌우 여백을 더해 정합니다. 여백은 기본 18이며 긴 이름에는 12를 적용합니다. 상하 여백은 6입니다. 현재 목적지 이름표는 따뜻한 금색 배경으로 강조합니다. 목적지가 바뀌거나 지도가 다시 보이면 배경만 두 번 부드럽게 밝아졌다가 금색으로 유지됩니다. 이전 목적지는 원래 색으로 돌아가며, 내 위치 화살표는 가장 앞에 그립니다. **Tools → A305 → Mission → Update Town Map Building Labels**는 기존 지도·표시 연결을 유지하며 두 지도의 이름표를 갱신하고 기존 목적지 테두리를 제거합니다. 지도를 다시 만들 때도 같은 이름표가 적용됩니다.

[이웃]의 [지도에서 보기]로 고른 NPC(`NpcTracking`)는 미니맵과 큰 지도에 같은 핀으로 보입니다(`TownMiniMapView`). 핀은 흰 테두리의 코랄 원에 이름 첫 글자를 쓰고 아래에 이름표를 달며, 건물 이름표 위·내 위치 화살표 아래에 그립니다. 자리는 Npc 모듈의 `NpcLocator`가 정합니다. 마을에 켜진 몸이 있으면 그 몸을 따라가고, 몸이 없으면 일과로 일터 건물 칸 위쪽 가장자리 가운데(`TownMapArt.NeighborPoint`)에 꽂아 건물 아래의 장소 이름표를 가리지 않습니다. 근무지 코드로 건물 칸을 찾는 `TownMapArt.WorkplaceTile`은 미션 장소가 아닌 경찰서도 지도 그림의 경찰서 칸(`TownMapArt.PoliceTile`)으로 찾습니다. 숙소에서 쉬거나 걸어 다녀 자리를 모르면 핀을 숨깁니다. 그 NPC 3m 안에 다가가거나 다른 이웃을 고르면 핀이 사라집니다. 이미 만든 지도에는 **Tools → A305 → Mission → Apply Neighbor Pin**(`MiniMapBuilder.ApplyNeighborPin`)으로 핀만 더합니다.

## 기다리는 카드

카페 음료 주문처럼 대화를 마친 NPC가 무언가를 준비해 곧 건네기로 하면, 왼쪽 위 퀘스트 카드 바로 아래에 기다리는 카드(`Content/FollowUpCard`, `FollowUpCardView`)를 보입니다. 목표가 많아 퀘스트 카드가 길어져 아래에 두면 왼쪽 아래(데스크톱 미니맵, 휴대폰 이동 조이스틱)까지 내려가면, 퀘스트 카드 오른쪽 옆 같은 높이에 둡니다(`FirstDayMissionView`가 매 프레임 왼쪽 열이 내려갈 수 있는 끝을 알림). 아이스 라테·아침 식사·빨래·꽃다발처럼 무엇을 준비하는지는 서버가 정하고(대화 종료 CONV-08의 `followUp`), NPC별 데이터 없이 모든 NPC에 같은 카드를 씁니다. 기다리는 목록은 [Dialogue 모듈](../Dialogue/README.md)의 `FollowUpStore`가 씬 밖에서 기억하고, 다 되면 그 NPC가 제자리에서 부릅니다([Npc 모듈](../Npc/README.md#동작-규칙)).

| 기다리는 것이 있음 | 머리말 "받을 것" 아래 하나마다 한 줄씩, 먼저 되는 것부터 보입니다. 줄에는 동그라미 체크, 받을 것(`itemKo`, "아이스 라테"), 누가 어디서("Mia · 카페"), 남은 시간("0:42")이 있습니다. 남은 시간은 서버가 센 `remainingSeconds`를 받은 때부터 실제로 흐른 시간만큼 줄입니다. |
| 장소 이름 | 마을 매장 직원은 가게 이름("Rosa · 식당"), 그 밖에는 씬 이름(카페·호텔·드럭스토어·집, 마을 거리는 "마을")을 씁니다. 이름은 지도 범례와 같은 `TownMapArt.PlaceName`에서 고릅니다. |
| 다 됨 | 그 줄을 "아이스 라테가 준비됐어요"와 그 아래 "카페 Mia에게 받으러 가세요"로 바꾸고 남은 시간 대신 초록 체크를 보이며, 줄 바탕(강조색)이 두 번 반짝이고 통 튀어 알림임을 알립니다. 반짝임은 한 번뿐이라 씬을 옮기거나 새로고침해 서버 목록으로 다시 맞춰도 다시 반짝이지 않습니다. 카드가 숨어 있던 사이 다 된 것은 카드가 다시 보일 때 반짝입니다. |
| NPC가 건넴 | NPC가 불러 시작한 대화든 [말 걸기]로 먼저 건 대화든, 서버가 첫 대사로 건네면(CONV-01 `deliveredFollowUpId`) 그 줄을 지웁니다. 남은 것이 없으면 카드를 숨깁니다. |
| 새로고침·장소 이동 | 씬에 들어올 때 아직 건네지 않은 것 전부(CONV-13 `GET /api/v1/follow-ups`)를 다시 받아 맞춥니다. 받지 못하면 기억하던 것을 그대로 둡니다. |
| 돌발 부탁 | 대화 중 NPC의 부탁을 수락하면(`FavorStore`의 `ACCEPTED`·`GOT`) 기다리는 것보다 위 첫 줄에 부탁 제목("Jake의 부탁 · 크루아상 사다 주기"), 다음 할 일("Maple Bakery에서 크루아상 포장 주문하기" → 산 뒤 "Jake에게 돌아가기"), 남은 시간을 보입니다. 남은 시간은 게임 시각 기한(`expiresAtGameMinute`)까지를 대화 밖에서 흐르는 실제 시간(게임 하루 = 600초)으로 바꾼 값입니다. 산 것을 받으면 초록 체크로 바뀝니다. 그 줄의 X는 부탁을 그만둡니다(FAV-02). 글자는 `FavorCard`가 만듭니다([NPC 생활·관계 설계](../../../../../docs/npc-life-design.md) 7.11). |
| 숨김 | 기다리는 것이 없을 때, 미션 화면을 끈 동안(튜토리얼), 수첩·퀘스트 목록·큰 지도를 연 동안 숨깁니다. 퀘스트 카드처럼 대화 중에는 보입니다. |
| 가운데 창 | 카드는 퀘스트 카드와 같은 폭이고 퀘스트 카드 아래에 이어집니다. 단어장이나 피드백을 열면 가운데 창이 카드 일부를 가릴 수 있습니다. |

돌발 부탁의 길 안내도 이 모듈이 정합니다. 수락한 심부름은 가게를 목적지 안내(`GuideDestination`)로 가리키며 퀘스트 목적지보다 먼저 보이고, 산 것을 받은 뒤에는 부탁한 NPC를 [이웃]의 찾는 이웃 표시(`NpcTracking`)로 가리킵니다. 부탁을 들어주면(`FavorStore.Completed`) 부탁한 NPC의 생활 욕구를 채우고(`NpcLives.Find` → `FillForFavor`, 대화 중이면 이름 옆 게이지도 다시 그림), 대화를 마친 뒤 늘어난 코인을 "Jake의 부탁 +6코인" 영수증으로 보입니다(`CoinChange`).

카드는 퀘스트 카드와 같은 테마 유리(`UiThemeRole.Panel`)·폭(시안 410px × 1.2)·글꼴(Jua·Pretendard)과 목표 줄의 체크 그림(`Art/UI/Hud/CheckEmpty`·`CheckDone`)을 쓰고, 알림만 보이는 카드라 누르기를 받지 않습니다. 줄 글자는 `FollowUpCardText`, 한 줄의 표시와 반짝임은 `FollowUpRowView`가 맡습니다. **Tools → A305 → Mission → Apply Follow-up Card**(`QuestCardBuilder.ApplyFollowUpCardToPrefab`)가 `Prefabs/Mission/FirstDayMission.prefab`에 카드를 지우고 다시 만들어 연결하며, **Apply Quest Card**도 마지막에 같은 카드를 만듭니다. 공간 씬은 이 프리팹을 그대로 쓰므로 씬마다 따로 놓지 않습니다.

## 의자·벤치·소파 앉기

장소 씬에서 호버 단어가 의자(`chair`)·벤치(`bench`)·소파(`sofa`)·스툴(`stool`)·이발 의자(`barber chair`)인 가구에는 모두 같은 조작으로 앉습니다. 침대와 계단은 앉는 가구로 보지 않습니다. 앉을 자리마다 `RestSeat`가 하나씩 있고, 벤치·소파는 가구 폭 방향으로 여러 자리를 둡니다. 카페는 의자 6자리와 소파 4자리 모두 주문 후 5초 착석을 같은 퀘스트 휴식으로 인정합니다. 식당(`MapleDinerInterior`) 부스·스툴은 주문 대기를 세는 `DinerMealRest`가 따로 앉힙니다. 쉬는 NPC도 같은 자리에 앉으므로(`INpcSeat`, [Npc 모듈](../Npc/README.md#생활)) 한 자리에는 한 명만 앉습니다.

| 상황 | 동작 |
| --- | --- |
| 자리에서 1.55m 안에 섬 | 가장 가까운 자리 하나에만 [잠깐 앉기]를 띄웁니다(`RestSeatPicker`). 버튼이나 E 키로 앉습니다. 대화 중, 이동 잠금 중, 행인 제안이나 다른 [말 걸기]가 떠 있으면 띄우지 않습니다. |
| NPC가 앉은 자리 | 그 자리는 빼고 남은 자리 중 가장 가까운 자리에 띄웁니다. NPC는 플레이어가 앉은 자리에 앉지 않습니다. |
| 앉음 | 모든 자리에서 [일어서기]를 띄우고, 버튼이나 E 키를 누를 때까지 앉아 있습니다. 일어서면 앉기 전에 서 있던 곳으로 돌아갑니다. 카메라는 플레이어가 다가온 쪽에서 앉은 캐릭터를 봅니다. 자세와 카메라는 [Player 모듈](../Player/README.md)의 `PlayerSeatPose`가 맡습니다. |
| 미션 휴식 | 미션이 휴식을 세는 동안(`SetAvailable(..., mealWait: true)`)에는 같은 자리에서 앉은 시간을 셉니다. 앉은 뒤에 미션이 세기 시작하면 그때부터 셉니다. 5초(`SeatedMealTimer.RequiredSeconds`)를 채우면 `RestCompleted`를 한 번 알리고 일으키며, 그 전에 [일어서기]를 누르면 세지 않습니다. |
| 카페 | 첫날 미션이 상태를 읽기 전과 서버 요청 중에는 앉기를 막습니다. 주문 뒤 첫 휴식(`CountsAsCafeRest`)일 때 미션 휴식을 세고, 채우면 서버에 휴식을 보냅니다. |
| 카페 밖 장소 | 집·마을·호텔·마을 매장·경찰서에서는 미션 상태와 상관없이 앉고, 미션 휴식으로 세지 않습니다(`FirstDayMissionState.ManagesSeatsIn`). 서버도 마지막 장소가 카페일 때만 휴식을 받습니다. |

## 튜토리얼용 기본 미션

기존 `MissionBoard`·`MissionPanelView`는 첫날 미션 화면이 없는 장면(서버 없는 데모)에 유지합니다. 튜토리얼은 이 창을 안내하지 않고 마지막에 첫날 미션의 퀘스트 카드를 안내합니다. 이 경로는 키워드를 사용하며 서버 연계 여정의 완료 판정에 사용하지 않습니다. 튜토리얼이 오늘의 목표 단계에 이르거나 끝나면 `MissionController.SetStoryAvailable`로 기본 창을 숨기고 새 수첩을 표시합니다. 퀘스트 카드를 눌러 수첩을 열면 `FirstDayMissionView.JournalOpened`로 알립니다. 아래는 이 기본 미션 경로의 구성입니다.

## 동작 규칙

| 상황 | 동작 |
| --- | --- |
| [미션 시작] | 그 미션을 진행 중으로 바꿉니다. 진행 중인 다른 미션이 있으면 바꾸고, 미션 창 안내에 "'A' 대신 'B' 미션을 시작했어요"로 멈춘 미션을 함께 알립니다. |

| 완료한 미션 | [미션 시작]이 사라지고 다시 시작할 수 없습니다. |

미션 창을 언제 보일지는 이 모듈이 정하지 않고, 튜토리얼 같은 진행 흐름이 `MissionController.SetPanelVisible`로 정합니다. 화면 정렬 순서는 105입니다.

카페 의자·소파의 좌석 연결은 `A305.Mission.Tests`에서 검사합니다. PlayMode의 카페 검증은 실제 씬을 사용하고 API 응답은 대체 구현으로 처리합니다.

실행 방법은 [프론트엔드 개발 지침](../../../../AGENTS.md)을 따릅니다.

메이플 버거에서는 `DinerMealRest`가 부스 4곳과 카운터 스툴 4개에 앉기를 연결합니다. 퀘스트 시작 전이나 다른 단계에서도 가까이 가서 [잠깐 앉기]를 누르고, [일어서기]로 원래 위치에 돌아옵니다. 부스와 스툴은 각각의 높이·깊이에 맞춰 자세와 시점을 잡습니다. 자유 착석은 음식 수령이나 퀘스트 진행을 발생시키지 않습니다.

식당 마을 퀘스트에서 주문 후 대화를 끝내고 앉으면 `SeatedMealTimer`가 실시간 5초를 누적하며 일어선 시간은 제외합니다. 준비 배지는 서비스 테마를 따르고 시간 안내문은 별도로 늘리지 않습니다. 수령 실패 시 자동 반복 호출하지 않고 [음식 받기]로 다시 시도합니다. 완료 후 서버 상태로 쏟은 사건을 엽니다. 첫날 카페 주문 후 휴식도 실제 착석 5초로 셉니다. 그 밖의 착석은 시간을 세지 않고 [일어서기]를 누를 때까지 앉아 있습니다. 착석 중에는 해당 NPC의 ‘받을 것’ 남은 시간을 착석 타이머에 맞추고, 완료하면 해당 주문만 카드에서 즉시 지워 별도 1분 대기를 남기지 않습니다. CONV-14로 서버에도 저장하며 저장 실패 시 다음 목록 갱신에서 재시도합니다. 늦게 도착한 목록은 이미 받은 주문을 다시 띄우지 않습니다.

[잠깐 앉기]·[일어서기]·[음식 받기]에는 공용 상호작용 버튼의 말풍선을 표시하지 않습니다.

후속 매장은 따로 장면이지만 서버 장소는 마을(`TOWN`)이므로, 미니맵은 씬 코드뿐 아니라 지금 장면이 마을 매장인지(`PlaceScenes.IsTownShop`)를 확인합니다. 매장 장면에서는 미니맵을 숨기고 비가 와도 우산을 펴지 않으며, 대화·큰 지도·다른 창의 기존 숨김 조건도 유지합니다.
