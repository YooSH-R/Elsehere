# Npc 모듈

NPC 몸·이름표 클릭은 “이름에게 말을 걸까요?” 확인 창을 엽니다. 수락(E)을 선택한 뒤에만 사용자 시작(`initiatedBy: USER`) 대화를 만들고, 취소(Esc)하거나 거리 밖으로 나가면 요청을 보내지 않습니다. NPC가 먼저 보낸 이벤트 제안은 기존 용건을 유지하며 클릭만으로 수락하지 않습니다.

평소 가까이 있다는 이유만으로 대화 제안을 띄우지 않습니다. 먼저 다가오는 제안은 튜토리얼·퀘스트가 NPC를 기다리게 한 경우와 근무 중인 직원의 카운터 응대에 쓰며, 준비물이 완성된 후속 이벤트는 기존 `TryCall` 경로로 알립니다.

플레이어에게 먼저 다가와 대화를 제안하는 행인과, 대화하지 않는 동안 NPC가 일과와 욕구에 따라 지내는 [생활](#생활)을 담당합니다. 먼저 다가오는 제안은 튜토리얼·퀘스트, 카운터 응대나 후속 이벤트가 있을 때 사용합니다. 플레이어는 8m 안의 NPC 몸이나 머리 위 이름표를 클릭·탭해 대화 시작을 확인합니다(기능 명세 F-22). 가까이 가는 것만으로는 말 걸기 버튼을 표시하지 않습니다. PC에서는 커서를 올린 NPC에 테두리를 그립니다([클릭·탭으로 말 걸기](#클릭탭으로-말-걸기)).

이 서비스의 진행 흐름을 다루는 게임 전용 기능입니다. 플레이어 위치·이동 잠금은 `A305.Player`, 대화 시작·종료는 `A305.Dialogue`의 공개 API로 요청합니다.

## 구성

`Passerby`는 제안 수락 여부와 별개로 `DialogueController.IsTalkingTo`가 가리키는 실제 대화 상대를 멈추고 플레이어를 바라보게 합니다. 복습처럼 제안 없이 시작하는 대화도 같은 정지·대화 카메라를 유지하며, 대화가 닫히면 생활을 다시 진행합니다. 복습에는 본편의 대화 시작·종료 이벤트를 보내지 않습니다.

대화 중에는 `NpcDialogueVisibility`가 대화 상대 이외 NPC의 Renderer만 숨깁니다. `NpcIdentity`가 자동으로 붙이므로 출퇴근 중 새로 나타나는 NPC에도 적용됩니다. 생활·이동·충돌과 Renderer의 `enabled` 상태는 유지하고, 대화 종료·컨트롤러 제거·NPC 비활성화 때 기존 `forceRenderingOff` 값을 복원합니다. 머리 위 이름표는 기존 이동 잠금 기준으로 숨깁니다.

| 파일 | 역할 |
| --- | --- |
| `PasserbyApproach` | 기다림 → 다가감 → 제안 → 대화 → 쉼으로 상태를 바꾸고, 클릭으로 먼저 말을 걸 수 있는지 정합니다. 준비해 둔 것이 다 되면 제자리에서 부르는 제안(`TryCall`)도 맡습니다. Unity 객체 없이 테스트합니다. |
| `PasserbyRules`, `PasserbySettings` | 감지·제안·무시 거리, 쉬는 시간, 거절 가능 여부, 하루에 한 번만 다가오기, 준비해 둔 것을 건네려고 부르는 거리(기본 6m), 걷는 속도. 설정은 데이터 에셋입니다. |
| `Passerby` | 행인을 걷게 하고 제안 화면·대화와 연결합니다. 다가오지 않는 동안 `NpcRoutine`이 있으면 생활을 맡깁니다. 모델은 `Visual` 아래, 이동은 루트의 `CharacterController`가 맡습니다. |
| `NpcIdentity` | NPC 키(ERD `npcs.code`)와 머리 위치(`LookTarget`). 실행 시 해당 NPC의 공통 음성·표정 연결을 준비합니다. |
| `PasserbyOfferView` | NPC의 대화 제안과 플레이어의 대화 시작 확인 창을 표시합니다. 보이는 창은 E로 수락하고 Esc로 취소하며, 거절할 수 없는 튜토리얼 제안은 Esc로 닫히지 않습니다. 데스크톱의 대화하기 버튼에는 상호작용 안내와 같은 테두리 있는 E 키 모양을 붙이고, 거절 버튼에는 [Esc]를 표시합니다. 터치 화면에서는 키 안내를 숨깁니다. **Tools → A305 → Npc → Apply Offer Shortcuts**로 안내를 갱신합니다. 공용 `TalkPrompt` 영역은 택시·앉기 등 다른 상호작용에도 쓰므로 유지하지만, NPC에게 가까이 갔을 때 말 걸기·가입 버튼을 띄우는 데는 쓰지 않습니다. 말풍선은 대화하기·말 걸기와 기사와의 대화를 시작하는 택시 타기에 표시합니다. 앉기·일어서기·음식 받기·가입 안내·대화 불가·이벤트 확인은 말풍선 없이 표시합니다. |
| `NpcClickTalk` | NPC 몸이나 머리 위 이름표를 클릭·탭하면 말을 걸지 확인합니다. 8m(`ReachMeters`) 안에서 말을 걸 수 있는 NPC만 받고, PC에서는 커서를 올린 그 NPC에 테두리를 그립니다. 누른 자리의 맨 위 UI가 이름표면 그 이름표의 NPC를(`NpcNameTagView.NpcOf`), 다른 UI면 막고, UI가 없으면 맨 앞에 보이는 NPC 몸을 고릅니다. 제안 화면 프리팹(`PasserbyOffer`)에 붙어 있어 장소 씬을 고치지 않고도 NPC가 있는 모든 장소에서 동작합니다(`NpcBuilder.PrepareAssets`). |
| `NpcPointerRaycast` | 클릭·탭한 방향에서 맨 앞에 보이는 것이 NPC 몸일 때만 그 NPC를 찾습니다. 플레이어 몸과 보이지 않는 감지 영역은 지나치고, 사물 카드가 뜨는 영역(`ObjectHoverHitArea`)이 앞에 있으면 사물을 누른 것으로 봅니다. |
| `RendererOutline` | 대상 아래 모든 몸 그림에 테두리 재질(`Art/Npc/NpcHoverOutline.mat`, 셰이더 `A305/NpcHoverOutline`)을 하나 더 붙였다가 원래 재질 목록으로 되돌립니다. 재질 에셋은 바꾸지 않습니다. 테두리 색·두께는 재질에서 조정합니다. |
| `GuestSignupDialogView` | 게스트 가입 안내 창. 가입하면 대화·단어·NPC와의 사이가 이어지며 [Google로 가입하기]는 같은 탭에서 Google 로그인을 엽니다. 일일 대화 한도 소진 시에는 가입을 유도하지 않습니다. |
| `PasserbyOfferText` | 제안 화면 문구. 머리말은 대화 대본의 이름과 역할을 함께 받아 "Mia(카페 직원)의 대화 제안"으로 보입니다. 이름이나 역할만 있으면 그 이름·역할 뒤에 받침에 맞는 조사를 붙여 "카페 직원이 말을 걸었어요"처럼 보이고, 둘 다 없으면 "누군가 말을 걸었어요"입니다. 택시의 기사에게 말 걸기 버튼도 이 모듈의 문구를 사용합니다. 준비해 둔 것을 건네려고 부를 때는 "Mia이(가) 불러요"와 "기다리던 아이스 라테가 준비됐어요"이고, 조사는 받침에 맞춥니다(`SubjectParticle`). |
| `PasserbyRestRecord` | 행인별로 다시 다가올 수 있는 시각을 공간이 바뀌어도 기억합니다. |
| `PasserbyOfferRecord` | 하루에 한 번만 다가오는 행인이 마지막으로 먼저 말을 건 날짜(기기 날짜)를 기억합니다. 게임을 껐다 켜도 이어지게 이 기기(Web 빌드는 브라우저)의 `PlayerPrefs`에 저장합니다. |
| `PoliceReportDesk` | 경찰서 창구. 서버가 문맥으로 판정한 출동 응답을 받아 화면 위쪽 상태 판에 신고 장소를 보입니다. NPC가 대화를 끝낸 턴도 접수하며, 무례한 말과 신고가 아닌 말에는 서버가 출동 응답을 보내지 않습니다. 대화를 닫으면 사용자 턴 ID·담당 경찰관·목적지를 `PoliceDispatchOrder`에 보관하고, 경찰서를 나와 마을이 열리면 순찰차(`PoliceCar`)가 순서대로 출동합니다. 같은 턴 ID는 중복 접수하지 않으며, 출동을 맡은 경찰관은 귀환 전까지 창구에 나타나지 않습니다. 접수 문구의 장소 이름은 순찰차 목적지와 같은 목록을 Builder가 옮겨 둡니다. |
| `TaxiRide` | 본길을 도는 택시의 수평 반경 8m 안에서 방향과 관계없이 탑승할 수 있습니다. 현재 위치에 세워 바로 태우고 기사와 대화하게 합니다. 버튼은 공용 `TalkPrompt` 영역에 뜹니다. 태우지 못하면 선 택시 곁에 [기사에게 말 걸기]를 보입니다. `IsHailAllowed`가 false면(튜토리얼 동안) [택시 타기]를 보이지 않습니다. 어떤 버튼을 보일지는 `TaxiPrompt`가 고릅니다. |
| `NpcLifeData`, `NpcLife` | 생활 데이터(`Data/Npc/NpcLife.json`)와 NPC 한 명의 일과 활동·욕구·할 일 고르기. AI 하루 시뮬레이션과 같은 규칙이며 Unity 객체 없이 테스트합니다. |
| `NpcRoutine` | 다가오지 않는 동안 `NpcLife`가 고른 사물까지 걸어가 쓰고, 의자·벤치·소파면 앉습니다. 착석 중에는 `SeatedArms`로 양손을 허벅지 앞에 두고 일어서면 기존 팔 자세를 복원합니다. 걷기·애니메이션은 `Passerby`의 것을 씁니다. 구역(`stayInArea`·`area`)을 켜면 그 안의 사물·자리만 고릅니다. 켜질 때마다 장면의 사물·자리를 다시 모으는데, 장면 전체 찾기는 한 프레임에 한 번만 하고 같은 프레임에 켜지는 NPC가 함께 씁니다(교대 시각에 여럿이 켜질 때 멈춤 방지, 장면을 불러오거나 내리면 다시 찾음). 사물 크기는 구역을 볼 때만 잽니다. |
| `NpcDuty` | 직원이 지금 근무 중인지(교대 밖이면 근무 외)와 같은 카운터를 맡은 직원 중 누가 응대할지 정합니다([일터와 응대](#일터와-응대)). Unity 객체 없이 테스트합니다. |
| `NpcWhereabouts` | [이웃] 정보 카드의 지금 위치 한 줄. 같은 게임 시각이면 어느 장면에서 보든 같도록 일과(`NpcDayPlan`)로 근무(○○에서 일하고 있어요)·짧은 휴식(○○ 앞에서 잠깐 쉬고 있어요)·출근(○○으로 출근하는 길이에요)·퇴근·마을에서 쉼·숙소(행인은 집)에서 쉼을 고릅니다. 행인과 근무지가 마을인 NPC는 마을을 돌아다니고, 택시 기사는 택시를 몹니다. 서버 장소는 거리 매장 직원을 모두 마을로 두므로 근무지 코드(`NpcLifeEntry.Workplace`)의 한글 이름(빵집·오락실 등)은 여기 둡니다. Unity 객체 없이 테스트합니다. |
| `NpcLocator`, `NpcTracking` | [이웃]의 [지도에서 보기]. `NpcLocator`는 고른 NPC의 지금 자리를 정합니다. 플레이어가 마을에 있고 그 NPC의 몸이 켜져 있으면 몸(`Body`)을 먼저 따르고, 몸이 없으면 일과로 근무 중·짧은 휴식은 일터(`Workplace`), 숙소 휴식은 `Resting`, 걸어 다니는 중이거나 행인·마을 거리 직원·택시 기사처럼 정해진 건물이 없으면 `Unknown`으로 둡니다. `NpcTracking`은 찾는 NPC 한 명(키·이름·생활 데이터)을 장면을 옮겨도 기억하고, 다른 이웃을 고르면 바뀌며, 플레이어가 그 NPC 3m 안에 오면 찾기를 끝냅니다. 지도 핀은 Mission 모듈이, 머리 위 표시는 `NpcNameTagView`가 이 값을 봅니다. 둘 다 Unity 객체 없이 테스트합니다. |
| `NpcDetailDistance` | 카메라가 12m 안에 있을 때만 NPC의 팔 관통 보정(`LittleMungArmClearance`)을 켭니다. 이 보정은 매 프레임 피부 정점을 계산합니다. 머리 정점을 모두 계산하던 때는 캐릭터 하나에 수 ms가 들어 마을을 걷는 NPC 모두에게 돌리면 마을이 느려졌습니다(마을 NPC 16명 기준 한 프레임 약 125ms). 지금은 머리·몸통의 바깥 끝 정점만 계산합니다([Player 모듈](../Player/README.md)). 공용 `Passerby.prefab`에 붙어 있어 이 프리팹으로 놓는 NPC가 모두 받습니다. 앉아 있는 동안에는 `StandingPoseCorrections`가 보정을 꺼 두므로 건드리지 않고, 일어선 뒤 거리에 맞춥니다. |
| `NpcNameTags`, `NpcNameTagView` | 플레이어에서 8m 안의 NPC 머리 위 이름표. 근무 중인 직원(생활 데이터 역할 `STAFF`, 일과 `WORK`)은 이름 위 파란 칩에 역할(예: 벨보이·경찰관)을 함께 보이고, 행인과 쉬는 시간·퇴근한 직원은 이름만 보입니다(`NpcRoutine.IsOffDuty`, 첫날 미션이 찾아가라는 직원은 근무 중으로 봄). 이름·역할은 대화 대본(`Data/Dialogue/MockDialogueScripts.asset`)에서 읽고, 이름이 없는 NPC는 띄우지 않습니다. 대화나 창 때문에 플레이어가 움직이지 못하는 동안에는 숨깁니다. [이웃]에서 찾는 NPC(`NpcTracking`)는 거리와 상관없이 이름표를 띄우고 이름 위에 코랄 '찾는 이웃' 표시(`Tracked`)를 답니다. 지도 핀과 같은 색이며, 3m 안에 다가가면 찾기를 끝내 표시를 거둡니다. NPC마다 3D 글자판을 두지 않고 제안 화면 프리팹(`PasserbyOffer`)의 `NameTags` 층 한 장에서 그립니다. 이 층은 다른 화면 UI와 휴대폰 터치 조작판(-10)보다 아래(-20)에 놓이고, 이름표 바탕 전체가 클릭을 받아 그 NPC에게 말을 겁니다([클릭·탭으로 말 걸기](#클릭탭으로-말-걸기), **Tools → A305 → Npc → Apply Name Tags**). 나란히 선 NPC의 이름표는 서로 겹칠 수 있으며, 카메라에서 가까운 NPC 이름표를 위에 그립니다. 매 프레임 NPC를 훑을 때 장면 전체를 찾지 않도록 `NpcIdentity.Active`(지금 켜진 NPC 목록)를 씁니다. 판단은 EditMode `NpcNameTagsTests`가 Unity 객체 없이, 제안 화면 프리팹의 이름표 층 연결·그리는 순서·클릭 받기는 `NpcNameTagPrefabTests`가, 실제 마을 장면은 PlayMode `NpcNameTagViewTests`가 확인합니다(가까운 경찰관의 역할 칩, 쉬는 시간의 경찰관과 행인은 이름만, 먼 NPC·움직이지 못할 때는 없음, 찾는 이웃은 멀리서도 표시와 함께 보이고 3m 안에 오면 찾기를 끝냄). 이름표 클릭과 겹친 이름표는 `NpcClickTalkTests`가 확인합니다. |
| `NpcStayArea` | 구역을 켠 NPC가 고를 수 있는 위치인지 정합니다. Unity 장면 없이 테스트합니다. |
| `NpcWalkArea` | Builder가 장면마다 구운 NPC 바닥(NavMesh)을 장면이 켜져 있는 동안 등록합니다. |
| `NpcWalkRoute` | 마을 NPC가 다음에 향할 길 지점과 출퇴근 경로를 고릅니다. 인도만으로 갈 수 있는 목적지는 횡단보도를 밟지 않는 인도 길로 가고, 인도 길이 건너는 길의 1.25배+1.5m보다 길 때만 길을 건넙니다. 건너는 길에서도 횡단보도 바닥을 인도의 두 배 거리로 쳐서 건너기 전후에 횡단보도 끝자락을 밟지 않게 합니다. 정한 길이 앞으로 0.6m 안에서 횡단보도로 들어가는지와 건너는 방향, 발밑이 인도인지도 알려 줍니다. 횡단보도 경계선을 따라 붙어 가는 구간은 들어가는 것으로 보지 않습니다. 실제 마을 보행 데이터로 EditMode `NpcWalkRouteTests`가 확인합니다. |
| `NpcAnimation`, `NpcAnimations` | 사물을 쓰는 동안 재생할 동작(일하기·물건 집기·앉기)을 행동 이름으로 고릅니다. 값은 NPC 전용 Animator의 `Action` 번호와 같습니다. |
| `INpcSeat` | NPC도 앉을 수 있는 자리. [Mission 모듈](../Mission/README.md#의자벤치소파-앉기)의 `RestSeat`가 구현합니다. |

| 튜토리얼이 플레이어를 붙잡아 이 행인을 기다리게 함(`IsPlayerWaiting`) | 이동이 잠긴 플레이어에게도, 감지 거리 밖에서도 다가가고 멀다고 그만두지 않습니다. |

| 기다리거나 쉬는 NPC에게 가까이 감 | 말 걸기 버튼이나 키 안내를 표시하지 않습니다. NPC 몸이나 이름표를 클릭·탭하면 대화 시작 확인 창을 엽니다. |
| 다른 대화 중이거나 다른 행인이 제안 중 | 다른 대화 중에는 클릭 대화를 시작할 수 없습니다. 다른 행인의 제안 중 클릭은 아래 [클릭·탭으로 말 걸기](#클릭탭으로-말-걸기) 기준을 따릅니다. |
| 남은 대화 | 게스트에게는 대화 제안·시작 확인 창에 "게스트 남은 대화 2번"을 보입니다(AI-01 `remainingConversations`). 가입 사용자는 대화 횟수 제한이 없어 보이지 않습니다. |
| 게스트가 대화 횟수를 다 씀 | 먼저 다가오지 않고, 가까이 가도 버튼을 띄우지 않습니다. NPC 몸이나 이름표를 클릭·탭하면 대화 대신 가입 안내 창(`GuestSignupDialogView`)을 엽니다. |
| 대화에서 준비해 주기로 한 것이 다 됨 | 음료·식사·빨래처럼 서버가 대화 종료에서 알려 준 것([Mission 모듈의 기다리는 카드](../Mission/README.md#기다리는-카드))이 다 되고 플레이어가 그 NPC의 부르는 거리(기본 6m) 안에 있으면, NPC가 자리를 떠나지 않고 같은 제안 화면으로 "Mia이(가) 불러요"·"기다리던 아이스 라테가 준비됐어요"를 보입니다. 직원은 일터를 떠나지 않고 그 자리에서 플레이어 쪽으로 돌아섭니다. 하루 한 번 다가오기·카운터 자리·대화 뒤 쉬는 시간과 상관없이 부르고, 부른 것은 그날 먼저 말을 건 것으로 세지 않습니다. 다른 대화·제안 중이거나 새 대화를 시작할 수 없으면 부르지 않습니다. |
| 부른 제안에 [대화하기] | NPC가 건 대화(`ConversationInitiator.Npc`)로 시작하고, 서버가 첫 대사로 건넵니다(CONV-01 `deliveredFollowUpId`). 클릭·탭으로 먼저 말을 걸어도 서버가 같은 방법으로 건넵니다. 어느 쪽이든 기다리는 카드에서 그 줄이 사라집니다. |
| 부른 제안에 [지금은 안 할래요]·부르는 거리 밖으로 감 | 제안을 닫고, 쉬는 시간이 지나면 아직 남아 있을 때 다시 부릅니다. 불러서 대화했는데 건네지 못해 남아 있어도 쉬는 시간이 지난 뒤에 다시 부릅니다. |
| 다른 이유로 새 대화를 시작할 수 없음 | NPC를 클릭해도 대화를 시작하지 않습니다. |

- 마을 행인 Ben은 튜토리얼에서 길을 묻는 사람과 같은 사람입니다. 튜토리얼 진행(`TutorialDirector`)이 단계마다 `Passerby.SetTutorialScript`를 불러, 튜토리얼 중에는 튜토리얼 대본·인사말(키 `TUTORIAL_PASSERBY`)과 튜토리얼 설정으로 집 앞에서 길을 묻고 생활하지 않게 합니다. 튜토리얼을 마치면 NPC 키로 평소 대화하고 평소 설정으로 생활합니다. 튜토리얼에서 길을 물은 것도 그날 먼저 말을 건 것으로 세므로, 튜토리얼을 마친 그 게임 날에는 다시 다가오지 않습니다.
- 카페 직원은 새 컴포넌트 없이 행인 프리팹을 쓰고, 걷는 속도 0이라 플레이어에게 걸어가지 않습니다. 플레이어가 카운터 앞 2m 안에 오면 카운터 뒤 자리로 돌아가([생활](#생활)) 매대 끝을 포함해 응대 구역 안에서 대화를 제안합니다. 행인과 직원이 같은 제안 화면을 쓰므로 머리말은 대화 대본의 이름과 역할을 함께 보여 누가 말을 걸었는지 알립니다.

- NPC 키는 ERD `npcs.code`와 같아야 하므로 서버 시드 데이터와 맞춥니다. 이름·성격·대사는 서버 데이터입니다.
- 퀘스트에서 이 행인을 만나야 하는 동안에는 `Passerby.WaitAt`으로 정한 자리에 붙잡아 둡니다. 그 자리로 옮겨 생활 대신 그 자리를 지키고, 거절하면 그 자리로 돌아가며, 그날 이미 말을 걸었어도 다가와 제안합니다. `StopWaiting`으로 풀면 평소 생활로 돌아갑니다. 자리는 [Mission 모듈](../Mission/README.md)의 `QuestNpcWaitSpot`이 정합니다.
- 행인이 다가와도 되는지는 `Passerby.IsApproachAllowed`로 진행 흐름이 정합니다. false면 플레이어가 바쁠 때처럼 다가오지 않고 클릭 대화도 받지 않으며, 이미 제안 중이면 제안을 거두지 않습니다. 지금은 [Tutorial 모듈](../Tutorial/README.md)이 튜토리얼 동안 Ben만 Ben 만나기·길 안내 단계에서 다가오게 하고, 다른 NPC는 누구와 말해야 하는지 헷갈리지 않게 튜토리얼을 마친 뒤 다가오게 합니다. 하루에 한 번만 먼저 다가오는 행인도 튜토리얼에서 플레이어가 기다리며 붙잡혀 있으면(`IsPlayerWaiting`) 그날 이미 말을 걸었어도 다가옵니다.
- 거절하거나 대화를 마친 뒤에도 클릭·탭으로 다시 대화를 확인할 수 있으므로, 쉬는 시간과 하루 한 번 제한은 NPC가 다시 먼저 다가오는 것에만 씁니다. 준비해 둔 것을 건네려고 부르는 것은 이 제한을 받지 않고, 부른 것을 거절·무시했을 때만 쉬는 시간을 기다립니다.

### 클릭·탭으로 말 걸기

NPC 몸이나 머리 위 이름표를 클릭(휴대폰·태블릿은 탭)해 원하는 NPC에게 말을 겁니다(`NpcClickTalk`). 이름표를 누르면 그 NPC 몸을 누른 것과 같고, 가까이 가도 별도의 말 걸기 버튼은 뜨지 않습니다.

| 상황 | 동작 |
| --- | --- |
| PC에서 8m 안의 말을 걸 수 있는 NPC나 그 이름표에 커서를 올림 | 그 NPC의 몸·옷·머리 둘레에 옅은 노란 테두리를 그립니다. 커서가 떠나거나, 8m 밖이거나, 말을 걸 수 없는 상태가 되면 지웁니다. 휴대폰·태블릿에는 커서가 없어 테두리를 그리지 않습니다. |
| 8m 안의 기다리거나 쉬는 NPC, 다가오는 NPC를 클릭·탭 | "이름에게 말을 걸까요?" 확인 창을 엽니다. [대화하기]나 E를 눌러야 사용자 시작 대화(CONV-01 `initiatedBy: USER`)를 만들며, 취소하거나 거리 밖으로 나가면 요청하지 않습니다. |
| 다가와 제안하는 NPC를 클릭·탭 | 기존 제안 창을 유지합니다. 클릭만으로 수락하지 않고 [대화하기]나 E로 수락합니다(`ConversationInitiator.Npc`). |
| 다른 NPC가 제안하는 중에 다른 NPC를 클릭·탭 | 제안한 NPC는 거절한 것처럼 쉬고, 누른 NPC의 대화 시작 확인 창을 엽니다. 거절할 수 없는 제안(튜토리얼 Ben)이 떠 있으면 반응하지 않습니다. |
| 대화를 다 쓴 게스트가 클릭·탭 | 대화 대신 가입 안내 창을 엽니다. |
| 8m보다 멀거나, 다른 대화 중이거나, 창이 열려 이동이 잠겼거나, 진행 흐름이 막은 NPC(`IsApproachAllowed` false) | 반응하지 않고 테두리도 그리지 않습니다. |
| 화면을 끌어 시점을 돌림, UI 위를 누름 | 사물 카드와 같은 기준으로 클릭으로 보지 않습니다. 화면을 덮는 터치 조작판 위의 탭은 받습니다. |
| NPC 앞을 벽이나 사물 카드가 뜨는 사물이 가림 | NPC를 고르지 않습니다. 사물이면 사물 카드가 뜹니다. 플레이어 몸과 문턱 같은 보이지 않는 감지 영역은 지나칩니다. |
| 이름표 위에 커서를 올리거나 이름표를 누름 | 이름표 바탕 전체(이름·역할 칩 포함)가 클릭을 받습니다. 이름표가 사물 앞에 떠 있어도 사물 카드는 뜨지 않고 그 이름표의 NPC만 고릅니다. |
| 나란히 선 NPC의 이름표가 겹친 곳을 누름 | 카메라에서 가까운 NPC 이름표가 위에 그려지고, 그 NPC에게 말을 겁니다. |
| 메뉴·창·HUD 버튼이 이름표를 덮음 | 이름표는 다른 화면 UI보다 아래에 그려지므로 덮은 UI를 누른 것으로 보고 말을 걸지 않습니다. |

이름표 층(`NameTags`)은 휴대폰 터치 조작판(정렬 -10)보다 아래(-20)에 그립니다. 이름표가 클릭을 받아도 이름표 위에서 시작한 끌기는 조작판이 받아 시점·이동이 그대로 되고, 탭만 이름표 클릭으로 봅니다. PC의 시점 끌기는 끌기를 받는 UI(스크롤 목록 등)만 막으므로 이름표 위에서도 됩니다(`UiDragTarget`).

거리는 수평 거리로 재고, 8m는 사물 카드를 띄우는 최대 거리와 같습니다. 택시 기사는 지금처럼 [택시 타기]·[기사에게 말 걸기]로만 부릅니다(`Passerby`가 아닌 NPC는 클릭 대상이 아닙니다).

## Ben의 외형과 걷기

Ben(`TOWN_PASSERBY`)은 마스터 골격(Humanoid)의 비즈니스맨 외형을 씁니다([Builder](#builder)). 정지·걷기·벤치 앉기는 다른 Humanoid NPC와 같은 `NpcLife` 컨트롤러로 재생하고, 대기 자세는 비즈니스맨 전용 Idle을 씁니다. 이동 위치는 계속 `Passerby`가 맡습니다.

`Prefabs/Npc/BenVisual.prefab`은 예전 도형 캐릭터에 짧은 팔다리용 **Generic 뼈대**와 전용 걷기 동작(`Art/Characters/Npc/Ben/`의 `BenLocomotion.controller`·`BenIdle.anim`·`BenWalk.anim`)을 붙인 외형으로, 지금은 Ben에 연결하지 않습니다. **Tools → A305 → Npc → Build Ben Rig**는 Ben의 외형이 예전 도형 외형이나 `BenVisual`이 아니면 바꾸지 않고 멈춥니다. **Preview Ben Walk**는 `Scenes/Sandbox/BenWalkSandbox.unity`와 정면·측면 렌더로 이 Generic 외형의 걷기를 보여 줍니다. Sandbox를 Play한 뒤 Ben의 자식 `LittleMungV7Visual`을 선택하고 Animator 창의 Parameters에서 `Speed`를 1.1로 바꾸면 걷고, 0이면 멈춥니다.

## 생활

Mia(`CAFE_STAFF`)·Jake(`HOTEL_STAFF`)·Alex(`SHOP_STAFF`)는 생활 원본의 `resident: true`로 24시간 근무합니다. 휴식·퇴근으로 떠나지 않고 씬을 다시 열어도 근무지에 남습니다. 나머지 퀘스트 담당자를 포함한 NPC는 기존 교대를 유지합니다. 원본을 바꾼 뒤 `ai/tools/npc_life_export.py`로 일과를 다시 내보냅니다.

생활 데이터가 있는 NPC는 게임 시각의 교대에 따라 근무지·타운·숙소를 오갑니다. 근무 중에는 기존 생활·응대 동작을 사용하고, 근무 밖의 출현과 출퇴근은 `NpcPopulation`이 관리합니다. 규칙과 숫자는 [NPC 생활·관계 설계](../../../../../docs/npc-life-design.md)를 따릅니다. 택시 기사 Joe는 운전석에 있어 걸어서 출퇴근하는 대상에서 제외합니다.

상황 복습 방문은 `NpcReviewPresence` 요청이 유지되는 동안 해당 직원의 근무지 모습을 사용할 수 있습니다. 실내 입장·생활·근무 외 응대 판정이 같은 요청을 확인하며, 출퇴근 모습과 동시에 나타나지 않습니다. 요청을 해제하면 현재 시각의 원래 일과로 돌아갑니다. 본편의 `NpcDuty.MissionNpcCode`, 영업시간·게임 시각·사용량 제한은 변경하지 않습니다.

호텔 프런트 직원 Jake(`HOTEL_STAFF`)는 근무 중에는 데스크 중앙의 자기 자리에서 일하고 다른 사물을 찾아 돌아다니지 않습니다. 손님을 응대할 때도 그 자리에서 방향만 바꿉니다. 24시간 상주하므로 교대가 끝나도 데스크에 남습니다.

생활 데이터는 AI 규칙 원본(`ai/npcs/rules/world-rules.json`, `ai/npcs/life/`)에서 `ai/tools/npc_life_export.py`가 내보낸 파일이라 직접 고치지 않습니다. 규칙이나 NPC 생활 파일을 바꾸면 다시 내보내며, AI 테스트가 다시 내보낸 결과와 같은지 확인합니다.

```bash
ai/.venv/Scripts/python ai/tools/npc_life_export.py
```

## 일터와 응대

일터마다 여러 직원이 교대(`NpcLife.json`의 `schedule`, AI 생활 파일의 `shift`)를 나눠 맡습니다. 일터에는 근무 중인 직원만 나타납니다. 첫날 미션·튜토리얼이 붙잡아 둔 NPC는 진행을 위해 자리를 지킵니다.

### 출퇴근과 숙소

인도를 따라 걷다 횡단보도 끝을 스치는 걸음은 길을 건너는 것으로 보지 않습니다. 횡단보도 바닥은 인도 안쪽까지 들어와 있고(카페 앞 횡단보도 동쪽 끝은 연석에서 약 1.2m) 교차로의 네 횡단보도는 모서리에서 하나로 이어져 있어서, 걷는 방향 앞의 바닥만 보면 인도를 지나가는 NPC도 신호를 기다리거나 횡단을 시작했다가 되돌아갔습니다. 지금은 `NpcWalkRoute`가 정한 길이 앞으로 0.6m 안에서 횡단보도로 들어갈 때만 신호를 보고, 그렇게 다가가 발밑이 횡단보도가 된 뒤에만 횡단을 시작합니다. 신호를 기다리는 동안에는 횡단을 시작하지 않습니다. 교차로 모서리처럼 몇 cm 차이로 경로가 다른 횡단보도로 바뀌는 곳에서는 다가가기 시작한 횡단보도(들어설 지점·건너는 방향)를 정해 두고 그 횡단보도로 건넙니다. 본길과 가로길 신호는 출발할 수 있는 시간이 겹치지 않아서, 경로가 바뀔 때마다 기다릴 신호를 바꾸면 모서리에서 건너지 못했습니다. 인도만으로 가는 길이 되거나 정해 둔 지점에서 1.5m 넘게 멀어지면 정해 둔 횡단을 풉니다. 기다릴 신호와 횡단 중 되돌아갈 때 보는 신호는 연석 모서리까지의 짧은 구간이 아니라 길이 횡단보도를 지나는 방향(횡단보도에 들어간 뒤 1.5m 지점)으로 같게 정합니다. 인도 위인지는 횡단보도와의 거리 대신 발밑 바닥으로 판단해서, 횡단보도에 바짝 붙은 교차로 모서리 인도에서도 인도에 선 채 신호를 기다립니다. 생활(`NpcRoutine`)처럼 길을 따로 정하지 않는 보행은 기존처럼 걷는 방향 0.6m 앞을 봅니다.
신호가 있는 횡단보도에서는 지금 자리에서 건너편 끝까지 걸어서 건너는 시간(보행 속도 1.6m/s + 1초 여유)만큼 가로지르는 차로의 빨간불이 남았을 때 출발합니다. 앞에서 기다리던 사람이 출발한 뒤 연석에 닿은 사람도 그 시간이 남았으면 따라 건너, 한 신호에 여럿이 함께 건넙니다. 거리를 잴 수 없으면 8초를 요구합니다. 횡단의 출발·도착 지점은 실제로 설 수 있는 인도에서 고릅니다. 차도·횡단 영역과 물리 장애물이 겹치는 지점은 제외하며, 신호 변경으로 되돌아올 때도 같은 기준을 따릅니다. 작은 경로 모서리는 끝까지 이동하고, 다음 모서리까지 NavMesh와 몸체가 모두 통과할 수 있을 때만 앞 모서리를 건너뜁니다. 장애물을 이미 지나 원래 길이 열렸으면 예전 우회점으로 돌아가지 않습니다. 물리 몸체의 접촉 여유와 탐색용 충돌 검사가 다른 기준으로 길을 막지 않도록 맞춥니다.

인도만 따라가는 경로에서 다른 NPC를 피할 때는 우회할 한 걸음도 인도 안에서 고릅니다. 횡단을 끝낸 NPC가 건너편 인도에서 사람을 피하다가 횡단보도로 되돌아가는 일을 막습니다.

`NpcPopulation`은 출근 경로·실제로 관찰한 보행 거리·출발 여유·지각 게임분을 `Passerby.TravelContext`에 연결합니다. 순간이동이나 씬 복원으로 건너뛴 거리는 걷기로 세지 않습니다. 대화 시작에 이 상황을 복사해 서버로 보내므로, 대화 중에는 첫 인사·후속 대사·재시도가 같은 사실을 사용합니다. 실제 출입문에 도착한 출근 기록은 `NpcJourneyLog`가 같은 플레이 세션의 실내 직원에게 연결하고, 게임 시계가 바뀌거나 하루 이상 지난 기록은 사용하지 않습니다. 여가 방문객은 근무 중인 직원으로 설명하지 않습니다. AI는 이 사실을 바탕으로 먼 일터라 일찍 나왔거나 걸어서 피곤하다는 이야기를 할 수 있지만, 실제로 측정하지 않은 부상·극심한 탈진을 만들어내도록 지시하지 않습니다.

근무지의 이름표는 `NpcRoutine.IsOffDuty`로, 거리의 출퇴근 사본은 `NpcTownWalker.IsStaff`로 근무 밖의 직원인지 확인합니다. 쉬는 직원은 근무지용 생활 컴포넌트가 없어도 역할 칩 없이 이름만 표시합니다.

`NpcPopulation`은 숙소부터 일터까지의 실제 NavMesh 경로 길이로 인물별 출근 출발 시각을 계산합니다. 필요한 게임 분은 `ceil(((경로 길이 + 출입구 자리 찾기 여유 9.4m) / 보행 속도 1.6m/s + 경로상 횡단보도별 최대 신호 대기 초) × 2.4)`입니다. 신호 주기(가로길 초록 10초)에서 본길 횡단은 최대 23초, 가로길 횡단은 최대 21초를 더합니다. 이 계획은 넉넉하게 횡단에 8초가 필요하다고 보고 잡습니다. 근무 시작 시각에서 이 시간을 뺀 때 출발하며, 앞선 근무가 끝나기 전으로 당기지는 않습니다. 신호 여유가 생겨도 느리게 걷지 않고 평소 속도로 먼저 이동합니다. 경로를 구하지 못하면 기존 60게임분을 사용합니다.

퇴근 후 30분은 여가 목적지로 이동, 이후 90분은 시설 이용 또는 거리 산책, 다음 30분은 숙소로 돌아가기로 나눕니다(모두 게임 분). 짧은 휴식은 일터 앞에서 쉬고 돌아오며 근무 시작·종료 시각은 유지합니다. 행인은 `FREE` 일과 동안 기존 타운 생활을 하고, 일과 밖에는 같은 방식으로 숙소를 이용합니다. 이동 중인 직원에게 먼저 말을 걸면 근무 외 일상 대화로 이어집니다.

여가 목적지는 `Resources/NpcOutings.asset`의 기존 시설 11곳(카페·약국·은행·우체국·식당·빨래방·꽃집·이발소·빵집·오락실·생활용품점)과 보도 산책 구간 6곳에서 고릅니다. `NpcOutings`는 인물과 날짜를 바탕으로 다른 목적지를 고르고, 자기 일터·닫힌 시설·갈 수 없는 경로는 제외합니다. 현재 위치부터의 이동·신호 대기와 최소 이용 시간(실제 2초)이 남은 여가 안에 들어오는 곳만 선택합니다. 시설·산책 구간별 정원은 기본 2명이며, 이동 중인 예약과 문으로 퇴장 중인 손님도 셉니다. 같은 장소가 찼으면 다음 목적지를 고릅니다. 짧은 휴식과 근무표는 유지합니다.

실내 방문은 실제 출입문 앞에 도착한 뒤 시작합니다. 실내가 로드돼 있으면 `NpcFacilityVisitors`가 같은 외형·NPC ID의 방문객을 두고 `NpcRoutine`으로 손님용 사물을 이용하거나 둘러보게 합니다. 방문객은 직원 업무나 카운터 응대를 맡지 않습니다. 같은 NPC의 거리 모습은 숨기고, 방문이 끝나면 실내 문까지 걸어 나온 뒤 거리로 복귀합니다. 실내를 로드하지 않은 동안에는 방문 상태만 유지하며, 실내만 새로 불러오면 기존 출퇴근과 같이 게임 시각에 맞는 상태를 복원합니다. 방문 기록은 현재 플레이 동안 유지하며 서버에 별도로 저장하지 않습니다.

**Tools → A305 → Npc → Apply Leisure Outings**는 시설의 편집 원본과 기존 출퇴근 프리팹을 읽어 목적지 카탈로그를 갱신합니다. 시설 배치나 출입구를 바꾸면 다시 실행합니다. 실내 구성은 기존 `ShopInteriorScenes`의 장소 코드와 씬을 재사용합니다.

이동은 타운의 NavMesh 경로를 따릅니다. 다른 씬에 다녀와도 현재 게임 시각에 해당하는 경로 위치에서 이어집니다. 작은 경로 진행도 매 프레임 따라가며 보통 최대 1.6m/s로 걷습니다. 출근·귀가 또는 문 도착이 늦어 예정 위치보다 4m 이상 뒤처지면 서두르고, 1.5m 안으로 따라잡으면 평소로 돌아갑니다. 한산한 보도에서만 최대 2.6m/s로 달리며, 플레이어 2.5m·다른 NPC 2m 안, 출입문 근처, 횡단보도와 모서리·장애물 앞에서는 걷거나 기존 규칙대로 기다립니다. 튜토리얼·퀘스트로 기다리는 NPC는 서두르지 않습니다. 일터에서 말을 걸러 다가오는 속도가 0인 직원도 출퇴근은 할 수 있습니다.

`NpcPopulation`이 전달한 기존 `NpcDayPhase`와 직원 여부로 응대를 구분합니다. 근무가 이미 시작된 `Working` 상태의 직원이 아직 일터로 이동 중이고, 기존 4m 뒤처짐 기준으로 서두르는 경우에만 대화를 거절합니다. 별도의 지각 시간·성격 설정은 추가하지 않습니다. 출근 전(`GoingToWork`)·귀가(`GoingHome`)·휴식(`Resting`, `Leisure`, `LeavingWork`) 중에는 달리고 있어도 평소처럼 대화 확인을 거쳐 대화할 수 있습니다.

출근에 늦은 직원을 클릭하면 1:1 대화 확인 대신 "늦어서 서둘러야 해요. 다음에 이야기해요!"라는 짧은 이벤트를 영어·한국어로 보여 줍니다. NPC와 플레이어의 이동, 게임 시각과 카메라는 그대로 이어지고 대화 횟수도 쓰지 않습니다. 사람 가까이에서 걷는 중이어도 아직 일정에 뒤처져 있으면 같은 이벤트로 응답합니다. [알겠어요]·E·Esc 또는 5초 뒤에 창을 닫습니다. 평소 대화 확인 중 늦은 상태로 바뀌었을 때도 대화를 새로 만들지 않고 이벤트로 바꿉니다.

**Tools → A305 → Npc → Apply Hurry Movement**는 실제 걷기·달리기 속도에 맞춘 전용 이동 컨트롤러 `Resources/NpcCommuter.controller`를 만듭니다. 출퇴근 모습은 시작할 때 이를 사용하고 기존 캐릭터 전용 클립을 유지합니다. 플레이어 이동 컨트롤러는 변경하지 않습니다. **Capture Hurry Event**는 실제 이벤트창과 달리기 자세를 예시 값으로 렌더해 로컬에 저장합니다(`NPC_HURRY_PREVIEW_OUTPUT`으로 폴더 지정).

장애물 때문에 목적지까지 직진할 수 없으면 현재 위치에서 갈 수 있는 경로를 다시 찾아 모서리를 돌아갑니다. 차도는 우회 경로에서도 제외합니다. `NavMeshObstacle`의 carving으로 반영한 장애물은 보행 경로를 다시 계산합니다. 거리에서는 보행 데이터에 없는 물리 콜라이더도 몸 앞에서 검사하고, 몸이 통과할 여유와 NavMesh 연결이 있는 양옆 모서리 중 짧은 경로로 우회합니다. 고른 쪽을 장애물을 지날 때까지 유지하며, 두 방향 모두 막혔으면 정지하고 통로가 열렸을 때 재시도합니다. 가로등·표지판·건물 벽처럼 이미 보행 데이터에 들어 있는 장애물은 표면 바로 앞 바닥에 NavMesh가 없으므로 몸 앞 검사에서 막힌 것으로 보지 않습니다. 이런 장애물은 경로가 이미 비켜 가며, 몸 앞 검사는 NavMesh의 장애물 여유(굽는 격자 오차로 0.2m대까지 좁아짐)보다 넓게 막아 경로가 붙어 지나는 가로등 옆에서 NPC가 멈췄습니다. 실내 사물 이용은 `NpcRoutine`의 도착·정체 판단을 그대로 따릅니다.

낮은 보도 턱은 보행 데이터와 캐릭터 몸체 모두 월드 높이 0.3m까지 올라갈 수 있게 맞춥니다. 캐릭터 크기에 맞춰 몸체의 `stepOffset`을 환산합니다. 실제 수평 이동량으로 걷기 속도를 전달하므로 충돌로 막혔을 때 제자리 걷기를 계속하지 않습니다. 턱을 넘기 위한 자동 점프는 사용하지 않습니다.

연속 플레이에서는 근무·휴식 시각이 되어도 거리 NPC가 일터 또는 숙소 문에 도착할 때까지 걷게 하고, 도착한 뒤 거리 모습을 끕니다. 일터 직원은 거리 모습이 도착하기 전에 중복으로 켜지지 않습니다. 씬을 처음 불러오거나 게임 시각을 크게 건너뛰면 해당 시각의 위치를 복원합니다. 매장 안 직원의 퇴근은 기존 근무 시각에 따른 출현 방식을 사용합니다.

`NpcWalkingSpace`는 몸통 캡슐보다 넓은 리틀 멍의 머리를 고려해 NPC 간 보행 간격을 확보합니다. 같은 프레임에 떠나는 사람을 먼저 비활성화하고, 새 출근자는 예정 위치에서 가까운 NavMesh 빈자리를 찾습니다. 숙소 입구에 사람이 몰리면 직선으로 연결된 9m 범위까지 살피며, 빈자리가 없으면 겹쳐 등장시키지 않고 다음 프레임에 재시도합니다. 보행 중 상대의 여유 공간에 진입할 이동량을 제한하고, 막히면 정지 동작을 전달합니다.

출퇴근 보행은 앞사람의 여유 공간 바깥으로 비켜갈 방향을 정하고, 상대를 지날 때까지 같은 쪽을 유지합니다. 우회할 방향의 NavMesh 연결을 확인하며, 목적지에서 자리를 지키는 상대나 막힌 통로에는 간격을 두고 기다립니다. 서로 자리를 바꾸며 이동 중인 두 NPC는 고정된 목적지 점유로 보지 않고 비켜 지나갑니다. 횡단 중에도 건널 방향을 유지하면서 옆으로 비켜갈 수 있고, 선택한 쪽 인도에 도착하면 횡단 상태를 해제합니다. 평소 교행에서는 밀어내거나 순간이동하지 않으며, 장시간 실제로 움직이지 못하는 경우에만 아래 복구 규칙을 사용합니다. 가까운 상대를 비켜가는 처리이며, 군중 전체의 우회 경로를 다시 계획하는 기능은 아닙니다.

| 같은 카운터의 직원이 여럿 근무 중 | 손님이 카운터 앞에 오면 `NpcDuty.PickServer`가 한 명만 고릅니다. 첫날 미션이 지금 찾아가라고 한 NPC가 먼저이고, 그다음은 하는 일(음료 만들기 등)이 없는 직원 중 지금 서 있는 곳이 카운터에 가장 가까운 직원, 모두 일하는 중이면 가장 가까운 직원, 거리가 같으면 NPC 키 순서입니다. 고른 직원은 손님이 카운터를 떠날 때까지 바뀌지 않고, 하던 일을 그만두고 자기 자리로 와서 응대합니다. 나머지는 하던 일을 계속하고 클릭·탭으로 시작하는 대화만 받습니다. |
| 첫날 미션이 찾아가라고 한 NPC | 교대 밖이어도 근무 중으로 보고 자리를 지켜 미션 대화가 이어지게 합니다(`NpcDuty.MissionNpcCode`, 첫날 미션 상태를 읽을 때마다 정함). |

카페·호텔의 카운터 뒤 통로는 한 사람 폭이라 원래 직원만 그 안에 서고, 새 직원은 카운터 양 끝에 섭니다. 누가 응대할지는 자리가 아니라 그때 한가한지와 카운터까지의 거리로 정합니다. 마을 행인 10명은 다른 확인이 플레이어를 세우는 집 앞·경찰서·동서 길 서쪽에서 감지 거리보다 먼 본길 북쪽 인도와 공원에 둡니다. Arthur·Margaret 부부는 나란히 서서 시작하지만 함께 걷는 동작은 없고, 함께 산책하는 개(Pepper) 모델도 아직 없습니다.

## 택시

마을 본길의 노란 택시 운전석에 택시 기사(`TAXI_DRIVER`)가 앉아 있습니다. 가까이에서 탑승 버튼을 누르면 바로 뒷좌석에 타고 기사와 대화합니다.

| 상황 | 동작 |
| --- | --- |
| 택시 중심에서 수평 반경 8m 안 | [택시 타기]와 키 안내(E)를 보입니다. 길 건너편, 택시 뒤, 유턴 구간에서도 거리만 맞으면 표시합니다. 반경 밖에서는 숨깁니다. |
| [택시 타기] | 클릭 시 거리와 튜토리얼 제한을 다시 확인하고, 택시를 현재 위치에 세워 곧바로 뒷좌석에 태웁니다. |
| 대화를 시작하지 못해 기다리는 택시의 반경 8m 안 | [Joe에게 말 걸기]로 뒷좌석에 타서 대화합니다(`ConversationInitiator.User`). |
| 남은 대화 | 게스트에게는 [택시 타기]·[Joe에게 말 걸기] 위에 "게스트 남은 대화 N번"을 보입니다(AI-01 `remainingConversations`). |
| 게스트가 대화를 다 씀 | 두 버튼 대신 [가입하고 계속 대화하기]와 "게스트 대화를 모두 썼어요"를 보이고, 누르면 가입 안내 창을 엽니다. |
| 다른 이유로 새 대화를 시작할 수 없음 | 두 버튼 대신 누를 수 없는 버튼으로 이유("지금은 대화할 수 없어요")를 보입니다. E 키도 택시를 세우지 않습니다. |
| 목적지를 말함 | 서버의 의도 판정이 최근 대화까지 보고 고른 목적지(턴 응답의 `taxiDestination`)로 이동합니다. "거기 가 주세요"처럼 앞에서 말한 장소를 가리켜도 됩니다. 카페·호텔·드럭스토어·집과 우체국·식당·은행·빨래방·꽃집·이발소·경찰서의 총 11곳이며, 도착 후 하차하고 기존 피드백 흐름을 이어갑니다. |
| 가는 도중에 다른 곳을 말함 | 도착해 내리기 전이면 새 목적지로 바꿉니다. |
| 도착 전에 대화를 마침 | 길 바깥쪽에 내려준 뒤 택시가 다시 달립니다. |
| 대화하지 않고 8m보다 멀어짐 | 기다리지 않고 다시 달립니다. 세우러 오는 중에는 세운 자리까지의 거리만큼 더 기다립니다. |

다른 대화 중이거나 행인이 제안 중이면 택시 버튼을 보이지 않습니다. 승용차는 세울 수 없고, 택시와 마찬가지로 신호와 앞을 막은 사람에 맞춰 섭니다. 기사 Joe는 중년 남성 리틀 멍 외형(`Prefabs/Npc/Review/LittleMung_MiddleAge_Male.prefab`)이 운전석에 앉아 운전대를 잡은 자세입니다. 머리 꼭대기가 지붕 안감 아래(택시 기준 1.5m)에 오도록 배율을 줄여 앉힙니다. 배치와 연결은 **Tools → A305 → World → Apply Town Street Life**가, 이미 배치된 기사의 외형 교체는 **Tools → A305 → World → Replace Taxi Driver Model**(NPC 키·사물 단어·택시 대화 연결 유지)이, 운전 자세는 **Apply Taxi Cabin**이 맡습니다. 운전석에서는 서 있는 자세 보정과 함께 외형의 얼굴 제어 스크립트도 지우지만, 대화가 시작되면 공통 연결(`DialogueSpeaker`)이 기사 얼굴에 립싱크·눈 깜박임을 적용합니다. 대화 밖의 자동 깜박임은 하지 않습니다.

[목적지와 구성·확장 방법](../../../../../docs/unity/taxi-ride.md)을 참고합니다.

## 경찰서

마을 남서쪽 끝 경찰서(카페·호텔처럼 따로 장면인 `PoliceStationScene`) 창구 뒤에 경찰관 Dan(`POLICE_OFFICER`)·Victor(`POLICE_SERGEANT`)·Taylor(`POLICE_ROOKIE`)가 24시간 교대로 있습니다([일터와 응대](#일터와-응대)). 카페 직원처럼 행인 프리팹을 쓰고 플레이어에게 걸어가지 않으며, 경찰서 1층 안에서만 지냅니다. 경찰관마다 신고 창구(`PoliceReportDesk`)가 있어 누구에게 신고해도 순찰차가 출동합니다. 신고 여부와 목적지는 서버의 `PoliceDesk`가 문맥으로 판정합니다. 창구는 턴 응답의 출동 정보를 받아, 대화를 마치면 신고한 경찰관·목적지·사용자 턴 ID를 `PoliceDispatchOrder`에 보관합니다. 같은 턴 ID는 한 번만 접수하며, 추가 신고는 순서대로 기다립니다. 신고한 경찰관은 순찰차가 돌아와 주차할 때까지 창구와 마을의 생활 모습에 나타나지 않습니다.

| 대화에서 말한 내용 | 대화를 마친 뒤 순찰차 |
| --- | --- |
| 장소를 하나 말한 신고 (My wallet was stolen at the diner.) | 경광등을 켜고 그 장소 앞에 20초 서 있다가 돌아옵니다. |
| 신고한 뒤에 장소를 하나 말함 (My bag was stolen. → It was the cafe.) | 마지막에 말한 장소로 출동합니다. |
| 장소 없는 신고 (I lost my wallet.) 또는 장소를 여럿 말한 신고 | 경광등을 켜고 본길을 한 바퀴 순찰하고 돌아옵니다. |
| 신고가 아닌 말 (Hello, officer.), 부정·가정 (Nothing was stolen.) | 출동하지 않습니다. 신고 전에 말한 장소는 기억하지 않습니다. |
| 아직 출발하지 않은 신고가 있을 때 한 신고 | 새로 받지 않고 "신고 접수 · 순찰차가 이미 출동하기로 했어요"를 보입니다. 순찰차는 먼저 받은 신고로 출동합니다. |

신고는 대화 중에 접수만 하고, 경찰서를 나와 마을이 열리면 순찰차가 출발해 밖으로 나온 플레이어가 출동하는 모습을 보게 합니다. 신고하고 문이 아닌 다른 길(집 버튼 등)로 나가도 다음에 마을이 열릴 때 출동합니다. 카페는 배우는 사람이 자주 틀리는 caffe·caffee도 알아봅니다(택시 목적지와 같은 장소 이름). 배치와 연결은 **Tools → A305 → World → Apply Police Station**이 합니다([World 모듈](../World/README.md#경찰서와-순찰차)).

## 외형 표

모든 NPC의 외형(리틀 멍 외형 프리팹)과 머리·옷·신발·눈동자 배색은 `Scripts/Editor/Npc/NpcCast.cs` 한 곳에서 정합니다. 외형별로 바꿀 수 있는 색 범위는 `NpcLooks.cs`, 색을 바꾼 텍스처·재질 사본은 `NpcCastDresser`가 `Art/Characters/NpcCast/<NPC 키>/`에 만듭니다. 배색을 비운 부분은 외형의 원래 색이고, 배색이 없는 NPC는 원래 재질을 씁니다.

배색 이미지 축소는 CPU에서 수행하므로 `-nographics` 백그라운드 실행에서도 피부·머리·옷의 색을 보존합니다. 캐시가 단색이면 배색 기록이 같아도 원본에서 다시 만들고, 단색 결과는 저장하지 않습니다. **Tools → A305 → Npc → Repair Cast Textures**는 손상된 배색만 복원하며 기존 텍스처 GUID와 씬·출퇴근 프리팹의 연결을 유지합니다.

| 규칙 | 내용 |
| --- | --- |
| 쓰는 외형 | 플레이어(기본) 외형은 NPC에 쓰지 않습니다. 바리스타·카페 남자 유니폼은 카페 직원만, 남녀 호텔 유니폼은 호텔 직원만, 검수한 남녀 경찰 제복은 경찰관만 입습니다. 일반 행인 외형은 다른 역할에서도 쓸 수 있습니다. 경로와 배정은 `NpcLooks`·`NpcCast`가 관리합니다. |
| 성별·나이 | 인격 카드(`ai/npcs/<NPC 키>.json`)의 나이대·배경에 맞는 외형을 고릅니다. Arthur와 60대 수리공 Frank는 할아버지 외형을 쓰되 옷·머리·신발 배색을 구분합니다. 컨시어지 Walter는 회색 머리 정장, 비번 소방대장 Ray는 중년 평상복을 씁니다. 역할이 정해지지 않은 외형을 기존 NPC의 성별 변경으로 임의 배정하지 않습니다. |
| 서로 다른 사람 | 같은 외형을 쓰는 두 NPC의 눈동자 색이 같으면 머리와 옷 색이 모두 달라야 하고, 옷 색이 같으면 눈동자·머리·신발 색이 모두 달라야 합니다. 경찰관 Dan·Victor는 남성 제복, 신입 Taylor는 여성 제복을 씁니다. 같은 남성 외형은 눈동자·머리·신발 배색으로 구분합니다. |
| 색 이름 | 같은 색인지는 `NpcCast.Palette`의 색 이름으로 가립니다. 같은 이름에는 같은 값을 씁니다. |

- 머리카락과 피부·바지가 비슷한 색인 외형(중년 남성·할머니·바리스타)은 몸 높이로 머리만 고르고(머리 꼭대기 1, 발바닥 0), 가닥 사이에 남는 가는 선은 같은 색으로 메웁니다(`NpcColorSwap.FillGaps`).
- **Render Workplace Lineups**는 외형 종류 대신 직장·행인 무리별로 전신·얼굴·뒷머리를 함께 렌더합니다. 저장 폴더는 `NPC_CAST_LINEUP_OUTPUT`으로 지정합니다. 기존 12종을 36명에게 재사용하므로 같은 모델의 배색 변형은 남아 있습니다. 소방관은 현재 설정상 비번 평상복이며 전용 소방 제복 모델은 아직 없습니다.
- 중년 여성은 머리와 피부의 색 범위가 겹치므로 원래 금발을 유지하고 옷·눈 색으로 구분합니다. 기존 남성 호텔 직원의 눈은 원본 색을 유지하며 옷·머리로 구분합니다. 색 범위만 넓혀 피부나 머리 가닥에 얼룩이 생기는 배색은 사용하지 않습니다.
- 배색이 같으면 텍스처를 다시 쓰지 않습니다(가져오기 설정의 userData에 배색을 적어 둠). 색을 칠하는 규칙을 바꾸면 `NpcCastMember`의 `RecipeVersion`을 올립니다.
- 카페·호텔 직원을 포함해 눈 깜박임을 사용하는 외형은 별도 눈 메시의 `*EyeColor` 텍스처에 홍채 배색을 적용합니다. 몸 텍스처와 눈꺼풀 피부색은 눈동자 배색 대상으로 쓰지 않습니다.
- **Tools → A305 → Npc → Render Cast Lineups**는 같은 외형의 NPC를 외형 표 순서대로 세워 몸 전체·얼굴·뒤통수를 찍은 그림을 외형마다 저장합니다(기본 `artifacts/unity/npc-cast/`, 환경 변수 `NPC_CAST_LINEUP_OUTPUT`로 바꿈). 외형 표를 바꾸면 이 그림으로 서로 다른 사람으로 보이는지 확인합니다. 경찰 검수 사본에는 모자까지 포함됩니다.

## NPC 추가

1. 서버 시드(`backend/.../db/seed/world.sql`)·AI 인격 카드·생활 파일에 NPC 키가 먼저 있어야 합니다. 생활 데이터는 `npc_life_export.py`로 내보냅니다.
2. [외형 표](#외형-표)(`NpcCast.Members`)에 외형과 배색을 더합니다. `NpcCastTests`가 시드의 모든 NPC에 외형이 하나씩 있는지, 같은 외형끼리 서로 다른 사람으로 보이는지, 유니폼을 그 일터 직원만 입는지 확인합니다.
3. 둘 자리를 적습니다. 카페·호텔·드럭스토어 직원과 마을 행인은 `NpcCastBuilder`의 `Newcomers`(자리·방향과 설정을 따를 같은 일터의 원래 NPC), 경찰관은 `PoliceStationBuilder`의 `Officers`, 거리 매장 직원은 `BuildingStaffBuilder`의 표입니다. 카운터 직원은 원래 직원보다 카운터에서 조금 멀게 둡니다([일터와 응대](#일터와-응대)).
4. 확인용 인사말(`NpcBuilder`의 `MockGreetings`)과 확인용 대본(`MockDialogueScriptSource`의 예시, 이름·역할 이름은 시드와 같게)을 더합니다.
5. **Tools → A305 → Npc → Build Cast**와 **Dialogue → Build**를 실행하고, **Render Cast Lineups**로 외형을 확인합니다.

행인 프리팹을 손으로 놓을 때는 `Prefabs/Npc/Passerby.prefab`을 씬의 `Characters` 아래에 놓고 `NpcIdentity`의 `Code`와 `Passerby`의 `Settings`를 정한 뒤 **Tools → A305 → World → Set Up Open Scene**으로 플레이어·대화 처리·제안 화면과 잇습니다. 서 있는 자리와 방향이 돌아갈 제자리입니다.

## Builder

**Tools → A305 → Npc → Refresh Scene Visuals**는 카페·호텔·상점·마을·경찰서에 배치된 36명의 외형을 외형 표에 맞춥니다. 기존 **Connect Reviewed Staff Visuals** 메뉴도 같은 작업을 실행합니다. 검수 외형의 마스터 골격·동작, 모든 외형의 Humanoid Avatar·13개 얼굴 채널을 확인하고 연결합니다. NPC 위치·회전·일과를 유지하며 새 NPC나 NavMesh를 만들지 않습니다. 새 바리스타 배치는 기존 여성 외형과 같은 1.6 배율을 쓰고 기존 인스턴스의 조절값은 유지합니다. 캡슐과 시선 높이는 씬 배율을 포함한 각 외형에서 측정하고, 운전석 Joe는 기존 좌석 자세와 시선을 보존합니다. 카페·호텔 외형 표도 실제 대화 얼굴 프리팹을 가리키므로 원본과 대화 사본 사이의 경로가 어긋나지 않습니다. 여성 신입 Taylor의 인격 카드·목소리는 `POLICE_ROOKIE` 코드로 연결합니다.

**Tools → A305 → Npc → Build**(`Scripts/Editor/Npc/NpcBuilder.cs`)가 다음을 준비합니다. 공간 Builder(**World → Build Spaces**)도 함께 실행합니다.

- 설정(`Data/Npc/`): 없을 때만 만들고, 있으면 값을 유지합니다.
- 확인용 인사말(`Data/Npc/MockNpcLines.asset`): 없으면 만들고, 있으면 아직 없는 NPC 키의 인사말만 덧붙입니다. 이미 있는 인사말은 바꾸지 않습니다.
- 행인 프리팹 `Prefabs/Npc/Passerby.prefab`과 제안 화면 `Prefabs/Npc/PasserbyOffer.prefab`(제안 패널과 공용 상호작용 버튼, NPC 클릭·탭 `NpcClickTalk`과 테두리 재질 `Art/Npc/NpcHoverOutline.mat`): 컴포넌트와 연결만 맞추고 모델·디자인을 유지합니다. 없는 요소만 새로 만듭니다. 행인 프리팹에는 카메라에서 먼 동안 팔 관통 보정을 끄는 `NpcDetailDistance`도 붙입니다. 제안 화면에는 머리 위 이름표 층(`NameTags`)도 더합니다(`NpcNameTagBuilder`).
- 마을(`TownScene`) 집 앞에 행인 Ben을, 카페(`CafeScene`) 카운터 뒤에 카페 직원을 둡니다. 같은 NPC 키가 이미 있으면 위치를 바꾸지 않습니다. 예전처럼 집 앞 튜토리얼 행인(`TUTORIAL_PASSERBY`)과 동서 길 행인이 따로 있으면, 집 앞 행인을 Ben으로 바꾸고 동서 길 행인은 지웁니다. Ben에게는 평소 설정과 튜토리얼 설정을 함께 연결하고, 외형을 아래처럼 연결합니다.
- 서서 지내는 NPC의 외형: **Tools → A305 → Npc → Connect Character Visuals**(`Scripts/Editor/Npc/NpcVisualBuilder.cs`)가 NPC 키별 외형을 장면의 NPC 아래에 둡니다. `TownScene`의 Ben은 비즈니스맨 `Prefabs/Npc/Review/LittleMung_Business_Male.prefab`, `ShopScene`의 드럭스토어 직원 Alex(`SHOP_STAFF`)는 흑인 남성 `Prefabs/Npc/Review/LittleMung_BlackYoung_Male.prefab`입니다. 다른 행인·직원도 쓰는 공용 `Passerby.prefab`의 `Visual`은 바꾸지 않고 꺼 둡니다. 예전 외형(도형 `LittleMungV7NpcVisual`, Generic 뼈대 `BenVisual`)은 NPC 아래에서 지우고, 대기 자세의 발바닥을 바닥에 맞춘 뒤 `CharacterAnimationDriver`의 Animator, 캡슐 높이(외형의 키), 시선(`LookTarget`)을 눈 높이로 맞춥니다. 공용 손짓 동작은 이 체형에서 무릎을 굽히고 팔을 내민 자세가 되므로 Ben은 `Passerby.talkGesture`를 꺼, 말을 건네고 대화하는 동안 자기 Idle로 서게 합니다. Alex는 다른 직원과 같이 손짓합니다. 이미 연결한 외형은 다시 만들지 않습니다. **Npc → Build**(Ben), 드럭스토어 Builder와 **Mission → Adjust Shop Counter Sightline**(Alex)도 같은 연결을 실행합니다.

**Tools → A305 → Npc → Build Building Staff**(`Scripts/Editor/Npc/BuildingStaffBuilder.cs`)는 [거리 매장 직원](#거리-매장-직원)을 `TownScene`의 각 건물 1층에 둡니다. 정한 자리가 카운터·가구와 겹치면 1층 안의 가장 가까운 빈자리로 옮기고(`NpcPlacement`), 문 쪽을 보게 세웁니다. 같은 NPC 키가 이미 있으면 위치를 바꾸지 않습니다. 외형은 [외형 표](#외형-표)의 외형을 `NpcVisualBuilder`로 붙이고, 배색은 `NpcCastDresser`가 입힙니다(몸 텍스처는 1024로 줄임, 머티리얼 사본은 실행할 때마다 외형의 원래 머티리얼 설정에 맞춤). 확인용 인사말·설정(`Data/Npc/BuildingStaffSettings.asset`)도 연결합니다. 이어서 **Build Daily Life**를 실행해 생활을 붙이고, 직원마다 구역을 자기 건물 1층으로 정합니다. 생활 데이터에 직원이 없으면 내보내기(`npc_life_export.py`)를 먼저 하라고 알리고 멈춥니다.

**Tools → A305 → Npc → Build Cast**(`Scripts/Editor/Npc/NpcCastBuilder.cs`)는 다른 Builder가 두지 않는 카페·호텔·드럭스토어 직원과 마을 행인을 [일터](#일터와-응대)에 두고, 경찰관은 `PoliceStationBuilder.PlaceOfficers`로 경찰서 장면의 창구 뒤에 둡니다. 같은 NPC 키가 이미 있으면 위치를 바꾸지 않고, 정한 자리가 가구와 겹치면 가까운 빈자리로 옮깁니다. 다가감 설정은 같은 일터의 원래 NPC를 따르고, 외형·캡슐·시선은 각자 외형 표와 자기 메시를 사용합니다. 이어서 다섯 장면의 모든 NPC에 외형 표의 배색을 입히고 **Build Daily Life**를 실행한 뒤 경찰관이 경찰서 1층 안에서만 지내게 합니다. 확인용 인사말도 덧붙입니다.

**Tools → A305 → Npc → Build Daily Life**(`Scripts/Editor/Npc/NpcLifeBuilder.cs`)는 카페·호텔·드럭스토어·마을에서 생활 데이터가 있는 NPC에 `NpcRoutine`을 붙이고, NPC 몸 크기(반지름 0.3m, 키 1.8m, 턱 0.3m)로 바닥을 구워 `Data/Npc/WalkAreas/`에 저장한 뒤 `NpcWalkArea`로 연결합니다. 사람·차·트리거 콜라이더는 굽지 않습니다. 장면의 `NavMeshModifier`·`NavMeshModifierVolume`이 정한 바닥 구역을 따릅니다. 마을 NPC는 [길 안내](../Wayfinding/README.md#횡단보도로-건너기)가 만든 차도(`Road`)를 경로에서 제외하고 횡단보도(`Crosswalk`)로 건너며, 차도와 횡단보도에 목적지를 두지 않습니다. 신호가 있는 교차로에서는 차량 신호가 충분히 빨간 동안에만 건너기 시작하고, 횡단 중에는 대화로 멈추지 않습니다. 차량 신호가 바뀌었을 때 횡단보도의 출발 경계부터 진행한 거리가 전체의 20% 이하이면 출발 인도로 돌아가 기다리고, 20%를 넘었으면 반대편 인도까지 계속 건넙니다. 복귀를 시작한 뒤에는 신호가 다시 바뀌어도 먼저 출발 인도까지 돌아갑니다. 차량은 앞에 NPC가 있으면 기다립니다. 가구 배치를 바꾸면 다시 실행합니다. 같은 메뉴가 `NpcAnimationBuilder`로 동작 FBX를 Humanoid로 가져오고 NPC 전용 Animator(`Art/Characters/Npc/NpcLife.controller`)를 만들어 `NpcRoutine`에 연결합니다. 장면에 저장된 모델은 플레이어와 같은 이동 컨트롤러 그대로 두고, 생활이 켜질 때 Humanoid 모델에 바꿔 끼웁니다(장면 모델의 키·발 높이 검사가 그대로 유지됩니다). 모델이 자기 Idle처럼 캐릭터 전용 클립을 덮어쓴 컨트롤러(`AnimatorOverrideController`)를 쓰면 `NpcLifeAnimator`가 그 클립을 생활 컨트롤러에 이어받습니다. 컨트롤러는 없을 때만 만들므로 구성을 바꾸려면 지우고 다시 실행합니다.

마을 본길 양옆 상가 사이의 폭 2m 미만 틈은 보행 데이터를 만들 때 통행 불가로 표시합니다. 각 건물의 `Interior/Floor` 충돌 범위 사이를 사용하므로 간판·처마 돌출 때문에 인도가 막히지 않습니다. 숙소에서 상가로 갈 때는 넓은 연결 인도로 나와 본길 인도를 이용하며, 공원·상점 출입구와 기존 횡단보도 연결은 유지합니다. 마을 보행 데이터만 갱신하려면 **Tools → A305 → Npc → Rebake Town Walk Area**를 실행합니다. 건물·NPC의 물리 콜라이더나 시각 배치는 바꾸지 않습니다.

## 공통 표정·립싱크 연결

`NpcIdentity`가 있는 NPC는 카페 전용 Builder 없이 `DialogueSpeaker`를 통해 자기 얼굴을 자동 연결합니다. 공통 얼굴 채널이 있는 모델에만 립싱크·미소·눈 깜박임을 적용하며, 부족한 모델은 누락 목록을 남기고 음성을 유지합니다. 이동·대화 제안·카메라 코드는 바꾸지 않습니다. 모델 준비 규격과 검사 메뉴는 [NPC 얼굴 재사용 기준](../../../../../docs/unity/cafe-female-face.md#다른-npc의-자동-연결)을 참고합니다.

마을 행인 Ben(비즈니스맨), 드럭스토어 직원 Alex(흑인 청년 남성), 택시 기사 Joe(중년 남성)의 외형은 입 모양 9개, 좌우 미소, 좌우 눈 감기를 모두 갖춰 대화 중 같은 방식으로 립싱크·미소·눈 깜박임을 적용합니다. 서 있는 Ben·Alex의 대기 중 깜박임은 외형의 `CharacterIdleBlink`가 맡습니다([행인 눈 감기](../../../../ArtSources/Characters/ServiceNpcs/README.md#나머지-행인의-base-눈-이식)).

서비스 매대 높이는 Tools/A305/World/Lower Service Counters로 배포 씬 전체에 적용합니다. 매대 높이를 0.45m로 낮추며 바닥 위치와 충돌을 유지하고 상판 위 별도 소품도 함께 내립니다. 매장 디자인을 다시 생성했다면 이 메뉴를 다시 실행합니다.

카페 직원 통로는 **Tools/A305/Cafe/Widen Staff Aisle**로 앞 매대와 뒤 작업대 사이에 2.4m를 확보합니다. 앞 매대·상판 소품·계산 담당의 응대 위치를 함께 옮기고 카페 NavMesh를 다시 굽습니다. 두 캐릭터가 나란히 지날 6m 경로를 검사한 뒤 씬을 저장하며, 반복 실행해도 통로가 더 넓어지지 않습니다. 카페 디자인을 다시 생성했다면 매대 높이를 적용한 다음 실행합니다.

### 실제 일과와 신호 지연 관찰

정체가 실제로 발생한 경우에는 요청한 이동 방향·우회 뒤 방향·횡단 상태·허용 걸음과 실제 이동·주변 NPC·물리 장애물도 기록합니다. `NPC_OBSERVATION_SIGNALS=on`은 정상 신호만, `NPC_OBSERVATION_END_MINUTE`는 진단 종료 시각(누적 게임분)을 선택합니다. 짧은 진단 실행은 하루 전체 통계로 사용하지 않습니다.

`NPC_DAILY_REVIEW_OUTPUT`을 지정하고 그래픽을 켜서 실행하면 실제 일과의 건물 주변 이동·횡단·은행 앞 보행·시설 문 진입 프레임을 PNG와 게임 시각 CSV로 기록합니다. 촬영 조건에서는 외형 동작을 유지하고 URP 렌더 완료 뒤 화면을 기록합니다. 이동 속도·시간 배율·일정은 바꾸지 않습니다. `NPC_FACILITY_REVIEW_OUTPUT`은 은행 손님 PlayMode 사례의 실내 활동·퇴장을, `NPC_OBSTACLE_REVIEW_OUTPUT`은 은행 앞 장애물 우회 사례를 기록합니다. 전자는 자연스러운 일과 실행, 후자는 검사에서 정한 상황의 재현입니다.

**Tools → A305 → Npc → Observe Daily Commutes**는 운영 TownScene과 근무표를 연속 이틀 실행합니다. 첫날은 준비하고 둘째 날의 출근을 집계하며, 같은 난수 시드로 정상 신호와 보행 신호 제약만 제거한 경우를 비교합니다. 대기 제거 조건에서도 출발 여유 계산은 유지하고 실제 보행 대기만 없앱니다. 실제 게임 시각 배율·보행 속도·물리 설정은 유지하고 보행 프레임은 30fps로 고정합니다. 진단에서는 서버 API와 UI·시각적 애니메이션을 제외합니다. 출근별 출발 여유·도착 지연·신호 대기·거절 조건 발생·미도착 위치, 실제 여가 방문과 목적지별 최대 예약 인원을 JSON으로 기록합니다. 거절 조건 발생은 해당 상태를 한 번이라도 거친 출근 건수이며 실제 사용자 클릭 횟수가 아닙니다.

`NPC_DAILY_OBSERVATION_OUTPUT`으로 출력 파일을 지정합니다. `NPC_OBSERVATION_SIGNALS=off`는 대기 제거 사례만 실행합니다. `NPC_OBSERVATION_WARMUP_DAYS=0`이면 준비일 없이 첫 하루를 측정합니다(기본 준비일 1일). batchmode에서는 `-executeMethod A305.EditorTools.Npc.NpcDailyObservation.Run`으로 실행하며 `-quit`을 함께 쓰지 않습니다. 관찰 완료 후 Unity가 종료됩니다. 이 도구는 상시 회귀 검사에 포함하지 않는 수동 진단입니다. 측정 종료 시 미도착 건은 완료된 이동의 평균 지연에 섞지 않고 별도로 집계합니다. 실제 서버·브라우저 플레이 검증과 구분합니다.
