# Onboarding 모듈

접속 직후의 입구 화면(화면 01~05)입니다. 로그인, 가입 정보 입력, 배울 언어 선택, 레벨 테스트, NPC 대화 난이도 설정을 거쳐 튜토리얼(`HomeScene`)로 보내고, 초기 설정을 마친 사용자는 마지막 장소(없으면 마을 `TownScene`)로 보냅니다. 게스트는 캐릭터만 골라 바로 튜토리얼로 갑니다. 배포용 씬 `EntryScene`이 Scene List의 첫 씬입니다.

공간 화면에서 내 정보를 보고 닉네임을 바꾸거나 시점 감도를 조절하거나 로그아웃하는 마이페이지도 이 모듈이 맡습니다. 로그아웃하면 `EntryScene`의 로그인 화면으로 돌아옵니다.

서버 연동이 있는 게임 전용 기능입니다. 진행 판단은 일반 C# 클래스에 두고, 패널은 입력 전달과 표시만 맡습니다.

## 구성

| 파일 | 역할 |
| --- | --- |
| `OnboardingFlow` | 접속 상태로 첫 화면을 정하고, 화면에 필요한 데이터를 불러 둔 뒤 다음 화면으로 넘깁니다. 요청이 실패하면 화면을 그대로 두고 서버 메시지를 담으며, 로그인이 풀렸으면 로그인 화면으로, 접속 상태부터 읽지 못했으면 [다시 시도] 화면으로 갑니다. |
| `EntryRouter` | BOOT-01과 ONB-08의 마지막 레벨 테스트 상태로 화면을 정합니다. |
| `SignupForm`, `NicknameRule` | 가입 정보 입력 상태와 닉네임 규칙. 서버(AUTH-04)와 같은 기준으로 입력 중에 바로 안내하며, 안내 문구(`NicknameRule.Describe`)는 마이페이지와 함께 씁니다. |
| `IOnboardingApi`, `IMyPageApi`, `ILogoutApi`, `OnboardingApi` | BOOT-01, AUTH-01·03·04·05·06·07·08, ONB-01·02·07·08·09, WORLD-01, USER-04와 개발용 로그인의 경로와 본문. 입구 화면·마이페이지·로그아웃이 필요한 API만 보도록 인터페이스를 나눕니다. |
| `MyPageFlow`, `MyPageText` | 마이페이지의 내 정보 읽기(BOOT-01)와 닉네임 변경(USER-04), 보여 줄 문구. Unity 객체 없이 테스트합니다. |
| `GuestPanelText` | 게스트 캐릭터 선택 화면의 닉네임·대화 횟수 안내. 횟수를 읽지 못하면 횟수 없이, 0이면 대화할 수 없다고 안내합니다. Unity 객체 없이 테스트합니다. |
| `AvatarButtons` | 가입·게스트 화면의 [여성]·[남성] 중 고른 버튼을 강조색으로 칠하고 체크 배지(`Check`)를 켭니다. |
| `LogoutFlow` | 로그아웃(AUTH-05). 이미 로그인이 풀렸어도 입구 화면으로 보냅니다. Unity 객체 없이 테스트합니다. |
| `MyPageView` | 오른쪽 위 메뉴의 [내 정보]와 마이페이지 창·로그아웃 확인 창. 단어장 HUD 프리팹(`Prefabs/Learning/LearningHud`)에 붙어 있어 장소 씬마다 배치하지 않습니다. |
| `OnboardingScreen` | 패널 입력을 `OnboardingFlow`에 전달하고 결과 화면을 보여 줍니다. 튜토리얼·마을 단계가 되면 씬을 바꿉니다. |
| `LoginPanelView` | 화면 01 로그인 메인. 확정 시안(e1 다듬은 A안)대로 마을 배경 위 왼쪽을 크림색 그라데이션으로 덮고, 왼쪽 열에 '낯선 마을에서 보내는 첫날' 칩·ElseHere 로고(남색 Else, 코랄 Here)·소개 문장, 같은 폭의 [Google로 계속하기]·[게스트로 둘러보기], 밑줄 친 이용약관 · 개인정보 처리방침을 둡니다. 칩은 남색, [게스트로 둘러보기]는 코랄로 로고 색에 맞추고, 소개 문장과 약관 링크는 로고의 남색을 옅게 한 색입니다. 칩·로고·버튼은 렌더링한 그림(`Art/UI/Login`)이고, 소개 문장과 약관 링크는 글자입니다. 마을 배경(`LoginTown`)은 **Tools → A305 → Onboarding → Capture Login Town**(`LoginTownCapture`)이 지금 마을(`TownScene`)에서 낮 11시로 찍습니다. 마을 모습이 바뀌면 다시 찍습니다. **Tools → A305 → Onboarding → Apply Login Screen**(`LoginScreenBuilder`)이 만들며, 테마 Builder(`UiThemeBuilder`)도 입구 화면을 칠한 뒤 이 Builder를 부릅니다. 개발용 로그인은 Editor·개발 빌드에서만 약관 링크 아래에 보입니다. |
| 그 밖의 입구 패널 | 화면 02~05, 게스트 캐릭터 선택(`GuestPanelView`), 접속 실패 화면(`ConnectionPanelView`). 언어·난이도 카드와 약관 줄은 템플릿을 복제합니다(`TemplateClones`). 창·버튼·입력칸은 화면 디자인(글래스 팝: 반투명 유리 창과 입체 버튼)으로 칠하고, 고른 캐릭터와 카드는 `ThemedElement.SetSelected`로 테마의 강조색 쪽으로 칠합니다. 고른 캐릭터 버튼에는 체크 배지도 켭니다. 약관·선택 동의 줄(가입·게스트·내 정보)의 체크는 줄 높이와 상관없이 같은 크기의 동그라미 그림(`Art/UI/Onboarding/ConsentCheckOff`·`ConsentCheckOn`)으로, 꺼지면 빈 동그라미, 켜지면 코랄 동그라미에 굵고 둥근 흰 체크입니다(**Tools → A305 → UI → Apply Consent Checks**). 화면 뒤 배경은 테마 강조색을 엷게 깐 색입니다. |
| `OnboardingSettings` | 튜토리얼·마을 씬 이름과 개발용 로그인 사용자(`Data/Onboarding/OnboardingSettings.asset`) |
| `BrowserRedirect`, `Plugins/WebGL/BrowserRedirect.jslib` | Google 로그인을 같은 탭에서 엽니다. |
| 나머지 | API 요청·응답 DTO |

## 의존성

| 대상 | 용도 |
| --- | --- |
| `A305.Api` | 서버 호출 |
| `A305.Player` | 마이페이지가 열려 있는 동안 이동 잠금(`PlayerMover.SetMovementLocked`), 시점 감도 배율(`LookSensitivity`) |
| uGUI, TextMeshPro | 화면 |
| `com.github.kou-yeung.webglinput` | Web 빌드의 닉네임 입력창에서 한글 조합(IME)을 받습니다. Builder가 입력창에 붙입니다. |

## 동작 규칙

| 상황 | 동작 |
| --- | --- |
| 로그인하지 않음(BOOT-01 401) | 화면 01. [Google로 계속하기]는 같은 탭에서 Google 로그인으로 이동하고, 끝나면 서버가 첫 화면으로 돌려보냅니다. 실패하면 `?loginError=true`로 돌아와 안내합니다. 창 아래 [이용약관]·[개인정보 처리방침]은 새 탭에서 서버 약관 문서(`/terms/2026-10`, `/privacy/2026-11`)를 엽니다. 주소는 서버 `ConsentCatalog`의 버전과 같게 둡니다. |
| [게스트로 시작하기] | 서버를 부르기 전에 캐릭터 선택 화면을 열고, 게스트 안내(AUTH-08)로 대화할 수 있는 횟수를 읽어 "게스트는 NPC와 3번까지 대화할 수 있어요"로 보입니다(횟수는 서버 설정값). 읽는 동안 버튼을 막지 않고, 읽지 못하면 횟수 없이 안내합니다. 캐릭터를 골라야 [시작하기](AUTH-07)를 누를 수 있고, [뒤로]는 화면 01입니다. 닉네임은 서버가 `guest-` 뒤에 숫자를 붙여 정하고, 언어·난이도는 영어·초급으로 정해 튜토리얼로 갑니다. 게스트는 NPC 대화 횟수가 정해져 있어, 다 쓰면 대화 시작 때 서버 안내(`AI_QUOTA_EXHAUSTED`)가 대화 상태 문구로 보입니다. |
| 가입 대기 | 화면 02. 닉네임 규칙과 [중복 확인](AUTH-06), 캐릭터, 필수 약관 동의가 모두 있어야 [가입하기]를 누를 수 있습니다. 닉네임을 바꾸면 다시 확인해야 합니다. 약관 아래에는 음성 처리(선택)에 동의해야 [말하기]를 쓸 수 있고 나중에 내 정보에서 바꿀 수 있다는 안내를 둡니다. |
| `LANG` | 화면 03. 고를 수 없는 언어는 "준비 중"입니다. |
| `LEVEL` | ONB-08의 마지막 테스트가 없거나 진행 중이면 화면 04, 끝났으면 화면 05입니다. |
| 화면 04 | MVP는 [레벨 테스트 진행하기]를 막아 두고 [건너뛰기](ONB-07)만 씁니다. |
| 화면 05 | 고른 적이 없으면 고를 수 있는 첫 단계(초급)를 미리 골라 둡니다. 추천 단계에는 "레벨 테스트 추천" 배지가 붙습니다. |
| `TUTORIAL` | `HomeScene`을 엽니다. 튜토리얼은 처음부터 다시 진행합니다. |
| `DONE` | 마지막 장소(`lastSceneCode`)가 있으면 장소 목록(WORLD-01)에서 그 장소의 Unity 씬(`unityKey`)을 찾아 엽니다. 값이 없거나, 닫혔거나, 목록이나 이 빌드의 Scene List에 없으면 `TownScene`을 엽니다. 장소 안의 위치는 씬에 놓인 플레이어 위치에서 시작합니다. |

| 접속 상태를 읽지 못함 | 연결 실패, 서버 오류, 가입 대기 사용자의 약관 조회 실패처럼 첫 화면을 정하지 못하면 "접속하지 못했어요" 화면과 [다시 시도]를 보여 줍니다. 실패 이유는 화면 아래 안내 문구에 나옵니다. |
| 요청을 기다리는 중 | 버튼을 막고 화면 아래에 "잠시만 기다려 주세요..."를 보여 줍니다. 서버 오류가 아닌 예외는 로그를 남기고 "문제가 생겼어요. 다시 시도해 주세요."로 안내합니다. |

### 마이페이지

| 상황 | 동작 |
| --- | --- |
| [내 정보] | 오른쪽 위 메뉴(≡)를 펼치면 [단어장]·[피드백 목록] 아래에 있습니다. 누르면 화면을 어둡게 덮고 마이페이지 창을 열며, 열 때마다 BOOT-01로 닉네임·캐릭터·배우는 언어를 다시 읽습니다. 열려 있는 동안 플레이어 이동을 잠급니다. 대화처럼 다른 화면이 이동을 잠근 동안에는 누를 수 없습니다. |
| [닉네임 변경] | 가입과 같은 닉네임 규칙으로 먼저 확인해 어긋나면 서버를 부르지 않고 고칠 점을 안내합니다. 지금 닉네임과 같으면 보내지 않습니다. 다른 사람이 쓰는 닉네임이면 서버 안내(`NICKNAME_TAKEN`)를 보여 줍니다. |
| 시점 감도 | 닉네임 안내 아래 슬라이더로 0.5~2배를 0.1 단위로 고릅니다. 움직이는 대로 저장해 창을 닫지 않아도 다음 회전부터 마우스·터치 모두에 적용됩니다. 서버가 아니라 이 기기(Web 빌드는 브라우저)에 저장하므로 다른 기기에는 따라가지 않습니다. |
| [로그아웃] | 확인 창에서 처음 화면으로 돌아간다는 점과, 게스트는 같은 기록으로 다시 들어올 수 없다는 점을 알립니다. 확인하면 AUTH-05 뒤 `EntryScene`을 엽니다. 실패하면 이유를 보이고 다시 누를 수 있습니다. |
| [회원 탈퇴] | 회원에게만 보입니다. 게스트(BOOT-01 `user.guest`)는 지울 계정이 없고 내용도 게스트 정리 규칙으로 지워지므로 보이지 않습니다. 게스트인지 알기 전(내 정보를 읽기 전·읽지 못함)에도 숨깁니다. 확인 창을 거쳐 USER-05 뒤 `EntryScene`을 엽니다. |
| [닫기] | 창을 닫고 이동 잠금을 풉니다. 요청을 기다리는 동안에는 닫지 않습니다. |

- Editor와 개발 빌드에서는 [개발용 로그인]이 보입니다. 백엔드를 local 프로필로 띄우고, `OnboardingSettings`의 사용자 ID가 DB에 있어야 합니다. Editor는 브라우저 쿠키를 쓰지 않으므로 Google 로그인 대신 이 버튼을 씁니다.
- 가입 화면은 Google 가입 대기 세션이 있어야 열리므로 로컬에서는 Google 로그인 설정이 있어야 확인할 수 있습니다.

## 확인 방법

1. **Tools → A305 → Onboarding → Build**로 프리팹·설정·씬을 만듭니다. 처음이면 **UI → Set Up Fonts**를 먼저 실행합니다.
2. 백엔드를 local 프로필로 실행하고 `Scenes/Sandbox/OnboardingSandbox.unity`를 Play합니다.
3. 한글 입력은 Editor에서 확인되지 않습니다. **Tools → A305 → Onboarding → Build Ime Check Web**으로 입력창 하나만 둔 Web 빌드(`Builds/ImeCheck`)를 만들어 브라우저에서 한글을 입력해 봅니다.

## 테스트

`Tests/EditMode/Onboarding/`(`A305.Onboarding.Tests`)에서 화면 분기, 닉네임 규칙과 안내 문구, 가입 입력 상태, API 경로, 진행 흐름(가짜 API), 게스트 대화 횟수 안내(읽기·실패 시 횟수 없이·0번), 고른 캐릭터 체크, 약관·선택 동의 체크 모양(`ConsentCheckPrefabTests`), 로그인 메인 배치(`LoginScreenPrefabTests`), 마이페이지(내 정보 읽기·게스트 여부·닉네임 변경 규칙·중복·요청 중 다시 보내지 않기·표시 문구·[회원 탈퇴]는 회원에게만)와 로그아웃(성공·이미 풀린 로그인·실패 이유·중복 요청)을 검증합니다. 마이페이지 창 배치는 Play·브라우저에서 확인합니다.
