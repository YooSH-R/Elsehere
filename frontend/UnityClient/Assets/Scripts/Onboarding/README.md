# Onboarding 모듈

접속 직후의 입구 화면(화면 01~05)입니다. 로그인, 가입 정보 입력, 배울 언어 선택, 레벨 테스트, NPC 대화 난이도 설정을 거쳐 튜토리얼(`HomeScene`)로 보내고, 초기 설정을 마친 사용자는 마지막 장소(없으면 마을 `TownScene`)로 보냅니다. 게스트도 캐릭터를 고른 뒤 레벨테스트 안내를 먼저 봅니다. [시작하기]는 테스트 API를 호출하지 않고 로그인 안내 모달을 띄웁니다. [Google로 로그인]은 현재 게스트 세션의 로그인 경로로 연결하고, [건너뛰기]·[게스트로 계속하기]는 테스트 건너뛰기 기록을 생성하지 않고 원래 목적지인 튜토리얼·마지막 장소로 이어집니다. 모달의 ×는 소개 화면으로 돌아갑니다. 게스트 세션이 남은 채 다시 접속한 게스트에게는 게임에 들어가기 전에 가입과 게스트로 계속하기를 고르게 하고, 게스트가 Google로 가입하면 게스트 때 기록을 그대로 이어 게임으로 돌아갑니다. 배포용 씬 `EntryScene`이 Scene List의 첫 씬입니다.

공간 화면에서 내 정보를 보고 닉네임을 바꾸거나 시점 감도·NPC 말 빠르기를 조절하거나 로그아웃하는 마이페이지도 이 모듈이 맡습니다. 로그아웃하면 `EntryScene`의 로그인 화면으로 돌아옵니다. 창에 줄을 더하면 `MyPagePreview.Capture`(`Tools/A305/Onboarding/Capture My Page`)로 실제 HUD 프리팹의 내 정보 창을 서버 호출 없이 캡처해 겹침·잘림을 확인합니다. 이미 만든 HUD에 NPC 말 빠르기 줄만 덧붙일 때는 `Tools/A305/UI/Add NPC Speech Speed Setting`을 씁니다.

서버 연동이 있는 게임 전용 기능입니다. 진행 판단은 일반 C# 클래스에 두고, 패널은 입력 전달과 표시만 맡습니다.

## 구성

| 파일 | 역할 |
| --- | --- |
| `OnboardingFlow` | 접속 상태로 첫 화면을 정하고, 화면에 필요한 데이터를 불러 둔 뒤 다음 화면으로 넘깁니다. 요청이 실패하면 화면을 그대로 두고 서버 메시지를 담으며, 로그인이 풀렸으면 로그인 화면으로, 접속 상태부터 읽지 못했으면 [다시 시도] 화면으로 갑니다. |
| `EntryRouter` | BOOT-01과 ONB-08의 마지막 레벨 테스트 상태로 화면을 정합니다. |
| `SignupForm`, `NicknameRule` | 가입 정보 입력 상태와 닉네임 규칙. 서버(AUTH-04)와 같은 기준으로 입력 중에 바로 안내하며, 안내 문구(`NicknameRule.Describe`)는 마이페이지와 함께 씁니다. 게스트가 가입하는 중이면(AUTH-03 `guest`) 게스트 때 캐릭터와 음성 처리 동의로 채워 시작합니다. 약관 단계의 [전체 동의](`AgreeAll`·`IsAllAgreed`)와 [다음](`CanContinueFromTerms`, 필수 약관만 필요)도 판단합니다. |
| `TermsPanelView` | 가입의 첫 단계인 약관 동의 창. [전체 동의], 서버 약관 수만큼 복제하는 약관 줄(`ConsentRowView`), 음성 처리 안내, [다음]. 체크는 늘 `SignupForm` 상태에 맞춥니다. e3 시안을 두 단계로 나눈 것이라 같은 유리 창·줄 모양을 쓰고, [다음]·좁은 [가입하기] 그림(`EntryNext`·`EntrySignupShort`)은 시안 버튼 그림에서 글자만 Jua로 바꿔 그렸습니다(**Tools → A305 → Onboarding → Apply Terms Step**). |
| `GuestReturnPanelView`, `GuestReturnText` | 게임에 들어가기 전에 한 번 멈춰 알리는 화면. 게스트로 다시 접속하면 [Google로 가입하고 이어 하기]·[게스트로 계속하기], 게스트 세션에서 이미 가입한 계정으로 들어오면 합치지 않았다는 안내와 [계속하기]를 보입니다. 시안이 없어 접속 실패 창과 같은 유리 창에 테마 알약 버튼을 둡니다(**Tools → A305 → Onboarding → Apply Guest Return Panel**). |
| `IOnboardingApi`, `IMyPageApi`, `ILogoutApi`, `OnboardingApi` | BOOT-01, AUTH-01·03·04·05·06·07·08, ONB-01~10, CONV-02(레벨 테스트 말하기 답, `purpose: LEVEL_TEST`), WORLD-01, USER-04와 개발용 로그인의 경로와 본문. 입구 화면·마이페이지·로그아웃이 필요한 API만 보도록 인터페이스를 나눕니다. |
| `LevelTestSession` | 화면 04에서 푸는 레벨 테스트(ONB-03 응답). 보이는 문항과 "문항 n / N"·진행률, 고른 보기·쓴 답, 듣기 횟수(처음 한 번 + 다시 듣기 한 번), [다음]을 누를 수 있는지, 서버에 보낼 답, 결과 문구(추천 난이도 이름, "듣기 3 / 4", "말하기 2 / 2 통과")를 정합니다. Unity 객체 없이 테스트합니다. |
| `LevelTestPanelView` | 화면 04 레벨 테스트 창. 안내(L1), 듣기(L2, `LevelTestListenView`·보기 줄 `LevelTestChoiceRow`), 말하기(L3, `LevelTestSpeakView`), 결과(L4, `LevelTestResultView`)를 한 유리 창에서 바꿔 보이고 창 높이는 보이는 내용에 맞춥니다. 듣기 음성(ONB-10)은 `LevelTestSpeechPlayer`가 받아 들려주고, 말하기 녹음은 창에 붙은 `VoiceRecorder`로 받습니다. 고른 보기·쓴 답·들은 횟수·녹음은 이벤트로 알리고, 상태는 `OnboardingFlow.LevelTest`가 가집니다. 확정 시안 L1~L4대로 **Tools → A305 → Onboarding → Apply Level Test Screens**(`LevelTestScreenBuilder`)가 만들며, 칸·버튼·아이콘·점수 칸은 시안을 렌더링한 그림(`Art/UI/Entry/LevelTest*`), 서버 글자와 버튼 이름은 글자(제목·버튼 Jua, 본문 Pretendard)입니다. |
| `MyPageFlow`, `MyPageText` | 마이페이지의 내 정보 읽기(BOOT-01)와 닉네임 변경(USER-04), 보여 줄 문구. Unity 객체 없이 테스트합니다. |
| `GuestPanelText` | 게스트 캐릭터 선택 화면의 닉네임·대화 횟수 안내. 0(기본, 제한 없음)이면 "게스트도 NPC와 마음껏 대화할 수 있어요", 1 이상이면 횟수, 읽기 전이거나 읽지 못하면 닉네임 안내만 보입니다. Unity 객체 없이 테스트합니다. |
| `AvatarButtons` | 가입·게스트 화면의 [여성]·[남성] 중 고른 버튼을 강조색으로 칠하고 체크 배지(`Check`)를 켭니다. |
| `LogoutFlow` | 로그아웃(AUTH-05). 이미 로그인이 풀렸어도 입구 화면으로 보냅니다. Unity 객체 없이 테스트합니다. |
| `MyPageView` | 오른쪽 위 메뉴의 [내 정보]와 마이페이지 창·로그아웃 확인 창. 단어장 HUD 프리팹(`Prefabs/Learning/LearningHud`)에 붙어 있어 장소 씬마다 배치하지 않습니다. |
| `SessionExpiredView` | 장소 화면에서 서버가 로그인이 풀렸다고 알리면(`ApiSession.Expired`) 다른 모든 창(수첩 포함) 위에 "접속이 끊겼어요" 안내를 띄우고 이동을 막습니다. [처음 화면으로]는 `EntryScene`의 로그인 화면으로 돌아갑니다. HUD 프리팹의 `SessionExpired`(정렬 2000의 자체 캔버스)에 있어 장소 씬마다 배치하지 않습니다. |
| `OnboardingScreen` | 패널 입력을 `OnboardingFlow`에 전달하고 결과 화면을 보여 줍니다. 튜토리얼·마을 단계가 되면 씬을 바꿉니다. |
| `LoginPanelView` | 화면 01 로그인 메인. 확정 시안(e1 다듬은 A안)대로 마을 배경 위 왼쪽을 크림색 그라데이션으로 덮고, 왼쪽 열에 '현지에서 살며 배우는 언어' 칩·ElseHere 로고(남색 Else, 코랄 Here)·소개 문장, 같은 폭의 [Google로 계속하기]·[게스트로 둘러보기], 밑줄 친 이용약관 · 개인정보 처리방침을 둡니다. 칩은 남색, [게스트로 둘러보기]는 코랄로 로고 색에 맞추고, 소개 문장과 약관 링크는 로고의 남색을 옅게 한 색입니다. 오래 머물며 여러 언어로 넓힐 서비스이므로 칩·소개 문장에 '첫날'이나 특정 언어 이름을 쓰지 않습니다. 칩·로고·버튼은 렌더링한 그림(`Art/UI/Login`)이고, 소개 문장과 약관 링크는 글자입니다. 마을 배경(`LoginTown`)은 **Tools → A305 → Onboarding → Capture Login Town**(`LoginTownCapture`)이 지금 마을(`TownScene`)에서 낮 11시로 찍습니다. 마을 모습이 바뀌면 다시 찍습니다. **Tools → A305 → Onboarding → Apply Login Screen**(`LoginScreenBuilder`)이 만들며, 테마 Builder(`UiThemeBuilder`)도 입구 화면을 칠한 뒤 이 Builder를 부릅니다. 개발용 로그인은 Editor·개발 빌드에서만 약관 링크 아래에 보입니다. |
| 그 밖의 입구 패널 | 화면 02~05, 게스트 캐릭터 선택(`GuestPanelView`), 접속 실패 화면(`ConnectionPanelView`). 언어·난이도 카드와 약관 줄은 템플릿을 복제합니다(`TemplateClones`). 창·버튼·입력칸은 화면 디자인(글래스 팝: 반투명 유리 창과 입체 버튼)으로 칠하고, 고른 캐릭터와 카드는 `ThemedElement.SetSelected`로 테마의 강조색 쪽으로 칠합니다. 고른 캐릭터 버튼에는 체크 배지도 켭니다. 약관·선택 동의 줄(가입·게스트·내 정보)의 체크는 줄 높이와 상관없이 같은 크기의 동그라미 그림(`Art/UI/Onboarding/ConsentCheckOff`·`ConsentCheckOn`)으로, 꺼지면 빈 동그라미, 켜지면 코랄 동그라미에 굵고 둥근 흰 체크입니다(**Tools → A305 → UI → Apply Consent Checks**). 화면 뒤 배경은 테마 강조색을 엷게 깐 색입니다. |
| 진입 화면 e2~e5 | 접속 확인·대기와 로그인 뒤 게스트 캐릭터 고르기(`GuestPanelView`), 가입 정보 입력(`SignupPanelView`), 접속 실패(`ConnectionPanelView`)는 확정 시안 e2·e3·e5대로 흐린 마을(`Background/WindowTown`) 위 화면 가운데의 불투명한 유리 창입니다. 창이 없는 접속 확인 중에는 로그인과 같은 마을 배경·크림색 그라데이션(`Background/Town`, `Background/Shade`)을 보이고, 가운데 창이 뜨면 그라데이션 없이 흐린 마을로 바꿉니다(`EntryBackdropView`). 시안은 e2·e3을 왼쪽에 두지만 로그인 뒤에는 창 하나만 떠서 e5처럼 가운데에 둡니다. 화면 04 레벨 테스트 창도 같은 배경 위 가운데 유리 창입니다(`LevelTestPanelView`). 버튼·캐릭터 카드·와이파이 아이콘은 시안을 렌더링한 그림(`Art/UI/Entry`, 버튼 글자는 아래 두께까지 포함한 가운데)이고, 캐릭터 카드는 고르면 코랄 테두리·체크 그림으로 바뀝니다(`ChoiceArt`). 게스트 안내는 첫 줄에 대화 횟수(코랄 굵은 글자), 둘째 줄에 닉네임 안내를 둡니다(`GuestPanelText`). 가입 화면의 음성 동의 안내는 시안에 없지만 동의 줄 아래에 둡니다. 배치는 **Tools → A305 → Onboarding → Apply Entry Screens**(`EntryScreensBuilder`)가 만들고 테마 Builder도 이 Builder를 부릅니다. 레벨 테스트 창은 이 Builder가 `LevelTestScreenBuilder`에 맡깁니다. |
| `OnboardingSettings` | 튜토리얼·마을 씬 이름과 개발용 로그인 사용자(`Data/Onboarding/OnboardingSettings.asset`) |
| 나머지 | API 요청·응답 DTO |

## 의존성

| 대상 | 용도 |
| --- | --- |

| `A305.Player` | 마이페이지가 열려 있는 동안 이동 잠금(`PlayerMover.SetMovementLocked`), 시점 감도 배율(`LookSensitivity`) |

## 동작 규칙

| 상황 | 동작 |
| --- | --- |
| 로그인하지 않음(BOOT-01 401) | 화면 01. [Google로 계속하기]는 같은 탭에서 Google 로그인으로 이동하고, 끝나면 서버가 첫 화면으로 돌려보냅니다. 실패하면 `?loginError=true`로 돌아와 안내합니다. 창 아래 [이용약관]·[개인정보 처리방침]은 새 탭에서 서버 약관 문서(`/terms/2026-10`, `/privacy/2026-11-09`)를 엽니다. 웹 Nginx가 버전이 붙은 주소만 서버로 넘기므로 버전 없는 주소는 쓰지 않고, 서버 `ConsentCatalog`의 지금 주소와 같은지 `LoginScreenPrefabTests`가 확인합니다. |
| [게스트로 시작하기] | 서버를 부르기 전에 캐릭터 선택 화면을 열고, 게스트 안내(AUTH-08)로 대화할 수 있는 횟수를 읽어 안내합니다. 기본은 제한이 없어 "게스트도 NPC와 마음껏 대화할 수 있어요"이고, 서버에서 제한을 켜면 "게스트는 NPC와 3번까지 대화할 수 있어요"처럼 횟수를 보입니다. 읽는 동안 버튼을 막지 않고, 읽지 못하면 닉네임 안내만 보입니다. 캐릭터를 골라야 [시작하기](AUTH-07)를 누를 수 있고, [뒤로]는 화면 01입니다. 닉네임은 서버가 `guest-` 뒤에 숫자를 붙여 정하고, 언어·난이도는 영어·초급으로 정해 튜토리얼로 갑니다. 게스트가 첫 호텔 퀘스트를 끝내면 가입 안내 창이 뜹니다([Mission](../Mission/README.md)). 서버에서 게스트 대화 횟수 제한을 켜면, 다 쓴 뒤 [말 걸기] 자리에 [가입하고 계속 대화하기]가 보입니다([Npc](../Npc/README.md)). 입구는 BOOT-01로 받은 게스트 여부를 장면을 옮겨도 남는 `PlayerAccount`([Api](../Api/README.md))에 둡니다. 방금 게스트로 시작했으면 가입을 권하지 않고 바로 튜토리얼로 갑니다. |

## 확인 방법

캐릭터 선택 사진은 실제 남녀 플레이어의 정면 모습으로 만듭니다. 기본 상태는 편안한 입 모양이고, 선택하면 미소·코랄 테두리·체크 배지가 있는 사진으로 바뀝니다. 머리 높이는 사진 영역의 76%, 위 여백은 8%로 맞춰 캐릭터를 바꿔도 카드 속 크기와 위치가 달라지지 않게 촬영합니다. 남성 촬영 복사본은 골반부터 가슴·목·머리까지 정면 자세를 복원하고, 실제 양쪽 눈 위치로 얼굴의 좌우 회전·기울기를 맞춥니다. 여성은 기존 촬영 자세를 유지합니다. **Tools → A305 → Onboarding → Capture Player Portraits**로 `Art/UI/Entry`의 게스트·가입 카드 8장을 다시 촬영할 수 있습니다. 자세와 입 모양 변경은 촬영용 복사본에만 적용하므로 게임 캐릭터 원본과 런타임 표정에는 영향을 주지 않습니다. 기존 `ChoiceArt` 연결과 이미지 GUID를 유지합니다.

1. **Tools → A305 → Onboarding → Build**로 프리팹·설정·씬을 만듭니다. 처음이면 **UI → Set Up Fonts**를 먼저 실행합니다.
2. 백엔드를 local 프로필로 실행하고 `Scenes/Sandbox/OnboardingSandbox.unity`를 Play합니다.
3. 한글 입력은 Editor에서 확인되지 않습니다. **Tools → A305 → Onboarding → Build Ime Check Web**으로 입력창 하나만 둔 Web 빌드(`Builds/ImeCheck`)를 만들어 브라우저에서 한글을 입력해 봅니다.

`Tests/EditMode/Onboarding/`(`A305.Onboarding.Tests`)에서 화면 분기, 닉네임 규칙과 안내 문구, 가입 입력 상태, API 경로, 진행 흐름(가짜 API), 게스트로 다시 접속하면 가입·계속하기를 먼저 고르고 계속하면 원래 장소로 가기, 방금 시작한 게스트는 바로 튜토리얼, 이미 가입한 계정 안내, 게스트 가입은 게스트 캐릭터·음성 동의로 시작해 가입 뒤 원래 장소로 가기, 게스트 대화 횟수 안내(읽기·실패 시 횟수 없이·0번), 게임 전 멈춤 화면과 가입 화면 안내 문구 연결(`GuestReturnPanelPrefabTests`), 가입 두 단계(약관 먼저·[다음]은 필수 약관만·[뒤로]는 동의 유지·[전체 동의] 켜고 끄기)와 두 창이 가로 휴대폰에 들어가고 약관 6줄이 안내·[다음]과 겹치지 않는지(`EntryScreensLayoutTests`), 고른 캐릭터 체크, 약관·선택 동의 체크 모양(`ConsentCheckPrefabTests`), 로그인 메인 배치(`LoginScreenPrefabTests`), 화면 04 레벨 테스트(문항·"문항 n / N"·다시 듣기 한 번·[다음] 조건·보낼 답·결과 문구는 `LevelTestSessionTests`, 시작·답 저장·마지막 문항 채점·채점 실패 뒤 다시 채점·그만하기·결과 뒤 화면 05·받아 적은 말로 답 바꾸기는 `OnboardingFlowTests`, ONB-03~06·10과 CONV-02 `LEVEL_TEST` 경로는 `OnboardingApiTests`), 화면 05에서 추천 난이도 미리 고르기(`LevelSettingPreselectionTests`), 마이페이지(내 정보 읽기·게스트 여부·닉네임 변경 규칙·중복·요청 중 다시 보내지 않기·게스트 닉네임 막기·표시 문구·[회원 탈퇴]는 회원에게만)와 로그아웃(성공·이미 풀린 로그인·실패 이유·중복 요청)을 검증합니다. 마이페이지 창 배치와 레벨 테스트 창의 시안 일치·음성 재생·마이크 녹음은 Play·브라우저에서 확인합니다.

로그인의 Google·게스트 버튼은 같은 Jua 글꼴·크기의 TMP 글자와 고정 아이콘 열을 사용합니다. Google은 기존 브랜드 그림에서 로고만 표시하고, 게스트는 사람 아이콘을 표시합니다. 같은 폭의 아이콘 칸·문구 칸을 한 묶음으로 가로·세로 중앙에 맞추고, 글자는 문구 칸의 같은 시작점에서 표시합니다. 아이콘 그림의 투명 여백을 제외한 크기를 24px로 맞추며 아이콘 열과 문구 사이에 18px 간격을 둡니다. 흰색·코랄 바탕과 기존 클릭 동작은 유지합니다. 바탕과 게스트 아이콘은 `LoginButtonArt`가 생성하고 `LoginScreenBuilder`가 연결합니다.

게스트 레벨테스트 로그인 모달은 기존 입구 안내창을 재사용하고 뒤의 테스트 입력을 막습니다. **Tools → A305 → Onboarding → Apply Guest Level Test Login**이 입구 프리팹과 연결을 갱신합니다. 외부 호출 없는 화면 확인은 GUEST_LEVEL_PREVIEW_OUTPUT을 설정하고 GuestLevelTestLoginBuilder.Capture를 실행합니다. 일반 회원의 언어 선택·레벨테스트 API 흐름은 기존대로 유지합니다.
